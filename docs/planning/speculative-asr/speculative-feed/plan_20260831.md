## 0. The design in one paragraph

The feed is a new `@MainActor` object in `VoccaAudio` (`SpeculativeFeed`) that becomes the
ring's consumer during `.recording`: it drains the ring on a 50 ms repeating timer, converts
each drain through the *same* `AudioFormatConverter` `MicrophoneSource` already owns (chunked
`convert` per tick, `finish` at `endCapture`), holds chunks back until the accumulated buffer
passes the engine's minimum, and yields `AsyncStream<AudioBuffer>` into the shipped
`DictationPipeline.routeStreaming`. The router starts the feed on `.opening`, and on every
terminal stops the timer; on `.ended(.completed)` it appends the outcome's audio — the
*remainder* `endCapture` drained — as the stream's final chunk, finishes the stream, and routes
through `routeStreaming`; on `.ended(.cancelled)` and `.captureUnavailable` it cancels the
feed (stream finished, nothing appended). The production `pipelineAssembly` wires a real
`PartialTranscriptSink` into the widget store. **No new dependency; no change to the realtime
thread; the ring's SPSC warrant is preserved because the feed tick and `endCapture` are both
main-actor, hence serialized.**

### Phase (a) — The ring-consumer ownership contract: documented and pinned

**Goal.** Make the ownership change deliberate *before* any behavior changes: the SPSC warrant and
`MicrophoneSource`/`CaptureGraphSeam` docs now say the feed is the ring's consumer during
`.recording` and `endCapture` drains only the remainder. Pin the new contract by test. Name and
reject the alternative.

**Prerequisites.** None.

**Files to modify.**
- `Sources/VoccaAudio/AudioRingBuffer.swift` — the SPSC warrant comment (`:51-58`, claim 1).
  Currently: "at most one thread calls the producer API and at most one thread calls the consumer
  API ... Either role may *move* between threads over the buffer's life ... but only with a
  happens-before edge between the outgoing and incoming occupant". Amend claim 1 to record that
  the consumer role is **handed over** at the session boundary: `SpeculativeFeed` owns it during
  `.recording`, `MicrophoneSource.endCapture` takes it for the remainder drain — both main-actor,
  serialized by it, so the "at most one consumer thread at a time" discipline and the
  happens-before edge (the machine's synchronous `.ended` transition) still hold. Keep the
  claim-2 sentence "**No atomic in this file has two writers**" untouched — nothing here adds a
  writer. Also amend the `availableToRead`/`drain` consumer-side trap note if it names
  `endCapture` as the only consumer.
- `Sources/VoccaAudio/MicrophoneSource.swift` — the type's header ("The conformance is the
  consumer: it drains this at `endCapture()`", `:36-38` is the seam's `ring` doc) and the
  "Exactly once per session" section (`:114-120`) and the `endCapture()` doc (`:199-210`): state
  the remainder contract — a mid-session consumer (the feed) has already drained part of the
  ring; `endCapture` drains the *rest*, exactly once, and the conversion is contiguous with the
  feed's because it is the same converter.
- `docs/STATUS.md`, `CLAUDE.md`, `ARCHITECTURE.md` §16 — record the ownership change (the doc-sync
  obligation; same commit).

**The rejected alternative (spec req 2; PRD Q4), quoted against the warrant.** *A second
feed-owned buffer written by the interleaver* is rejected. The warrant it violates is
`AudioRingBuffer.swift:51-58`: "At most one thread calls the producer API (`write`) and at most
one thread calls the consumer API (`read`, `drain`, `availableToRead`, `refusedSampleCount`),
and they are different roles." A second feed-owned buffer adds a **second realtime-path writer**
(the interleaver writes both the ring and the feed's buffer), which is "two concurrent producers
... break this type. There is no CAS anywhere here that would make them safe" (`:56-58`), and a
second realtime write site is a second place `RealtimeSafetyTests` and the drop-newest argument
(`:249-254`) would have to cover. The feed-as-consumer adds **no** realtime-path code. This
decision is final; the plan records it so a later reviewer does not re-litigate it as a fresh
idea.

### Phase (b) — The feed producer object

**Goal.** Ship `SpeculativeFeed`: session-keyed start, 50 ms drain tick, chunked converter
lifecycle, `AsyncStream<AudioBuffer>` emission, terminate-with-remainder. Make `MicrophoneSource`
own it (the only object that legitimately holds ring + converter) and expose it. This is the
phase whose commit message is the PRD's named example.

**Prerequisites.** Phase (a) committed.

**Files to create.**
- `Sources/VoccaAudio/SpeculativeFeed.swift` — the feed. `@MainActor final class`, constructed
  with `(ring: AudioRingBuffer, converter: AudioFormatConverter, timer: any RepeatingTimer,
  cadence: Duration = SpeculativeFeed.cadence, subMinimum: (@Sendable (Int) -> Bool)? = nil)`.
  Public surface, deliberately small:
  - `static let cadence: Duration = .milliseconds(50)` — **the one file that names the feed tick**
    (phase (e) scans it single-source).
  - `var chunks: AsyncStream<AudioBuffer>` — the stream `routeStreaming` consumes; created once,
    continuation stored.
  - `func start()` — arms the timer; a tick drains the ring, converts via
    `converter.convert(drained)`, accumulates; yields an `AudioBuffer(samples: sampleRate:
    AudioBuffer.interchangeSampleRate)` per tick.
  - `func terminate(with remainder: AudioBuffer?)` — stop the timer; if `subMinimum` holds
    accumulated samples, flush them; append `remainder.samples` (the outcome's audio — already
    converted by `endCapture`, so no conversion here); finish the stream. **Idempotent**: a second
    `terminate`/`cancel` is a no-op.
  - `func cancel()` — stop the timer, finish the stream with nothing appended. Idempotent.
  - Internal: a `stopped` flag the tick consults *before* draining ("nothing is read while idle" —
    the `SessionWatchdog.wake()` precedent, `SessionWatchdog.swift:300-312`); ticks after
    stop are no-ops. Empty drains are skipped (no empty `AudioBuffer` is ever yielded).
  - The sub-minimum hold: while `subMinimum?(pending.count) == true`, converted samples are
    accumulated and **not yielded**; the first yield happens at the tick where the accumulated
    count crosses the minimum, and carries the whole accumulated prefix (so the engine still sees
    every sample — see §2e). With a nil predicate (the default), every tick yields immediately
    (byte-for-byte "no suppression").
  - **Constraints honored:** never touches the realtime thread (drain + convert + yield all run on
    the main actor); no lock taken in a tick beyond the ring's own read; no `AsyncStream` yield
    after `finish`.
- `Tests/HarnessTests/SpeculativeFeedTests.swift` — the feed's unit tests (write first, RED):
  - A scripted growing ring (the `LatencyBenchmarkTests.write` helper shape,
    `LatencyBenchmarkTests.swift:953-957`) + a fake `RepeatingTimer` (the `ProbeTimer`/`FakeTimer`
    shape) + real `AudioFormatConverter` (48 kHz mono input): each manual timer fire converts the
    drained samples; the emitted chunks are contiguous 16 kHz mono (assert concatenation ==
    `converter.finish`-of-the-whole, the `testChunkedConversionProducesExactlyTheSameAudioAsASingleCall`
    precedent, `AudioFormatConverterTests.swift:461-483`).
  - `terminate(with:)` after N ticks: remainder appended as the last chunk, stream finished,
    further `start()`/`terminate()`/`cancel()` are no-ops, no chunk is yielded after finish.
  - A mid-tick terminal cannot strand a chunk: fire the timer once (one chunk yielded), then
    `terminate` — the stream ends with exactly the chunks yielded before terminate; the
    remainder is the last element; nothing after.
  - Empty drains are skipped: a tick with nothing in the ring yields nothing.
  - MicrophoneSource ownership: `MicrophoneSource` gains `public let feed: SpeculativeFeed`
    constructed in `init` (same ring, same converter) with injectable `feedTimer` /
    `feedSubMinimum` parameters (defaults keep every existing `MicrophoneSource` test
    byte-for-byte green: nil timer → an internal `MainRunLoopTimer`, nil predicate → no
    suppression).
- `Tests/HarnessTests/MicrophoneSourceTests.swift` — the **real ownership behavior** (the phase
  (a) contract test, now with the actual feed): start the feed, drain two ticks through a real
  ring, `endCapture()`; assert remainder == unconsumed tail exactly, missingSampleCount unchanged
  in meaning, and the stream + remainder concatenate to the whole audio (the batch-equivalence
  precondition the phase (c) test asserts end to end).

**Files to modify.** `Sources/VoccaAudio/MicrophoneSource.swift` (construct + expose the feed),
`Sources/VoccaAudio/AudioRingBuffer.swift` (already amended in (a)).

**Validation.**
1. `swift test --filter HarnessTests/SpeculativeFeedTests` — RED before the feed exists (the
   type does not compile).
2. Implement, then:
3. `swift test --filter HarnessTests/SpeculativeFeedTests`
4. `swift test --filter HarnessTests/MicrophoneSourceTests`
5. `Scripts/test-with-floor.sh` — raise `MINIMUM_EXECUTED_TESTS` to the new count in this commit
   (expect 1625 + the tests added here).

**Commit message.** `Add the feed's ring drain and its ownership change`

**§2c note — one feed, two machines.** Both `MicrophoneSource`s (hold and toggle) own a feed; at
most one session is in flight (the machine's single-session invariant). The router must start and
stop the feed of the *machine that is recording*. Because mode cannot change mid-session
(hotkey-rebinding rebuilds only when both machines are quiet), the router can hold a single
`activeFeed` slot set by the root on mode-routing changes, and start/stop that exact instance.
The plan pins: the router stores the instance it started and terminates that instance — never a
re-read of the active slot — so a terminal cannot stop the wrong feed. Flag to the founder if the
root's mode-routing seam (`ModeRoutingSink`) does not expose a hook to set the slot; the
alternative (both feeds wired, router keyed on wiring) is a larger change and is not needed.

### Phase (f) — The benchmark-gate span decision, named

**Goal.** Resolve the PRD's named contract question — *what does the gate measure with the feed
live?* — as a deliberate decision, never silent drift.

**The decision (named, recorded in the plan and in `docs/STATUS.md`):** **the gate and the closed
four-span contract stay post-key-up, unchanged.** `routeStreaming` measures the ASR span from its
own entry (`DictationPipeline.swift:211-227`), which is key-up; the speculative feed's pre-key-up
work is display + speculative accumulation and is **not** a latency span and carries **no claim**.
The gate's closed-span checks (`LatencyBenchmarkTests.swift:673-727`: every record's spans must be
`[.captureClose, .asr, .inject]` in order, no `cleanup`) and its p95-derived budgets are therefore
untouched. **Rejected alternatives, both named:** (i) *move the ASR span start to feed start* —
that redefines the span as session duration, making the 800 ms p95 budget meaningless, and
(ii) *add a `speculative` span kind* — it would break the closed-span check by construction and
re-baseline every budget for a number CI cannot produce.

**What does change** (the honest half): the **benchmark harness gains a streaming variant** — the
PRD's "writes fixture audio incrementally" (`BenchmarkHarness.runCycle` precedent,

## 5. Environment & privacy

- **Zero network, unchanged.** The feed adds no network name: it lives in `VoccaAudio`, reads
  only the in-session ring, and the probe's streaming cycle (`ZeroNetworkTests.swift:673`) must
  stay green with zero `connect(2)`. The probe presses no hotkey, so its feeds are constructed
  and never started; if the root's new `speculativeFeed:` parameter forces the probe to pass one,
  it passes its microphones' own feeds untouched.
- **Mic-dot policy untouched.** The feed drains only between `.opening` and a terminal; idle, its
  timer is stopped and nothing is read (`SessionWatchdog`'s "nothing is read while idle" rule,
  `SessionWatchdog.swift:300-312`). The audio engine stays cold when idle; only the *model*
  re-warms (M7, another aspect).
- **Audio stays on-device.** The feed converts on the consumer side and yields `[Float]` buffers
  in-process; no egress, no persistence, nothing new transmitted. The partial path was already
  widget-only by construction (`PartialTranscriptSink.swift:19-24`).

## 6. Edge cases & error handling

- **Every terminal cancels the feed** — the full set: all `RetainedEndReason` cases
  (`EndReason.swift:50-123`; the PRD's named four are a subset — `.modifierReleased`,
  `.tapDisabled`, and every `SystemTrigger` flow through the same `.ended(.completed)` row), the
  `.userCancelled` row, `.captureUnavailable`, and app termination (quit path; process death
  structurally stops the timer and releases the mic regardless).
- **Cancellation mid-drain-tick.** A stop event and a feed tick are both main-actor; the machine's
  terminal transition is synchronous (`SessionMachine.swift:656-662`), so no tick interleaves
  with `endCapture`. After `terminate`/`cancel`, the `stopped` flag makes later ticks no-ops and
  `terminate`/`cancel` are idempotent (a second call yields nothing, finishes nothing twice). The
  ordering pin is the `wake() → tick()` precedent (`SessionWatchdog.swift:312-401`).
- **The key-up remainder.** `endCapture` runs *before* the router sees `.ended` and drains the
  unconsumed tail; the router appends that remainder as the stream's final chunk, so the engine
  still receives the whole audio (batch-equivalence preserved). A remainder that is empty (the
  feed just drained everything) is skipped — no empty chunk is appended.
- **Sub-minimum whole session.** Everything accumulated (plus the remainder) is flushed on
  `terminate`; the engine's below-minimum empty answer (seam contract, `ASREngine.swift:28-37`)
  hits `routeFinal`'s empty guard (`DictationPipeline.swift:345-348`) → `.emptySkip`, exactly as
  today.
- **Empty final.** Already shipped: `routeFinal` never pastes `""` (`:345-348`); the streaming
  route keeps it (`DictationPipelineStreamingTests.swift:246-260`).
- **Engine throwing mid-stream.** Already shipped: `routeStreaming`'s catch finalizes `.aborted`
  on `CancellationError` and `.failed` otherwise (`DictationPipeline.swift:228-241`); the feed is
  already terminated by then, so no chunk is stranded.
- **Converter throwing in a drain tick.** The one genuinely new failure mode. `convert(_:)`'s
  error path discards the converter's stream state (`AudioFormatConverter.swift:361-365`), so the
  session's audio is no longer continuable. **Decision:** the feed logs loudly (consumer-side
  `Logger`), stops draining, and finishes the stream; the route completes over whatever audio was
  already fed. The alternative — trapping mid-sentence — is rejected (the trap belongs to
  `endCapture`, the session's last word, `MicrophoneSource.swift:235-243`, where failure still
  traps unchanged). Named limitation: a mid-session conversion failure produces a short final,
  and `missingSampleCount` does not carry the lost chunk (the pipeline does not aggregate
  per-chunk completeness). The founder's first real run (SMOKE step N+1) is where this is
  observed if it is reachable at all.
- **App quit mid-recording.** The quit path cancels the feed before `terminate`; the OS releases
  the input device at process exit. The recording in progress is lost with the process — the
  "never lost" invariant governs ended sessions, not a killed app; this is the existing state of
  the world, unchanged.
