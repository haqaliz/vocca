## Phases

### Phase (a) — The pure idle-policy decision (headless)

- **Goal:** the 5-minute constant and the policy's decision table exist in exactly one place each,
  proven headlessly with an injected clock and a counting trigger. Nothing else changes.
- **Prerequisites:** none (Core-only).
- **Files:**
  - create `Sources/VoccaCore/IdleReWarmPolicy.swift` (stdlib-only):
    - `public enum IdleReWarmTargets` — `public static let idleDuration: Duration = .seconds(300)`.
      Doc: provisional (PRD Q5), re-baselined by the founder's real run (SMOKE 120/121), pinned by
      the single-source scan — the `WarmStartTargets` precedent.
    - `public final class IdleReWarmPolicy` — non-Sendable final class in the main-actor domain
      (the `SessionMachine` shape; **not** `@MainActor`-annotated — the annotation belongs to the
      owner that drives it):
      - `private let clock: any MonotonicClock` — injected; `clock.now` only, no wall clock.
      - `private let trigger: () async -> Void` — injected, non-throwing (the wiring catches and
        logs the resolver's error); tests inject a counting closure.
      - State: `private var windowOpenedAt: Duration?` (nil while a session is active),
        `private var triggeredThisWindow = false`.
      - `noteSessionStarted()` — closes the window (`windowOpenedAt = nil`) and resets
        `triggeredThisWindow` (a session start during the window cancels **and** reschedules).
      - `noteSessionEnded()` — opens a fresh window at `clock.now`.
      - `@discardableResult func tick() async -> Bool` — the one decision point: window nil →
        false; `triggeredThisWindow` → false; `clock.now - windowOpenedAt < idleDuration` → false;
        otherwise mark `triggeredThisWindow = true`, `await trigger()`, return true.
        **Mark-before-fire**, so a second tick during the fire cannot double it.
      - The first window opens at construction (launch-idle counts; a failed launch prepare thereby
        gains a bounded 5-minute auto-retry through the resolver — phase (c), edge cases).
  - create `Tests/HarnessTests/IdleReWarmPolicyTests.swift` (license header):
    1. `IdleReWarmTargets.idleDuration == .seconds(300)`.
    2. **Single-source scan:** the `.seconds(300)` literal appears in exactly
       `IdleReWarmPolicy.swift` + `IdleReWarmPolicyTests.swift` and nowhere else in `Sources/` or
       `Tests/` — the `WarmStartRatioTests.swift:106-131` shape, vacuity-guarded both directions.
       Tests never write 300 as a literal — they advance the clock by the constant's name.
    3. Decision table over a `TestClock` + counting trigger:
       - idle < 5 min → no fire (count 0).
       - idle ≥ 5 min → exactly one fire (two ticks in a row → count 1).
       - a session start during the window cancels it (`noteSessionStarted()` at minute 3, tick at
         minute 6 → no fire).
       - a session end reschedules (end at minute 2, tick at minute 8 → one fire; tick again → 1).
       - two windows → two fires.
       - the first window opens at construction (no sessions ever, tick at minute 5 → one fire).
       - mark-before-fire: a suspending trigger (gated closure) does not allow a second tick —
         count stays 1.
- **Validation:** `swift test --filter IdleReWarmPolicyTests`, then full floor script (raise the
  floor in this commit by the added count).
- **Commit:** `add the idle re-warm policy decision and its 5-minute target`

### Phase (b) — The engines' genuine re-warm path (seam-disciplined)

- **Goal:** a second `prepare()` remains a no-op, but each engine has a real re-warm behind a Core
  seam: load-new-then-swap, never unload first; the first transcribe after a re-warm is warm and
  recorded as `.warmTranscribe`, **never `.firstAfterLaunch`** (the 1.2 launch bound stays
  launch-pure); the re-warm records a new `EngineTiming.Kind.rewarm` row; a failure leaves the old
  model resident and the engine fully usable. The launch-once pins are untouched.
- **Prerequisites:** phase (a).
- **Files:**
  - create `Sources/VoccaCore/EngineRewarmable.swift`:
    `public protocol EngineRewarmable: Sendable { func rewarm() async throws }` — doc: the re-warm
    contract — "make the model resident again as if freshly prepared; the next transcribe must be
    warm; never a network download (the store short-circuits verified-present); called only on a
    loaded engine (the resolver routes the unprepared case); a failure must leave the previous
    load usable". Both real engines conform; a non-conforming engine is a loud resolver error,
    never a silent no-op.
  - `Sources/VoccaASR/Parakeet/EngineTiming.swift` — add `case rewarm` to `Kind` (`:26-35`; doc:
    the idle re-warm's load, recorded never gated). No switches to update (verified).
  - `Sources/VoccaASR/Parakeet/ParakeetEngine.swift` — conform to `EngineRewarmable`:
    - `rewarm()`: strict `guard loadState.hasLoaded else { throw VoccaError.modelUnavailable(...) }`
      (the resolver guarantees loaded); `loadState.beginAttempt()`; measure `clock.now`;
      `downloadIfMissing` (no-op when present); `modelLoader(await loadDirectory())`; build a
      **fresh** `AsrManager(config: .default)` and `loadModels(models)`; **only then** swap
      `self.manager` and `self.decoderState = try TdtDecoderState()`; `loadState.complete()`;
      `timing.record(.rewarm, elapsed:)`. On catch: `loadState.fail()` + throw `modelUnavailable`
      — the old manager/decoder survive untouched.
    - **The ordering pin (Q5's answer):** `private var rewarmInFlight: Task<Void, Error>?` — set by
      `rewarm()` (unstructured task over the body, awaited by `rewarm()` itself); the first line of
      `transcribe(_:)` becomes `if let rewarmInFlight { try? await rewarmInFlight.value }` — a
      transcription arriving mid-re-warm **waits for the in-flight re-warm** (the first dictation
      after idle is deterministically warm); a failed re-warm never blocks a transcription (`try?`;
      the error was already surfaced to `rewarm()`'s caller). The readiness gate is untouched — a
      session starting mid-re-warm is never refused.
    - `transcribedSinceLoad` is **not** reset by `rewarm()` — firstAfterLaunch stays launch-only.
  - `Sources/VoccaASR/Whisper/WhisperContext.swift` — add `func reprepare(modelFileURL: URL) throws`
    to the seam (`:32-43`; doc: "re-creates the inference context; called only on a prepared
    context; a failure must leave the previous context usable" — swap-on-success).
  - `Sources/VoccaASR/Whisper/WhisperCAPI.swift` — the one file permitted to name the C family
    (H8b): implement `reprepare` — build the new context; only on success free/replace the old
    handle. Executed by nothing in CI; the contract is pinned through the stub.
  - `Sources/VoccaASR/Whisper/WhisperCppEngine.swift` — conform, mirroring Parakeet: strict
    `hasLoaded` guard; `loadState.beginAttempt()` (a no-op on `.prepared` by design,
    `WhisperLoadState.swift:48-55`); `downloadIfMissing`; `context.reprepare(...)`; `complete()`;
    record `.rewarm`; catch → `fail()` + `modelUnavailable` (old context survives); `rewarmInFlight`
    task; `transcribe` awaits it first; `transcribedSinceLoad` untouched.
  - create `Tests/HarnessTests/EngineRewarmTests.swift` — driven through the engine-store doubles
    (check `ParakeetCoreTests`'s injected `modelLoader` and `WhisperEngineTests`'s stub
    `WhisperContext` for the existing double shapes; reuse them):
    1. Parakeet: `rewarm()` on a loaded engine re-runs the loader exactly once and records exactly
       one `.rewarm` sample; `loadAttempts` becomes 2 while `hasLoaded` stays true throughout.
    2. Parakeet: the first transcribe after a re-warm records `.warmTranscribe` — **not**
       `.firstAfterLaunch` (the launch-bound purity pin); a transcribe before any re-warm still
       records `.firstAfterLaunch`.
    3. Parakeet: a failing re-warm (loader throws on its second call) throws `modelUnavailable`,
       leaves `hasLoaded` true, and the next transcribe still works on the old manager.
    4. Parakeet: a transcribe arriving while a re-warm is parked (gated loader) **awaits** it —
       the transcribe returns only after the re-warm completes (the ordering pin, engine half).
    5. Parakeet: `rewarm()` on an unloaded engine throws (strict guard).
    6-10. Whisper: the same five rows over the stub context (reprepare called once, `.rewarm`
       recorded, warm-transcribe-after, failure keeps the old context usable, transcribe awaits an
       in-flight re-prepare, unloaded guard throws).
    11. `EngineTiming.samples(for: .rewarm)` round-trips what `record(.rewarm, ...)` wrote.
- **Validation:** `swift test --filter EngineRewarmTests`, `swift test --filter WarmStartLaunchTests`
  (the pins pass unchanged), then the full floor script (raise the floor in this commit).
- **Commit:** `give both engines a genuine re-warm path behind the rewarm seam`

### Phase (c) — The resolver entry point and the policy wired to the root (ordering pins)

- **Goal:** the policy's fire reaches a real re-warm exactly once per idle window, single-flight
  against any in-flight prepare, on the currently selected tier's engine; a session starting while
  a prepare or re-warm is in flight is never refused and the first dictation waits on the in-flight
  re-warm; the launch pins and the zero-network probe stay green.
- **Prerequisites:** phases (a) + (b).
- **Files:**
  - `Sources/VoccaCore/DictationEngineResolver.swift` — add:
    - `public func rewarmIfNeeded() async throws`, the ordering ladder under the one-flight
      discipline:
      1. `if let inFlight = inFlightPrepare { try await inFlight.value; return }` — a prepare in
         flight **is** the warm-up; awaiting it and returning means no second load (spec's
         single-flight acceptance, `:129-136` precedent).

         ordinary eager path (also the bounded auto-retry for a failed launch prepare).
      3. Otherwise run the re-warm under the **same** `inFlightPrepare` slot (a second
         `rewarmIfNeeded` during one awaits it — never doubled). Body: `guard let rewarmable =
         engine as? any EngineRewarmable else { throw DictationEngineResolverError.rewarmUnsupported }`
         then `try await rewarmable.rewarm()`. `prepared` stays `true` on success **and** failure
         (a failed re-warm never closes the gate; the next idle window retries — the resolver's
         retry-on-failure precedent).
    - `public enum DictationEngineResolverError: Error, Equatable` — `case rewarmUnsupported`
      (loud, never silent).
  - `Sources/VoccaBootstrap/AppBootstrap.swift` (the root's `init`):

    2. `rewarmIfNeeded()` while a prepare is in flight (parked) awaits it and performs **no**

    3. `rewarmIfNeeded()` on an unprepared engine runs the ordinary `prepareIfNeeded()`.
    4. A failing re-warm leaves `isPrepared` true and `engineIfReady()` answering; a later

## Environment & privacy

- No new environment variables. The real-run row reuses `VOCCA_LATENCY_BENCH` / `VOCCA_MODEL_DIR`.
- **Zero network:** the re-warm path calls `downloadIfMissing` with a verified-present manifest —
  a no-op; `ModelHub.offlineMode = true` keeps the SDK's own download path dead; the policy never
  fires in the probe's short run. A test whose result depends on the network is a bug in the plan.
- **Mic dot untouched:** the re-warm reloads the model only — never the audio engine
  (`ARCHITECTURE.md:336`); it never touches `MicrophoneSource`, the capture graph, or any
  `SessionAudioSource`. Disk-only; nothing lights.
- **Battery/App Nap:** the tick rides the existing 1 s health poll (zero marginal timer cost). Under
  darwin suppression the poll fires late (~1.15× measured) — the fire can be seconds past the
  threshold; acceptable, and every recorded row carries the suppression state.
- **On-device only:** the timing rows live in the in-memory `EngineTiming` ledger; nothing is
  transmitted.

## Edge cases & error handling

- **Idle policy racing a session start:** the window closes on `.started`/`.opening` and reopens
  on `.ended` (the effect funnel is the single observer — both modes, all terminals). A refused
  press (`.captureUnavailable`) does not close the window (no session happened).
- **Re-warm racing a prepare:** the resolver awaits the in-flight prepare and performs no second
  load — the fresh prepare is the warm-up.
- **Session starting mid-re-warm:** never refused (the gate stays open — the re-warm never touches
  `EngineReadiness`); the first dictation waits on the in-flight re-warm (engine-level
  `rewarmInFlight` await) and is therefore deterministically warm — Q5's ordering, pinned at both
  the engine and the root.
- **Tier switch during idle:** the fire re-reads `self.resolver` at fire time — the new selection's
  engine re-warms, the old one never does. A switch *during* an in-flight re-warm leaves the old
  tier's load completing harmlessly (it installs nothing and opens nothing) — logged, accepted.
- **Engine failure on reload:** the old model stays resident (`prepared` stays true, transcribe
  unaffected); the resolver's retry-on-failure precedent applies — the next idle window retries.
  A failed re-warm never closes the gate and never blocks a transcription.
- **Failed launch prepare + 5 minutes idle:** `rewarmIfNeeded` routes to `prepareIfNeeded` — a
  bounded (once per window) auto-retry.
- **Model removed mid-re-warm:** the load throws (bytes gone); the removal machinery already
  closes the gate; the failure is logged.
- **App Nap / suppression:** the tick may fire seconds late — recorded not gated (SMOKE 121).
- **The probe:** never ticks past the threshold in its short run; the trigger is wired but never
  fired — zero-network unchanged.
- **Parakeet SDK risk (flagged):** a second `AsrManager` beside a resident one is unverified. The
  design avoids concurrency by construction (the re-warm runs on the engine actor; transcriptions
  await it). If the SDK refuses a fresh manager, the fallback is to re-run the loader into the
  existing manager; the swap-on-success shape is unchanged.
