### The canonical pattern this aspect implements (whisper.cpp's own stream example, both halves in the pinned header)

Repeated `whisper_full` on the growing buffer + `new_segment_callback` harvesting segments (the callback fires as segments complete during a decode; `n_new` = segments since the last fire; read the last `n_new` via `whisper_full_n_segments`). The key-up final = the last full decode = a batch transcription of the same buffer **by construction** (same params, same audio, same `whisper_full` machinery).

## 3. Design decisions (read before Phase a — two are spec ambiguities resolved here)

1. **Seam shape — a new method, not a changed one.** `WhisperContext` gains `transcribeStreaming(samples:) throws -> [WhisperSegment]`. The existing `transcribe(samples:)` is **untouched** — the batch path must be byte-for-byte identical. The engine's `stream` uses the new method; the batch `transcribe` uses the old one.
2. **Partial delivery is per-iteration, not intra-decode.** Each `stream` iteration (chunk accumulated) runs one full decode of the current buffer and yields one partial = that decode's segments. The C callback is registered and is the harvest mechanism (spec.md requires it; it is what whisper.cpp's own stream example uses), but it delivers into a per-call box, and the caller-visible cadence is the iteration's. Mid-decode (intra-`whisper_full`) delivery to the continuation is **deferred**: the engine is decode-bound anyway, the widget cadence is the feed's, and adding it later needs no seam change because the callback is already registered. The adapter's doc comment says so.
3. **`single_segment` stays `false` in the streaming variant — this is the subtle one.** The header's "useful for streaming" (:498) applies to the *stateful incremental* pattern (N2), not to this one. Forcing single-segment in the streaming variant would change segmentation versus the batch path and **break the final ≡ batch by-construction guarantee**. The streaming params must be field-for-field identical to the batch params plus the callback fields.
4. **The streaming params construction is duplicated, not extracted.** The CAPI's batch `transcribe` body is not refactored at all (no shared `makeParams()` helper). Reason: no test in CI executes the CAPI (the tap-adapter precedent — the lint pins the file, not the behavior), so a shared helper could drift the batch path with nothing to catch it. The streaming method builds its own params, field-for-field identical, with a comment in both places demanding parity. A shared helper becomes safe only after SMOKE step 19's real run. (PRD "any change to shared params must be pinned by existing tests" — nothing executes the CAPI, so the only pin available is *don't share*.)
5. **Cancellation ends the stream with the accumulated final, never a throw** — mirroring the seam's batch default exactly (`ASREngine.swift:94-100`: break on cancellation, then yield the one final, then finish). "Both shapes terminate the same way, so the pipeline is written once" (:42-45). A cancelled consumer has already terminated the continuation, where yield is a no-op; the pipeline's own guard tests pin zero injection. A stream that *ends mid-utterance* (chunk source finished) terminates the same way: partials so far, then exactly one final from the last decode, clean `finish()`.
6. **Timing: only the final decode is recorded.** The stream records exactly one `EngineTiming` sample — the last decode's elapsed — under the existing `.firstAfterLaunch`/`.warmTranscribe` split (`transcribedSinceLoad`, `:174-179`). Per-iteration partial decodes record nothing (the ledger is bounded, cap 512; partials are provisional by construction). A stream with zero decodes records nothing and does not flip the split. (Flagged decision.)
7. **Missing-sample accounting:** the stream accumulates `min(Σ chunk.missingSampleCount, samples.count)` and carries it on every yield (partials and final) — the completeness link (I1) survives streaming; the cap keeps a missing count from exceeding the samples it describes. (Flagged decision.)
8. **Sub-minimum: no guard, empty-only** — same policy as batch (`WhisperCppEngine.swift:154-169`). The stream's first decode runs on the first chunk (tiny audio); if whisper refuses short audio rather than padding, the stream throws on the first iteration — **that observation is exactly what SMOKE step 19's streamed cycle records**, and the fix, if needed, is one measured constant in the engine applied to both paths (mirroring `ParakeetEngine.isBelowSDKMinimum`). Until measured, the row is documented **unverified**, never assumed.
9. **Decode every chunk.** The engine decodes on every chunk arrival (the canonical pattern). A minimum-accumulation throttle is a measured decision deferred to after step 19 — the O(n²) cost is acknowledged, not hidden (see cost honesty, Phase c).
10. **Empty partials are yielded** (a decode that returns zero segments yields an empty partial) — matching "partials as decodes complete"; the widget's provisional placeholder covers them. (Flagged decision.)

**Ambiguities in the spec worth a reviewer's eye:** (i) spec.md says partials appear "as segments complete" — interpreted here as *as decodes complete* (decision 2); (ii) the acceptance row "stream ending mid-utterance terminates the seam stream cleanly" — interpreted as *chunk source ends → partials + one final, no throw* (decision 5); (iii) spec.md names `new_segment_callback` as the harvest mechanism but never says what cadence the caller sees — resolved by decision 2.

## 6. Testing strategy

- **Headless contract rows first** (Phase a, `spec.md` "Acceptance criteria (tests written first)"): partials-then-one-final; final equals batch by construction (engine half); mid-utterance end terminates cleanly; plus empty-stream, failure, cancellation, timing, missing-sample, transport, and unprepared rows. All drive `StubWhisperContext` — no model file, no GPU, no C call, ever.
- **The two-sided seam lint** (`WhisperSeamTests`) is the C-surface guard: the new callback names live only in `WhisperCAPI.swift`; `WhisperContext.swift` and `WhisperCppEngine.swift` name none of them.
- **The no-branch pin** (`DictationPipelineStreamingTests.swift:358-374`) is a caller pin — untouched, must stay green (the pipeline never learns the engine streams).
- **Batch-path pinning:** no existing batch test changes except the `:226-228` assertion flip (which pins the *flag*, not the batch behavior); `transcribe(samples:)` is byte-for-byte untouched; `WhisperTranscriptMapper.map`'s new parameter defaults to `true`, so every existing mapper call site is byte-identical.
- **Run order per phase:** targeted filter first, then `./Scripts/test-with-floor.sh`; floor raised in the Phase c commit.
- **Not in CI, by design:** the CAPI's real behavior (executed by nothing — the tap-adapter precedent), whisper's accuracy, sub-minimum behavior, and the O(n²) cost. Those are SMOKE step 19's rows, recorded never gated.

## 7. Environment & privacy

- **Zero network, unchanged:** the stream touches only the resident model, the injected context, and the actor's memory. The zero-network probe and `ZeroNetworkTests` must pass untouched. No new env vars; `VOCCA_MODEL_DIR` remains the env-gated real-run gate (skips visibly in CI).
- **No new dependencies** (`Package.swift` untouched; the `WhisperCpp` binary target at :85-89 already pinned). No audio or text egress — the stream is on-device by construction.
- **Threading:** `whisper_full` is called synchronously on the engine actor's executor; the C callback fires on that same thread inside the call; the per-call harvest box is confined to the call — no shared state, no lock, whisper's "not thread safe for same context" satisfied by the actor's serialization.

## 8. Edge cases & error handling

- **Empty final** (zero chunks or all-empty chunks): one empty final, never a throw, the context never called — the batch empty-buffer policy at `ASREngine.swift:28-37`, stream-shaped.
- **Sub-minimum audio:** no guard (decision 8). If whisper refuses short audio, the stream throws on the first iteration and the pipeline surfaces `.reasonOnly(.transcriptionFailed)` — honest, recoverable, and *the measured* fix (one constant, both paths) lands after step 19, never before.
- **Engine failure mid-stream** (decode throws): `finish(throwing: .transcriptionFailed(identity, underlying:))`, cause intact, nothing yielded after the throw, no final — the pipeline shows the failure affordance and the transcript invariant (never lost) holds via the failsafe surface.
- **Cancellation mid-segment:** chunk-source end ⇒ partials + one final, clean finish; consumer cancellation ⇒ `onTermination` cancels the task, the stream terminates without hanging or throwing (decision 5). The pipeline's own cancellation rows (`.aborted`, zero injection) are already pinned by `DictationPipelineStreamingTests`.
- **No model file / not prepared:** the stream's task-start guard throws `modelUnavailable` before consuming any chunk; the context is never called.
- **Callback lifecycle:** the harvest box is retained per call and released in a `defer` on every path — no leak, no use-after-free, no cross-call state; the C pointer stays inside the seam's one file and never leaves the actor.
- **What happens when the layer can't do its job:** every failure path terminates the stream (throw or clean finish), never hangs; the pipeline's existing decision table turns any terminal into a widget-visible outcome with the transcript never lost.
