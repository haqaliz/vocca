## Decisions made in planning
- **D1 (shape):** one `static` on `AppBootstrap` — `composeConverseIntentClosures(root: @escaping @Sendable () -> DictationLoopRoot?)`
  returning `(provider: @Sendable (String) async -> IntentResolution?, handler: @Sendable (ActionInvocation, String) async -> String?)`.
  `configure` passes `{ rootBox.value }`. (Tests pass a closure over a harness root.) The agent confirms the
  right isolation of the root accessor against the compiler; deviations go in the report.
- **D2 (card line):** the wrapper is in the static, NOT in `IntentWiring` (its "honest-drop" test and the
  `performAction` contract are untouched). Wrapper rule: call `performAction`; non-nil → return it unchanged;
  nil → if `root.widgetStore.state.confirmation != nil` return the constant
  `AppBootstrap.confirmOnScreenReply = "Confirm on screen."`, else nil.
- **D3 (resolve mapping):** `intentProvider` returns the wiring's `IntentResolution` as-is (`.none` echoes via the
  driver's existing branch — identical to nil).
- **D4 (no probe change):** PROBE-CONVERSE keeps nil closures; only its stale comment (`ConverseLoopDrive.swift:~196`) is corrected.

## Environment & privacy
No env vars, no files, no network, no child process (`spawnsSubprocess=false`). Phrase/enablement files are read per turn as before.

## Edge cases
Root released mid-session → nil → echo; wiring absent → nil → echo; card already up → confirm line, no second card; record failure → failure copy never the confirm line; `.ask`/`.none` unchanged; a wrapper must never return the confirm line when no card is showing.
