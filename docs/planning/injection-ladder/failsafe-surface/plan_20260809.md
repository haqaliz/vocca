## 0. Project setup

No new dependencies. Commands: `Scripts/test-with-floor.sh` (floor raised per commit),
`swift build`. Apache-2.0 header on every new file. The `VoccaUI` work follows the
`download-ui` precedent exactly (`Sources/VoccaUI/DownloadState.swift` + reducer tests +
`DownloadProgressView.swift`): a Core-owned seam, a headless-tested state reducer, and a
window file that is glue executed by nothing in CI.

## 1. Design decisions already taken (do not relitigate)

- **The journal is atomic with the failsafe hand-off** (PRD R6, the critique's hard
  question): `hold` does not return until the text is durable on disk. A crash between
  "ladder exhausted" and "journal write" is a lost transcript, so the ordering is asserted
  by test, not documented.
- **The journal lives in `VoccaInject`** (the failsafe rung's domain), behind the Core
  `TranscriptHolder` seam from the injector-seam aspect. `VoccaUI` imports only
  `VoccaCore` (`ModuleBoundaryTests.swift:281`), so the window consumes the seam, never the
  journal.
- **`FileManager` is confined to one file** — a new H9-style seam lint (the adapters
  aspect's Phase D pattern). The journal *logic* (bounded eviction, purge-on-resolve,
  atomic-write protocol) is a separate file tested over an injected file-system seam.
- **The failsafe window is a non-activating `NSPanel`** (`PRODUCT_SPEC.md:22`, never takes
  focus): key equivalents ⌘C / ⏎ / ✕ are handled on the panel so the copy works while the
  target app keeps focus (`PRODUCT_SPEC.md:106`). The copy writes the held text to the
  pasteboard — the panel joins the pasteboard seam's permitted list (its write is a raw
  call, no decisions; the *what* is the reducer's).
- **The full six-state widget is out of scope** (PRD §7). Only the FAILSAFE semantics
  land: persistent, selectable, scrollable, cause-specific reason, retry, dismiss, restart
  recovery.
- **Retry re-runs the ladder against a freshly resolved target** (`PRODUCT_SPEC.md:116`);
  the window's retry action calls back into an injected `retry` handler (the composition
  root wires it in the loop-wiring unit — out of scope; the failsafe surface exposes the
  action, the handler is injected).

## 2. Implementation phases

### Phase A — Recovery journal: logic + one-file FileManager adapter

**RED first (`Tests/HarnessTests/RecoveryJournalTests.swift` + `JournalTestDoubles.swift`):**

- an injected file-system seam (temp-file + rename recorded as an atomic pair; a simulated
  crash leaves no partial file — the write protocol is temp+rename, asserted by the fake);
- **atomicity ordering** (PRD R6): after `hold` returns, the durable file exists — the
  contract test is written against the *logic* + fake store and re-asserted against the
  real store with a temp directory (real `FileManager` works in CI);
- bounded: a capped journal drops the oldest entry first (`ARCHITECTURE.md:437`);
- purge-on-resolve: `release()` removes the resolved transcript;
- relaunch-equivalent reload: entries written by one journal instance are read by a fresh
  instance pointing at the same directory (the `capturedAt` note survives —
  `PRODUCT_SPEC.md:117`);
- malformed/corrupt file: skipped, not fatal (the journal must never block or lose the
  rest).

**GREEN:**

- `Sources/VoccaInject/Journal/RecoveryJournal.swift` — the logic: bounded store protocol,
  eviction policy, resolve/purge, load-on-launch, all over an injected `JournalStore` seam;
- `Sources/VoccaInject/Journal/JournalStore.swift` — the seam protocol (save/load/remove,
  list);
- `Sources/VoccaInject/Journal/FileSystemJournalStore.swift` — **the one file naming
  `FileManager`**: Application Support path resolution
  (`~/Library/Application Support/Vocca/recovery/`, `ARCHITECTURE.md:437`), atomic
  temp+rename writes, directory-creation. Raw operations only.
- `Sources/VoccaInject/Journal/JournalTranscriptHolder.swift` — implements the Core
  `TranscriptHolder` seam, journal-backed; `hold` awaits the durable write (R6).
- New seam lint: exactly one file in `Sources/` names `FileManager` — the H9 two-sided
  form, with planted-violation positive control (the adapters aspect's Phase D template).
- `docs/technical/ARCHITECTURE.md` §10 (TranscriptCustody) amendment note: the journal is
  the first implementation of the recovery half of custody.

**Validation:** suite green; floor raised; a temp-dir test proves the real store is
CI-runnable (FileManager is local, zero-network).
**Commit:** `Add the recovery journal: durable-before-return holds, bounded, purged, atomic — behind the held-transcript seam`

### Phase B — Failsafe state reducer (headless, the download-ui pattern)

**RED first (`Tests/HarnessTests/FailsafeStateReducerTests.swift`):** the window's whole
decision table as pure state transitions, the `DownloadStateReducerTests` pattern:

- states: `hidden` → `presenting(transcript)` → `dismissed` / `retrying` / `copied`;
- hold → presenting with the cause-specific reason; never auto-dismisses (a time-based
  transition simply does not exist in the reducer — `PRODUCT_SPEC.md:99-104`);
- copy → `copied` (the reducer decides *what* is copied: the full text);
- retry → `retrying` with the transcript retained (a failed re-run returns to
  `presenting`, never loses the text);
- dismiss → `hidden` (the text is dropped only on explicit user dismiss — or `release()` on
  the holder);
- relaunch → the held entry loads into `presenting` with its captured-at note;
- the reducer never reads a clock, a file, or a pasteboard — pure.

**GREEN:** `Sources/VoccaUI/FailsafeState.swift` — the reducer + state vocabulary
(`VoccaUI` may import only `VoccaCore`; the state speaks `HeldTranscript` and
`FailsafeReason`). No AppKit in this file (`DownloadState.swift` imports Foundation +
VoccaCore only — same shape).
**Commit:** `Add the failsafe state reducer: persistent, cause-specific, never auto-dismissing`

## 4. Testing strategy

- Headless in CI: journal logic over the fake store; the real `FileManager` store against
  a temp directory; the atomicity ordering; the reducer's full decision table; the panel's
  copy/retry contracts over injected seams.
- Executed by nothing in CI (smoke steps): the panel's focus behaviour, key equivalents
  against a live window server, the real pasteboard write, real relaunch recovery.
- Zero-network: the journal and the reducer add no network; the probe's default path is
  unchanged (the journal is only touched when a failsafe fires — but the module-coverage
  guard still requires `VoccaInject` driven, which the seam aspect's probe drive already
  does; no new probe work).

## 5. Environment & privacy

- Journal location: `~/Library/Application Support/Vocca/recovery/` — local, on-device;
  bounded and purged (`ARCHITECTURE.md:437`). No env vars.
- Privacy: the journal is the *only* place a transcript is stored at C4, and it is local,
  bounded, user-purgeable (`PRODUCT_SPEC.md:212` retention control is settings work, later);
  nothing leaves the box.

## 6. Edge cases & error handling

| Case | Behaviour |
|---|---|
| Crash between exhaustion and journal write | Impossible by construction (R6: hold is durable before return); asserted by the ordering test |
| Journal disk write fails | `hold` throws → the ladder surfaces the error; the transcript remains in memory for the window; the zero-loss claim is bounded by the same "always succeeds" floor — the smoke checklist records the honest limit |
| Journal full | Oldest evicted first; nothing else changes |
| Corrupt journal entry | Skipped, rest intact — never a block, never a loss of the rest |
| Retry pressed with no focused field | Re-run resolves `nil` → the `.noFocusedField` reason returns the failsafe to `presenting` with the updated copy — text retained |
| Copy pressed repeatedly | Idempotent; each ⌘C writes the same full text |
| App relaunches after a failsafe | The held entry reloads into `presenting` with its captured-at note |
| Secure Input field | The `.secureInput` copy shows the honest refusal (`PRODUCT_SPEC.md:111`) — no rung is ever attempted |
