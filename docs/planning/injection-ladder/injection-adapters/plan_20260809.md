# Implementation plan — `injection-adapters` (aspect 2 of C4)

**Date:** 2026-08-09 · **Branch:** `feat/injection-ladder/aliz` · **Sources:** `spec.md`,
`prd.md` (R3, R4, R5, S2, R9) · **Method:** strict TDD — RED before GREEN.

## 0. Project setup

No new dependencies. Same commands as the seam aspect: `Scripts/test-with-floor.sh`
(floor raised per commit), `swift build`. Every new file carries the Apache-2.0 header.

**The core doctrine this aspect exists to serve** (`CLAUDE.md`, the tap-adapter precedent):
the adapters are **executed by nothing in CI** — `CGEvent.tapCreate`-family behaviour needs
an Accessibility grant, TCC cannot be granted on a hosted runner, and the real pasteboard is
session-bound. Every decision is above the seam; each adapter file is translation with no
decisions in it. What *can* run in CI (the clipboard's save/set/paste/restore over an
injected pasteboard seam, the never-clobber rule, the allowlist gate, the Secure Input
decision) is tested headless; what cannot is pinned by lints and smoke steps.

## 1. Design decisions already taken (do not relitigate)

- **The keystroke adapter is the sole `CGEvent`-naming file in `VoccaInject`** and exposes
  both `typeText(_:)` and `pressPaste()` behind an internal protocol; the clipboard rung
  calls `pressPaste()` through the seam and names no `CGEvent` (PRD R3, the lint-structure
  fix from the PRD critique).
- **The H7 amendment is per-seam, not per-file-anything-goes**: the tap seam keeps its rule
  untouched; the keystroke seam gains one permitted file. The old global `≤ 1` count
  assertion (`HotkeySeamBoundaryTests.swift:201-209`) becomes a per-seam count assertion.
- **Decisions live above the one-file adapters**: `ClipboardRungStrategy` (snapshot →
  write → paste → settle → restore-if-ours) is a logic file tested over an injected
  pasteboard seam + a racing fake manager; `SystemPasteboard` is the one file that names
  `NSPasteboard` and does nothing else. Same split for AX: `AccessibilityRungStrategy` +
  `TargetResolution` (logic, tested over injected reads) vs `AXSource` (one file, raw
  `AXUIElement` calls).
- **Secure Input is read at injection time** by the target resolver via an injected
  `SecureInputReading` protocol; `SystemSecureInputRead` is one Carbon line in one file
  (the `SystemSecureInputState` precedent, `SecureInput.swift:92-105`). The decision never
  reads it directly — `TargetContext.isSecureInput` carries the answer (seam aspect).
- **The seeded allowlist** (PRD S1) is data, not decisions: a `SeededInjectionAllowlist`
  holding the known-good bundle IDs; the *gate* is the `InjectionAllowlist` protocol from
  the seam aspect.

### Phase B — Clipboard rung: the headless-tested half of the workhorse

**RED first (`Tests/HarnessTests/ClipboardRungTests.swift` + `ClipboardTestDoubles.swift`):**

- an event-logging fake pasteboard records snapshot/set/restore calls and *simulates* a
  clipboard manager taking ownership (moves `changeCount` between set and restore);
- the save→set→paste→settle→restore ordering is pinned by the event log
  (`ARCHITECTURE.md:408-414`);
- **never-clobber**: when the fake manager moved `changeCount`, the rung does NOT restore —
  the event log shows no restore, and the rung records the outcome (PRD R3,
  `ARCHITECTURE.md:412-414`);
- restore happens when the change count is still ours;
- the ⌘V goes through the injected `KeystrokeSynthesizing` seam — asserted by a fake
  keystroke source receiving `pressPaste()` exactly once, and the clipboard file naming no
  `CGEvent` (covered by the lint too);
- the settle delay is an injected value (80 ms default pinned in one place, PRD R3);
- failure paths: pasteboard write fails → rung reports `RungAttempt.failed` (the decision
  falls through).

**GREEN:** `Sources/VoccaInject/Clipboard/ClipboardRungStrategy.swift` (conforms to the
seam aspect's `InjectionRungStrategy`, internal protocol) + `Sources/VoccaInject/Clipboard/PasteboardSeam.swift`
(the `PasteboardManaging` protocol — snapshot all types + changeCount, write, read back,
restore) + `Sources/VoccaInject/Clipboard/SystemPasteboard.swift` — **the one file naming
`NSPasteboard`/AppKit pasteboard**, raw operations only, no decisions. The clipboard rung
is CI-runnable end to end except the real pasteboard write (the seam makes the logic run
headless; the real `SystemPasteboard` is exercised by the smoke checklist and can run in
CI where a window session exists).

**Validation:** suite green; floor raised; the new pasteboard seam lint (Phase D) is
written in this same commit so the one-file claim is enforced from the first moment the
file exists.
**Commit:** `Add the clipboard rung: save, set, paste, settle, restore-if-ours — never clobbering a clipboard manager`

### Phase C — AX rung + target resolution + Secure Input read

**RED first (`Tests/HarnessTests/AccessibilityRungTests.swift`):**

- the allowlist gate: for an unallowlisted bundle ID the strategy order never proposes
  `accessibility` (default-order test, seam aspect's Phase C — here: the `AX` rung itself,
  when consulted directly for an unallowlisted app, declines before any AX call — the
  "not read-then-discard, but never read" shape that C12 later requires of context);
- the verification rule: `tryInject` returns `succeeded(verified:)` from an injected
  insert+read-back reader; the *interpretation* ("unverified = failure") is the decision's,
  already pinned in the seam aspect — this aspect pins only that the rung reports truth;
- target resolution over injected reads: focused app → `bundleID` + `windowTitle`; no
  focused field → `nil` bundle (drives the `.noFocusedField` row); Secure Input read at
  resolution time → `isSecureInput` set (the fresh, injection-time read per PRD R2);
- `TargetContext` carries no `AXElementRef` — the AX element is resolved inside the adapter
  file and never crosses the seam (PRD R1, the `understanding.md §3.2` fix).

**GREEN:**

- `Sources/VoccaInject/Accessibility/AXSource.swift` — **the one file naming
  `AXUIElement`/ApplicationServices/`kAX` identifiers**: focused-element lookup, insert via
  `kAXSelectedTextAttribute`, read-back. Raw results only (inserted? what's in the field?),
  never interprets. Per-call timeout below the system default — the timeout is applied
  here (it is the API's own guard), the *policy* (what a timeout means) is above.
- `Sources/VoccaInject/Accessibility/AccessibilityRungStrategy.swift` — conforms to
  `InjectionRungStrategy`; consults the allowlist; calls `AXSource`; returns
  `RungAttempt.succeeded(verified:)` truthfully.
- `Sources/VoccaInject/Accessibility/TargetResolution.swift` — focused-app resolution
  logic over injected reads (the AX calls injected via a small protocol so resolution is
  headless-testable; the `AXSource` file is the real conformance).
- `Sources/VoccaInject/Accessibility/SecureInputRead.swift` — **the one file naming

  `SecureInput.swift:15`). The value cannot be asserted in CI (it is a fact about other

**Validation:** suite green; floor raised; smoke-checklist entries (Phase E of this plan)

## 4. Testing strategy

- Headless in CI: clipboard rung logic over the pasteboard seam + fake manager; the
  allowlist gate; the verification-reporting rule; target resolution over injected reads;
  the Secure Input decision (already in the seam aspect) — plus all lint two-sided pins.
- Executed by nothing in CI (documented, pinned by lints + smoke steps): `AXSource`'s real
  calls, `SystemPasteboard` against a live pasteboard, `KeystrokeSource`'s real `CGEvent`
  synthesis, the Carbon read's real value.
- Integration: none beyond the seam aspect's probe drive — the adapters are injected into
  the ladder by the composition root, which is the loop-wiring unit (out of scope).
- Test command: `Scripts/test-with-floor.sh` after every phase; floor raised with the
  tests.

## 5. Environment & privacy

- No env vars, no services, no network — pasteboard, AX and CGEvent are all local APIs;
  the zero-network probe already drives the ladder over injected fakes, and this aspect
  adds no code to the probe's default path (the probe never touches the real adapters).
- Privacy: no egress; the AX reads are the focused app's identity for the *target*, not
  content — context capture is C12 and out of scope.

## 6. Edge cases & error handling

| Case | Behaviour |
|---|---|
| App has no Automation permission | The app falls to the clipboard rung (`ARCHITECTURE.md:506`) — the AX rung's failure is a fall-through, tested in the seam aspect's fault suite; here the rung reports `failed` truthfully |
| Pasteboard manager races the restore | Never clobber: restore skipped when `changeCount` moved, outcome recorded (Phase B's load-bearing test) |
| No focused field | Resolution yields `bundleID == nil` → `.noFocusedField` row (seam aspect) |
| Secure Input at injection time | `isSecureInput` set at resolution → rung-0 refusal, honest copy |
| Keystroke synthesis into a field that ignores it | Rung reports `failed`; the ladder falls through; no silent success is ever reported by an adapter |
| AX call exceeds its timeout | Timeout applied at the API (Phase C); the rung reports `failed` — a timeout is a failure, never a success-with-verification |
