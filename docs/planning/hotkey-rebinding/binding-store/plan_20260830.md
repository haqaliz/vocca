# Implementation plan: `binding-store`

**Unit:** `hotkey-rebinding` · **Aspect:** `binding-store` · **Date:** 2026-08-30
**Sources:** `prd.md` (M1, M2, M3), `binding-store/spec.md`
**Prerequisite:** `binding-vocabulary` — shipped 2026-08-30 (`7a4dfa4`), floor 1527

> Not greenfield. No scaffolding, no dependencies. This aspect adds two keys to an existing store
> and one read to the composition root.

---

## 0. What already exists, and must be copied rather than reinvented

`activationMode` is the template and it is worth following exactly:

- **The split:** `PersistedSettings` (`VoccaCore`, pure, Foundation-free) owns the defaults and the
  tolerant decode; `UserDefaultsSettingsStore` (`VoccaUI/Settings`) owns the one `UserDefaults`
  call. Every decision about what a bad string means therefore runs headlessly.
- **The three-answer contract** (`PersistedSettings.swift:69-84`): absent → default, **silent**;
  malformed → default plus **exactly one** report; known → the value, silent.
- **`rawValue(forKey:)`** (`UserDefaultsSettingsStore.swift:138-142`) uses `object(forKey:)`, not
  `string(forKey:)`, routing a present non-string through the `presentButNotAString` sentinel so a
  corrupted plist takes the **loud** path rather than the silent absent path. The new keys must go
  through the same helper — bypassing it re-introduces exactly the bug that comment describes.

---

## 1. Design decisions this plan fixes

### 1.1 Two keys, both strings

`settings.hotkey.keyCode` and `settings.hotkey.modifiers`, each a **decimal string**, matching the
store's existing habit of persisting strings only. Two keys rather than one encoded chord so a
half-written pair degrades to the default rather than to a chord nobody chose (spec, PRD §6).

### 1.2 A half-written pair is malformed, not absent

**Both keys absent ⇒ absent** (silent default). **Exactly one present ⇒ malformed** (default plus
one report). This is the case two keys were chosen to make visible, so it must not be allowed to
read as absent.

### 1.3 The stored chord is validated, not trusted

A decoded chord that `HotkeyBindingRules.validate` **refuses** is treated as malformed. Both live
in `VoccaCore`, so the check costs nothing. Without it, a hand-edited plist reaches a binding the
recorder would have rejected — and §0.1 of the sibling plan explains what a bare `e` costs.
A chord that `warned` is **accepted**: warnings are not refusals, and `shortcut-conflicts` must
never become a gate on startup.

### 1.4 Caps Lock is masked before storage

`ModifierSet.locking` is already masked on both sides of every comparison, so persisting the bit
would store something that can never match. Mask on write **and** on read — on read because an
older or hand-edited value may carry it.

## 2. Implementation phases

Strict TDD throughout: one behaviour, watch it fail, minimal code, watch it pass.

### Phase 1 — The pure decode
- **Files:** modify `Sources/VoccaCore/PersistedSettings.swift`.
- **Add:** `defaultHotkeyKeyCode: UInt16 = 49`, `defaultHotkeyModifiers: ModifierSet = [.option]`,
  and `decodeHotkeyChord(keyCodeRaw:modifiersRaw:onInvalidValue:) -> HotkeyChord`.
- **`HotkeyChord`** is a new tiny `Sendable, Hashable` struct in Core (`keyCode`, `modifiers`) —
  the chord without an activation. `HotkeyConfiguration` keeps its three fields and is built from
  a chord plus an activation at the root. Do **not** add a fourth field to `HotkeyConfiguration`,
  and do **not** persist a `HotkeyConfiguration`: activation is already stored separately and
  storing it twice creates two sources of truth for one fact.
- **Validation:** the decode table below, all failing first.
- **Commit:** `Decode a stored chord, tolerantly`

### Phase 2 — The seam and the adapter
- **Files:** modify `Sources/VoccaCore/SettingsStore.swift`, and
  `Sources/VoccaUI/Settings/UserDefaultsSettingsStore.swift`.
- **Add:** `hotkeyChord() -> HotkeyChord` and `setHotkeyChord(_ chord: HotkeyChord)` to the
  protocol — synchronous, total, non-throwing, per the seam's stated contract
  (`SettingsStore.swift:25-35`). Two frozen key literals beside the existing three.
- **Every other conformer must be updated** — search the test tree for `SettingsStore` fakes; an
  unimplemented protocol requirement will not compile, which is the point.
- **Validation:** round-trip tests; the seam lint still green.
- **Commit:** `Persist the chosen chord beside the activation mode`

### Phase 3 — The composition root reads it
- **Files:** modify `Sources/VoccaBootstrap/AppBootstrap.swift`.
- **Replace** the two hardcoded `HotkeyConfiguration(keyCode: Self.shippedHotkeyKeyCode,
  modifiers: [.option], activation:)` call sites (`:399-400`, `:437-438`) with the stored chord
  plus each activation. **Keep `shippedHotkeyKeyCode`** — it becomes the default's source, named
  once, and `PersistedSettings.defaultHotkeyKeyCode` must equal it (asserted by test, not by
  comment, so the two cannot drift).
- **`shippedHotkeyDisplayName` is now derivable** from `HotkeyChordFormatter` over the default
  chord. Assert equality rather than deleting it in this aspect — deleting it is
  `general-tab-recorder`'s M10, where the menu bar and onboarding change together.
- **Validation:** the launch-read tests, including the no-change-for-an-existing-install pin.
- **Commit:** `Read the hotkey from settings at launch`

### Phase 4 — Floor
- Run `./Scripts/test-with-floor.sh`, read the executed count, set
  `MINIMUM_EXECUTED_TESTS` to it, re-run green.
- **Commit:** `Raise the suite floor for the stored chord`

## 3. Testing strategy — the decode table

Every row is a test, each written and failing before its code.

| Input | Answer | Reports? |
|---|---|---|
| both keys absent | ⌥Space | **no** — the silent path |
| both valid (`49` / `2`) | that chord | no |
| valid safe single key (`105` / `0`) | that chord | no |
| **keyCode present, modifiers absent** | ⌥Space | **yes, exactly one** |
| **modifiers absent, keyCode present** (mirror) | ⌥Space | yes, exactly one |
| non-numeric keyCode (`"space"`) | ⌥Space | yes, exactly one |
| keyCode out of `UInt16` range | ⌥Space | yes, exactly one |
| modifiers out of `ModifierSet` bit range | ⌥Space | yes, exactly one |
| a **present non-string** (the sentinel) | ⌥Space | yes, exactly one |
| a chord `HotkeyBindingRules` **refuses** (bare `e`) | ⌥Space | yes, exactly one |
| a chord that **warns** | that chord | no — warnings are not refusals |
| stored chord carrying `.capsLock` | that chord, bit masked | no |

Plus:
1. **Round-trip** set → read over the default, a modified chord, and a safe single key.
2. **The launch read reaches both machines** — after `configure`, hold-to-talk and toggle carry the
   stored chord and differ only in `activation`.
3. **Nothing changed for an existing install** — with no stored keys, `configure` produces exactly
   today's two configurations (the `pipeline-wiring` B2 precedent).
4. **`PersistedSettings.defaultHotkeyKeyCode == AppBootstrap.shippedHotkeyKeyCode`**, and the
   formatted default chord equals `shippedHotkeyDisplayName`.
5. **Seam lint:** no second file in `Sources/` names `UserDefaults`.

Commands: `swift build`, `./Scripts/test-with-floor.sh`. Never bare `swift test` for the final
check. Zero warnings — strict concurrency fails CI on any.

## 4. Environment & privacy

No environment variables, no external services, no network. `UserDefaults` only, in the existing
domain, behind the existing one-file seam. The zero-network invariant is untouched, and the probe's
`PROBE-CYCLE` / `PROBE-LATENCY` output must be unchanged — assert it if anything looks like it
moved.

---

## 5. Edge cases & failure behaviour

| Case | Behaviour |
|---|---|
| Preferences file corrupted wholesale | every read takes the loud path and returns ⌥Space; Vocca starts and dictates |
| A write fails | best-effort, never throws — the seam's contract. The in-memory value is still adopted, so the user's change works now and is lost on relaunch. Worse would be refusing the change |
| Stored chord valid but refused by a **later** table change | reads as malformed ⇒ ⌥Space plus a report. Deliberate: the safe-key table is expected to widen, and a narrowing must not leave a user with a binding the app would now reject |
| Both keys written, one later deleted by hand | malformed ⇒ ⌥Space plus one report (§1.2) |

**The aspect cannot lose a dictation.** It runs at launch and at settings-write time only; nothing
on the dictation path reads it.

## 6. Agent execution notes

- One agent, sequential. Phases 1→2→3 are strictly dependent.
- **Ask before proceeding if** `PersistedSettings.defaultHotkeyKeyCode` cannot be made equal to
  `AppBootstrap.shippedHotkeyKeyCode`, or if any existing `SettingsStore` fake cannot be updated
  without changing its meaning — both signal a wrong assumption rather than a test to adjust.
- **Do not** touch `HotkeyConfiguration`'s field list, delete `shippedHotkeyDisplayName`, or change
  any UI. Those belong to later aspects.
