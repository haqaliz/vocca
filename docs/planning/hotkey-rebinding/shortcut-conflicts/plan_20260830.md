# Implementation plan: `shortcut-conflicts`

**Unit:** `hotkey-rebinding` · **Aspect:** `shortcut-conflicts` · **Date:** 2026-08-30
**Sources:** `prd.md` (M8), `shortcut-conflicts/spec.md`
**Prerequisite:** `binding-vocabulary` (shipped `7a4dfa4`) — supplies `HotkeyBindingWarning`.

> **This is the unit's weakest must-have and is marked first-to-cut** (`spec.md` header). Shipping
> without it was offered and declined. If the unit runs long, this is what goes.

---

## 0. The honest boundary, restated before any code

- `com.apple.symbolichotkeys` covers **only Apple's own remappable shortcuts** — Spotlight, Mission
  Control, screenshots, input-source switching. Undocumented, but readable with no entitlement.
- There is **no API to enumerate hotkeys registered by other processes**, via Carbon
  `RegisterEventHotKey` or their own `CGEventTap`. Closed by design.
- **So Raycast and Alfred — the two apps risk C1-E names — are structurally invisible.** This
  aspect cannot detect the risk it was written for.

Everything below is scoped to that. The copy telling the user so is `general-tab-recorder`'s M9,
not this aspect's; but nothing here may be written as if the check were complete.

---

## 1. The seam decision, made deliberately

The natural API is `UserDefaults(suiteName: "com.apple.symbolichotkeys")`. That names the
`UserDefaults` family, which `InjectionSeamBoundaryTests` confines to **two files, both in
`VoccaUI`** (`completion`, `settings`). Three options:

| Option | Verdict |
|---|---|
| Put the reader in `UserDefaultsSettingsStore.swift` | **No.** The lint's own doc comment forbids exactly this reasoning: one file per seam, and *"we already have a `UserDefaults` file"* must not become the argument for the next one |
| Read the plist via `FileManager` + `PropertyListSerialization` | **No.** Takes the FileManager family from four seams to five for no benefit, and hand-parsing a plist is worse than the API |
| **Add a third `UserDefaults` seam row** | **Yes** — `"systemShortcuts"` → `VoccaHotkey/SystemShortcutReader.swift` |

The third row is exactly what the table's doc describes as correct: a **separate seam**, because it
answers a different question (what has the system already claimed) and is read at a different
moment (while a chord is being recorded). This mirrors the `settings` seam's own addition, and the
URLSession family's one-file-to-two amendment.

**Module:** `VoccaHotkey` — an adapter module that already imports `VoccaCore` and already owns
keyboard translation. `VoccaUI` may import only `VoccaCore` (`ModuleBoundaryTests`), so the reader
cannot live beside the recorder anyway.

## 2. Implementation phases

### Phase 1 — The seam and the pure decision
- **Files:** create `Sources/VoccaCore/SystemShortcutReader.swift`.
- **Contents:** the seam (`func occupiedChords() -> [SystemShortcut]`), the `SystemShortcut` value
  (`chord: HotkeyChord`, `name: String?`), and the pure
  `SystemShortcutRules.warning(for:against:) -> HotkeyBindingWarning?`.
- **Note:** `HotkeyChord` is introduced by `binding-store`. If that aspect has not landed, define
  the comparison over `(keyCode, ModifierSet)` and adopt the chord type when it exists — do not
  block, and do not create a second chord type.
- **Commit:** `Ask what the system has already claimed`

### Phase 2 — The decode, over fixtures
- **Files:** create `Sources/VoccaCore/SymbolicHotkeyDecoding.swift` (pure), plus tests.
- **Format** (undocumented; treat every field as hostile): a dictionary keyed by integer ID, each
  value carrying `enabled: Bool` and `value.parameters` = `[characterCode, keyCode, modifierMask]`.
  **We read `parameters[1]` (the key code) and `parameters[2]` (the modifier mask), and ignore
  `parameters[0]`** — the character code is layout-dependent and the key code is not.
- **The modifier mask is Carbon's**, neither `CGEventFlags`' nor ours. Translate explicitly, case
  by case, in one table: `shiftKey` 0x20000, `optionKey` 0x80000, `controlKey` 0x40000,
  `cmdKey` 0x100000. **Every value must be verified against `Carbon/HIToolbox/Events.h` before
  use, not taken from this plan** — this is a real translation with a real chance of being wrong,
  and it is criterion 6.
- **Commit:** `Decode Apple's own shortcut table, tolerantly`

### Phase 3 — The adapter
- **Files:** create `Sources/VoccaHotkey/SystemShortcutReader.swift` (the adapter; thin, no
  decisions); modify `Tests/HarnessTests/InjectionSeamBoundaryTests.swift` to add the third row.
- **The adapter is executed by nothing in CI** — it reads the runner's own preferences, and
  asserting anything about those is asserting a fact about the machine, exactly as
  `SystemSecureInputState` cannot be tested. All decisions are in Phase 2, over fixtures.
- **Commit:** `Read the system shortcut table, in one file`

### Phase 4 — Names, and the floor
- A small table mapping the IDs we can name (Spotlight is 64/65 on current macOS — **verify on the
  machine, do not trust this number**; older references say 32/33). Unknown IDs warn **without** a
  name rather than being dropped.
- Bump `MINIMUM_EXECUTED_TESTS`.
- **Commit:** `Name the shortcuts we can, and warn about the rest`

## 3. Testing strategy

| Criterion | Test |
|---|---|
| 1 | enabled entry matching the candidate ⇒ warns, and names it |
| 2 | **disabled** entry ⇒ no warning. The `enabled` flag is honoured |
| 3 | unknown ID ⇒ warns with `name: nil` — an unnamed collision is still a collision |
| 4 | absent / unreadable / malformed ⇒ **no warning, no refusal** — driven over: missing file, empty dict, truncated `parameters` (0 and 2 elements), non-integer mask, `enabled` missing, a value of the wrong type at every position |
| 5 | **a warning never blocks** — `warned` is accepted by validation and by the store's decode. Pin it, and plant the mutation (make `warned` refuse) to prove the pin fires |
| 6 | Carbon mask → `ModifierSet` over a table, including all four singly and in combination |
| 7 | seam lint: the third row exists, the adapter names the family, and no fourth file does |

Nothing here needs the network, a window server, TCC, or a microphone. The decode is fully
headless; the adapter is not executed at all.

---

## 4. Edge cases & failure behaviour

**Every failure mode is silence.** Absent, unreadable, malformed, unparseable, unknown format
version — all yield no warning. A detection failure must never block a rebind, and must never
refuse one. This is criterion 4 and it is the whole safety story of the aspect: the worst outcome
is that Vocca fails to mention a collision the user will notice within seconds anyway.

The opposite failure — warning about a chord that is actually free — is annoying but harmless,
because we **warn, never refuse**. The user may bind it regardless. That asymmetry is why warn was
chosen: their machine is the authority on their Spotlight, not our table.
