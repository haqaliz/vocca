## Vetted facts

1. **The capture seam family today.** `SessionAudioSource` (VoccaCore,
   `Sources/VoccaCore/SessionAudioSource.swift`) is **pull-shaped, per-session**:
   `beginCapture() -> CaptureStart` / `endCapture() -> Buffer`, with two load-bearing
   contracts a continuous conformance would have to fake: "called exactly once for every
   `beginCapture()` that returned `.opened`" (`:91`) and "**this must not return until the
   input device is released** … a conformance that can fail to release the input must trap
   rather than return" (`:99-116`). Its one conformance is `MicrophoneSource`
   (`Sources/VoccaAudio/MicrophoneSource.swift`), written against `CaptureGraphSeam`
   (`:35-68`: `ring`, `captureFormat`, `levelPeak`, `isRunning`, `start()`, `stop()` — with
   the release contract that "**`stop()` returns only when the device is released**",
   `:29-34`). The seam table (`ARCHITECTURE.md:256`) names the row "Capture | `AudioCapture`
   | `PushToTalkCapture`, `StreamingCapture` (C10)" — C1-era names; the record corrects
   them (see the seam-shape decision).
2. **The SPSC warrant** (`Sources/VoccaAudio/AudioRingBuffer.swift:60-68`): one realtime
   producer and one consumer per ring, "at most one consumer thread at a time"; the
   consumer role may *move* between threads only with a happens-before edge. Claim 1
   already documents the dictation handover (feed during `.recording`, `endCapture` at the
   end — both main-actor). **The voice loop's ring has its own graph, its own interleaver
   (hence its own producer) and its own consumer** — the warrant holds per ring; nothing in
   this aspect adds a second producer or a second consumer to any existing ring.
3. **The two-graphs precedent** (`Sources/VoccaBootstrap/AppBootstrap.swift:284-304`,
   constructed `:288-341`): "Two graphs, not one: the hold-to-talk and toggle machines each
   own their microphone" — one graph+ring+`MicrophoneSource` per mode, `ringCapacity =
   8_388_608` (`:712`, a power of two). **A third graph for the voice loop follows that
   precedent** — but it is composed by `barge-in-loop` (PRD R9), **not by this aspect**.
4. **The probe contract.** Models are never prepared inside `AppBootstrap.configure` (the
   zero-network probe's charter). **Probe-leg decision (pinned): no PROBE leg in this
   aspect.** The seam-level proof is the scripted-graph suite below; the composed realtime
   leg (`PROBE-TURN`, driving the loop's default work over fallbacks) is `barge-in-loop`'s
   R9. A capture-only probe leg would construct a graph nothing consumes — a hot mic in
   the probe process, proving nothing the scripted suite does not — so the honest answer is
   none, recorded here.
5. **The AVFoundation expected-import set is EXACTLY five files**
   (`Tests/HarnessTests/AudioFormatConverterTests.swift:1150-1186`): `VoccaAudio/AudioFormatConverter.swift`,
   `VoccaAudio/AudioCaptureGraph.swift`, `VoccaAudio/MicrophoneAuthorization.swift`,
   `VoccaASR/Parakeet/ParakeetEngine.swift`, `VoccaSpeech/System/SystemSynthesizer.swift`.
   The lint asserts **equality both ways** — a new AVFoundation-naming file fails CI
   automatically (too many). **This aspect adds no AVFoundation file**: `StreamingCapture`
   names nothing below `CaptureGraphSeam` + `AudioFormatConverter` + `AudioRingBuffer`, so
   it needs no framework import (the `MicrophoneSource` trick, `MicrophoneSource.swift:17-25`).
   The reviewed-amendment mechanism stays reserved for `playback-ducking`.
6. **VoccaAudio's adapter rules** (`Tests/HarnessTests/ModuleBoundaryTests.swift:123-126`):
   imports `VoccaCore` and no other Vocca module. The timer therefore arrives as the
   `(schedule, unschedule)` closure pair, exactly as the feed's does
   (`SpeculativeFeed.swift:42-53`: "The plan named the constructor parameter `timer: any
   RepeatingTimer` … the module rules do not permit `VoccaAudio` to import `VoccaHotkey`").
7. **The mid-session consumer precedent is `SpeculativeFeed`** (`SpeculativeFeed.swift`):
   50 ms drain tick (`:76`, the one file that names the cadence), timer injected as the
   closure pair, chunked conversion through the microphone's own `AudioFormatConverter`,
   terminate-with-remainder semantics (`:157-170`), documented-confinement class whose
   `tick()` asserts the main actor (`:189-193`), converter-error path = log loudly, stop
   draining, finish the stream (`:200-211`, recorded as **not headlessly drivable** — the
   real converter cannot be made to throw in a test; the plan records that honestly rather
   than fabricating a driver). This aspect follows that shape one-to-one.
8. **The realtime conversation is executed by nothing in CI** (no mic on runners; the tap
   and graph precedents). `MicrophoneSource` is proven over a fake `CaptureGraphSeam` with
   a **real ring and real converter** (`Tests/HarnessTests/MicrophoneSourceTests.swift:453-499`:
   the ledger fake: real ring, recorded starts/stops, scriptable `nextStart`). This aspect's
   tests use the same recipe with a fresh fake of its own.
9. **`AudioBuffer`** (`Sources/VoccaCore/AudioBuffer.swift`) carries `samples` + `sampleRate`
   + `missingSampleCount`; 16 kHz mono is asserted in the initializer (`:74-88`). The
   completeness link's meaning: "**the transcript produced from it** is short by exactly N
   samples" (`:50-58`) — a per-chunk value has no transcript meaning in a continuous stream
   (the slice is not a hand-over), so chunks carry `0` and the countable loss lives on the
   conformance (decided below, pinned by test).

## The seam-shape decision (the one design choice — integrator checkpoint 1)

**Decision pinned: (a) — a new protocol in VoccaCore, `ContinuousAudioSource`, with
`StreamingCapture` as its first implementation.** `SessionAudioSource` is not extended, not
renamed, not touched.

```swift
/// VoccaCore — Sources/VoccaCore/ContinuousAudioSource.swift (new)
public protocol ContinuousAudioSource: AnyObject {
    /// Open the microphone and return the chunk stream. Throws once per start attempt;
    /// see ContinuousAudioSourceError.
    func start() throws -> AsyncStream<AudioBuffer>
    /// Close the microphone and end the stream. Idempotent; a no-op before start().
    func stop()
}
```

`ContinuousAudioSourceError` (VoccaCore, same file): `.alreadyStarted` (the ownership
refusal — a second stream would be a second consumer on one ring, the SPSC violation) and
`.unavailable` (the graph refused to open — the `CaptureStart.unavailable` analogue,
`SessionAudioSource.swift:21-29`; the loop maps it the way the machine maps that case).

**Why (a) and not (b):** R4's words are "a `StreamingCapture` conformance of the existing
capture seam" — the seam *family* of the table row, not the `SessionAudioSource` protocol.
Conforming `StreamingCapture` to `SessionAudioSource` would require it to satisfy, per
session-less life, the two contracts fact 1 quotes: "called exactly once … never while
already open" and the trap-on-failure release obligation — both of which are
machine-custody contracts whose guarantor is the session machine's single funnel, which the
voice loop does not have and must not fake. `endCapture() -> Buffer` is a hand-over; the
loop needs a stream it can stop. And the barge-in design (`ARCHITECTURE.md:571`) makes the
lifecycle shape load-bearing: capture is **continuous, never started at interrupt time** —
a `start()`/`stop()` pair is the honest spelling; a per-session pull is not. (b) would
warp the dictation seam for a consumer that does not exist yet — the exact "do not warp
the seam" posture the seam doctrine demands.

**Seam doctrine note, recorded here (the table-row correction):** `ARCHITECTURE.md:256`
names `AudioCapture`/`PushToTalkCapture`; the real names are `SessionAudioSource` +
`MicrophoneSource` (dictation) and `ContinuousAudioSource` + `StreamingCapture` (C10). The
`ARCHITECTURE.md` edit itself rides with the `record` aspect (PRD decomposition); this plan
records the correction so `record` does not re-derive it. The doctrine's "a seam with one
implementation is not a seam" applies to the *family*: the family has two implementations
at ship (push-to-talk, streaming); `ContinuousAudioSource` has one conformance, and that
interim state is recorded here, honestly — no second continuous engine is planned.

### Phase 2 (GREEN) — the seam and the conformance

**Goal.** Make Phase 1 green. Two files, one commit. The dictation files are not opened.

**Files.**
- `Sources/VoccaCore/ContinuousAudioSource.swift` (new) — the protocol, the
  `ContinuousAudioSourceError` enum, the seam doc (the interim-state record, the
  "continuous, never started at interrupt time" contract sentence). VoccaCore imports
  nothing (`CoreBoundaryTests` fact).
- `Sources/VoccaAudio/StreamingCapture.swift` (new) — the conformance. Public surface,
  deliberately small:
  - `public static let cadence: Duration = .milliseconds(50)` — **the one file that names
    the voice-loop drain tick** (single-source-scan material, the
    `SpeculativeFeed.cadence` precedent).
  - `public init(graph: any CaptureGraphSeam, schedule: (Duration, @escaping () -> Void) -> Void, unschedule: () -> Void, cadence: Duration = Self.cadence) throws` — builds its own `AudioFormatConverter` from `graph.captureFormat` (throws `AudioFormatConversionError`), like `MicrophoneSource.init` (`:198-219`). One instance, one graph, one ring, one converter, one consumer — by construction.
  - `public func start() throws -> AsyncStream<AudioBuffer>` — order is load-bearing,
    mirroring `beginCapture` (`MicrophoneSource.swift:228-237`): read the refusal
    baseline (`ring.refusedSampleCount`) and `converter.beginSession()` **before**
    `graph.start()` (the reset anchors at the start that cannot be skipped; the measured
    stale-converter defect, `AudioFormatConverter.swift:131-135`); then `try graph.start()`
    (throw → `.unavailable`, **nothing scheduled, `running` stays false, no stream
    exists**); then create the stream, set `running`, schedule the tick. A second `start()`
    while `running` throws `.alreadyStarted` and changes nothing (the first stream stays
    live). `start()` is **not** called from any realtime thread (the
    `CaptureStartTiming.whenTheOwnerAsks` discipline is the loop's, but the conformance
    documents it).
  - `public func stop()` — guard `running` else return (idempotent, and a no-op before
    any start). **Order: `graph.stop()` first** (device released; the refusal counter —
    producer-written — becomes stable; the `endCapture` ordering, `MicrophoneSource.swift:253-259`),
    then `running = false`, `unschedule()`, drain the ring's remainder, `converter.finish(remainder)`
    (flush the resampler's tail), yield the converted remainder as the final chunk if
    non-empty (no empty chunk ever), `continuation.finish()` — **exactly once**. The
    final-drain conversion cannot fail the release (the release already happened) and no
    hand-over is owed, so a conversion failure here logs loudly and finishes the stream —
    **the trap is deliberately not inherited**: `endCapture`'s trap exists because its
    return is the machine's "released and done" claim over a transcript that was owed;
    this stop path owes nothing and cannot leave a hot mic (the release preceded it).
  - `public var refusedSampleCount: Int` — `ring.refusedSampleCount - refusedAtStart`:
    the countable loss over the capture life (the "countable is counted" standard). The
    chunks themselves carry `missingSampleCount: 0` (fact 9).
  - Internal `tick()`: `MainActor.preconditionIsolated(...)` (the `SpeculativeFeed.swift:189-193`
    precedent — the timer fires on the main run loop, and the ring's consumer discipline
    depends on it), guard `running`, drain, skip empty, `converter.convert(drained)`.
    **Converter throw (the one genuinely new failure mode): log loudly, stop the graph
    (device released — never a silent hot mic), unschedule, `running = false`, finish the
    stream** — the `SpeculativeFeed.swift:200-211` answer, plus the release this type must
    add because capture does not end at a session boundary. Documented, reviewed, and
    **not headlessly drivable** (fact 7 — the real converter cannot be made to throw; the
    plan rejects fabricating an injection seam to fake it; the drivable invariants of the
    path — every terminal releases the device, streams finish exactly once — are pinned by
    the stop-path and restart tests).
  - `import VoccaCore` + `import OSLog` only. **No AVFoundation import** (fact 5).

## Testing strategy

All twelve contract tests drive a **real `StreamingCapture` over the fake graph** — real
ring, real converter — exactly the `MicrophoneSource` precedent (`MicrophoneSourceTests.swift:453-499`):
the conformance's end-to-end path (drain → convert → yield) is only real if the ring and
converter are; the graph is the one thing faked, because the real one is executed by
nothing in CI.

1. `testStartOpensTheGraphAndYieldsTheStream` — `start()` returns a stream and the graph's
   ledger shows one `start()`.
2. `testStartThrowsUnavailableWhenTheGraphRefusesToOpen` — `nextStart = .failure`; `start()`
   throws `.unavailable`; nothing scheduled, `running` false, no stream exists.
3. `testChunksAreConvertedToTheInterchangeFormatInOrder` — write known 48 kHz blocks; tick
   three times; the chunks are 16 kHz mono (the converter's own property: `AudioBuffer`'s
   initializer traps otherwise), contiguous, in order.
4. `testOneChunkPerNonEmptyTickAndNoEmptyChunks` — an empty-ring tick yields nothing; a
   populated tick yields exactly one chunk; **no empty `AudioBuffer` is ever yielded**.
5. `testStopMidStreamFinishesWithTheRemainderAsTheFinalChunk` — tick, write more, `stop()`;
   the final chunk is the unconsumed remainder (`converter.finish` flush included); the
   stream then ends; the graph's ledger shows the stop; `graph.isRunning == false` at the
   moment the final chunk is observed (the release-precedes-drain ordering).
6. `testDoubleStopIsANoOp` — a second `stop()` neither drains again nor finishes a second
   stream nor crashes.
7. `testStopBeforeStartIsANoOp` — `stop()` on a fresh conformance: no-op, no stream
   finished, no graph call.
8. `testASecondStartWhileRunningIsRefused` — **the ownership pin**: a second `start()`
   throws `.alreadyStarted`, and the first stream stays live (one more tick still yields) —
   the API-level refusal that keeps "at most one consumer thread at a time" true for the
   conformance's ring.
9. `testStartAfterStopBeginsANewStreamWithAFreshBaseline` — stop, start again: a fresh
   stream, a fresh `beginSession()` reset (the measured stale-converter trap,
   `AudioFormatConverter.swift:131-135`), a fresh refusal baseline; both streams finished
   exactly once.
10. `testTheLossIsCountedOnTheConformanceNotTheChunks` — force refusals (write blocks the
    ring refuses, the test-side retry caveat of `AudioRingBuffer.swift:357-359`); every
    yielded chunk carries `missingSampleCount == 0` (fact 9's slice semantics) while
    `refusedSampleCount` reports exactly the baseline-subtracted delta.
11. `testTwoInstancesOnTwoRingsDoNotInterfere` — two conformance instances, each on its own
    fake graph/ring; ticking one yields nothing from the other — the "owned separately
    from the dictation rings" fact at the unit level (the composition-level proof is the
    Phase-3 pin: the dictation files never meet `StreamingCapture`).
12. `testTheStreamEndsExactlyOnceAcrossConsumerDropAndStop` — the "stream cancelled vs
    stopped" edge: a consumer stops iterating (task cancelled) mid-capture; `stop()` then
    completes without a trap and finishes the stream once; the graph is released.

Not drivable headlessly, recorded honestly (fact 7): the mid-stream converter-throw path.
Its observable invariants — every terminal releases the device, streams finish exactly
once — are the ones tests 5, 6, 9 and 12 pin on the drivable paths; the failure path
itself is documented in the type and reviewed, the `SpeculativeFeed.swift:200-211`
precedent. The AVFoundation set lint (fact 5) and the module-boundary lint (fact 6) run
for free against the new files.

## Edge cases

- **Stop before start** → no-op (test 7). **Double stop** → no-op (test 6).
- **Second start while running** → `.alreadyStarted`, first stream untouched (test 8).
- **Start after stop** → fresh stream, `beginSession()` reset, fresh baseline (test 9).
- **Stream cancelled vs stopped**: dropping the stream does **not** stop capture — the
  lifecycle is `stop()`'s and the loop owns it; yields after a drop are buffered by the
  stream and the documented main-actor confinement (tick and consumer serialized, one
  chunk per tick) keeps the buffer at ≤1 in practice — the feed's confinement, restated
  (test 12).
- **Missing samples**: chunks carry `0` (a continuous slice is not a hand-over; the
  completeness link has no transcript meaning here); the countable loss is exposed as
  `refusedSampleCount`, baseline-subtracted (test 10).
- **Converter failure mid-stream** → log loudly, release the device, finish the stream —
  never a hot mic with no reader; recorded as not headlessly drivable (fact 7). The
  `endCapture` trap is **not** inherited, deliberately: it guards a transcript hand-over
  this path does not owe (Phase 2, `stop()` rationale).
- **The 120 s ceiling does NOT apply here.** The ceiling is a dictation-machine fact (the
  session machine's bounded sessions); the voice loop is **unbounded by design**
  (`ARCHITECTURE.md:571`: capture is continuous) — `StreamingCapture` carries no ceiling
  logic, and the ring's capacity (8,388,608, the composition-root constant) is the loop's
  composition decision, not this conformance's.
- **Graph start failure** → `.unavailable` (the loop maps it like `CaptureStart.unavailable`).
- **Configuration change mid-capture** → the graph's `onConfigurationChange` callback is
  the composition root's wiring and the loop's trigger, not the conformance's (the
  `MicrophoneSource` stance, `MicrophoneSource.swift:181-182`).
