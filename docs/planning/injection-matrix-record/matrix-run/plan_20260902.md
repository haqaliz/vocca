**Date:** 2026-09-02 · **Feature:** injection-matrix-record · **Spec:** `docs/planning/injection-matrix-record/matrix-run/spec.md`

## Context

The evidence slice (`evidence-logging`) is landed and the app builds with it: every real
dictation now emits `session opened` + `delivery` info lines under
`log show --predicate 'subsystem == "dev.vocca.Vocca"'`, and the harness appends a run-log
JSONL file per row. This plan is **founder-machine execution** — the harness cannot press ⌥Space
or guess a rung (`Scripts/injection-matrix.sh:24-30`). The agent's role: execute the
record/verify side, keep the branch green, and never touch ladder behavior. The founder's role:
the dictation gestures, per the checklist's own gesture text.

Prerequisites before starting: the app built from this branch (`feat/injection-matrix-record/aliz`),
Accessibility + Microphone grants live, the Parakeet model prepared, hotkey working — the
checklist's precondition discipline (`SMOKE_CHECKLIST.md` preamble rules).

## Phase 1 — Prepare the machine (founder + agent)

1. Run `Scripts/injection-matrix.sh --verify-bundle-ids` in the worktree. Record the CONFIRMED /
   UNVERIFIED totals. Zero mismatches is the bar; fix any mismatch in the harness table AND the
   shipped seed if the row is seeded (`SMOKE_CHECKLIST.md:87`), test-first if the seed changes.
2. Run `Scripts/injection-matrix.sh --dry-run` and list the rows that are NOT installed.
   **Swap selection (OQ1):** for each missing row, choose an installed same-class app from the
   dry-run output — same class, not already a row, preferred from the founder's real usage.
   Candidate classes: Pages (native AppKit) → e.g. Freeform/Preview; Notion (Electron) → any
   installed non-row Electron app; Ghostty (terminal) → e.g. iTerm2; IntelliJ (Java/AWT) → any
   installed JVM app, else the row stays skipped (documented); Zed (native non-AppKit) → any
   installed non-AppKit native editor, else skipped; 1Password (known-hostile) → step 92 runs
   via the PasswordField row if no password manager is installed.
3. Record each swap in the harness table (`Scripts/injection-matrix.sh` ROWS) AND the checklist's
   ID-source column (`SMOKE_CHECKLIST.md:1755-1778`), exactly like the baseline's iTerm2→Warp and
   Slack→Teams swaps. Bundle ids read via `plutil` from the installed apps.
4. Fresh memory: quit Vocca, delete `~/Library/Application Support/Vocca/strategies.json`,
   relaunch.

## Phase 2 — Step 87 baseline run (the run that learns)

Per `SMOKE_CHECKLIST.md:87` gesture text, with evidence now expected:

1. Run the full matrix (`Scripts/injection-matrix.sh`). Per row the founder dictates the fixed
   phrase; the harness does select-all/copy/byte-compare; the founder answers the rung y/N —
   now answerable from the log, not memory.
2. **Evidence verification per row (agent):** `log show --predicate 'subsystem ==
   "dev.vocca.Vocca"' --last 10m` must name the session and the landing rung for each row; the
   run-log file (`~/Library/Application Support/Vocca/matrix-runs/<date>.jsonl`) must carry the
   row. A row whose observation has no machine corroboration repeats the v0.1.0 failure
   (`SMOKE_CHECKLIST.md:1905`) — that row is recorded "reported, not measured" and the run is
   not a matrix run (`SMOKE_CHECKLIST.md:1726-1728`).
3. Record per row: rung named in the log, bytes matched, surprises. The observations ARE the
   recalibrated expected-rung column.
4. **Pass:** zero mismatches + every installed row produced a recorded observation. **Failure:**
   a row with no recorded observation — recorded as the work list.

## Validation

- Every installed row's observation cites: log window + run-log line + (where a strategy
  changed) `strategies.json`.
- FMS = deliverable rows whose expected rung landed / deliverable rows run; ≥19/20 is the bar,
  anything else is recorded as itself.
- No gate claim. No tolerance re-baseline. No ladder fix to chase 19/20 (work list instead).

## Edge cases

- A swapped app that itself fails the byte-compare: recorded as a miss, becomes the work list.
- A swap candidate that is ALSO a promotion candidate (e.g. a native AppKit app): its expected
  rung stays `.clipboardPaste` per OQ1 until the baseline says otherwise.
- The run-log file missing a row → the row is "reported, not measured"; investigate the session
  (did the app actually run with the evidence build?) before re-running the row.
- Secure Input during the run (a password prompt stealing the tap): the tap-disabled stop ends
  the session cleanly; the row is voided, not failed (checklist preamble rule 1).
