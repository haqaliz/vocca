## Design decisions (decided here, recorded — the projection contract after Phase 2 is final)

**D1 — One CONVERSING state with a phase payload, not a pair.** `WidgetState` gains exactly one case,
`.conversing(phase: ConversePhase)`, where `ConversePhase` is a closed two-case enum (`.listening`, `.speaking`).
The PRD's latitude ("the sixth widget state — or the listening/speaking pair", `prd.md:138-139`) resolves here
to one state for three reasons:
1. **The never-a-target rule becomes structural.** `.conversing` carries **no target payload** — the type
   itself cannot express a target app name, which is the strongest form of `PRODUCT_SPEC.md:200`'s "the widget
   never shows a target app name". A pair would still need a payload-free design; one case makes the absence a
   property of the type, not of a choice at each render.
2. **A converse session is one continuous loop.** The listening/speaking transition (reply playback starts,
   stops) is a *phase of the same session*, not a mode change: the capture never stops, the pill must not
   collapse/reopen between utterances, and there is no separate timer bookkeeping for "speaking". A pair of
   `WidgetState` cases would imply two independent states the reducer could diverge on; one case with a phase
   keeps the session's continuity in the type.
3. **The projection stays a total function over the machine's vocabulary.** The loop's five `TurnState`s
   collapse into two widget-visible phases plus idle (D2); one case with a phase makes that collapse explicit
   in the projection, never in a caller.
`ConversePhase` lives in `VoccaCore` beside `WidgetState` (stdlib-only; `Equatable + Sendable`).

**D2 — The `TurnState` → `WidgetState` projection leg.** A new overload on `WidgetProjection`,
`project(turnState: TurnState) -> WidgetProjectionResult`, total over the closed five-case set:

| `TurnState` | Projected | Why |
|---|---|---|
| `.idle` | `.state(.idle)` | The loop is stopped — the converse session ended (the stop affordance or a system trigger). |
| `.listening` | `.state(.conversing(.listening))` | Continuous capture + VAD, nothing spoken. |
| `.uttering` | `.state(.conversing(.listening))` | The user is mid-sentence; the widget still listens (`◈ listening…`). |
| `.committed` | `.state(.conversing(.listening))` | The turn was handed over, the reply is pending, nothing is being spoken — the honest statement is still "listening". |
| `.playing` | `.state(.conversing(.speaking))` | The reply is being rendered; Vocca is speaking. |

The invariant this leg pins: **`.conversing` comes only from the turn-state projection — never from a
`SessionEffect` fold** (the dictation leg's table at `:97-104` is unchanged, and the closed-set test asserts
no `SessionEffect` maps to `.conversing`). The converse session's *end* is `.idle` from `TurnState.idle` — the
loop is stopped, the widget returns to IDLE, the panel hides. The projection never invents a state (the
`widget-live-states` rule, `spec.md:46`): this is a total function over the machine's own vocabulary.

**D3 — The shape tokens.** `PRODUCT_SPEC.md:193` contrasts "rounded rectangle" (dictate) with "pill with a
distinct notch" (converse). The shipped dictate shape is `Capsule()` (`WidgetView.swift:72`), which is a
rounded rectangle at maximal radius — **dictation visuals are untouched** (out of scope). The converse
distinction is the **notch**: a small triangular notch cut into the leading edge of the pill. Shipped as:
- `WidgetShape` — a closed two-case enum (`.capsule`, `.notchedPill`) with `WidgetShape.for(_ state: WidgetState)`,
  a pure mapping: `.conversing` → `.notchedPill`, every other state → `.capsule`. The tested half — a second
  implementation, or a drifted mapping, cannot appear where CI cannot see it.
- `NotchedPill` — a SwiftUI `Shape` (the capsule + the notch), glue executed by nothing in CI.
- `VoccaTheme.Panel.converseNotchDepth` / `converseNotchWidth` — the notch metrics (a single place each), named
  per the token doctrine (`DesignTokens.swift:17-31`).

**D4 — The color token.** `VoccaTheme.State.conversing` = `Color(nsColor: .systemPurple)`. "Clearly different
hue (not a tint of the same one)" (`:194`): purple is the system semantic hue furthest from the widget's other
fills — opening's accent (blue), recording's red, delivered's green, transcribing's secondary, egress's
orange (`DesignTokens.swift:44-60`) — while staying a semantic system colour that follows Increase Contrast
and the user's appearance (the DesignTokens rationale, `:19-31`). `:203` is honored: color is the **third**
cue — the notch (shape) and the `◈` label carry the signal for the common color-vision deficiencies, so the
purple/red distinction does not have to survive deuteranopia alone. A token test pins it is a distinct hue,
not an equal or tinted colour.

**D5 — The label copy and the never-a-target pin.** Three strings, decided here:
- `WidgetCopy.conversePersistentLabel = "◈ Vocca"` — pinned to `PRODUCT_SPEC.md:195` (the §5 label row: "no
  target — nothing will be typed"). The mode's persistent identity.
- `WidgetCopy.converseListeningLabel = "◈ listening…"` — pinned to `PRODUCT_SPEC.md:83` (the §2 CONVERSING art,
  verbatim glyph `◈` U+25C8). Rendered while `.conversing(.listening)`.
- `WidgetCopy.converseSpeakingLabel = "◈ speaking…"` — **new copy the spec does not write** (the §2 art writes
  only the listening line; the task's "`◈ listening…`/speaking in-state" and the §5 pattern are the source).
  Mirrors `:83` exactly: the `◈` glyph + the gerund + `…`. Rendered while `.conversing(.speaking)`.
- `WidgetCopy.converseLabel(_ phase: ConversePhase) -> String` — the phase → label mapper (the one place the
  phase's words live).
The never-a-target pin is **structural + asserted**: `.conversing` carries no payload (D1), `WidgetCopy` has
no converse function that takes a `targetAppName`, the converse view branch has no target input, and a test
asserts no converse render can produce a `→`.

**D6 — The sound: a seam, the lower tick, the "distinct from dictate" recorded honestly.** The converse cue is
`PRODUCT_SPEC.md:339`'s "lower tick, clearly different from dictate". No sound exists in the tree (Vetted
fact); the dictate tick is deferred (N1/S4). Shipped as:
- `WidgetSound` — a closed one-case enum (`.converseStarted`). §9's other three events (`:336-338` recording
  start, delivered, failsafe) are recorded as future cases, **not added empty** — YAGNI, and a future
  dictation-tick aspect fills its own slot. The doc comment records the reservation.
- `WidgetSoundSelection.sound(from previous: WidgetState, to next: WidgetState) -> WidgetSound?` — the pure,
  tested half: `.converseStarted` exactly on a transition **into** `.conversing` (any non-converse state →
  converse, including the first entry from IDLE; the listening↔speaking phase change plays nothing). Nothing
  else plays anything — the dictation transitions are silent because the dictate tick is not built.
- `WidgetSoundPlaying` — a `Sendable` protocol, one synchronous `func play(_ sound: WidgetSound)` (the
  `LiveLevelSource` seam shape, `LiveLevelSource.swift:30-33`).
- `SystemWidgetSoundPlayer` — the real conformance in `VoccaUI` (AppKit/AVFoundation is free, ModuleBoundaryTests),
  glue executed by nothing in CI: a short (~60 ms), quiet, **low** tone with a fast decay envelope. The tone's
  pitch is the recorded "lower" decision: chosen at the low end of the tick range, with the dictate tick's
  slot reserved higher — **the audible "clearly different from dictate" is verified when the dictate tick
  ships (SMOKE), never gated here**. Audio is created lazily on first `play`, so constructing the default
  player is headless-safe.
- The **panel hook**: `WidgetPanel` gains a defaulted `soundPlayer: any WidgetSoundPlaying = SystemWidgetSoundPlayer()`
  and a `lastState` diff — on every `apply`, `sound(from: lastState, to: state.state)` plays. `LiveWidget`
  passes the player through (defaulted; `AppBootstrap.swift:1839`'s call site compiles unchanged). The first
  entry to converse creates the panel (Vetted fact) and the initial `apply` plays the tick. The hook is glue;
  the *selection* is the tested decision (a `RecordingWidgetSoundPlayer` fake in tests).

**D7 — The stop affordance: PRIMARY = the converse chord again.** Recorded per R4 (`prd.md:142-146`), which
demands "stoppable by an explicit user action … — the exact surface decided in the aspect spec, recorded".
The decision: **the primary explicit stop is the converse chord pressed again** (`⌥⇧Space` — `converse-hotkey`'s
chord, referenced not owned). Justified against `PRODUCT_SPEC.md:198-201` and the mic-truthfulness principle:
1. **R1 names it.** "A chord for the **active** mode is that session's own control (dictate: hold/toggle as
   today; converse: the stop affordance, R4)" (`prd.md:120-125`). The chord-again stop is the direct analog of
   ⌥Space-again-to-stop in dictate.
2. **It cannot read as the other mode's chord.** The same chord that started the session ends it; equality-match
   semantics (`SessionRules.swift:66-72`) keep `⌥⇧Space` distinct from `⌥Space`, so the stop is never a dictate
   chord and never an implicit switch (`:199`); a dictate chord pressed during converse is the mode machine's
   no-op (R1) — the mode is never inferred.
3. **The dictate amendment endorses the toggle end.** `PRODUCT_SPEC.md:355`: toggle became the shipped default
   because "neither end of the session is a release the user has to sustain". Converse inherits the same end.
4. **No pointer needed.** The P3 spoken-exchange leg runs with the keyboard untouched except the app's own
   chord (`ROADMAP.md:215-217`); the menu-bar toggle needs a mouse.
**Secondary — the menu-bar toggle also stops a live converse session** (R5's surface; the record plan's SMOKE
137 requires "a converse session actually stoppable from the menu" — `record/plan_20260916.md:241-256`). It is
the explicit non-chord surface (`prd.md:101`). **Not the stop — Esc.** Esc is dictation's cancel (discard the
session, `WidgetProjection.swift:103`); converse has no transcript to discard, and routing Esc to stop would
blur the two modes' cancel vocabularies. Whether `mode-machine` additionally routes Esc is its decision —
recorded as not-decided-here. The **system-trigger stops** (sleep, display sleep, tap disabled — R4) are the
machine's/watchdog's, not this surface's. No-silent-listening is satisfied: the stop is one chord press
reachable without looking at the screen, and CONVERSING is a visible state the whole time (`prd.md:102-103`) —
there is no state in which the mic is live and the widget is quiet.

**D8 — The menu-bar mode toggle's reducer path.** `PRODUCT_SPEC.md:361` (§11): the menu bar shows "current
state, mode toggle". Shipped as:
- `MenuBarConditions` gains `mode: SessionMode = .dictation` (a `VoccaCore` type, already public,
  `SessionMode.swift:25-31`; the defaulted field keeps every existing construction site compiling —
  `AppBootstrap.swift:1250` and the tests).
- `MenuBarCopy` gains the mode rows: `modeTitle(.dictation) = "Dictation"`, `modeTitle(.conversing) = "Conversation"`,
  and `modeToggleTitle(_ mode: SessionMode)` — **new copy the spec does not write** (§11 names the toggle's
  existence, not its words), exact-equality pinned with the decision recorded. The product's own vocabulary
  (`conversing`/`Conversation`, `prd.md:47-52`).
- `MenuBarItem` gains a **mode section** in `menu(for:)` (`:113-134`): the two rows, the **active mode checked**
  (derived from the current mode), each row invoking `onSelectMode(_ mode: SessionMode)` — a new defaulted
  callback (`= { _ in }`), so `AppBootstrap`'s construction (`:645-651`) compiles unchanged and the routing
  (start/stop/refuse) is `converse-wiring`'s + `mode-machine`'s. **Explicit only**: the rows name the mode they
