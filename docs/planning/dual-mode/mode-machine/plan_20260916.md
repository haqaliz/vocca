## Design decisions (pinned — do not re-decide)

- **D1 — Where the machine lives.** Four new files under `Sources/VoccaCore/Mode/`, the
  capability-directory convention (`VoiceDetection/`, `TurnDetection/`, `TurnTaking/`). The
  machine **lives beside** the enum, not in `SessionMode.swift` (the "or the machine lives
  beside it" branch of `understanding.md:53`): the enum is `Sendable, Equatable` vocabulary
  consumed by `CleanupContext` and `MatrixEvidence`, and the house separates vocabulary from
  machine (`SessionEffect.swift` vs `SessionMachine.swift`). `SessionMode.swift` gets a doc-only
  amendment naming the machine. (ARCHITECTURE.md:101's `Session/` sketch is a doc-sync item for
  the `record` aspect, not a binding.)
- **D2 — Synchronous, owner-isolated, effects — the `SessionMachine` shape.** A final class,
  not `Sendable`, not an actor, no `await` on its surface: the mode decision arrives from the
  same tap path that cannot suspend (`SessionMachine.swift:41-55`). It holds the three facts R1
  names — the current mode, the epoch, the in-flight `ModeSession` — and returns
  `SessionModeEffect` values; the owner performs (activates wirings, fills the record, routes
  the stop). The owner never keeps a second copy of the mode: it reads `machine.currentMode` to
  route (the `SessionMachine.configuration` precedent, `SessionMachine.swift:71-76`).
- **D3 — The chord→mode routing is injected as a decided intent; the machine never sees a
  chord.** Input: `SessionModeIntent.start(SessionMode)` — the hotkey aspect owns the second
  chord (persistence, rebind, the equality match) and delivers the *decision*; the machine owns
  the *rules*: starts are keyed to a mode, never inferred, and the refusal cannot be bypassed by
  a second opinion. The machine is chord-agnostic (no keyboard in `VoccaCore` tests), and the
  equality semantics below it are pinned already (`SessionRules.swift:187`) — consumed, not
  re-litigated.
- **D4 — The transition table is closed and exhaustive.** State `idle | active(mode)`. The
  table in Phase 1's Testing strategy is the whole of the behavior: **mid-session switching is
  impossible** (there is no `active(m) → active(other)` row — it is `.refused`), **one active
  capture at a time** (only `.idle` can produce `.started`), **no implicit switching** (no input
  can change the mode except a start from idle), and **no session outlives a system trigger**
  (the `.system` row covers every `SystemTrigger` case, swept by `CaseIterable`).
- **D5 — The reset is pinned by the epoch-minted `ModeSession` handoff.** The machine owns the
  mode-scoped session record — `ModeSession<Audio>` with the three slots R2 names (`buffer`,
  `transcript`, `target`) — minted fresh at every `.start`, filled by the owner through the
  three `fill` methods, handed out inside `.stopped`, and cleared with `currentMode` at the
  stop. There is exactly one `session` field, replaced at every start: **carryover is
  unrepresentable inside the machine**, and the reset test drives full cycles in both directions
  to prove it. The machine does not reach into driver-owned state (the dictate ring, the
  router's resolution) — duplicating it would be the two-copies-of-one-fact desync the house
  bans (`SessionMachine.swift:103-105`); the record is the *typed carrier* at the machine's own
  boundary, and the dictation funnels stay untouched (`SessionOutcome.make` one-place rule).
- **D6 — The stop affordance is a first-class input.** `SessionModeIntent.stop` + the
  `.stopped(mode, epoch, session)` effect. The *exact surface* (converse chord again, Esc, the
  menu-bar toggle — `prd.md:142-145`) is the widget aspect's decision (R4/O5); the machine
  exposes the stop so that aspect has one seam to wire. The active-mode chord row
  (`.sessionControl(.conversing)`) is the chord-leg of the same affordance; the dictate chord's
  meaning stays the rules' (unchanged).

## Phase 2 — GREEN: the machine

**Goal.** The four production files under `Sources/VoccaCore/Mode/` make every Phase-1 test
green. The signatures pinned here are the contract the `converse-wiring` and `widget-converse`
aspects compile against — final after this phase.

**Files:**

1. `Sources/VoccaCore/Mode/SessionModeIntent.swift` — the input enum:
   `public enum SessionModeIntent: Sendable, Equatable { case start(SessionMode); case stop; case system(SystemTrigger) }`.
   Doc: the intent is a **decision**, never a key event — the chord→mode mapping is the hotkey
   aspect's, delivered here; the machine never sees a chord (D3).
2. `Sources/VoccaCore/Mode/ModeSession.swift` — the handoff record:
   `public struct ModeSession<Audio: CapturedAudio>: Sendable, Equatable { public let mode: SessionMode; public let epoch: UInt64; public var buffer: Audio?; public var transcript: String?; public var target: TargetContext?; public init(...) }`.
   Doc pins: minted by the machine at every start (the only constructor in production is the
   machine's — the lint row), filled by the owner through `SessionModeMachine.fill*`, handed out
   inside `.stopped`, and never shared across activations; the `target` slot stays nil in a
   converse cycle by construction (`PRODUCT_SPEC.md:200`).
3. `Sources/VoccaCore/Mode/SessionModeEffect.swift` — the closed effect enum:
   `public enum SessionModeEffect<Audio: CapturedAudio>: Sendable { case started(SessionMode, epoch: UInt64); case sessionControl(SessionMode); case refused; case stopped(SessionMode, epoch: UInt64, session: ModeSession<Audio>); case unchanged }`,
   `Equatable where Audio: Equatable` (the `SessionEffect.swift:62` shape). Doc pins the
   delivery contract for the wiring aspect: `.started(m)` → the owner activates m's wiring;
   `.sessionControl(m)` → the owner forwards to the active wiring (dictate: the rules decide;
   converse: the stop affordance's chord leg); `.refused` → a no-op, nothing delivered, the key's
   propagation stays the routing table's concern; `.stopped` → the owner routes the stop to the
   active wiring and the record onward.
4. `Sources/VoccaCore/Mode/SessionModeMachine.swift` — the machine, `public final class
   SessionModeMachine<Audio: CapturedAudio>`:
   - `public private(set) var currentMode: SessionMode?` (nil = idle), `public private(set) var
     epoch: UInt64 = 0`, `public private(set) var session: ModeSession<Audio>?` (minted at
     `.started`, cleared at `.stopped`).
   - `public func observe(_ intent: SessionModeIntent) -> SessionModeEffect<Audio>` — the one
     funnel (the `SessionMachine.observe` shape, `SessionMachine.swift:308-374`), the committed
     table switched inside, no `default:`:
     - `.idle` + `.start(m)` → mint `ModeSession(mode: m, epoch: epoch &+ 1)`, `epoch &+= 1`,
       `currentMode = m` → `.started(m, epoch:)`.
     - `.active(m)` + `.start(m)` → `.sessionControl(m)`. `.active(m)` + `.start(other)` →
       `.refused` — nothing changes, not even the epoch.
     - `.active(m)` + `.stop` → `let s = session`, clear `session`/`currentMode` →
       `.stopped(m, epoch, s)`. `.idle` + `.stop` → `.unchanged`.
     - `.active(m)` + `.system(_)` → the stop row above (every case — `CaseIterable` is the
       test's sweep). `.idle` + `.system(_)` → `.unchanged`.
   - `public func fill(buffer: Audio)`, `fill(transcript: String)`, `fill(target: TargetContext)`
     — precondition: a session is active (`currentMode != nil`); the record's slot is set. The
     owner calls these when the driver produces the value (dictate: the outcome's buffer at the
     terminal, the pipeline's text, the resolved target; converse: the committed utterance, the
     cleaned text — never a target).
   - Class, not actor, not `Sendable` — owner-isolated, the `SessionMachine.swift:41-55`
     argument verbatim; no `@unchecked` anywhere.

**Also in this phase:** the `SessionMode.swift` doc amendment — :17-21's "Declared, never read
at C5 … consumed by C6/C11, never here" becomes "read by `SessionModeMachine` since C11"; add a
`- SeeAlso` to the machine; :23-24's activation-mode disclaimer stays (it is now *more* true).
Doc-only, in the same commit.

**Why these signature choices (pin the reasoning in the seam doc comments):**

- **`SessionMode` as the input payload, never a `HotkeyChord` or `RawKeyEvent`.** The machine
  decides *about modes*, and the chords are the hotkey aspect's persistence and match problem
  (`prd.md:132-137`). A chord on this surface would drag the keyboard into `VoccaCore` tests
  and duplicate the equality match the rules already own (`SessionRules.swift:187`).
- **One `observe` funnel.** Every input travels one path through the same switch — a second
  entry point is how a state machine acquires an unguarded row (the `SessionMachine` argument,
  `SessionMachine.swift:308`).
- **The record is minted by the machine, not by the owner.** "Full reset" then has one subject
  (`session`), replaced at every start — the reset test cannot be made to pass by a fake that
  forgets to clear. The epoch makes activations distinguishable even when the mode is the same
  (`testSameModeRestartIsAlsoATransition`).
- **Effects carry the epoch; refusals do not mint.** `.refused` leaves `epoch` untouched, so a
  refused press is *provably* not a session — the no-op is total, not merely "no visible
  effect" (R1's "refused as a no-op").
- **No `.ending` state.** The mode machine's stop is synchronous bookkeeping (mint → hand out →
  clear); the async-ish handoff window is the drivers' (`SessionMachine`'s `.ending` exists for
  the audio source's `endCapture`, `SessionMachine.swift:656-662`). The mode machine has no
  resource to close; a second `.stop` lands in `.idle` and is `.unchanged`.

## Testing strategy

**The committed transition table** — the whole of the machine's behavior, one test per row.
Epoch starts at 0; every `.start` from `.idle` increments by 1.

| # | State | Input | Effect | Contract row |
|---|---|---|---|---|
| 1 | idle | `.start(.dictation)` | `.started(.dictation, epoch+1)` | the only route into `.active` — one capture at a time |
| 2 | idle | `.start(.conversing)` | `.started(.conversing, epoch+1)` | same |
| 3 | active(dictation) | `.start(.dictation)` | `.sessionControl(.dictation)` | the session's own chord — owner forwards to the dictate wiring; the rules decide (toggle-off / hold-release) |
| 4 | active(conversing) | `.start(.conversing)` | `.sessionControl(.conversing)` | the stop affordance's chord leg (R4) |
| 5 | active(m) | `.start(other)` | `.refused` | the other-mode chord is a no-op — never a switch (R1, G2); epoch unchanged |
| 6 | active(m) | `.stop` | `.stopped(m, epoch, session)` | the stop affordance seam (R4/O5) |
| 7 | idle | `.stop` | `.unchanged` | nothing to stop |
| 8 | active(m) | `.system(t)`, every t | `.stopped(m, epoch, session)` | continuous listening never outlives the triggers (R4) |
| 9 | idle | `.system(t)` | `.unchanged` | nothing to stop |

**The reset discipline (R2b)** — the three-slot record, minted per start, is the machine's only
session state: `ModeResetTests` drives full cycles (fill all three slots in dictate; fill
buffer+transcript in converse and assert `target == nil`), then starts the other mode and
asserts the fresh record is empty, the epoch differs, and the old values are reachable nowhere
on the machine. The same-mode restart row closes the "transition" definition: *any* start
resets.

**The prohibition (R2a), three layers:**
1. The vocabulary: `ModeSession`/`SessionModeEffect` are pinned plain data — the converse
   surface has no member that *could* hold an injector (compile pins + the exhaustive switch in
   `ModeProhibitionTests`).
2. The behavior: a full converse cycle emits only `.started(.conversing, _)` and
   `.stopped(.conversing, _, _)`; the target slot stays nil.
3. The scan: `Mode/` never names `TextInjector` (Phase-1 test), and the Phase-3 lint confines
   code-level `TextInjector` sightings in `VoccaCore` to `{TextInjector.swift,
   DictationPipeline.swift}` — a planted converse-path use fails the lint with the planted
   controls proving the detector works.

**Lint controls**: planted violations for all four family names, a planted second `ModeSession(`
mint site, a planted injector in a converse-shaped file, the comment-strip control, and the
non-vacuous guards (empty permitted set fails; each permitted file must name its family;
`TextInjector`'s permitted set non-empty and exactly the two files).

## Edge cases

- **Stop in `.idle`** → `.unchanged` (row 7); **second `.stop`** after a stop lands in `.idle`
  the same way — a stop is never queued and never errors (the B9 no-op posture,
  `SessionMachine.swift:631-633`).
- **System trigger in `.idle`** → `.unchanged` (row 9); the `CaseIterable` sweep pins all five
  cases in both states — a new `SystemTrigger` case fails to be swept only if the test's loop
  breaks, which the pinned loop makes a deliberate edit.
- **Refusal changes nothing**: after `.refused`, `currentMode`, `epoch`, and `session` are
  untouched, and a later `.stop` still ends the *original* session — pinned explicitly so a
  future "helpful" refusal that mints or clears cannot hide.
- **Fill with no session** → precondition failure (programmer error: the owner filled outside an
  activation). The tests assert the precondition fires; a `fill` after `.refused` also fails —
  the refusal is not an activation.
- **Same-mode restart** → a transition like any other (R1's reset wording), pinned by
  `testSameModeRestartIsAlsoATransition`.
- **Converse record's target** → structurally nil: the converse cycle never calls
  `fill(target:)`, and the reset test asserts the stopped converse record carries `target ==
  nil` — the never-a-target rule (`PRODUCT_SPEC.md:200`) as a machine fact.
- **Epoch arithmetic** → `UInt64` with `&+`/`&+=` (overflow is a mint collision at 2⁶⁴
  activations — out of scope, documented in the machine's doc comment, never special-cased).
- **The activation-mode collision (O6)** → naming only: this aspect's types are `SessionMode*`/
  `Mode*`; the hold/toggle activation (`ARCHITECTURE.md:590`) is not touched, and the machine
  never reads `defaultMode`/`setActiveMode` — that collision is a dictation-only configuration
  (`understanding.md:93-96`).
