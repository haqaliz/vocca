## Design decisions (decided here, recorded — the seam contract after Phase 2 is final)

**D1 — The protocol's exact signature.** The seam is the plainest possible boundary:

```swift
public protocol ReplyGenerator: Sendable {
    func reply(to text: String) -> String
}
```

- **Input is the cleaned transcript text (`String`), not the utterance frames (`[AudioBuffer]`), not
  `Transcript`.** The wiring recipe (R6) runs ASR and cleanup *before* the generator: frames are
  consumed by ASR, attribution/completeness (`Transcript.swift:32-66`) is consumed by nothing the
  reply cares about, and cleanup is `per-mode-cleanup`'s concern (it owns `CleanupContext`) — this
  aspect's input arrives already cleaned for `.conversing`. A seam that took frames would force the
  generator to depend on `AudioBuffer` vocabulary it never reads.
- **Synchronous, not async.** Reply generation runs once per committed turn, at a decision point,
  off the per-frame path — the `TurnDetector` precedent (`voice-detection/plan_20260915.md:204-209`).
  Both implementations are instant and deterministic; an actor hop buys nothing and would force the
  wiring to be async. **If C13's real agent forces an async leg, that is a C13 signature
  reconsideration — recorded, never added here** (the frozen-signature doctrine).
- **No identity on the seam.** The speech and cleanup seams carry `identity` because their outputs
  (chunks, cleaned text) flow into logs and ledgers. A reply text is consumed immediately by
  `scheduleReply` and rendered; the converse surface is state-only (N2) and the ledger is
  dictation-only — nothing downstream attributes it. Same reasoning the voice-detection plan
  recorded for VAD/turn seams. If C13 needs attribution it adds it — recorded, not added.
- **No wrapper type.** Output is `String` because `scheduleReply(_ text: String)` and
  `TurnEffect.speakReply(text: String)` are `String`-typed; a `ReplyText` wrapper would be a
  conversion at the only call site. The speech seam's `AudioChunk` vocabulary exists because the
  transport carries metadata; a reply string carries none.

**D2 — The two implementations and the honest copy.** The doctrine (`CAPABILITY_ROADMAP.md:414`)
requires two; O3 requires neither to be mistaken for an agent.

1. **`EchoReplyGenerator` — the shipped default** (the wiring aspect composes this one).
   `reply(to text:)` returns `text` **verbatim** — byte-for-byte, no normalization, no prefix, no
   trimming. Honesty posture (in the doc comment): the reply is the user's own words played back —
   it claims nothing beyond "the machine heard you", cannot be mistaken for agent intelligence, and
   doubles as a by-ear ASR-accuracy check for the P3 spoken-exchange SMOKE (hearing your words back
   is the strongest "the loop heard me" signal). It is deterministic by construction (identity
   function), local, and zero-network.
2. **`AcknowledgmentReplyGenerator` — the second implementation.** `reply(to:)` returns the fixed
   string **`"Vocca is listening."`** for every input, including empty. Copy decision: it states
   the mode's own honest state — the machine is listening, nothing more; no persona, no "got it"
   (which claims comprehension), no "the assistant is not here yet" (which sounds like a defect).
   It matches the widget's in-state label wording (`◈ listening…`, `PRODUCT_SPEC.md §5`), is short
   enough to speak, and can never be read as an answer to anything.

Both are stateless `struct`s conforming to the `Sendable` protocol — `Sendable` by construction
under strict concurrency, no `@unchecked` (the house's documented aversion,
`SpeechSynthesizerSeamTests.swift:196-199`).

**D3 — Test strategy.** Stub-free: unlike the synthesizers (whose real implementations need models
CI has not), **both implementations are headless and real**, so the contract tests and the
parameterized suite run over both directly — no stub, no env gate. The `SpeechFixtureSuite` shape
holds: fixtures in, results out, the body measures and records, **assertions live in the tests with
expected values written by hand** — never read back from the implementation. The seam-shape compile
pins (`requireGenerator(_:)`) make a weakened/renamed protocol stop compiling; the family lint
(Phase 3) confines both implementation names to their one file each inside VoccaCore, so a caller
cannot branch on an implementation it cannot name outside those files.

**D4 — Where the files land.** `Sources/VoccaCore/Reply/` — `ReplyGenerator.swift`,
`EchoReplyGenerator.swift`, `AcknowledgmentReplyGenerator.swift` (the `Speech/`, `TurnDetection/`,
`VoiceDetection/` subdirectory precedent). Stdlib-only; nothing to add to the empty import
allow-list.

## Edge cases

- **Empty input** → pinned for both implementations (see the tables): the echo returns empty, the
  ack returns the fixed string. The seam's empty behavior is explicit so the wiring can treat an
  empty reply as silence, never an error.
- **Whitespace-only input** → the echo returns it verbatim (no trimming — "verbatim" is a contract,
  not a convenience); the ack ignores it like everything else.
- **Unicode/punctuation input** → the echo is byte-for-byte (`String` identity, no normalization);
  pinned once so the behavior is explicit, not accidental.
- **Very long input** → no truncation, no budget: both implementations are O(1)/O(n) pure
  functions over a `String`; there is nothing to bound (contrast the cleanup seam's `budget` —
  `CleanupProvider.swift:59` — which exists because a provider can hang; a deterministic pure
  function cannot).
- **Non-finite / binary input** → not a case: the seam's input is text by construction; there are
  no numeric or audio paths to go wrong on.
- **The acknowledgment copy** → the one string in this aspect is pinned by exact equality; it is
  also deliberately **not** an agent-ish utterance (no "got it", no persona, no "let me check") —
  the O3 mitigation is the copy itself, and the test pins it.
