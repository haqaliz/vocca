## Design decisions (made here, justified, recorded)

### D1 — The stored shape: two key pairs, never a dictionary keyed by `SessionMode`

Four frozen keys, pair-per-chord. The dictation pair keeps `settings.hotkey.keyCode` /
`settings.hotkey.modifiers` byte-for-byte; the converse pair is `settings.hotkey.converse.keyCode`
/ `settings.hotkey.converse.modifiers`. The decode/encode functions are chord-agnostic and are
reused; only the fallback chord (and its rendered name in the report) differs.

Why not a dictionary keyed by `SessionMode` (e.g. `settings.hotkey.<mode>.*`): it re-means or
migrates the existing keys, which is exactly the event the frozen-key pin exists to prevent —
"change it and every existing user's choice becomes an absent value on their next launch,
silently" (`UserDefaultsSettingsStoreTests.swift:404-407`). Nothing consumes a mode-keyed
store today (the *machine* keys by chord value, not by stored key name), so the dictionary buys
nothing and costs a migration. Why this shape does not foreclose growth: a third chord is a
third pair (`settings.hotkey.<name>.*`) with no change to this one; per-mode activation, if a
later unit wants it, follows the same pair pattern; the two-keys-not-one rationale
(`UserDefaultsSettingsStore.swift:80-82`) is preserved **per chord** — a half-written converse
pair decodes loudly to ⌥⇧Space, never to a chord nobody chose.

### D2 — Where the chord→mode mapping lives: never here

The `mode-machine` aspect owns routing (R1): mode is selected by the chord that starts a
session, and the machine consumes the two chords this aspect persists and rebinds. This aspect
owns: the store seam (`converseChord()`/`setConverseChord(_:)`), the shipped defaults, the
General surface, the rebind gate, and the collision refusal. The seam is explicit so the
autonomous agent does not drift into building routing: **this aspect reads and writes chords;
it never decides which chord starts which mode.** The launch read stays per-pair — the decode
is the file format and does not cross-check. A hand-edited equal pair is therefore adoptable
at launch; the machine must answer that ambiguity honestly (its aspect, its test). The rebind
gate guarantees the app can never *create* an equal pair through its own surface.

### D3 — The rebind flow: the 7 steps generalize to `rebind(to:for:)`, with one new step

`rebind(to chord: HotkeyChord, for mode: SessionMode) -> RebindOutcome` replaces
`rebind(to:)` (compiler-named at every site). The 7 documented steps (`AppBootstrap.swift:2089-2100`)
generalize:

1. **unchanged** — `chord != boundChord(for: mode)` (per-mode; the old single `boundChord`
   becomes `boundChord(for:)`).
2. **NEW — the cross-chord collision** — `chord == boundChord(for: otherMode)` →
   `.refused(.collidesWithOtherMode)` (payload-free, see D4). Placed after the unchanged guard
   and before the rules: both are "the ask is wrong" checks, and the cheapest fails first. The
   refusal is returned, not logged (M5).
3. **rules validity** — unchanged (`PersistedSettings.isAdoptable`).
4. **quiet** — extended from `isQuiet(holdToTalk), isQuiet(toggle)` to **all wirings of both
   modes**, including the converse wiring (the wiring aspect's shape; the semantics pinned: a
   rebind of *either* chord is refused while *any* session — dictate or converse — is in
   flight, PRD R3).
5. **build** — per-mode: dictate rebuilds the hold/toggle pair via
   `hotkeyConfigurations(chord:)` (today's code); converse rebuilds the converse wiring via
   the wiring aspect's factory, with nothing adopted yet.
6. **persist** — `setHotkeyChord(chord)` or `setConverseChord(chord)` (after the build, before
   the swap — the M4-order rationale at `:2143-2147` holds per mode).
7. **swap + re-point** — one suspension-free block (the atomicity argument at `:2149-2154`
   holds per mode: no window in which one mode's wiring is new and the other old).
8. **stop the retired timers** — after the swap (`:2163-2169`).

The method stays synchronous (`:2102-2104`). The tap is not touched (`:2106-2108`).

### D4 — What the collision warning detects: equality, and nothing else

The cross-chord check detects **exactly**: the candidate equals the other mode's current
(wired, decoded) chord → **refused**. Justification: start matching is equality
(`SessionRules.swift:187,342`), so equality is the only configuration in which one press
matches both bindings and chord-keyed routing (R1) is ambiguous. It is a **refusal, not a
warning**: both chords are Vocca-owned facts, and house doctrine reserves warnings for facts
Vocca cannot verify (`SystemShortcutRulesTests.swift:22-25` — the user's machine is the
authority on their own shortcuts). The "collision warning" `PRODUCT_SPEC.md:252` names is the
system-shortcut warning, which already reaches both rows through the shared `validateChord`
seam with zero new code.

What is deliberately **not** a collision, pinned by test so it stays that way:

- **Same key code, strict-superset modifiers** (`⌥Space`/`⌥⇧Space` — the shipped pair): the
  superset press during a dictate hold-to-talk session is swallowed-ignored, which is the
  designed R1 no-op (`SessionRules.swift:122-128`), and the start equality is unambiguous.
- **Same key code, subset or disjoint modifiers; different key codes**: all unambiguous at
  start; containment-stop behavior is inherent to the stop rules, not a property of the
  binding (the documented trade at `SessionRules.swift:130-144`).
- **The asymmetric-unchanged trap**: candidate == the *same* mode's chord is `.unchanged`
  (no rebuild — `RebindBoundaryTests.swift:116-139`); candidate == the *other* mode's chord
  is `.refused(.collidesWithOtherMode)`. A single equality guard would silently answer
  `.unchanged` for the collision; the two questions are two guards, and both are pinned.
- **Caps Lock**: equality is masked on both sides by `HotkeyChord`'s init
  (`HotkeyChord.swift:39-42`), so the collision check inherits it — pinned once.

The vocabulary: a payload-free `collidesWithOtherMode` case in **both** `HotkeyBindingRefusal`
(the recorder's capture-time answer via the rules — the user is refused the moment they press
the other mode's chord, not after an apply round-trip) and `RebindRefusal` (the gate's
defensive twin, exactly the `.notBindable` precedent at `SettingsTab.swift:159-163`). The copy
says "the other mode" — the row the user is editing names the mode, and the chord is in their
hand. Payload-free keeps both `CaseIterable` syntheses alive and the closed-set pins
(`RebindBoundaryTests.swift:95-100`) compiling.

### D5 — The recorder and bindings seams take the mode

`SettingsBindings.rebind` becomes `(HotkeyChord, SessionMode) -> RebindOutcome` and
`validateChord` becomes `(HotkeyChord, SessionMode) -> HotkeyBindingValidity`; the wiring
closure computes the *other* mode's live chord for the collision input. New
`converseHotkeyDisplayName: () -> String` (dictation's stays `hotkeyDisplayName`, which
onboarding and the menu bar keep reading). `HotkeyRecorderView` gains `mode: SessionMode` and
renders the per-mode label from `SettingsCopy`; the General page composes two instances, each
with its own `@State`. The `HotkeyRecorderReducer` is untouched — the mode is surface context,
not reducer state.

### D6 — The General surface

`Section("Hotkey")` keeps its title and the two limit captions (they apply to both rows);
the section gains the converse row under the label `"Converse shortcut"`. Dictation first,
converse second (dictate is the older surface; the eye finds the known row first).

## Testing strategy

**The three-answer contract, second pair.** The converse decode answers exactly like the
dictation one (`PersistedSettings.swift:69-87`): absent → ⌥⇧Space, silent; half-pair or
malformed or unknown-bit or not-bindable → ⌥⇧Space plus exactly one report naming the value;
known → the value, silent. Every report names the fallback it degraded to. The dictation rows
are untouched and prove the generalized decode's wrapper is behavior-identical.

**The collision table.** Given the other mode's chord `O`, a candidate `C`:

| C | Verdict | Why |
|---|---|---|
| `C == O` | `.refused(.collidesWithOtherMode)` | equality is the only unambiguous-start violation (`SessionRules.swift:187,342`) |
| same key, `C.modifiers ⊃ O.modifiers` | `.accepted` | the shipped pair's shape; the superset press is the designed R1 no-op |
| same key, subset or disjoint modifiers | `.accepted` | start equality unambiguous; containment-stop behavior is inherent |
| different key | `.accepted` | nothing shared |
| `C == O` and macOS claims `C` | `.refused` | refusal outranks warning (`HotkeyBindingRules.swift:71-74`) |
| `C != O`, macOS claims `C` | `.warned(...)` | the `PRODUCT_SPEC.md:252` warning, on both rows |

**The rebind table.** Same-mode re-ask → `.unchanged`, nothing rebuilt, nothing written
(identity assertions). Other-mode's chord → `.refused(.collidesWithOtherMode)`, nothing
rebuilt, nothing written. Rules-refused → `.refused(.notBindable)` (unchanged). Any session in
flight in either mode → `.refused(.sessionInFlight)` (the closed set is now three, and the
`isQuiet` guard is over all wirings). Otherwise `.rebound`, per-mode persistence, per-mode
atomic swap, retired timers stopped — and the other mode's wirings provably untouched by
object identity.

**The no-branch pins** (callers never re-derive): the recorder asks `validateChord(chord,
mode)` (the wiring computes the other chord); the gate asks the rules through `isAdoptable`;
the closed-set tests iterate `allCases`; the copy switches are exhaustive with no `default:`;
the source scans pin the launch reads (one per chord) and the live reads.

**Lint controls**: the extended one-read scan (both chord reads exactly once, no
`[.option, .shift]` literal in `AppBootstrap`), the extended closure-wiring scan, the extended
live-read scan, the copy exhaustive-pin, and the unchanged `UserDefaults` one-file seam rule.

## Edge cases

- **A hand-edited equal pair at launch.** The launch read stays per-pair (the decode is the
  file format); the rebind gate guarantees the app never *creates* an equal pair. The machine
  must answer the hand-edited ambiguity honestly — recorded as the `mode-machine` aspect's
  seam, not built here.
- **Fallback equality.** A malformed converse pair decodes to ⌥⇧Space; if the dictate chord
  was rebound to ⌥⇧Space, the *wired* values are equal — and the rebind gate compares against
  wired truth, so the rebind that created the conflict is refused at step 2. The launch case
  is the machine's, as above.
- **Caps Lock.** Masked by `HotkeyChord`'s init on both sides; the collision check inherits
  it (pinned once).
- **`.unchanged` vs `.collidesWithOtherMode`.** Two guards, two answers; a single equality
  guard would answer `.unchanged` for the other mode's chord and silently do nothing. Pinned
  in both directions.
- **The shipped pair must never collide.** ⌥Space/⌥⇧Space share a key code — pinned accepted
  so a future "safety" tightening cannot refuse the product's own defaults.
- **Same-key swallowing.** During a dictate session a converse press is swallowed-ignored
  (`SessionRules.swift:122-128`) — the R1 no-op, the machine's behavior; this aspect only
  pins that the chords themselves are not a collision.
- **A no-op rebind writes nothing** (per mode, by object identity and write counts).
- **A rebind of either chord while any session is in flight** is refused — the closed-set
  rows cover both modes' machines.
- **Unknown stored values are never rewritten on read** (the `FileSystemDictionaryStore`
  rule, extended to the converse pair).
- **Payload-free refusal cases** — an associated value would break `CaseIterable` and the
  closed-set pins; the copy names "the other mode" instead.
- **The copy's two limit sentences** apply to both rows; they are rendered once, unchanged.
