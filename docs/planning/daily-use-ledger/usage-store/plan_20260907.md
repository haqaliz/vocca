## Phase 3 — GREEN: the format

Implement encode/decode and the atomic write.

**Shape** — see the spec for the full JSON. Key points:
- `version: 1`, and `bucketUpperBoundsMilliseconds` written into the file.
- `day` as `YYYY-MM-DD`; `CalendarDay.init?` is the parser's gate.
- Rung tallies keyed by `InjectionRung` raw values, as a string-keyed object so the file stays
  hand-readable.
- `JSONEncoder` with `.sortedKeys` for byte stability across runs
  (`PersistentInjectionStrategyStore.swift:161-165`).

**Decode discipline — copy it, do not improvise:** `JSONSerialization` for the top level, then one
`JSONDecoder` **per day row**, so a single bad row is skipped rather than losing the file
(`:177-215`). Three tolerance gates, each emitting exactly one message through the **injected**
log so tests assert loudness rather than hope for it (`:130-133`): top level not an object;
`version` unknown; **bounds mismatch**. Missing file → empty, silently, no log. A load never
rewrites the file.

**Atomic write** (`:255-262`): create directory, encode, write temp, then
`FileManager.replaceItemAt` — **not** `moveItem`, which refuses an existing destination. That
comment at `:63-69` is hard-won; keep its reasoning in the new file.

**Commit:** `usage-store: versioned, hand-readable JSON written atomically (GREEN)`

## Testing strategy

Real temp directories, real `FileManager`, per `InjectionStrategyStoreTests`' precedent — no
network, no clock, no model. The injected filesystem seam is what makes the failure paths (a
failing rename, a refusing create-directory) reachable; the injected log is what makes loudness
assertable.

## Edge cases

| Case | Behaviour |
|---|---|
| Missing file | Empty, silently. A first run is not an error |
| Corrupt single row | Skipped, one loud log, other rows load, file not rewritten |
| Not an object / unknown version / bounds mismatch | Empty, one loud log each |
| Stray `.tmp` from a crash | Never read |
| Impossible date in a hand-edited file | Row skipped, never repaired |
| Rename fails mid-save | Previous committed content intact |
| More than 30 days in a hand-edited file | Retention still applies on load |

## Agent execution notes

- **Phase 1 alone first.** Adding a module touches `Package.swift` and two lint tables; if CI goes
  red, one cause is findable and five are not.
- **Ask before proceeding if:** the seam exact-set pin cannot be satisfied by adding one row (that
  would mean the table's shape assumes something this module breaks); or `ModuleBoundaryTests`
  rejects `VoccaUsage` as an adapter for a reason the rules do not obviously predict.
- Do not weaken any lint to accommodate the new module. The lints are the reason the seams are real.

## Assumptions

1. `DayAggregate`, `OutcomeCounts`, `CalendarDay` and `LatencyHistogram` expose enough to
   reconstruct themselves from decoded values. If any needs an additional initialiser, adding one
   is in scope — but it must not weaken an existing invariant (e.g. `CalendarDay` must keep
   refusing impossible dates).
2. `LatencyHistogram`'s bucket counts are readable and constructible. If the type only exposes
   `record(_:)`, add a way to build one from counts — with a test that a round trip preserves
   percentiles.
