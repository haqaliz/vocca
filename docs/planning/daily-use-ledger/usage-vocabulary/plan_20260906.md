## Phase 1 — RED: the record does not carry its kind

**Goal:** one failing test, expressed behaviourally so it compiles against today's tree.

A test naming `SessionKind.onboarding` cannot compile before the type exists, and a compile error
is not a RED — the same constraint `loss-observability` hit. So assert through `describe()`, which
exists today: **an onboarding-composed session and a dictation-composed session render
identically**, and must not.

Build two pipelines over one `LatencyLedger` — one with `OnboardingInjector(sink:)`, one with a
ladder-style injector — run each to a delivered outcome, and compare their `describe()` lines with
the session id normalised out (a fresh ledger mints ids in order, so strip or account for
`session <n>:`). Assert the two renderings differ.

**Files:** `Tests/HarnessTests/LatencyLedgerTests.swift` (or `OnboardingInjectorTests.swift` if the
onboarding pipeline's construction helpers live there — use whichever already has both injectors
in reach, and say which you chose).

**Validation:** `./Scripts/test-with-floor.sh --filter <suite>` — the new test fails because the
two renderings are equal. Not a compile error, not a nil record.

**Commit:** `usage-vocabulary: pin that a session record does not carry its kind (RED)`

## Phase 3 — `CalendarDay` and day-number arithmetic

Pure TDD, no compile-order problem: write each failing test, then the function.

**Files:** `Sources/VoccaCore/CalendarDay.swift` (new),
`Tests/HarnessTests/CalendarDayTests.swift` (new).

`public struct CalendarDay: Sendable, Hashable, Comparable` — `year: Int`, `month: Int`,
`day: Int`, plus `dayNumber: Int`, a **proleptic Gregorian** days-since-epoch conversion.

Use the standard civil-from-days / days-from-civil algorithm (Howard Hinnant's `days_from_civil`
is the canonical integer form). **Do not invent one.** Integer arithmetic only.

**Tests (spec B7)** — each a separate test, each named for the behaviour:
- consecutive days across a month boundary (2026-01-31 → 2026-02-01)
- a non-leap February (2026-02-28 → 2026-03-01)
- a leap day (2028-02-28 → 2028-02-29 → 2028-03-01)
- a year boundary (2026-12-31 → 2027-01-01)
- `Comparable` orders by calendar order, and `dayNumber` differences match the number of days
  between two known dates

**Commit:** `usage-vocabulary: a calendar day with pure day-number arithmetic`

## Phase 5 — streak and retention

**Files:** extend `DayAggregate.swift` or add `UsageWindow.swift` — one type owning an ordered,
bounded set of days. `Tests/HarnessTests/UsageWindowTests.swift` (new).

- Streak: over the days present, the longest run ending at the most recent day, counting only days
  with ≥1 **non-onboarding** session.
- Retention: at most **30** days, oldest evicted. Pin the 30 in one named constant, following
  `InjectionStrategyStoreConstants.maximumRememberedApps`'s precedent
  (`InjectionStrategyStore.swift:47-51`), which itself cites `LatencyLedger.maximumRetainedRecords`.
- A day with no sessions is **absent**, not a zero row — absence is what breaks a streak.
- Inserting a day out of order updates that day, never duplicates it.

**Tests:** spec B8–B11.

**Commit:** `usage-vocabulary: streaks over real-use days, bounded at thirty`

## Phase 6 — the latency histogram and percentiles

**Files:** `Sources/VoccaCore/LatencyHistogram.swift` (new),
`Tests/HarnessTests/LatencyHistogramTests.swift` (new).

Fixed bucket upper bounds in **one** named constant. They straddle the P2 targets so the gate's
question lands exactly on a boundary (`ROADMAP.md:171` — p50 ≤ 400 ms, p95 ≤ 800 ms). Proposed, in
milliseconds, plus an overflow bucket:

```
25, 50, 75, 100, 150, 200, 300, 400, 600, 800, 1200, 1600, 2400, 3200, 5000, +overflow
```

A sample lands in the first bucket whose upper bound it is ≤. Percentiles are **nearest-rank over
the summed buckets**, stdlib-only — the harness's helper uses Foundation's `ceil`
(`LatencyBenchmarkRealEngineTests.swift:456-462`), so write the integer form rather than moving it.

**Honesty requirements, both testable:**
- **No samples yields `nil`**, never `0` — `LatencySpan.Presence.notPresent`'s rule and
  `LatencyBenchmarkRealEngineTests.swift:75-76` ("no samples, no percentile — a row must print n/a,
  never a fabricated number").
- A percentile is a **bucket upper bound**, not a spot millisecond value. The type should make that
  explicit in its name or return shape so `usage-tab` cannot render it as false precision. It
  answers "is p95 ≤ 800 ms?" exactly, which is the question the gate actually asks.
- Window percentiles sum buckets across days; **never** average per-day percentiles (spec B15 —
  the reason the histogram exists).

**Tests:** spec B12–B16, including the B16 source scan pinning the bounds to one constant, with a
vacuity guard both ways (the `InjectionStrategyStoreTests.swift:42` precedent).

**Commit:** `usage-vocabulary: a bounded latency histogram with honest percentiles`

## Testing strategy

Every test is pure, headless, deterministic and network-free. No fixture audio, no model, no
clock, no disk. Phases 3–6 are ordinary TDD over pure functions — write the failing test, watch it
fail, implement the minimum.

Phases 1–2 carry the only integration surface (the pipeline and bootstrap wiring), and their risk
is a compile ripple rather than behaviour.

**Watch:** `ZeroNetworkTests` parses the `PROBE-LATENCY` line (`:580-640`) and `describe()`'s
output changes in Phase 2 when the kind is rendered. It asserts grammar and `delivered(` rather
than a whole-line match, so it should hold — but **verify, and if it goes red, report before
editing it.** It is a permanent release blocker and its expectations are not to be loosened to
accommodate a refactor.

## Edge cases

| Case | Required behaviour |
|---|---|
| A day with only onboarding sessions | Present in the window, but does not extend a streak |
| An out-of-order day insertion | Updates that day; never duplicates. Streak reads the set, not arrival order |
| A day with sessions but no latency samples (all `aborted`/`emptySkip`) | Histogram empty; percentiles `nil`, rendered `n/a`, never `0` |
| A sample of exactly a bucket bound | Lands in that bucket (bounds are inclusive upper) — pinned, not incidental |
| More than 30 days | Oldest evicted on insertion, not at read |
