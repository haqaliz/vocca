# Implementation plan: command-registry

> Aspect of `shell-provider` · Date 2026-09-22 · Strict TDD: RED → GREEN → REFACTOR, one
> commit per step, floor ratchet in the suite's growth commit. Tests run via
> `Scripts/test-with-floor.sh`.

## Goal

`ShellCommandRegistry` — the persisted `shell-commands.json` definitions store, tolerant
decode, caps, atomic writes, destructive-by-default, validation. Storage shape only; no
execution, no `describe`/`invoke`.

## Prerequisites

- Worktree `feat/shell-provider/aliz` off `origin/master`, floor 2761 green.
- `Tests/HarnessTests/` conventions (temp dirs, loud-log injection, byte-level pins).

## Files to create/modify

- `Sources/VoccaActions/Config/ShellCommandRegistry.swift` — the store
- `Sources/VoccaActions/Config/ShellCommandDefinition.swift` — the model (id, argv,
  readOnly, parameters, clause)
- `Sources/VoccaActions/Config/ShellCommandParameters.swift` — named parameter slots
- `Tests/HarnessTests/ShellCommandRegistryTests.swift` — the suite
- `Scripts/test-with-floor.sh` — floor raise (in the growth commit)

## Implementation steps

1. **RED** — `ShellCommandRegistryTests`: the model + decode/encode contract. A well-formed
   fixture decodes (incl. `readOnly` absent → `false`); absent/corrupt/unknown-key files
   load empty with one loud log each (inject the log closure); save round-trips atomically;
   a cap violation throws and leaves the prior file intact; a duplicate-id / empty-argv /
   over-long-id row is skipped loudly; a forbidden key in the raw bytes is refused.
2. **GREEN** — `ShellCommandDefinition` + `ShellCommandRegistry` (tolerant decode, cap
   checks on save, temp-write-then-rename, validation skip). `VoccaActions` imports
   `["VoccaCore"]` only.
3. **REFACTOR** — align the loud-log shape with `ActionConfigStore`; ensure the 
   module-boundary and lint suites stay green.
4. Raise the floor in the same commit as the tests (the ratchet rule).
