## STEP 1 — decided 2026-09-22: NOT generic, a small shell leg is in scope

The arm surface does **not** render `dev.vocca.shell` tools once an enablement row exists.
The evidence, read on this branch:

- Tool rows exist **only** from `discoverySucceeded`: `ActionsTabState.swift:28-30` ("The
  rows the tools section renders: the last successful discovery's tools") and the reducer
  row at `ActionsTabState.swift:226-236` are the one producer of `toolRows`. An enablement
  row alone renders nothing — the enablement set is a membership set, never a row source.
- The shipped discovery is the bounded D2 refusal: `ActionWiring.swift:239-247` answers
  `.failed("discovery.unwired")` for every server, and discovery is keyed by **server id**
  (the wiring's mapping, `ActionsTabState.swift:212`) — there is no server row whose id is
  `dev.vocca.shell` (servers are user-added MCP servers with UUID ids), so no discovery can
  ever name the shell provider.
- The reducer's own guards confirm the gap: `toolEnabledChanged` requires the row to exist
  (`ActionsTabState.swift:245-247` — "a flip for a row nobody discovered mints nothing and
  enables nothing") and `armRequested` requires an enabled row (`ActionsTabState.swift:261-266`).

**The leg (built in this aspect, its own RED→GREEN unit inside the aspect's commits):**
a shell section on the Actions tab that renders the registry's commands as `ActionsToolRow`s
(providerID `dev.vocca.shell`, radius from the file's `readOnly` claim, `isEnabled` folded
from the persisted enablement — default off), reusing the existing generic toggle/Invoke/
Preview row rendering and the generic `setToolEnabled`/`armAction`/`previewAction` bindings.
The composition root routes `armAction`/`previewAction`/`loadShellCommands` and the
confirmation card's confirm/decline by the card's own providerID (shell → the shell wiring,
everything else → the action wiring). The D2 copy ("configuring a shell command runs that
command on your machine; Vocca cannot see inside a program it starts on your behalf") lands
in the section. S3's command-level overrides stay deferred (the sentence template is the
argv-derived rendering; an override UI is not this aspect's).
