## Repo facts (read before starting)

- **This is a Swift 6 package, not Python.** No `pyproject.toml`; do not run `uv`. The
  package is `Package.swift` with nine modules under `Sources/`. Tests are in
  `Tests/HarnessTests/` (1052 test functions today).
- **Test command:** `./Scripts/test-with-floor.sh` (from the worktree root). It runs
  `swift test` with strict concurrency, enforces `MINIMUM_EXECUTED_TESTS=1052` (raise the
  number by hand in the commit that changes the count), and compiles the `Tools/`
  harnesses. Targeted runs: `swift test --filter <TestClass>`.
- **Worktree:** `.claude/worktrees/feat-warm-start-streaming`, branch
  `feat/warm-start-streaming/aliz`. Commit per task; never commit to the primary checkout.
- **Zero-network invariant:** the default configuration makes zero `connect(2)` — asserted by
  the probe + interposer tests. Launch `prepare()` is disk-only (models in Application
  Support, `ModelHub.offlineMode = true`).

## Phases

### Phase 1 — The ratio evaluator and its target (W2)

- **Goal:** the 20% bound and the pure evaluator exist in exactly one place each; nothing
  else changes.
- **RED first:** write `Tests/HarnessTests/WarmStartRatioTests.swift` (new file, license
  header — copy any existing test file's header) driving a new `VoccaCore` type
  `WarmStartRatio`:
  - `evaluate(firstAfterLaunch: [Duration], steadyState: [Duration]) -> Verdict` where
    `Verdict` is `.insufficientSamples` (either side empty), `.withinBound(ratio:)`
    (ratio ≤ 1.2), `.exceedsBound(ratio:bound:)`. Table: 1.1 → within, 1.2 → within (inclusive),
    1.21 → exceeds, empty first → insufficient.
  - The bound lives in `WarmStartTargets.maxFirstAfterLaunchMultiple` (a new small enum in
    the same file, mirroring `ProvisionalCleanupTargets`'s single-source scan) — 1.2, and
    nothing else in the codebase may hard-code it.
- **Files:** create `Sources/VoccaCore/WarmStartRatio.swift` (stdlib-only: `Duration`,
  no Foundation/Dispatch/Darwin — the `CoreBoundaryTests` rule), `Tests/HarnessTests/WarmStartRatioTests.swift`.
- **Validation:** `swift test --filter WarmStartRatioTests`, then full
  `./Scripts/test-with-floor.sh`. If the floor count moves, raise `MINIMUM_EXECUTED_TESTS`
  in the same commit.
- **Commit:** `Add the warm-start ratio evaluator and its 20% target (red→green)`

### Phase 2 — The launch-path pins (W1, W5 headless half)

- **Goal:** tests that would fail if `prepare` moved onto the session path or ran twice.
- **RED first:** write `Tests/HarnessTests/WarmStartLaunchTests.swift`:
  1. Build a `DictationLoopRoot` (the `AppBootstrap.swift:589-964` type) with a counting
     stub engine (a `ProbeEngine`-shaped double with a `prepareCount` — reuse/extend the
     probe's `ProbeEngine` or the resolver tests' stub). Call `startEnginePreparation()`,
     await readiness (poll the gate or use the existing test seam the resolver tests use),
     assert `prepareCount == 1` and `resolver.isPrepared == true`.
  2. Drive one full session through the root (the `DictationLoopTests.swift` drive pattern
     with a scripted source) and assert `prepareCount` is still 1 — the session path never
     re-prepares.
  3. Assert `configure` (the zero-network composition root) itself never calls prepare:
     build via `AppBootstrap.configure` and assert the engine's `prepareCount` is 0 until
     `startEnginePreparation` is called (this pins `AppBootstrap.swift:854-856`'s comment
     as a test).
- **Files:** create `Tests/HarnessTests/WarmStartLaunchTests.swift`; extend a test double
  only if no existing stub exposes `prepareCount` (prefer reusing).
- **Validation:** `./Scripts/test-with-floor.sh`; the zero-network suite must stay green
  (nothing here touches the network path).
- **Commit:** `Pin the launch preload: prepare exactly once, never on the session path`

### Phase 3 — The gate's warm-start verdict (W4)

- **Goal:** the benchmark gate can fail on a cold first transcription — and names the ratio
  when it does.
- **Named contract decision (from spec's open question):** the closed four-span session
  record is **unchanged** — no new span name. The ratio is cross-session and lives in
  `EngineTiming` samples; the gate gains a warm-start verdict *row*, not a new span.
- **RED first:** extend `Tests/HarnessTests/LatencyBenchmarkTests.swift`:
  1. A stub engine that records `EngineTiming` kinds (firstAfterLaunch on its first
     transcribe, warmTranscribe afterwards) with a configurable first-call cost.
  2. `testTheWarmStartVerdictFailsWhenTheFirstTranscribeIsTwiceTheSteadyState` — 2× first
     call ⇒ gate `passed == false`, verdict names the ratio and the 1.2 bound.
  3. `testTheWarmStartVerdictPassesWithinTheBound` — 1.1× ⇒ passed, ratio printed.
  4. `testTheWarmStartVerdictIsInsufficientWithNoSamples` — no first-after-launch sample ⇒
     not a pass, not a fail — recorded, never fabricated (the `notPresent` precedent).
  5. A guard-the-guard test asserting the seeded-slow stub genuinely produces a >1.2 ratio
     (a gate that cannot fail proves nothing).
- **Files:** extend `Tests/HarnessTests/LatencyBenchmarkTests.swift` (+ test doubles in the
  existing doubles file, `Tests/HarnessTests/` — check `ASRTestDoubles.swift` first).
- **Validation:** `swift test --filter LatencyBenchmarkTests`, then the full floor script.
- **Commit:** `Gate the warm-start ratio: a cold first transcription must fail the benchmark`

## Testing strategy

- Table-driven unit tests for the pure evaluator (Phase 1); composition pins (Phase 2);
  gate-can-fail tests (Phase 3); env-gated record (Phase 4).
- Every `swift test` through `./Scripts/test-with-floor.sh`; floor raised in the commit that
  changes the count.
- No real model, no mic, no TCC anywhere in CI — all of this aspect is headless.

## Environment & secrets

- None new. `VOCCA_LATENCY_BENCH` / `VOCCA_MODEL_DIR` only for the founder's real run.

## Edge cases

- Empty `EngineTiming` samples → `.insufficientSamples`, never fabricated.
- Inclusive bound: exactly 1.2 is within (the ROADMAP's "within 20%" reads inclusive).
- A launch prepare that fails: the gate stays closed, sessions refuse with
  `.modelUnavailable` (existing `prepareAndAssemble` behavior) — pinned, not re-implemented.
