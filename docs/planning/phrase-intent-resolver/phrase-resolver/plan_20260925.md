## Phase 2: GREEN: the resolver

- **Files:** create `Sources/VoccaCore/Intent/PhraseIntentResolver.swift` (Apache header, doc
  comments in the `KeywordIntentResolver` density).
  - `public struct PhraseIntentRow: Sendable, Equatable { phrase, providerID, toolID; init }`
  - `public struct PhraseIntentResolver: IntentResolver`
    - `public let rows: [PhraseIntentRow]` (read-only; the probe counts the composed
      default's shell rows off it, so the fact is an effect of the run). In `init(rows:)`, precompute
      `[(normalized: String, row: PhraseIntentRow)]` in table order.
    - `public static func normalized(_ text: String) -> String`: iterate the `Character`s; a
      letter or number is appended `lowercased()`, anything else marks a pending separator; emit
      one `" "` between words only; no leading or trailing space.
    - `resolve`: `let key = Self.normalized(utterance)`; an empty key → `.none`. Build a
      `Set` of `"\(providerID)\u{0}\(toolID)"` from the catalog, skipping empty ids. Take the first
      precomputed row with `normalized == key` **and** its target in the set. Return
      `ActionInvocation(providerID:toolID:arguments: nil).map(IntentResolution.toolCall) ?? .none`.
- **Validation:** `swift test --filter 'PhraseIntentResolverTests|IntentResolverContractTests|CoreBoundaryTests'` is green.
  Then `./Scripts/test-with-floor.sh` shows `N == E`.
- **Commit:** `phrase-resolver: GREEN — the exact normalized phrase resolver`

## Edge cases

- Unicode: `Character.isLetter`/`isNumber` match the keyword tokenizer's classes. Diacritics
  are not folded, which is recorded in the spec.
- The catalog may contain duplicate tools; the set handles it.
- Do **not** refactor `KeywordIntentResolver` to share the tokenizer. That file is pinned.
