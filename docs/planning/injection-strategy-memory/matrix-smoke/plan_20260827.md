## The row table — single source of truth

The 22-row table from the spec (§Decision 1) lives **in the script as data** (the
`SeededInjectionAllowlist` pattern — data, not decisions). The checklist rows are written from
it, in the same commit. `--self-check` greps every row name into `SMOKE_CHECKLIST.md`, so drift
between the two artifacts fails the self-check loudly instead of living on silently.

Columns: name | app-name (for `open -a`) | class | seeded | expected rung | note.

The five fixed expectation classes: `.accessibility` (seeded 1–3), `.accessibility` (promotion
candidate 4–6 — clipboard until step 91 observes the promotion), `.clipboardPaste` (7–20),
**no rung attempted** (21–22).

### Phase 1 — The checklist section: the 22-row matrix, memory active (steps 87–93)

- **Files:** append a new section to `docs/SMOKE_CHECKLIST.md` after step 86:

  with the two-rules reminder adapted to the matrix (the fixed-phrase discipline, the
  "nothing in the field is a bug" rule, the precondition checks) and the **tracked table**
  header with the FMS definition and the 19-of-20 bar (spec Decision 5).
- **The seven new steps:**
  - **87. The baseline calibration run.** Memory reset (delete
    `~/Library/Application Support/Vocca/strategies.json`), full 22-row run, no
    expected-rung assertions — the run *learns* each app. Record per app: first landing rung,
    promotion candidates observed, and the Docs-in-Chrome seed scope finding (spec open
    question 3). The per-app table this produces becomes the expected-rung source for step 88.
  - **88. The tracked per-release run — the matrix with memory active.** The 22 rows, expected
    rungs from the baseline, harness-driven, founder observes each log line. Pass per row:
    byte-compare **and** the log names the expected rung. Tally FMS (deliverable rows only,
    19-of-20 bar); append a row to the tracked table with release, date, rows run/skipped, FMS,
    notes.
  - **89. Seeded-hostile first run — the discovery cost is paid by the seed.** On a
    memory-fresh install (or after reset), the first dictation into Slack and into Google Docs:
    the log names **`.clipboardPaste` as the first attempt** — no `.accessibility` attempt, no
    AX discovery cost on the founder's first use. A first attempt of `.accessibility` on a
    seeded-hostile app is a failure of R5.
  - **90. The re-probe observation — Slack rediscovers, once.** After ≥5 clipboard deliveries
    spanning ≥ the provisional re-probe window (read from the `memory-order` code's one
    constant, recorded beside the row), the next dictation's log names the **one-shot
    `.accessibility` re-probe attempt**, which fails and re-demotes with a fresh window. A log
    with no re-probe attempt after the window has elapsed is a failure of R4's decay schedule,
    not a pass.
  - **91. The promotion observation — Xcode (or the first native promotion candidate).** After
    clipboard deliveries spanning the window, the log names an `.accessibility` attempt that
    lands **read-back-verified**; the next dictation starts at `.accessibility` (the strategy
    flipped). The row asserts the flip is visible in `strategies.json` too. A
    promotion that lands without read-back verification, or a log that never re-probes, is a
    failure.
  - **92. Secure Input in the matrix — the refusal rows with memory active.** Rows 21–22:
    log records `attempted: []` (no rung — not even clipboard), the failsafe shows the
    password-field copy, the transcript is copyable, and **memory records nothing** (R8:
    Secure Input refusals write no strategy). Memory must not learn from a refusal.
  - **93. The tracked table's own row — "per release" defined.** Every release appends one
    row: release, date, rows run / skipped / swapped, FMS (recorded, never a gate), and a note
    column. The section states: an unrun release is a failed step (the preamble's own rule).

### Phase 2 — The harness: `Scripts/injection-matrix.sh`

- **Goal:** the semi-automated driver: it automates the comparison and the tally; the
  dictation and the rung observation stay the founder's (documented, never hidden).
- **Files:** create `Scripts/injection-matrix.sh` with the `provision-cleanup-fixtures.sh`
  conventions (Apache header, `set -euo pipefail`, usage docstring, validation-before-side-effect).
  Modes:
  - `--self-check`: validates the internal row table (≥20 rows, unique names, expected rung in
    the closed vocabulary {`.accessibility`, `.clipboardPaste`, `.keystrokeSynthesis`, none},
    hostile rows expect none) and greps every row name into `SMOKE_CHECKLIST.md`; exits non-zero
    on any violation. No app, grant, or window server required — this is the CI-runnable half.
  - `--dry-run`: prints the row table with per-row install status (`open -Ra` exit code) and
    expected rung; exits 0 (missing apps print `SKIP`, never fail the dry-run — a machine
    without the matrix apps is not a broken script).
  - `--row <name>`: run a single row (used by steps 89–92's focused rows).
  - default: the full run — for each row: `open -Ra` check (missing → print SKIP and continue,
    the tracked table records it), `open -a` to front, print the expected rung and the field to
    click into, **prompt the founder to dictate** (the script cannot press ⌥Space: the tap needs
    the Accessibility grant and the session needs a microphone — state this in the prompt and in
    the header), wait for the founder's Enter, then select-all + copy via
    `osascript -e 'tell application "System Events" to keystroke "a" using command down'` (and
    `"c"`), `pbpaste` byte-compare against the fixed phrase, and prompt the founder to confirm
    the ladder's log named the expected rung (y/n). A row passes only on byte-compare **and**
    rung-confirm; tally FMS over deliverable rows; print the summary and the ≥95% bar
    (19/20).
  - Preconditions the script checks and documents: the terminal hosting it has Automation
    grants for the target apps (a denied copy step is **voided**, not failed — rule 1: verify
    the selection was made; `pbpaste` returning stale content is the void signal); Vocca is
    running, armed, and its model is prepared; a clipboard manager may be running (step 28
    discipline — the matrix is honest under a manager).
- **Validation:** `bash -n Scripts/injection-matrix.sh`; `./Scripts/injection-matrix.sh --self-check`
  (green on any machine, target apps or not); `--dry-run` on the founder machine; `--row Notes`
  once, live, on the founder machine (the script's first real execution is step 87's run).
- **Commit:** `Add the semi-automated injection matrix harness with self-check and dry-run`

## Edge cases

- **Apps missing on the machine:** `open -Ra` fails → the row prints SKIP and is recorded as
  skipped in the tracked table; the founder swaps in a same-class app (the class coverage is the
  invariant, the brand is not — spec open question 1). A skipped row is never a pass.
- **First-run vs steady-state memory:** step 87 runs on a memory reset; step 88 runs on
  steady-state memory. The rows say which, because the expected-rung column is only meaningful
  in steady state.
- **The `.accessibility`-named-with-nothing-in-the-field rule:** carried into every row — a row
  whose log names `.accessibility` while the byte-compare fails is a bug (the read-back
  verification lied), not a fallback.
- **Secure Input rows write nothing:** step 92 asserts memory records no strategy from rows
  21–22 (R8) — a refusal must not teach the memory anything.
- **A denied copy step is voided, not failed:** the script's System Events ⌘A/⌘C can be denied
  by Automation TCC per target app; stale `pbpaste` output is the void signal (rule 1 — the
  precondition "the selection was made" must hold before a negative is asserted).
- **Pages' rich text:** if Pages' copy round-trip mutates bytes, the row is swapped for another
  native AppKit app (Reminders, Bear) rather than weakened (rule 2).
- **The re-probe window may not have elapsed:** a matrix run before the window has elapsed has
  no re-probe row to observe — recorded in the tracked table, not a pass or a fail (X2's
  provisional-until-rebaselined status).
- **The script's host needs Automation too:** the terminal's own TCC grants for the target apps
  are part of the documented preconditions; a founder who has only granted Vocca will see voided
  copy steps, not script failures.
