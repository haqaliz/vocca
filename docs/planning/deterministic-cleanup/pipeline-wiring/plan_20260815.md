     ```swift
     let textToInject: String
     if let cleanup {
         textToInject = await cleanIfWired(
             cleanup, transcript: transcript, target: target, sessionID: sessionID)
         // A cancellation that landed during cleanup: the cleaned text is discarded, nothing is
         // injected (`PRODUCT_SPEC.md:129`) — the post-transcribe guard's shape (`:228-231`).
         guard !Task.isCancelled else {
             await finalize(sessionID: sessionID, outcome: .aborted, engine: transcript.engine)
             return .idle
         }
     } else {
         textToInject = transcript.text
     }
     let result = await injector.inject(textToInject, into: target)
     ```
     The nil path is the old code untouched; the re-check exists only on the cleanup path.
  4. **`cleanIfWired`** (private, after `transcribeAndInject`):
     ```swift
     private func cleanIfWired(
         _ provider: any CleanupProvider, transcript: Transcript, target: TargetContext,
         sessionID: SessionRecord.ID?
     ) async -> String {
        let start = clock?.now
        let cleaned: String?
        if let clock, let start {
            // `start` is unwrapped here so the group's closures capture a non-optional
            // `Duration` (`clock.now - start` must typecheck) — the `let start` binding is
            // the measured start, and the unwrap is the seam's "no measurement, no race".
            cleaned = try? await withThrowingTaskGroup(of: String.self) { group in
                group.addTask {
                    try await provider.clean(transcript, context: CleanupContext(
                        target: target, mode: .dictation, dictionary: [],
                        budget: Self.cleanupBudget))
                }
                group.addTask {
                    while (clock.now - start) < Self.cleanupBudget {
                        await Task.yield()
                    }
                    throw CleanupBudgetExpired()
                }
                for try await text in group { return text }
                throw CleanupBudgetExpired()
            }
        } else {
            cleaned = try? await provider.clean(transcript, context: CleanupContext(
                target: target, mode: .dictation, dictionary: [],
                budget: Self.cleanupBudget))
        }
         await recordCleanupSpan(from: start, sessionID: sessionID)
         guard let cleaned, !cleaned.isEmpty, !cleaned.allSatisfy(\.isWhitespace) else {
             return transcript.text
         }
         return cleaned
     }
     ```
     **The budget mechanism, precisely:** the provider and a deadline-watcher race in one
     `withThrowingTaskGroup`. The watcher reads only the **injected clock** (`clock.now - start`)
     and suspends with `Task.yield()` — deliberately **not** `Task.sleep`, because the injected
     clock is the pipeline's only time source (`MonotonicClock.swift:15-21`): a hand-moved
     `TableClock` must be able to fire the deadline instantly, and a wall-clock sleep would be a
     second time source. When `clock.now - start >= budget`, the watcher throws the fileprivate
     `CleanupBudgetExpired()` marker; the group scope's exit cancels the still-running provider
     child and awaits it (TaskGroup semantics — see §6 for what the provider must do to be
     cancellable), and the throw escapes `try?` as `nil` → raw proceeds. Any provider throw —
     including `CancellationError` from the *route task* being cancelled (Esc) — also lands in
     `nil`; the post-cleanup re-check in step 3 turns that into the `.aborted` discard. If the
     provider wins first, its string is the group's value and the watcher is cancelled. The
     provider is handed `CleanupContext.budget` as information only — the deadline lives in the
     caller's watcher (`ARCHITECTURE.md:509`: enforced by the caller, never the provider).
     `dictionary: []` is the C5 posture: the pipeline cannot know the rules; the provider owns
     its dictionary (`ShippingRulesCleanupProvider` in Task 4), and `CleanupContext.dictionary`
     stays the advisory channel for future providers — documented in the doc comment as
     declared-not-read at C5, exactly like `SessionMode` (`SessionMode.swift:15-20`).
     **Never-empty:** `isEmpty` or whitespace-only (stdlib `Character.isWhitespace` — never
     Foundation `trimmingCharacters`) → the raw text (the empty-text guard at `:235-238` already
     ran, so this is cleanup's own guard: cleanup never injects `""`).
  5. **`recordCleanupSpan`** — a mirror of `recordASRSpan` (`:267-272`): guard on
     sessionID/recorder/start/clock, then
     `LatencySpan.recorded(name: .cleanup, elapsed: clock.now - start)` for the session id.
     Called on **every** answer inside `cleanIfWired` — success, throw, and budget-expiry — the
     ASR-span precedent (`:201-203`: a degrade's elapsed is real latency). No new vocabulary:
     `SpanName.cleanup` exists (`LatencySpan.swift:27-29`), `LatencyLedger.describe` already
     renders recorded spans (`LatencyLedger.swift:109-136`), `cleanupNotPresent()`
     (`LatencySpan.swift:69-71`) stays for the nil-cleanup pipeline's untouched records.
  6. **`CleanupBudgetExpired`** — `private enum CleanupBudgetExpired: Error {}` (stdlib-only,
     fileprivate to the pipeline file).

## 6. Edge Cases & Error Handling

- **Esc during cleanup (B6):** the route task's cancellation surfaces inside the group as
  `CancellationError` from `next()` → caught by the degrade (`try?`) → a raw candidate exists
  — but the **post-cleanup `Task.isCancelled` re-check** (Task 2 step 3) discards it:
  `.aborted`, injector untouched. A cancellation that lands *after* the re-check but before
  `injector.inject` is the pre-existing :228-231 guard's domain (no new suspension between
  them, so no new race).
- **The hung provider (B3):** the deadline is the watcher's, on the injected clock; the group
  **cancels and awaits** the provider child when the watcher wins. TaskGroup semantics require
  the child to *observe* cancellation — the test double suspends with
  `try await Task.sleep(for: .seconds(3600))`, which throws on cancel, so the group's child-await
  completes instantly and the test never waits on wall time. **Documented residual:** a
  cancellation-blind provider (a suspension that ignores `Task.isCancelled`) would delay the
  group's exit until it returns — the budget guarantees raw-within-budget for any
  cancellation-cooperative provider (all well-behaved async code — `Task.sleep`,
  `URLSession`, continuations with handlers — is), and a blind one is bounded by its own
  eventual return. Recorded in the plan, not worked around: the alternative (a detached
  fire-and-forget provider) would leak the session's text past the pipeline's custody.
- **The provider that beats the deadline by a hair:** whichever child the group observes first
  wins — a string proceeds, or the watcher's throw routes raw. Both are correct I5 outcomes;
  the race is deliberately unresolved.
- **Empty/whitespace clean result (B5):** `isEmpty || allSatisfy(\.isWhitespace)` → raw.
  `Character.isWhitespace` is stdlib; **never** `String.trimmingCharacters` (Foundation, banned
  in Core).
- **No-cleanup-wired (B2):** `nil` → the old two statements, byte for byte; the re-check exists
  only on the cleanup path; `cleanupNotPresent()` and the `:671` test stay untouched.
- **Nil clock with a wired cleanup:** no measurement, no budget race, direct `try?` call, raw on
  throw — the recorder/clock no-op doctrine extended to cleanup. The B1 test exercises exactly
  this path (no recorder/clock wired).
- **Probe input stability (B9/B10):** `"1 2 3"` passes through the empty-dictionary rules path
  unchanged — the rules engine's built-ins do not touch digits/spaces (rules-engine acceptance
  tables already pin this headlessly).
- **Coverage-guard interaction:** VoccaText is not excludable (`candidateExclusions` admits only
  the probe and the dyld shim), so the witness **cannot** be the placeholder — the acceptance is
  a type minted *by* the drive's calls (`type(of: cleanup)` where the provider instance was
  constructed in `buildDictationCycle` and cleaned the cycle's transcript). Deleting the drive's
  wiring fails the guard by name.
- **The floor-lag finding (`prd.md:120-123`):** the floor currently equals the suite (914).
  Task 8 raises it to the printed executed total in the same commit — never beforehand, never
  afterwards. The latency-instrumentation gap (40 tests shipped unfloored) is recorded in the
  comment block as closed for this aspect.
- **Step renumbering (B12):** the two new steps displace the benchmark pair 69-70 → 71-72 and
  the eval-harness F2 reservation 71 → 73. This is the only reading consistent with "numbered in
  the existing sequence"; the three unit-doc citations are synced in the same commit (Task 9),
  and the pipeline-wiring spec's "step 69" label is understood to name the benchmark step
  (whose content at `:1191` is what flips).
- **Dictionary in the root:** no prepare step; `ShippingCleanup.make()` loads lazily over the
  default store; a missing/corrupt `dictionary.json` is an empty rule set — local, zero network,
  never fatal (the loud-log discipline is the dictionary aspect's).
- **Strict concurrency:** the provider doubles are actors; `TableClock` is already
  `@unchecked Sendable`; the group's children capture only `Sendable` values; the pipeline's new
  stored property is `(any CleanupProvider)?` (a `Sendable` protocol). Any isolation surprise
  here means a design deviation — stop and flag (§7).
