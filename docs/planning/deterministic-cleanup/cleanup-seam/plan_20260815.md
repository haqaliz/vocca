## 2. Implementation Phases

### Phase 1 — RED: the seam-contract tests, written before the types exist

- **Goal:** `Tests/HarnessTests/CleanupProviderSeamTests.swift` fails to compile — the failing
  tests that define the contract (spec B1–B5).
- **Prerequisites:** none.
- **Files to create:** `Tests/HarnessTests/CleanupProviderSeamTests.swift` — stub conformers
  (`StubCleanupProvider` with explicit `identity`, a second conformance without `requiresNetwork`
  declared, a third declaring `requiresNetwork = true`) and the five tests:
  - `testProtocolShapeCleanThrowsAndReturnsString` (B1): drive `try await provider.clean(transcript,
    context:)`; the stub returns a marker string; assert it arrives unchanged; the stub declares
    `throws` so the signature is pinned at the protocol level.
  - `testRequiresNetworkDefaultsToFalse` (B2): the undeclaring conformer reads `false`; the
    declaring one reads `true`.
  - `testIdentityIsRequiredAndNonOptional` (B3): conformer must declare `identity` (no default);
    assert `id`/`displayName` survive a drive equal via `==` (Hashable).
  - `testCleanupContextCarriesAllFourFields` (B4): hand-built context with a real `TargetContext`
    (use the same construction the pipeline tests use — check `TargetContext.swift:35-51` for its
    memberwise init), `SessionMode.dictation` and `.conversing` each constructible, an ordered
    `[ReplacementRule]` of ≥ 3 rules, `budget: Duration`; an echo stub asserts all four
    field-for-field, `budget` unchanged.
  - `testReplacementRuleVocabularyAndOrder` (B5): rules are `Sendable`/`Hashable`/`Equatable`/
    `Codable`; distinct `caseSensitive` and `wordBoundary` flags; an ordered array of ≥ 3 rules
    arrives in exactly the given order (no sorting, no dedup); a `JSONEncoder`/`JSONDecoder`
    round-trip in the test (legal there — the test target may import Foundation) round-trips all
    fields, proving the persistence contract fits while Core never touches JSON.
- **Validation:** `./Scripts/test-with-floor.sh` fails to compile — that IS the red state. Do not
  proceed to GREEN until the failure is exactly "no `CleanupProvider`/`CleanupContext`/
  `ReplacementRule`/`ProviderIdentity`/`SessionMode` in scope".
- **Commit message:** `Add the cleanup seam contract tests (red)` — per the unit's discipline the
  failing test commit lands first.

### Phase 2 — GREEN: the five Core types

- **Goal:** the seam exists and the tests pass.
- **Prerequisites:** Phase 1 committed.
- **Files to create (all in `Sources/VoccaCore/`, stdlib-only, public, `Sendable`):
  1. `SessionMode.swift` — `public enum SessionMode: Sendable { case dictation, conversing }`
     with a doc comment stating it is declared-never-read at C5 (per-mode selection is C6/C11;
     cite `ARCHITECTURE.md:222`).
  2. `ProviderIdentity.swift` — `public struct ProviderIdentity: Sendable, Hashable, Equatable,
     Codable { public let id: String; public let displayName: String }` with memberwise init.
     Doc comment: new type, NOT a rename of `EngineIdentity` — the ASR family's `isLocal` is the
     egress flag there; here egress is the protocol's `requiresNetwork` (cite `EngineIdentity.swift`,
     `ARCHITECTURE.md:273-277`).
  3. `ReplacementRule.swift` — `public struct ReplacementRule: Sendable, Hashable, Equatable,
     Codable { public let source: String; public let replacement: String; public let caseSensitive:
     Bool; public let wordBoundary: Bool }`. Doc comment: order is the contract — declared order is
     application order; the type carries no sorting (cite `prd.md:180-181`).
  4. `CleanupContext.swift` — `public struct CleanupContext: Sendable { public let target:
     TargetContext; public let mode: SessionMode; public let dictionary: [ReplacementRule]; public
     let budget: Duration }` with a memberwise init, free of defaults (the `TargetContext` precedent
     — a test must be able to build it by hand). `Duration` is stdlib, already used in Core
     (`SessionWatchdog.swift`).
  5. `CleanupProvider.swift` — the protocol, mirroring `ASREngine.swift:39-59` doc-comment style
     (cross-reference the ARCHITECTURE section): `public protocol CleanupProvider: Sendable {
     var identity: ProviderIdentity { get }; var requiresNetwork: Bool { get }; func clean(_
     transcript: Transcript, context: CleanupContext) async throws -> String }` with
     `extension CleanupProvider { public var requiresNetwork: Bool { false } }` (the default is a
     tested fact, spec B2). Doc comment must state the deliberate throwing divergence from
     `TextInjector` and why: timeout/failure is a first-class outcome the caller routes to raw
     (`ARCHITECTURE.md:273` — authoritative over the roadmap's draft wording).
- **Validation:** `./Scripts/test-with-floor.sh` — the new file's five tests pass; the full suite
  stays green (876 + 5 tests, floor 836 untouched).
- **Commit message:** `Add the cleanup provider seam and its contract vocabulary in Core`

## 4. Testing Strategy

- B1–B5 (spec `## Acceptance criteria`) are the failing tests of Phase 1 — written first.
- B6 (Core boundary) and B7 (module boundary) are existing suites that must pass **with no
  edits** — they are the proof, not additional tests.
- Integration: none in this aspect (no provider ships; the stub conformer is the only execution —
  the tap-adapter honesty discipline). Full-suite runs after each phase via
  `./Scripts/test-with-floor.sh`.
- Zero network: nothing here can reach the network; the probe/interposer suites must stay green as
  part of the full suite.

## 5. Environment & Privacy

- No environment variables, no external services, no new tooling.
- Privacy/local-first: the seam declares `requiresNetwork` default `false`; no egress capability
  exists in this aspect. All local.

## 6. Edge Cases & Error Handling

- **Naming collisions:** verify with grep that `SessionMode`, `ProviderIdentity`, `ReplacementRule`,
  `CleanupContext`, `CleanupProvider` are absent from `Sources/` and `Tests/` before creating them
  (spec agent verified `SessionMode`/`ProviderIdentity` absent; re-verify the rest).
- **`Duration` availability:** already used in Core (`SessionWatchdog.swift`) — no import needed.
- **Codable in Core:** the conformance keyword is stdlib; only the *decoders* need Foundation, and
  they live in tests/VoccaText (later aspects). If a reviewer worries, the test at B5 is the proof.
- **Strict concurrency:** the protocol is `Sendable`; the structs are value types — no actor
  isolation needed. Any `nonisolated`/`MainActor` surprises mean a design deviation — stop and flag.
- **Warning-as-failure:** any new warning (e.g. unused parameter in a stub) fails CI — keep stubs
  minimal and used.
