## 2. Decisions this plan fixes (the spec's open questions, `spec.md:186-210`)

### 2.1 Stand-in pair format and where they live

Pairs live under **`Tests/CleanupPairs/`** (the C2 fixture-home pattern). One pair is a triple of
siblings: `<name>.raw.txt` (the as-spoken/ASR-raw side), `<name>.clean.txt` (the golden clean
target — always present; a pair without it is broken), `<name>.class.txt` (one tag word; exact
spellings `fillers | punctuation | capitalization | numbers-units | dictionary | token-protection`).
Pair discovery keys on the `.raw.txt` suffix only, so `dictionary.json` and `FIXTURES.md` in the
same directory are never misread as pairs. The class tag is a **sidecar**, not a name convention:
the loader reads it, and a pair without one cannot print a per-class breakdown — it is a broken
fixture (`missingClassTag`). The F2 corpus uses the identical triple format.

### 2.2 Generation and golden format — the script wins

`Scripts/provision-cleanup-fixtures.sh` mirrors `provision-asr-fixtures.sh`: checked-in **goldens**
under `Tests/CleanupPairs/goldens/<class>/*.txt` (one golden per pair; the golden IS the clean
text — natural polished prose per class), the script applies **deterministic ASR-ish error
injection** (filler insertion, case collapse, missing terminal punctuation, unnormalized numbers —
class-specific plus a light common degradation; the exact matrix is documented in `FIXTURES.md`,
never assumed), and writes the triples into the output directory. Deterministic by construction:
one fixed python seed (`--seed`, default constant), two runs produce byte-identical output
(asserted). The goldens are chosen so the shipped rules **recover** the golden from the injected
raw (`produced == clean`) — except the planted pair (§2.3). `dictionary.json` is checked in by
hand, not generated (the corpus's shared rule set; the `user-dictionary` store reads
`<dir>/dictionary.json`). Invocation: `--goldens <dir>` (default `Tests/CleanupPairs/goldens`),
`--output <dir>` (default `Tests/CleanupPairs`), `--seed <hex>`.

### 2.3 Corpus size and the planted pair

**24 stand-in pairs = 4 per class × 6 classes** — a per-class tally is printable, and 24 is far
above the noise line the spec names at `spec.md:194-196`. The loader's **vacuity guard minimum is
20** (`CleanupPairSuite.minimumMeaningfulCorpusSize`): the shipped corpus sits above the floor and
a trimmed corpus fails the suite. One of the `numbers-units` four is the **planted raw-preferred
pair**, named `numbers-units-planted-raw-preferred`, whose golden contains a number word the rules
rewrite (e.g. "Twelve people came to the meeting.") and whose **raw == golden** (no injection) —
so the oracle verdict is `rawPreferred` (`raw == golden`, `produced != golden`). This is the
can-lose proof (B3): the scorer must be able to count a loss. **F2 target: ≥ 40 pairs, ≥ 5 per
class** — named in SMOKE step 73 as the founder's target (a target, not a gate; the loader's
20-minimum guard prevents a meaningless green).

### 2.4 Tie handling in the denominator — pinned by the spec, restated

`tie` and `noPreference` rows are **excluded from the denominator**: preference percentage =
`cleanedPreferred ÷ (pairs with a preference)` (`spec.md:42-43`). An all-tie or all-no-preference
run (denominator zero) throws the named `noPreferenceSample` error (B1). The choice is re-openable
only at the F2 re-baseline (`spec.md:197-200`), recorded in the tolerance record.

### 2.5 Blindness mechanics — mechanical, not promised

The judge never sees labels. For each pair the runner presents the two sides as **A and B** in a
seeded-random order (Fisher-Yates over the shared `SeededGenerator`), the judge answers
`left | right | tie | noPreference` per presented pair, and the **comparator** maps the blind
answer through the presentation order into `cleanedPreferred | rawPreferred | tie | noPreference`
— the comparator is what makes "blind" mechanical (`spec.md:37-46`): it never receives the texts,
only `(BlindJudgeAnswer, PairPresentation)`. The CI judge is the deterministic **oracle**: prefer
the side equal to the pair's golden clean target; both or neither ⇒ `noPreference`
(`oracleVerdict(raw:produced:golden:)`). The seed is **printed beside the verdicts**, so the
presentation is reproducible; a checked-in fixed order is never used (the risk `spec.md:205-207`
names). The real-run seed is generated once at ballot time and embedded in the answers file
(Phase 12), so both invocations present the same order.

### 2.6 Latency CI honesty

The CI p50 over the stand-in corpus is asserted `< 10 ms` against the named provisional table — a
mechanism gate over a pure stdlib function (the spec's honesty note, `spec.md:208-210`); the
founder re-baselines the 10 ms figure like every other number in the unit's one table.

## 6. Environment & Privacy

- **New env var: `VOCCA_CLEANUP_EVAL`** — a presence gate whose value names the **F2 pairs
  directory** (the `VOCCA_MODEL_DIR` pattern: the var names a directory). Skipping without it, the
  `XCTSkip` message names the var and cites `docs/SMOKE_CHECKLIST.md` step 73. Set-but-broken is a
  hard failure, never a skip. `VOCCA_MODEL_DIR` is additionally required only when an F2 pair
  carries a `<name>.wav` recording (provisioned via `Scripts/provision-asr-fixtures.sh`).
- **Zero network, structural:** no eval file may name `URLSession` (the new H8-family row, B3);
  nothing is fetched, nothing is uploaded; the corpus is checked-in text; the F2 audio and pairs
  never leave the founder's machine (R11, `prd.md:189-190`).
- **No telemetry, no persistence:** the harness prints and asserts; nothing is recorded beyond the
  process, nothing is transmitted.

## 7. Edge Cases & Error Handling

- **Empty corpus:** loader `noPairsFound` (B2); the scorer's `noPreferenceSample` on zero outcomes
  (B1, the WER empty-reference rule).
- **Missing golden:** `missingCleanTarget` naming the pair and its expected path (B2); the same
  shape for a missing class tag (`missingClassTag`) and an unknown tag (`unknownClassTag`).
- **Below-minimum corpus:** `corpusBelowMinimum` naming the 20-pair minimum — the vacuity guard (B2);
  a 24-pair shipped corpus sits above it; a trimmed corpus cannot read green.
- **Env var set but no corpus:** hard failure with provisioning instructions naming
  `VOCCA_CLEANUP_EVAL` and the pair triple format (B4) — never a skip, never a silent green.
- **Tie-heavy corpora:** `tie`/`noPreference` excluded from the denominator; an all-tie run throws
  `noPreferenceSample` rather than dividing by zero (B1); the human judge's tie rate is unknown
  until F2 and the choice is re-openable only at re-baseline (§2.4).
- **The gate that cannot fail:** the seeded-slow rule must genuinely exceed the 10 ms budget on the
  local machine before the test is committed (Phase 7's verification step); the planted pair must
  genuinely yield `rawPreferred` through the real engine + oracle (Phase 6's verification step).
- **Answers file gaps:** missing/unknown pair names or a missing seed line fail loudly, naming the
  gap (Phase 12) — a run that cannot score everything must not read green.
- **Recording sidecars without a model:** wav present + `VOCCA_MODEL_DIR` unset ⇒ hard failure
  naming `Scripts/provision-asr-fixtures.sh` (Phase 11).
- **Determinism:** two runs byte-identical (scorer table, stand-in run, provisioning script,
  seeded order).
- **Warning-as-failure:** any new warning fails CI — keep the new types plain `Sendable` value
  types; an unused parameter or a non-exhaustive switch in a stub means a design deviation — stop
  and flag.
