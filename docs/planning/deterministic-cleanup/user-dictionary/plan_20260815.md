### 1.1 Design decisions — the spec's open questions, closed here

- **Application Support path resolution: absolute-path contract, journal-shaped.** The store takes
  an injected directory `URL` (`init(directory:)` — tests pass temp dirs) plus a default `init()`
  that resolves `~/Library/Application Support/Vocca` with the journal's defensive fallback
  (`FileSystemJournalStore.swift:54-60`: `FileManager.default.urls(for:
  .applicationSupportDirectory, in: .userDomainMask).first ?? homeDirectoryForCurrentUser +
  "Library/Application Support"`) and points at `Vocca/dictionary.json`
  (`ARCHITECTURE.md:549`). The file URL is always `<directory>/dictionary.json`.
- **Actor vs struct: struct, caller-serialized — the honest shape.** `FileSystemDictionaryStore`
  is a `struct` mirroring `FileSystemJournalStore`, with no mutable state: every call is an
  independent read-or-atomic-write. An actor would serialize calls that are already safe by
  construction — the atomic rename means a concurrent load sees either the old or the new
  committed file, never a partial one. The single-writer contract is documented on the type and
  is the spec's own: one process, load once at session start, the rules engine reads the
  dictionary via `CleanupContext` (`spec.md:145-147`); no save path exists yet, and the first one
  (settings UI, P3) serializes through its caller. The concurrency claim is stated in the doc
  comment, not assumed.
- **Unknown fields on save: not preserved — a save normalizes the file.** Decode tolerates
  unknown keys (stock `JSONDecoder` behavior — skip unknown keys, skip invalid entries); encode
  writes only the four known fields from in-memory rules. Because the file is user-owned and
  version-controlled, re-emitting unknown fields would be pretend-fidelity (the spec's own
  reasoning, `spec.md:141-144`). The store's doc comment says "a save normalizes the file" in
  so many words.
- **Case comparison is locale-independent**: the semantics fixture folds case with plain
  `String.lowercased()`, never `localizedStandard*`; the boundary set is an explicit literal,
  table-tested, never `CharacterSet` heuristics (spec's open question, `spec.md:149-151`).
- **The store's logger is injectable** so B5's "loud" is asserted headless: the store takes
  `log: @Sendable (String) -> Void`, defaulting to a one-liner that routes through
  `Logger(subsystem: "dev.vocca.Vocca", category: "dictionary")` (the `AppBootstrap.swift:318`
  category precedent). Tests inject a collector and assert the exact log count.

## 4. Testing Strategy

### 4.1 `UserDictionaryTests.swift` — semantics as data (B1–B4)

The file owns a **test-fixture-only** applier — deliberately NOT shipped code, because rule
application is `rules-engine`'s M2 (`spec.md:50-51`). Its one job is to pin the reference
semantics M2 must satisfy. `private static func apply(_ rules: [ReplacementRule], to text:
String) -> String` applies rules in declared order, each rule re-scanning the **whole current
text** (including every earlier rule's output — that is what chained application means), never
reordering or deduplicating. Case folding is `String.lowercased()`; the word-boundary set is the
explicit literal `" \t\n\r.,;:!?()[]{}"'"` plus start-of-text and end-of-text. Every test is a
table row.

- `testDeclaredOrderIsApplicationOrder` (B1): the spec's pair `[("mcp" → "MCP"),
  ("mcp server" → "MCP server")]` and the reverse, asserted **both ways** over the input
  "mcp server" — the final text must equal the human-applied chain for that declared order, and
  the two runs must be deterministic (order is never a sorting or dedup artifact).
- `testALaterRuleReReplacesAnEarlierRulesOutputRegion` (B1, the load-bearing half): the seam
  doc's own distinguishing chain (`ReplacementRule.swift:19-20`): forward `[("gonna" →
  "going to"), ("going to" → "go to")]` on "gonna" yields "go to"; reverse
  `[("going to" → "go to"), ("gonna" → "going to")]` yields "going to" — the later rule's source
  is the earlier rule's output, so the two orders differ visibly.
- `testCaseSensitiveOffMatchesAnyCasingAndOnMatchesExact` (B2): rule `("kawa" → "Kawa")` with
  `caseSensitive: false` rewrites "kawa", "Kawa" and "KAWA"; the same rule with `caseSensitive:
  true` rewrites only "kawa". Table rows.
- `testCaseFoldingIsUnicodeAware` (edge: unicode rules): `("café" → "CAFÉ")` with
  `caseSensitive: false` matches "CAFÉ" and "Café" — `lowercased()` folds the accented forms;
  the test pins that the fold is plain lowercasing, not locale-dependent.
- `testWordBoundaryOnPreventsMatchesInsideWordsAndOffAllowsThem` (B3): `("cat" → "dog")` with
  `wordBoundary: true` leaves "catalog" untouched but rewrites "cat.", "the cat," and a
  start-of-text "cat"; with `wordBoundary: false` "catalog" → "dogalog". Table rows.
- `testJsonRoundTripPreservesOrderAndBothFlags` (B4, type level): `JSONEncoder`/`JSONDecoder`
  round-trip of an ordered `[ReplacementRule]` of ≥ 3 rules with mixed flags is exactly identical
  — order, `caseSensitive`, `wordBoundary` included (Foundation is legal in the test target;
  mirror of the seam's B5 test, `CleanupProviderSeamTests`).
- `testJsonRoundTripThroughTheStoresEncoderAndDecoder` (B4, the store's code path): driven
  through `FileSystemDictionaryStore.encode(_:)` then `FileSystemDictionaryStore.decode(_:
  onInvalidElement:)` — the exact functions `save`/`load` use — and the result is the identical
  array, no logs emitted.
- `testUnknownFieldsAreToleratedOnLoad` (forward-compat, `spec.md:141-144`): a rule's JSON with
  an extra unknown key decodes to the rule with all four known fields intact, no log.

### 4.2 `DictionaryStoreTests.swift` — the real store (B5, B6, B8)

Real temp directories (`FileManager.default.temporaryDirectory` + `UUID()` suffix, the
`RecoveryJournalTests.swift:334-337` fixture shape, `defer` cleanup) — `FileManager` works on a
hosted runner, so this adapter is **executed by CI**, not merely linted
(`spec.md:67-69`, `RecoveryJournalTests.swift:26-28`).

- `testMissingFileIsAnEmptyDictionary` (B8): store over an absent directory → `load()` returns
  `[]`, no throw, and the injected log collector is **empty** (no log).
- `testCorruptEntriesAreSkippedLoudlyAndNeverFatal` (B5): a real file containing `[valid rule,
  {"source": 42, "replacement": "x", ...}, {"replacement": "missing source"}, "not an object"]`
  (the valid element deliberately also carries an unknown key) → `load()` returns exactly the
  valid rule, emits **exactly one captured log per skipped element** (three), and does not throw.
- `testWholeFileThatIsNotAnArrayLoadsEmptyWithOneLoudLog`: a file whose top level is an object
  (not an array) → `load()` returns `[]`, exactly one log, no throw, **and the file on disk is
  byte-identical afterwards** — a failed parse never rewrites the user's file (`spec.md:70-75`).
- `testSaveIsAnAtomicTempWriteThenRenamePair` (B6, protocol half): the `RecordingDictionaryFileSystem`
  double (writes to a real temp dir) records the save as exactly `[tempWrite, rename]` — the
  journal's recorded pair (`RecoveryJournalTests.swift:44-58`); the real file holds the encoded
  rules and no `.tmp` remains.
- `testAFailedSaveAfterTheTempWriteLeavesThePreviousCommittedContent` (B6, torn half): save v1
  through the default file system; then a `FailingRenameFileSystem` double whose temp write
  lands on disk but whose rename throws → `save(v2)` throws; the committed `dictionary.json` is
  still v1's bytes (previous content, never partial); the leftover `.tmp` sits on disk; a fresh
  store over the real directory loads v1 — the `.tmp` is never readable as a dictionary.
- `testAStrayTempFileFromACrashIsNeverRead`: a planted `dictionary.json.tmp` beside a committed
  file (the `RecoveryJournalTests.swift:298-330` planted-hazard shape) → `load()` returns the
  committed content only.
- `testSaveRecreatesTheFileIfItWasDeletedBetweenLoadAndSave` (edge): load, delete the file,
  save — save succeeds (save never reads the prior file: create-directory, temp-write, rename
  are independent of prior existence) and the fresh file decodes.
- `testEmptyDictionaryRoundTrips`: `save([])` writes `[]`; a fresh store loads `[]`.
- `testOrderingSurvivesAReloadThroughTheRealStore`: save three rules with mixed flags, a fresh
  store over the same directory loads them in exactly the declared order with flags intact
  (the B4 claim over the file).
- `testUnicodeRulesRoundTripThroughTheRealStore`: a rule whose source is "café" → "CAFÉ"
  survives save/load byte-for-byte (UTF-8, not escaped-ASCII).
- `testSaveThrowsWhenTheDirectoryCannotBeCreated`: a double that throws on create-directory →
  `save` throws (the journal's refused-write contract, `RecoveryJournalTests.swift:144-162`).

### 4.4 The store's shape — `Sources/VoccaText/Dictionary/FileSystemDictionaryStore.swift`

Three declarations in the one file (the seam's one `FileManager`-naming file, mirroring how
`JournalStore.swift` + `FileSystemJournalStore.swift` split protocol from adapter — but here both
must live in the one permitted file):

- `public protocol DictionaryFileSystem: Sendable` — `createDirectory(at:)`,
  `write(_:to:)`, `moveItem(at:to:)`, `read(_:) -> Data?`, `fileExists(atPath:)`. **The seam
  through which the tests inject their doubles.**
- `struct DefaultDictionaryFileSystem: DictionaryFileSystem` — the one place in the module that
  spells `FileManager`; raw translation only (the journal's `FileSystemJournalStore.swift:15-40`
  doctrine).
- `public struct FileSystemDictionaryStore: Sendable` —
  - `public let directory: URL`; `public init(directory: URL, fileSystem: DictionaryFileSystem =
    DefaultDictionaryFileSystem(), log: @escaping @Sendable (String) -> Void = ...)` (the log
    default routes to `Logger(subsystem: "dev.vocca.Vocca", category: "dictionary")`); `public
    init()` resolving Application Support with the journal's defensive fallback, pointed at
    `Vocca/dictionary.json`.
  - `public static func encode(_ rules: [ReplacementRule]) throws -> Data` — strict
    `JSONEncoder`, used by `save` (in-memory rules are trusted; the spec's "save only ever
    writes an in-memory state the app itself produced", `spec.md:72-74`).
  - `public static func decode(_ data: Data, onInvalidElement: @Sendable (String) -> Void) ->
    [ReplacementRule]` — **element-wise tolerant**: decode the top level as a JSON array of
    untyped elements; per element, decode `ReplacementRule` (unknown keys skipped by stock
    `JSONDecoder`); each failed element yields exactly one `onInvalidElement` call and is
    skipped. A top level that is not a JSON array yields exactly one call and `[]`. Used by
    `load`. The element-wise path is what makes B5's mixed file decodable without a throw.
  - `public func load() async -> [ReplacementRule]` — **non-throwing**: file absent → `[]`
    silently (B8); read failure → one loud log + `[]`; otherwise `decode(_:onInvalidElement:)`
    with `onInvalidElement` wired to the injected log. Never rewrites the file.
  - `public func save(_ rules: [ReplacementRule]) async throws` — create-directory, encode,
    temp-write `<dir>/dictionary.json.tmp`, rename over `<dir>/dictionary.json` (the
    `FileSystemJournalStore.swift:64-73` protocol); throws on any failure — a failed save means
    the rules are not durable and the caller must know. `dictionary.json.tmp` is a fixed name,
    never read by `load`.
  - Doc comment states the contract: single process, one writer, load once at session start;
    atomicity means a concurrent load sees old or new, never partial; **a save normalizes the
    file** (unknown fields are not re-emitted).

## 6. Edge Cases & Error Handling

- **Corrupt file on disk** — bad element types: skipped with exactly one loud log each, the rest
  loads (B5). Whole file not a JSON array: one loud log, `[]`, file never rewritten.
- **File deleted between load and save** — harmless by construction: save never reads the prior
  file (create-dir, temp-write, rename); a test pins it.
- **Empty dictionary** — `load()` of absent file → `[]` silently (B8); `save([])` writes `[]`;
  both pinned.
- **Ordering after reload** — the file round-trip test pins declared order and both flags across
  store instances.
- **Unicode rules** — plain `lowercased()` folding (never locale APIs) and UTF-8 file content are
  both pinned; a "café"/"CAFÉ" rule round-trips and matches case-blind.
- **Stray `.tmp` from a crash** — never read by `load`, overwritten by the next save; pinned
  both by the torn-save test and the planted-tmp test.
- **Directory absent or uncreatable** — save creates it (`withIntermediateDirectories: true`,
  journal precedent); a refusing double makes save throw, and the throw is the contract.
- **Naming collisions** — grep before creating (`FileSystemDictionaryStore`, `DictionaryFileSystem`
  verified absent today).
- **Strict concurrency surprises** — the store is a `Sendable` struct; `@Sendable` on the log
  closure and the protocol. Any isolation surprise means a design deviation — stop and flag.
- **Warning-as-failure** — unused parameters in stubs and doubles fail CI; keep doubles minimal
  and used.
