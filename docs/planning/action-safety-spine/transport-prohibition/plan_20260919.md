## 0. Why this exists — put it in the file, not just the plan

Deviation **D2**, measured in the Phase 2 dig:

- `interposer.c:69-73` counts **loopback as NETWORK on purpose**, so an MCP server on
  `127.0.0.1` over HTTP/SSE is a violation, not a local convenience. Stdio is the only transport
  the invariant permits.
- But `DYLD_INSERT_LIBRARIES` is **stripped and purged** by restricted children, so
  `/usr/bin/env node server.js`, any `/bin/sh -c` wrapper, and any Apple platform binary are
  **BLIND**. One hop launders the insertion for the whole descendant tree.
- **The failure mode is a green test while a child egresses.**

`audit-log` just shipped `PROBE-ACTIONS`, which proves the *store* reaches no network name and
says nothing about a spawned transport. A future reader looking at a transport lint over a module
that contains no transport will reasonably think it redundant and delete it.

**Therefore: the file must carry the D2 rationale in a type-level doc comment.** That comment is
part of the deliverable, not decoration.

## 1. ⚠️ Two traps this module makes likely

**(a) `system` is a substring of `FileSystem`.** This module ships
`ActionAuditFileSystem.swift`, and the types `ActionAuditFileSystem` / `FileSystemActionAuditStore`
are all over it. A naive `system` match fires on every one. Use an identifier-boundary match —
the family regex shape used elsewhere is `\b(Prefix|…)[A-Za-z0-9_]*`, and `\b` before `system`
does **not** help inside `FileSystem` only if the match is anchored to an identifier *start*.
Verify the detector does not fire on `FileSystem`, and add that as an explicit test case, not
just a hope.

**(b) `Process` is a prefix of ordinary words.** `Processing`, `processed`, `Processor`. The
family regex `\bProcess[A-Za-z0-9_]*` will match `Processing` — which may be acceptable (it is a
prefix family, and that is how `URLSession*` catches `URLSessionConfiguration`), but decide it
deliberately and pin the decision with a test either way.

If either trap forces a choice between false positives and coverage, **prefer the false positive
and add a permitted exception with a comment** — a lint that misses `Process(` is worthless,
while one that also flags `Processing` merely costs a rename.

## 2. Phase 1 — the lint

**File:** `Tests/HarnessTests/ActionTransportProhibitionTests.swift`

**Scan root:** `Sources/VoccaActions/` **only**.
Do **not** scan `Sources/VoccaCore/Actions/` (see §4), and do **not** scan
`Sources/VoccaNetworkProbe/` — `ActionAuditDrive.swift` lives there and is not part of the
actions module.

**Forbidden identifier families:** `URLSession`, `NW`, `Network`, `Process`, `posix_spawn`,
`NSTask`, `system`.

**Structure (the `ModelDownloaderSeamTests.swift:190` empty-permitted-set shape):**
- The permitted set is **empty** — no file in `VoccaActions` may name any of these.
- **Vacuity guards, mandatory:** the scanned file list asserted **non-empty**, each scanned file
  asserted to exist, and **scanning nothing must FAIL rather than pass**.
- The detector is a pure `static func` over a `String`, never re-implemented per call site.

**Controls, both mandatory:**
- **Planted control** — run the detector against a deliberately violating sample and assert the
  **exact identifiers found**. Cover at least `URLSession`, `Process` and an `NW` type, so each
  family is watched firing at least once.
- **Comment-strip control** — the D2 doc comment in this very file names `URLSession`,
  `Process` and `127.0.0.1`. It must not trip the lint. This is not hypothetical: the rationale
  comment is the most transport-naming text in the repository.
- **The `FileSystem` non-match test** from §1(a).

**Commit.** `transport-prohibition: forbid every transport and subprocess family inside VoccaActions, with the D2 rationale the lint exists to carry`

## 4. The spec's open question — resolve and record

*Should the lint also cover `VoccaCore/Actions/`?*

**Recommended: no, and record why.** `VoccaCore`'s import allow-list is empty
(`CoreBoundaryTests.swift:116`) — not even Foundation. `URLSession`, `Process` and `NSTask` are
Foundation; `NW*` is Network.framework. All are structurally unreachable there, and
`CoreBoundaryTests` already fails on any import at all. A second lint would assert something
already guaranteed by a stronger check, and would need its own maintenance.

Write the reasoning into the doc comment so the next reader does not re-open the question.
