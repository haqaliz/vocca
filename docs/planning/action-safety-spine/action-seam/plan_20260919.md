Aspect spec: `docs/planning/action-safety-spine/action-seam/spec.md`

**Stack reality (the skill's Python/uv references do not apply):** Swift 6 package, macOS 15+.
Test command is `Scripts/test-with-floor.sh` (never bare `swift test` — it exits 0 having
discovered nothing). Per-suite iteration: `swift test --filter <SuiteName>`. CI builds under
**strict concurrency where any warning fails**.

---

## 0. Resolved open questions

**Q1 — where the confirmation token lives.** *Resolved:* `ActionConfirmation` is a
`public struct` in `VoccaCore/Actions/` with an **`internal` initializer**.

Measured, not assumed: `Tests/HarnessTests/` contains **201** files using plain
`import VoccaCore` against **3** using `@testable import VoccaCore`. Under a plain import an
`internal init` is genuinely unreachable — so "a test cannot forge a confirmation" is a
compile-time fact for the default convention, not a promise.

The residual hole is that a future test could add `@testable import VoccaCore` and mint one.
Closed by the family lint in Phase 3, whose permitted-file set spans **both `Sources/` and
`Tests/`**: `ActionConfirmation(` may appear only in the gate's own source file. A forging
test fails the lint even though it would compile.

**Q2 — `ActionOutcome.failed` payload.** *Resolved:* a **reason key** (`String`), not a
message. Foundation-free, bounded, and it keeps the audit entry's byte-pin satisfiable — a
free-form error message would smuggle unbounded text onto disk.

## 2. Phases

### Phase 1 — RED: the seam contract

**Goal.** Pin the vocabulary and the protocol before either exists. Per the C12 precedent
(`49766c1`), RED here means **the test target does not compile** because the types are absent.
That is the intended failing state; do not stub types to make it build.

**Files created:** `Tests/HarnessTests/ActionSeamTests.swift`

**Tests to write (all failing):**
1. `BlastRadius` is a closed enum with exactly `readOnly`, `destructive`, `outwardFacing`, and
   exposes a single documented predicate (`requiresConfirmation`) — asserted over **all three**
   cases via a `CaseIterable` sweep, so a fourth case added later fails here first.
2. `ActionInvocation` carries `providerID` and `toolID`; both non-empty by validation.
3. `ActionSummary` carries the concrete sentence; equality is value equality.
4. `ActionOutcome` has `.succeeded`, `.failed(reasonKey:)`, `.notInvoked`.
5. `ActionProvider` declares `describe(_:)` and `invoke(_:confirmation:)`; `describe` is
   **non-throwing and synchronous** (pinned by use, the D1 precedent — if the adapter needs
   async it becomes an actor with a `nonisolated` witness, recorded rather than drifted).
6. `NullActionProvider` exposes **zero** tools.
7. `NullActionProvider` refuses a `readOnly` invocation — the shipped default acts on nothing.
8. Every type is `Sendable` (asserted by use in a `@Sendable` closure).

**Validation.** `swift test --filter ActionSeamTests` fails to build. Record the compiler
error in the commit message — that is the RED evidence.

**Commit.** `action-seam: pin the ActionProvider contract — RED seam and NullActionProvider tests against a vocabulary that does not exist`

### Phase 3 — the seam-family lint, with its controls

**Goal.** Confine the action vocabulary to `VoccaCore/Actions/`, and close the
`@testable`-forgery hole from §0/Q1.

**Files created:** `Tests/HarnessTests/ActionSeamBoundaryTests.swift`
(shape: `ContextSeamBoundaryTests.swift:81-100`)

**Structure — three legs, none of which is sufficient alone** (the header at
`ContextSeamBoundaryTests.swift:143-147` explains why each one-sided check passes vacuously):
1. No file outside the permitted set names the family.
2. **Every** permitted file does name it.
3. The two counts are equal.

**Two families:**
- The action vocabulary (`ActionProvider`, `ActionInvocation`, `BlastRadius`, …) confined to
  `Sources/VoccaCore/Actions/`.
- **`ActionConfirmation(` — construction — confined to its own single source file, scanning
  `Sources/` AND `Tests/`.** This is the forgery guard.

**Controls (both mandatory):**
- **Planted control** — run the detector (a pure `static func` over a `String`, never
  re-implemented) against a deliberately violating sample; assert the **exact identifiers
  found**. A lint that has only ever seen a clean tree is a lint nobody has watched work.
- **Comment-strip control** — a doc comment naming the family must not trip it, via
  `SwiftSourceScanner.stripComments`. This is what lets the seam document what it confines.

**Vacuity guards.** The permitted file list is asserted non-empty and each file asserted to
exist; scanning nothing **fails** rather than passes.

**Validation.** `swift test --filter ActionSeamBoundaryTests` green, and the planted control
demonstrably fires.

**Commit.** `action-seam: the action-family seam lint and the ActionConfirmation forgery guard, with planted and comment-strip controls`

### Phase 4 — the executing stub (PRD M10)

**Goal.** Give the later aspects a non-empty domain. Without this, `confirmation-gate`'s
dry-run assertion and `audit-log`'s reconstruction assertion both quantify over nothing and
pass while proving nothing (PRD §6/C1).

**Files created:** `Tests/HarnessTests/ActionProviderStubs.swift`

**Contents.**
- `RecordingActionProvider` — a test-only provider that genuinely executes, with a call log
  recording every `describe` and `invoke` separately (the two must be distinguishable, or
  the dry-run assertion cannot be written).
- A mode in which `invoke` **fails the test if called** — C13's own wording for the dry-run
  acceptance ("asserted by a stub that fails the test if invoked"). Implemented by holding an
  `XCTestCase` reference or a failure callback, not by returning an error.
- A self-check test asserting the stub itself works: that it records calls, and that its
  fail-if-invoked mode actually fails when invoked (exercised via `XCTExpectFailure`).
  **A stub nobody has watched fail is not evidence.**

**Validation.** `swift test --filter ActionProviderStubs` green.

**Commit.** `action-seam: the recording stub provider and its self-check — the non-empty domain the dry-run and reconstruction acceptances need`

## 5. Edge cases & failure behavior

- **An empty `providerID`/`toolID`** must be refused at construction, not carried as a valid
  invocation — a nameless action cannot be described concretely, which breaks M2.
- **`NullActionProvider.describe`** on an unknown tool: return a refusal summary, never trap.
  The shipped default must be safe to call with anything.
- **A `readOnly` invocation of the null provider** still refuses — "read-only runs directly"
  is a *gate* rule about permission, not a promise that a provider must serve it.
- No recoverable-failure UI applies: this aspect ships no surface.
