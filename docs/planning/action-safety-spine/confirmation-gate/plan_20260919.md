## 0. Carried resolutions from `action-seam`

- `ActionConfirmation` is a `public struct` in `VoccaCore/Actions/` with an **`internal` init**.
- **The gate must therefore live in `VoccaCore`** — it is the only module that can mint a token.
  `Sources/VoccaCore/Actions/ActionGate.swift`.
- `BlastRadius` lives on `ActionSummary` (the provider's claim). The escalate-only rule in the
  spec is binding on this aspect.
- `invoke` is synchronous and non-throwing; failure is `ActionOutcome.failed(reasonKey:)`.
- `RecordingActionProvider` (Tests) logs `describe` and `invoke`/`execute` **separately** — this
  is what makes the dry-run assertion expressible.

## 1. ⚠️ The lint interaction — read before writing code

`ActionSeamBoundaryTests` Family B currently asserts that **`ActionConfirmation(` occurs nowhere
in the tree**, anchored on the init's access modifier rather than on a permitted set (because
the set is empty today).

**This aspect is the first legitimate construction site.** `ActionGate` must construct a token.

That is the lint **working as designed, not being defeated**: the guard exists to force every
minting site to be a deliberate, reviewed edit. The required change is therefore:

- Family B's permitted set becomes **exactly one file**: `Sources/VoccaCore/Actions/ActionGate.swift`.
- Leg (b) stops being vacuous and becomes real: that file **must** construct a token.
- The assertion that the init is not `public`/`package`/`open` **stays**.
- `Tests/` remains in Family B's scan root, and **no test file may be added to the permitted
  set** — a forging test must still fail.

**Constraints on the edit:** widen by exactly one file, never more. State the widening
explicitly in the commit message with its justification. If more than one file needs to mint,
STOP and report — that is a design problem, not a lint problem.

## 2. Phases

### Phase 1 — RED: the gate contract

**Files:** `Tests/HarnessTests/ActionGateTests.swift`

Write all of the spec's acceptance criteria as failing tests. Against a type that does not
exist, RED is a compile failure (the `action-seam` precedent). Do not stub to make it build.

1. **The load-bearing test.** A `destructive` invocation submitted **without** a token is
   **refused** — asserted by attempting the call and requiring refusal. Not "no prompt appeared".
2. `outwardFacing` behaves exactly as `destructive` today (both confirm) — pinned, so PRD C4's
   collapse-or-diverge decision is a visible edit.
3. **Dry-run invokes nothing:** `describe` may be called; the stub's invoke/execute counter must
   read **zero**. Uses `RecordingActionProvider` — non-empty domain (PRD C1).
4. A **disabled** tool is declined **before `describe` and before `invoke`** — asserted on the
   stub's call log reading zero of **both** kinds. This is the never-read property, not
   read-then-discard.
5. Enable → invoke → disable ⇒ the next invocation refuses. No carry-over.
6. **Per-invocation only:** confirming once does not confirm twice. Two invocations need two
   tokens.
7. A `readOnly` invocation of an **enabled** tool runs without a token.
8. **Escalate-only, positive:** a provider claiming `readOnly` for a tool local policy marks
   `destructive` is **confirmed, not auto-run** — asserted by attempting the auto-run path and
   requiring refusal.
9. **Escalate-only, negative:** no input produces a radius **below** the provider's claim.
   Asserted over all three `BlastRadius` cases (`CaseIterable` sweep).

**Validation.** `swift test --filter ActionGateTests` fails to build; capture the error.

**Commit.** `confirmation-gate: pin the gate contract — RED refusal, dry-run, enablement and escalate-only tests against a gate that does not exist`

### Phase 2 — GREEN: the gate

**Files:** `Sources/VoccaCore/Actions/ActionGate.swift` (+ a policy type if it earns its own file)

- **No imports.** `VoccaCore`'s allow-list is empty — not even Foundation.
- Prefer a **pure value**, not an actor: the gate has no I/O, and this repo's gates and scorers
  (`ContextGrantGate`, `TurnCommitmentScorer`) are pure. Enablement is passed in, not owned.
- The gate is the **only** minting site for `ActionConfirmation`.
- The local policy applies **escalate-only** (see the spec's table). Encode the monotonicity so
  it cannot be violated by a later edit — e.g. a `max`-style combine over an ordered radius,
  rather than a lookup that could return anything.
- Every type `public` + `Sendable`; Apache-2.0 header; zero warnings.

**Commit.** `confirmation-gate: the ActionGate — the structural refusal, the read-only direct path, dry-run and the escalate-only policy (GREEN)`

## 3. Edge cases

- **Refusal must be distinguishable from failure.** A refused action is not
  `ActionOutcome.failed` — it never reached the provider. Model it as its own decision value, or
  the audit log cannot tell "we stopped this" from "the tool errored", which is the distinction
  R8 turns on.
- **An unknown tool** (not in the enablement set at all) is declined like a disabled one —
  default off means absent is off.
- **Dry-run of a disabled tool** declines before `describe`; disabled beats dry-run.
