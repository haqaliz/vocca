## Context for the executing agent

Swift 6 package; suite via `Scripts/test-with-floor.sh` (floor 1755). The cleanup eval
harness (`CleanupEvalHarnessTests`, gated by `VOCCA_CLEANUP_EVAL`) scores a checked-in

(`STATUS.md:566-571`). This plan is the **first execution of the real half**: the
founder's own recordings, scored by the founder (`SMOKE_CHECKLIST.md:1372-1406`,
step 73). The corpus lives at `~/Vocca/f2-pairs/` — **never in the repo, never
uploaded, never copied into worktrees**. The P1 gate's ≥ 80% figure
(`ROADMAP.md:137`) is provisional until this runs once (`tolerances_20260815.md:43-44`);
this plan measures it and **records, never gates**.

The run's honest-expectation baseline: the TTS stand-in corpus is "unnaturally clean"
(`STATUS.md:351-353`) — the F2 number is the first real one and may differ materially.
That difference is the point (spec R3; `plan_20260901.md:80-82`).

**Style note:** this plan supersedes `docs/planning/p2-gate-measurement/cleanup-eval-f2/plan_20260901.md`
for the run; the stale-doc fixes there (floor 1731 → 1755, `VOCCA_CLEANUP_EVAL=1` →

disk; a seeded ballot printed and answered side-blind; per-pair verdicts,

## Phase 1 — Corpus recording (the long pole)

### Goal

A complete, loader-valid corpus at `~/Vocca/f2-pairs/`: **≥ 40 utterances, ≥ 5 per
class**, across the six `Tests/CleanupPairs/` classes (`CleanupPairwiseScorer.swift:22-29`):
`fillers | punctuation | capitalization | numbers-units | dictionary | token-protection`.

### Prerequisites

- One focused founder session (the long pole — plan for it to overlap the
  `whisper-wer` and `latency-record` sessions, PRD execution order step 5).
- No build work: the loader, scorer, and harness already exist. `f2-defect-fixes`
  needs only to have *landed* before Phase 2, not before recording.

### Steps

1. **Record** ≥ 40 utterances, dictation-length (3-15 s), **natural as-spoken speech** —
   fillers and false starts, not reading flat (`SMOKE_CHECKLIST.md:1379-1380`).
   Spread ≥ 5 per class; more is fine (more pairs tighten the number).
2. **Name each pair** `<name>` uniquely (suggest `<class>-NN`, e.g. `fillers-01` —
   names become `answers.tsv` keys, so they must be typo-proof and unique).
3. **Per pair, write four siblings** in `~/Vocca/f2-pairs/`:
   - `<name>.wav` — the recording, **16 kHz mono** (the SMOKE recording contract;
     the harness re-converts any WAV to 16 kHz mono Float32 anyway,
     `CleanupEvalHarnessTests.swift:601-632`, but record at the convention).
   - `<name>.raw.txt` — **required for discovery** — the loader keys on the `.raw.txt`
     suffix only (`CleanupPairSuite.swift:91-95`); a wav-only corpus loads **0 pairs**
     (`noPairsFound`). With the wav present, its content is *replaced* by the real
     engine's transcript at run time (`CleanupEvalHarnessTests.swift:475-518` — the
     `.raw.txt` is ignored for that pair); write the hand-typed fallback anyway — it is
     the honest raw side for any pair whose wav is later dropped.
   - `<name>.clean.txt` — the hand-polished golden: what should have been typed.
   - `<name>.class.txt` — the class tag, **exactly** one of the six raw values
     (`fillers | punctuation | capitalization | numbers-units | dictionary |
     token-protection`); any other tag throws `unknownClassTag`.
4. **`dictionary.json`** — the dictionary-class rules, as an array of
   `{"source": ..., "replacement": ...}` (the `DictionaryStoreTests` shape, e.g.
   `[{"source":"kawa","replacement":"Kawa"}]`). The harness loads it from the pairs
   directory (`FileSystemDictionaryStore`); an absent file is an empty dictionary —
   the dictionary class then has nothing to exercise, so write the rules that the
   dictionary-class pairs depend on and record what they were.
5. **Verify the layout** (founder-side counts — the loader's only vacuity guard is
   ≥ 20 pairs total, `minimumMeaningfulCorpusSize`, so the ≥ 5-per-class floor is
   *your* check, not the harness's):
   - total `.raw.txt` count ≥ 40;
   - per-class tallies: `for c in fillers punctuation capitalization numbers-units dictionary token-protection; do printf "%s " "$c"; rtk ls ~/Vocca/f2-pairs/ | rg -c "^$c-.*\.class\.txt$"; done` — every class ≥ 5;
   - every name has all four siblings (no orphan `.wav`/`.clean.txt`/`.class.txt`);
   - no pair is named `dictionary`, `answers`, `seed` or collides with a sibling
     suffix pattern.

### Validation

- The layout checks above pass; the directory's existence, counts, class tallies,
  machine, and date are captured for the step-73 note (Phase 5).
- Spot-check 2-3 wavs play back and are audible, 16 kHz mono (`afinfo`).
- **No repo file is created in this phase; nothing here is committed.**

### Commit message

None — the corpus is on-disk only by design. The step-73 row (Phase 5) is the record.

## Phase 2 — First run: the ballot

### Goal

The first `VOCCA_CLEANUP_EVAL=<pairs-dir>` invocation prints the seeded, side-blind
ballot; the founder answers it into `answers.tsv` without ever seeing which side is
cleaned.

### Prerequisites

- **`f2-defect-fixes` landed** — the ballot flow (seed generated and printed) is that
  aspect's build work; without it the first invocation only skips
  (`CleanupEvalHarnessTests.swift:459-463`).
- Corpus complete per Phase 1.
- Parakeet provisioned and verified (`VOCCA_MODEL_DIR` set — `provision-asr-fixtures.sh`);
  a `.wav` present without it is a **hard failure** (`CleanupEvalHarnessTests.swift:465-473`).

### Steps

1. **Command (exactly):**
   ```
   VOCCA_CLEANUP_EVAL=~/Vocca/f2-pairs VOCCA_MODEL_DIR=<provisioned-model-dir> ./Scripts/test-with-floor.sh --filter CleanupEvalHarnessTests
   ```
   The env value is the **directory**, not `1` (the `=1` spelling in the 20260901
   plan is the stale form S1 fixes; `CleanupEvalHarnessTests.swift:450`).
2. **Expected output:** the seeded ballot — `seed=0x<HEX>` at the top, then per pair
   `## <name> [<class>]`, `A: <text>`, `B: <text>`, `answer:`
   (`printBallot`, `CleanupEvalHarnessTests.swift:835-855`). The class tag is
   cosmetic; the guarantee is **side-blindness** — A/B sides are the seeded
   presentation (`rawFirst`/`cleanedFirst` per pair, deterministic in the seed), never
   labelled.
3. **Founder answers** into `~/Vocca/f2-pairs/answers.tsv`:
   - first line `seed\t<hex>` — copy the **hex digits only** from the printed line
     (no `0x`, no `seed=`): `parseAnswers` reads `UInt64(…, radix: 16)` and a `0x`
     prefix returns nil → `malformedAnswers` (`CleanupEvalHarnessTests.swift:807-830`);
   - one `name\tleft|right|tie|noPreference` line per pair. `tie` and `noPreference`
     are allowed and **excluded from the denominator** by design
     (`tolerances_20260815.md:22-26`) — do not feel forced to pick.
4. **Checkpoint:** before leaving the session, confirm every pair has an answer line
   and the seed line matches the printed seed; a missing pair's answer makes the
   second run throw `answersMissingPair` (`:868-870`).

### Validation

- The printed seed and `answers.tsv`'s first line are the same hex value.
- One answer line per corpus pair; no unknown names (an unknown name throws
  `unknownPairInAnswers`, `:871-873`).
- The judge (you) never saw which side was cleaned — no peeking at
  `.clean.txt`/`.raw.txt` contents during answering. **Blindness is the metric's
  foundation.**

### Commit message

None — `answers.tsv` lives beside the corpus on disk, never committed.

## Phase 3 — Second run: the verdict

### Goal

The per-pair rows, `preference=NN.N%`, per-class tallies, and the `RECORDED, not
gated` comparison line vs 0.80 — the first real measurement of the P1 gate's number.

### Prerequisites

- `answers.tsv` complete and seed-matched (Phase 2).
- Same env vars as Phase 2.

### Steps

1. **Command:** identical to Phase 2 (the seed in `answers.tsv` is what makes both
   invocations present the same sides — `presentations(for:seed:)` is shared by
   `printBallot` and `runReal`).
2. **Expected output** (`runReal`, `CleanupEvalHarnessTests.swift:879-906`):
   - one row per pair: `name\tverdict\tseed=0x<HEX>`;
   - `preference=NN.N%` (the scorer's exact arithmetic — `preferencePercentage`,
     tie/noPreference excluded from the denominator);
   - per-class tallies: `class: cleaned N, raw N`;
   - the comparison line: `verdict NN% vs provisional 0.80: RECORDED, not gated — the
     founder re-baselines (SMOKE_CHECKLIST.md step 73)`.
3. **Capture** the full run output (the printed record) into the step-73 note with the
   seed, percentage, and per-class tallies; keep the raw run output locally beside the
   corpus for provenance.

### Validation

- The run prints its record (the harness asserts the lines are non-empty and the
  percentage matches the scorer; `CleanupEvalHarnessTests.swift:527-534`).
- The per-pair verdicts reproduce the comparator's mapping for the printed seed — the
  SMOKE step's pass condition (`SMOKE_CHECKLIST.md:1396-1397`): re-run with the same
  seed and the same answers and you get the same rows.
- **Pass is the printed record, not a verdict.** The percentage is recorded, never a
  gate failure — a sub-0.80 result is a signal to fix the rules
  (`tolerances_20260815.md:40-41`).

### Commit message

None yet — no repo file exists from the run (the verdict is printed, not written).

## Phase 4 — Re-baseline decision

### Goal

The measured percentage lands, through the founder-signed procedure, in exactly the
named place — or the 0.80 target is recorded as met — or "not re-baselined" is
recorded with sign-off. Never silently relaxed.

### Prerequisites

- Phase 3's printed number and record.

### Steps

1. **Compare** the measured percentage against
   `ProvisionalCleanupTargets.preferenceMinimum` (0.80, `ProvisionalCleanupTargets.swift:30`).
2. **Case A — number ≥ 0.80 (with the founder's margin):** record the target as met.
   No code change. The margin absorbs recording noise and is a founder decision at
   re-baseline time, recorded in the step's note (`tolerances_20260815.md:28-41`).
3. **Case B — number < 0.80:** follow the chain in order
   (`tolerances_20260815.md:28-41`):
   - **Measure** — the printed percentage (Phase 3).
   - **Margin** — the founder picks the margin that absorbs recording noise; record
     the reasoning in the step's note (OQ1).
   - **Founder-signed** — a dated, signed row in
     `docs/planning/deterministic-cleanup/eval-harness/tolerances_20260815.md`: the
     measured percentage, the machine, the corpus provenance, and the margin.
   - **Land in exactly one file** — `Tests/HarnessTests/ProvisionalCleanupTargets.swift`
     (the `preferenceMinimum` line), nowhere else. The single-source scan
     (`testThePreferenceMinimumAppearsNowhereOutsideTheNamedFile`,
     `CleanupEvalHarnessTests.swift:551-559`) must stay green — a re-baseline edits
     exactly the named file, and `CleanupRealRunTargets` consumes it unchanged.
4. **Case C — explicitly record "not re-baselined":** if the founder declines either
   direction, write the signed "not re-baselined, 0.80 stays provisional" row in
   `tolerances_20260815.md` with the reason. A recorded non-decision is honest; a
   silent one is not.

### Validation

- Case B: the signed row exists in `tolerances_20260815.md` **before** the code
  change; `ProvisionalCleanupTargets.swift` changed in exactly one line; the
  single-source scan and `testTheRealRunConsumesTheProvisionalPreferenceMinimum`
  (`:539-545`) pass.
- Cases A/C: no code change; the record carries the decision.

### Commit message

- Code changed (Case B): `re-baseline the cleanup preference target from the F2 run (SMOKE 73)`
- Record only (Cases A/C — combined with Phase 5's row):
  `record the F2 cleanup eval verdict (SMOKE 73)`

## Environment & privacy

- **Env vars per run:** `VOCCA_CLEANUP_EVAL=~/Vocca/f2-pairs` +
  `VOCCA_MODEL_DIR=<provisioned-model-dir>`; `./Scripts/test-with-floor.sh --filter
  CleanupEvalHarnessTests` (filter syntax; every `swift test` goes through the floor
  script — `swift test` exits 0 when it discovers nothing).
- **Privacy:** the corpus is founder voice data on the founder's disk — never
  committed, never copied into worktrees, never transmitted. The eval is fully local;
  the wav→transcript pass runs the provisioned Parakeet engine with a stub transport
  (`CleanupEvalHarnessTests.swift:480-497`) — no network touches the recordings.
- **Zero-network invariant:** unaffected; the run is engine-local.

## Edge cases

- **Fewer than 5 per class, or < 40 pairs:** the loader only enforces ≥ 20 total
  (`minimumMeaningfulCorpusSize`) — the per-class floor is the founder's check in
  Phase 1. **Re-record before any run**; a thin class would make that class's tally
  statistically meaningless (R3).
- **Ballot seed mismatch:** `answers.tsv`'s first line must be `seed\t<hex>` with the
  hex digits only (no `0x` prefix — the printed `seed=0x<HEX>` form will not parse);
  a mismatch throws `malformedAnswers`. Fix the seed line, do not re-answer.
- **Tie-heavy answers:** `tie`/`noPreference` shrink the denominator by design
  (`tolerances_20260815.md:22-26`); tallies print `no-preference`-style rows. A
  tie-heavy corpus is a corpus-quality signal, not a failure — record it.
- **`.wav` without `VOCCA_MODEL_DIR`:** hard `XCTFail` (`:465-473`) — set both vars.
- **`.wav` without `.raw.txt`:** 0 pairs load (`noPairsFound`) — `.raw.txt` is the
  discovery requirement; the `f2-defect-fixes` aspect pins this.
- **Missing corpus directory with the env var set:** hard failure, never a skip
  (`:452-458`) — check the path before running.
- **Missing answers.tsv:** expected on the first invocation (the ballot path) — do not
  treat the skip as a failure.
- **Missing clean target / class tag, unknown tag:** named loader errors
  (`CleanupPairSuite.swift:103-116`) — fix the corpus, not the loader.
- **Unreadable recording:** `recordingUnreadable` (`:701-702`) — re-record that pair.
- **Answer rows for pairs that don't exist (typo):** `unknownPairInAnswers` — fix the
  name.
- **Unanswered pair:** `answersMissingPair` — the run must score everything or not
  read green.
- **The number misses 0.80:** expected to be *possible* — the stand-in corpus is
  "unnaturally clean"; the F2 number is the first real one and is recorded, never
  gated. A miss re-baselines via Phase 4 (Case B) or records not-re-baselined
  (Case C) — never silently relaxes.

## Do-not list

- **No scorer changes** — `CleanupPairwiseScorer`, the denominator rule
  (tie/noPreference excluded), and the presentation mapping stay untouched; reopening
  the denominator is an F2-re-baseline decision recorded in `tolerances_20260815.md`
  first, and it is out of scope for this aspect.
- **No 0.80 change without the signed procedure** — `ProvisionalCleanupTargets.swift`
  changes only via Phase 4's chain (measure → margin → founder-signed → land in
  exactly that file), never as a convenience.
- **No LLM cleanup measurement** — C6 claims nothing there (`STATUS.md:406-408`); the
  eval is rules-path only.
- **No corpus/answers/verdict files in the repo, ever** — including in a worktree or
  a commit-by-accident (`git status` check in Phase 5).
- **No gate-pass claim** — the verdict line says `RECORDED, not gated`; nothing in
  this aspect passes the P1 gate.
- **No peeking during the ballot** — blindness is the metric's foundation; the agent
  must not present labels while the founder answers.
- **No harness behavior changes to absorb a bad number** — a low percentage is a
  record and a signal to fix the rules, not a reason to change the mechanism.
