## Testing strategy

- `Scripts/test-with-floor.sh` after every commit — the single-source scans are the
  load-bearing checks: a re-baseline that duplicated a constant fails; a re-baseline
  that changed a value in a second file fails.
- 3B (if approved) is the only RED→GREEN slice: the copy test first, then the constant.
- No other new tests; docs-only commits.

## Environment & privacy

- No env vars, no network, no founder data in the repo: the F2 corpus is cited by path
  (`~/Vocca/f2-pairs/`) and never committed; the ballot seed is recorded as a number,
  not the answers; run outputs are cited, not committed.

## Edge cases

- **A step the founder declined to record** (e.g. the q5_0 WER run): gets the named
  "not-tested / not performed" row with the reason and date — a closed surface, not a
  silent one (the 2026-09-01 "Not performed — GGUF absent" precedent,
  `tolerances_20260810.md:68`).
- **A tolerance change in an earlier aspect:** this aspect audits, never re-writes; if
  the row and the land already agree, nothing moves.
- **Floor drift from the prior aspects:** read the floor, re-record it in every doc that
  cites it (CLAUDE.md, STATUS.md, this plan's context) — doc numbers are single-sourced
  too (`plan_20260901.md:82-84`).
- **The copy decision's second reading:** a founder who approves the copy change but
  wants numbers in the status lines signs a *separate* slice — never folded into 3B
  silently, because `SpeechTabCopyTests` pins the no-numbers posture.
- **A row whose run output was lost:** the row records "not verifiable — output lost" and
  the run is not re-claimed; no number is reconstructed from memory.
