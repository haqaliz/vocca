## 0. The vocabulary decision — resolved

Option 1 of the card: **`ActionInvocation` gains `arguments: String?`, holding the JSON text.**

Why this over the alternatives:
- **The seam signature does not change a third time.** `describe(invocation)` still receives
  everything it needs to render a concrete sentence, so the async change stays the last word on
  the seam's shape.
- **`VoccaCore` can hold a `String`** — the allow-list is empty, so no `Data`, no JSON type. The
  identifiers are already `String` for exactly this reason.
- **Option 2 was rejected**: a provider holding pending arguments keyed to an invocation is
  stateful with a lifetime problem, and two concurrent invocations of the same tool would race.
- **Option 3 was rejected**: a separate argument-carrying type means changing the seam signature
  again, for no gain over carrying it on the invocation.

**The honest cost, recorded:** `VoccaCore` cannot parse JSON, so it **cannot validate** that the
string is well-formed. The invocation holds an opaque blob it cannot check. The MCP provider
parses it and fails as a returned value. Say this in the doc comment — a type that cannot
validate its own contents should admit it rather than imply a guarantee.

**Add the field with a default (`arguments: String? = nil`)** so every existing construction site
keeps compiling; this is a purely additive change.

### Two properties that must not be undone

1. **Arguments are NEVER persisted.** PRD §5 (slice 1) records that the audit entry holds the
   rendered `summary`, not raw arguments. `ActionAuditEntry` takes an `ActionInvocation`, so this
   field is now *reachable* from the entry for the first time — **assert that it does not appear
   in the encoded bytes.** The key-set byte-pin already fails on a new key; add an explicit test
   that a distinctive argument string is absent from the file.
2. **The confirmation sentence stays concrete** (C13). Arguments exist so `describe` can say
   *"send this message to #general"* — assert the values reach the sentence.

### The bound

`summary` is bounded at 1 KB. **Bound `arguments` too, and pin the number in one place.** An
unbounded blob travelling through the gate is a needless liability even unpersisted. Pick the
bound in the plan, assert at the boundary and one byte over.

## 1. Phases

### Phase 1 — RED: the vocabulary

**File:** `Tests/HarnessTests/ActionSeamTests.swift` (extend)

1. `ActionInvocation` carries `arguments`; absent by default; equality includes it.
2. The bound is enforced at construction — at the boundary, and one byte over.
3. **The non-persistence pin:** an invocation carrying a distinctive argument string, recorded
   through the audit store, produces file bytes that **do not contain it**. Vacuity guard: assert
   the string genuinely was on the invocation first.

### Phase 2 — GREEN: the field

`Sources/VoccaCore/Actions/ActionInvocation.swift`. No imports. Doc comment records: why it is
text, that Core cannot validate it, the bound, and that it is never persisted.

### Phase 3 — RED + GREEN: `MCPProvider`

**Files:** `Tests/HarnessTests/MCPProviderTests.swift`,
`Sources/VoccaActions/MCP/MCPProvider.swift`

4. Tools discovered via `tools/list` become the provider's tool list.
5. `describe` renders a **concrete** sentence naming the tool and its argument values.
6. **The lying server.** A server declaring `readOnlyHint: true` for a tool the local policy
   floors as `destructive` must be **confirmed, not auto-run** — asserted by attempting the
   auto-run path and requiring refusal. This is slice 1's escalate-only rule meeting real
   untrusted input; a well-behaved server alone proves nothing.
7. A tool with **no** annotation is not read-only (carried from `protocol-core`, asserted here
   through the provider rather than the session).
8. `invoke` sends `tools/call` and maps the result; a server error becomes
   `.failed(reasonKey:)`, **never a trap**.
9. An unknown tool id returns a refusal summary / `.failed`, never a trap.
10. **`invoke` without a confirmation is unreachable** — the gate-level property, re-asserted
    against this provider (the third real provider to carry it).

**Five permitted rows** in the action-family lint for the new file — expected, structural, one
file. Say "five rows, one file" in the commit message.

## 2. Constraints

- **The transport prohibition lint must stay green with an EMPTY permitted set.** `MCPProvider`
  talks to `MCPTransport`, never to a process or socket. **If it fires, stop and report.**
- `VoccaActions` deps stay exactly `["VoccaCore"]`.
- Do **not** touch `AppBootstrap.swift`, `SessionMachine.swift`, `DictationPipeline.swift`
  (G5 pin), or `Scripts/test-with-floor.sh`.
- **Do not wire anything into the composition root.** No surface, no `AppBootstrap`.
- Untrusted-peer discipline continues: no force-unwraps, no `try!`, nothing indexed unchecked
  from a frame.
- Stage explicit paths only — never `git add -A` (recorded incident).

## 3. Agent notes

- **Stop and report if** adding `arguments` to `ActionInvocation` requires changing the seam
  signature, or if a distinctive argument string turns out to reach the audit file — the second
  would be a real defect in slice 1's privacy claim, not a test to relax.
- The lying-server test (6) is the most important in this aspect. If it cannot be written as an
  *attempted* auto-run requiring refusal, say so rather than weakening it to an inspection.
