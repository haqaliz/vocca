# Implementation plan — `protocol-core` (2026-09-20)

Card: `docs/planning/_card/issue.md` (read the Q3 decision and the vocabulary risk first)
Predecessor: `local-data-provider`, merged `0d0b723`, floor **2561**

**Aspect 1 of 3.** The transport seam, the in-memory implementation, and the JSON-RPC
protocol layer. **No `ActionProvider` conformance** — that is aspect 2, which is also where the
vocabulary question gets confronted.

**Sequenced first on purpose:** none of this needs `ActionInvocation`, so the vocabulary
decision gets made later with a real protocol layer in hand instead of in the abstract.

## 1. What ships

`Sources/VoccaActions/MCP/`:

| File | Purpose |
|---|---|
| `MCPTransport.swift` | The seam: send a JSON-RPC request, get a response. **No process, no socket.** |
| `InMemoryMCPTransport.swift` | A real, scriptable implementation — canned responses per method, recorded requests |
| `JSONRPC.swift` | Request/response/error encoding, id correlation |
| `MCPSession.swift` | `initialize` negotiation, `tools/list` discovery, `tools/call` |
| `MCPToolDescriptor.swift` | A discovered tool: name, description, annotations (incl. `readOnlyHint`) |

Foundation **is** available in `VoccaActions` (unlike `VoccaCore`) — the audit store already
uses `Data` and `URL`. Use `JSONSerialization` or `Codable`; do **not** add a dependency.

## 2. ⚠️ Constraints that will bite

**(a) The transport prohibition lint forbids `URLSession`, `NW*`, `Network`, `Process`,
`posix_spawn`, `NSTask`, `system` inside `VoccaActions`.** An in-memory transport names none of
them. **If this aspect trips that lint, that is a genuine finding — report it, do not widen the
lint.** The lint's permitted set is empty and must stay empty.

**(b) `NW` is a prefix family.** Watch for incidental matches in new code (`NWire`, etc.) — the
lint is case-sensitive and anchored to identifier start, but check rather than assume.

**(c) The seam must not leak a transport concept.** `MCPTransport` describes *sending a frame*,
not *a pipe*. No file descriptors, no PIDs, no endpoints in the protocol. If the seam's
vocabulary mentions processes or sockets, the stdio slice has already leaked into this one.

**(d) `VoccaActions` deps stay exactly `["VoccaCore"]`** — asserted by equality.

## 3. Phases

### Phase 1 — RED: the transport seam and JSON-RPC

**File:** `Tests/HarnessTests/MCPProtocolTests.swift`

1. A JSON-RPC request encodes with `jsonrpc: "2.0"`, a method, params, and an id.
2. Responses correlate **by id**; an out-of-order response is matched to its own request.
3. A JSON-RPC **error** response maps to a typed error, never a trap and never a silent success.
4. A malformed frame (not JSON, missing `jsonrpc`, missing id) is a **typed failure**, never a
   crash — an untrusted peer must not be able to trap the process.
5. `InMemoryMCPTransport` records every request it was sent, in order, so tests can assert what
   the session actually asked for.

### Phase 2 — RED: the session

6. `initialize` sends the protocol version and capabilities and parses the server's reply.
7. **A server that fails `initialize` leaves the session unusable** — `tools/list` afterwards
   fails rather than proceeding against an unnegotiated peer.
8. `tools/list` parses tool descriptors including annotations.
9. **A tool with no `readOnlyHint` is treated as NOT read-only.** Absent means unsafe; this is
   the fail-safe default and must be asserted, because "missing annotation" is the common case
   in real servers.
10. A server returning a malformed tool list yields **no tools**, not a partial list of
    half-parsed ones.
11. `tools/call` sends name + arguments and returns the server's content or error.

### Phase 3 — GREEN

Implement the above. Minimal, no speculative surface — no batching, no notifications, no
subscriptions, no resources/prompts. Only what the tests demand.

### Phase 4 — the probe drive

`VoccaActions` is already driven by `PROBE-ACTIONS`. **Extend that drive** to exercise an
in-memory MCP session end to end — `initialize` → `tools/list` → `tools/call` — inside the
interposer, proving the protocol layer opens nothing. Update the `ZeroNetworkTests`
post-condition **and its guard-the-guard** (four edits, per the house rule).

**Say in the doc comment what this does and does not prove:** it proves the *protocol layer*
reaches no network name. It proves nothing about a future stdio transport, which is **D2** and
is invisible to the interposer.

### Phase 5 — floor ratchet

## 4. Agent notes

- One commit per phase. Stage explicit paths only — never `git add -A` (recorded incident).
- Do **not** touch `AppBootstrap.swift`, `SessionMachine.swift`, `DictationPipeline.swift`
  (G5 pin), or `Scripts/test-with-floor.sh`.
- Do **not** implement `ActionProvider` here. If you find yourself needing `ActionInvocation`,
  **stop** — that is aspect 2 and it has an open design question attached.
- **Stop and report if** the transport prohibition lint fires, or if the protocol layer cannot
  be written without naming a process or a socket.
- An untrusted peer's data must never be able to trap: no force-unwraps, no `try!`, no array
  indexing without bounds, on anything that came off the wire.
