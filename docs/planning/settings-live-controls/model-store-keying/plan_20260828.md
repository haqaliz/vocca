## 2. The design decision this plan commits to

The interview chose "tier-specific `engineID` in the manifest". Implementing it literally would
break a stated invariant, so the plan expresses the same decision one level cleaner.

`ModelManifest.engineID` is documented as *"the store's directory key — `EngineIdentity.id` for
the engine this artifact belongs to"* (`ModelManifest.swift:130-131`), and
`EngineCandidate.id`'s own doc says *"the stable machine key the model store keys its directory
by"* (`EngineSelection.swift:42-43`). Both Whisper tiers belong to the **same**
`EngineCandidate.whisperTurbo`, whose `id` is `"whisper-large-v3-turbo"` — which is precisely why
they collide.

**Commitment:** storage is keyed by **tier**, not by engine. Introduce `EngineTier.storageID`:

| Tier | `storageID` | On-disk change |
|---|---|---|
| `.parakeetV3` | `parakeet-tdt-0.6b-v3` | **none** |
| `.whisperTurbo` | `whisper-large-v3-turbo` | **none** |
| `.whisperTurboQ5` | `whisper-large-v3-turbo-q5_0` | new directory (never populated — see Phase 0) |

Only the tier nobody can have on disk moves. `EngineCandidate.id` keeps its meaning for
*attribution*; the doc comments claiming it is the storage key are corrected in Phase 4, because
they are now wrong and a stale invariant is how this defect was born.

## 5. Testing strategy

- **Framework:** XCTest, matching `EngineSelectionConsumptionTests` and the rest of
  `Tests/HarnessTests/`. Doc comments on every test explaining the row, per house style.
- **No network, ever.** The store is driven over a **stub transport**; the zero-network invariant
  is a permanent release blocker. Nothing in this aspect downloads anything.
- **No real model.** Fixtures are synthetic files with computed digests, in a temp directory root
  (`ModelStore(rootURL:)` is injectable precisely for this).
- **Commands:** `swift test --filter ModelStoreTierKeyingTests` during the loop;
  `./Scripts/test-with-floor.sh` before every commit.
- **Manual verification:** none in this aspect. The Speech tab's smoke steps are aspect 6's.

## 6. Edge cases and safe failure

| Case | Required behaviour |
|---|---|
| A tier's directory holds every file but no `verified` marker | Reads **absent** — the marker is the commit record. Existing behaviour; pin it for the new per-tier query. |
| A `.part` file at any depth | Reads absent. Existing recursive scan; the per-tier query must inherit it, not re-implement it. |
| Removal of a tier that is not present | Succeeds silently — idempotent, no throw. |
| Removal while that tier's download is in flight | **Undecided here.** Document current behaviour with a test; the policy is aspect 4's M12. Do not invent one. |
| Disk usage on an unreadable directory | Answers `0` rather than throwing; a settings page must never fail to render because of a permissions quirk. |
| Two manifests collide in a future tier | The Phase 1 uniqueness guard fails CI at decode time — the point of spec R5. |

**Failure posture:** every failure here is a *storage* failure, and the product already has the
honest path for it — an absent or unverified model surfaces `.modelUnavailable` through
`EngineReadinessGate` **before the microphone opens**, so a press is refused with a notice rather
than recording into a void. Nothing in this aspect may weaken that.
