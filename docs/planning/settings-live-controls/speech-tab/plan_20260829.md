## 2. Decisions this plan commits to

**(a) M12 — download in flight.** The spec left this open; here is the policy:

| Interaction | Behaviour |
|---|---|
| Remove a tier whose download is in flight | **Cancel the download first, then remove.** The user said they do not want this model; refusing them is worse |
| Switch tier while a download is in flight | The download continues — it is that tier's model and it is still wanted |
| Switch engine while a download is in flight | The download continues, for the same reason |

Rationale for the cancel-then-remove ordering: aspect 1 measured what happens today when a
directory is deleted under a running transfer — the download fails with
`ModelDownloadError.transportFailed`, blaming the transport for something the app did. Cancelling
first means the failure is deliberate and correctly attributed.

**(b) Retire `DownloadWindow`.** `DownloadWindow.present` has **zero callers** and has had none
since C2 — confirmed by grep, and recorded in `CLAUDE.md` as an unshipped surface. With the Speech
tab embedding its own progress (the `OnboardingView` precedent), it will never gain one. Delete it,
or state in this plan's completion note why it survives. Dead UI is how a codebase acquires two
answers to one question.

**(c) The three-surface agreement (R6/M11) is a closed-set test, not three separate tests.** For
each in-between window, assert what the Speech tab, the menu bar and the pill each report **in one
test**, so a state that looks like working fails loudly. This is the repo's dominant bug class.

## 3. Phases

### Phase 1 — RED: the reducer and its state

**Files:** `Sources/VoccaUI/Speech/SpeechTabState.swift`, `SpeechTabReducer.swift` (new);
`Tests/HarnessTests/SpeechTabReducerTests.swift` (new).

Pure, headless, no view. State per row: engine, tier, install state, disk bytes, download progress.
Actions: snapshot loaded, selection chosen, download started/progress/committed/failed/cancelled,
removal requested/confirmed/completed/failed.

Tests: a row whose tier is present reads `installed`, absent reads `download`; **one Whisper tier
present never makes the other read `installed`** (aspect 1's fix, asserted at the UI level);
selection changes only on an explicit choose action (the never-auto-switch rule, inherited);
terminal download states do not move; a failed removal surfaces and does not clear the row.

**Commit:** `Add the Speech tab's reducer and its decision table`

### Phase 2 — RED: the copy, pinned

**Files:** `Sources/VoccaUI/Speech/SpeechTabCopy.swift`; `Tests/HarnessTests/SpeechTabCopyTests.swift`.

Pin byte-for-byte to `PRODUCT_SPEC.md:254-262` — the row labels, the two tradeoff sentences, the
`[ installed ]` / `[ download ]` affordances, and the management line. Follow `BadgeCopyTests` /
`AppsTabCopyTests`; where a spec phrase must deviate (sentence case on a button), derive it
programmatically from the spec phrase rather than hardcoding it twice.

**R7 — whisper's honest status.** Whisper has never transcribed anything
(`SMOKE_CHECKLIST.md` step 19 unexecuted; its tolerances seeded from Parakeet, not measured). The

**Commit:** `Pin the Speech tab's copy, including whisper's honest status`

### Phase 3 — RED: the three-surface agreement

**Files:** `Tests/HarnessTests/EngineStateAgreementTests.swift` (new); whatever projection the menu
bar and pill read.

One closed-set test per window: (a) model removed, selection unchanged; (b) selection changed and

tab says one thing and the menu bar another is the failure this pins.

**Commit:** `Pin that the Speech tab, menu bar and pill never disagree`

### Phase 4 — The page, and its bindings

## 5. Agent execution notes

- **The page is executed by nothing in CI** (window-server rule). The reducer, the copy and the
  agreement test are the tested half; the page's first execution is Phase 6's smoke step. Do not
  write a test that pretends to render it.
- **Checkpoint after Phase 3** — if the three surfaces cannot be asserted together without
  reaching into the view layer, the projection is wrong and that is a design question.
- **Do not weaken an existing test to make a new one pass.** If one contradicts this plan, stop and
  report: it may be pinning something this plan got wrong. That has already happened twice on this
  branch, and both times the existing test was right.
