# Implementation Plan — `cleanup-tab` (aspect 5 of `settings-live-controls`)

**Date:** 2026-08-29 · **Merge order:** last — the severable tail. Depends on aspect 2.

This aspect touches the one surface `ROADMAP.md` principle 2 says must survive an audit of the
actual code paths. A regression here is positioning-fatal (roadmap risk **R11**), not a UI bug.

## 1. The two defects, and the deferral this aspect was always meant to collect

**F3 — the tab reports a constant.** `AppBootstrap.swift:1050` passes
`cleanupSummary: { ("Built-in rules", nil) }`. A literal. A user on Ollama or BYOK sees **"Built-in
rules"** with no endpoint, while the widget's egress badge correctly shows the cloud marker.
`SettingsView.swift` calls the egress line *"the point of this tab … where they can check before it
ever does"* — and today that line can never appear.

**The choice is still a hand-edited file.** `SettingsCopy.cleanupNotEditable` says so.

**`CleanupConfigStore` is deliberately load-only, and named this aspect as its collector.** Its doc
comment (`CleanupConfigStore.swift:52-57`): *"There is no save path: the future settings surface
writes this same file … an untested-by-consumer save API would be pretend-fidelity."* So adding the
save path here is the design landing as intended, not a change of mind.

## 2. Phases

### Phase 1 — RED: the config store learns to write

**Files:** `Sources/VoccaText/Cleanup/CleanupConfigStore.swift`;
`Tests/HarnessTests/CleanupConfigStoreTests.swift`.

Atomic temp-write + `replaceItemAt`, the `FileSystemDictionaryStore` idiom. Tests: a written config
round-trips through `load()`; a failed write does not corrupt the existing file; the file stays
hand-editable (stable key order, readable formatting) because that is still a supported path.

**Commit:** `Give the cleanup config a save path, for the surface it was waiting for`

### Phase 2 — RED: the summary tells the truth (F3)

**Files:** `AppBootstrap.swift:1050`; `Tests/HarnessTests/CleanupSummaryTests.swift`.

The summary derives from the **resolved provider** — `identity` and `requiresNetwork`
(`CleanupProvider.swift:47,51`) — not a literal. Tests: a stubbed BYOK provider ⇒ the tab reports
its endpoint; rules ⇒ no endpoint. **This test fails today**, which is the point.

**Commit:** `Report the cleanup provider Vocca is actually using`

### Phase 3 — RED: the three rungs, pinned

**Files:** `Sources/VoccaUI/Cleanup/CleanupTabState.swift`, `CleanupTabCopy.swift`;
tests for both.

Pure reducer + copy pinned byte-for-byte to `PRODUCT_SPEC.md:264-274`, **including the ⚠️ line**.
Rung vocabulary from `CleanupProviderKind`; do not mint a second dialect.

**Commit:** `Add the Cleanup tab's reducer and its pinned copy`

### Phase 4 — RED: the confirmation the spec demands

**Files:** the reducer; `CleanupTabCopy`; tests.

`PRODUCT_SPEC.md:272`: *"Selecting the cloud rung shows a one-time confirmation naming exactly what
gets sent. Not a checkbox buried in a paragraph — a dialog the user has to read."*

Tests: selecting the cloud rung does **not** persist until confirmed; declining leaves the previous
choice **intact** (not "off", not "unset" — the value that was there); the dialog names what is
sent; and it is *one-time* — a persisted acknowledgement, so it does not nag, and re-selecting after
declining asks again.

**Commit:** `Require a read-it confirmation before text may leave the Mac`

### Phase 5 — The page, the probe, the floor

**Files:** `Sources/VoccaUI/Cleanup/CleanupSettingsPage.swift`; `SettingsView.swift` (replace the
read-only page); `SettingsCopy.cleanupNotEditable` (**delete — it becomes false**);
`SMOKE_CHECKLIST.md`; `Scripts/test-with-floor.sh`.

**The gate:** the zero-network probe stays green, `egress=none` unchanged for the default
configuration. Run it explicitly before committing. The egress badge stays non-dismissable — **no
test may relax it**.

**Commit:** `Make the Cleanup tab live, and retire the file-editing note`

## 3. Out of scope

Changing any provider, the chain's degrade behaviour, or the 5 s budget. Making the LLM budget
configurable (C6's N1, deliberately skipped). Any claim that LLM cleanup beats rules — unmeasured,
and `prd.md`'s "quality not implied" holds.

## 4. Edge cases and safe failure

| Case | Behaviour |
|---|---|
| Config written while the resolver has already resolved | Applies at the next resolve. **Say so in the UI** rather than implying immediacy |
| Cloud rung selected, confirmation declined | Previous choice intact; nothing written; no egress |
| BYOK selected with no key in the Keychain | Say so plainly; do not silently fall back to rules with a cloud label |
| Config file corrupt | Existing tolerant-decode behaviour: rules + loud log, file **not** rewritten |

## 5. Agent execution notes

- **The BYOK key stays in the Keychain.** The config file must never hold it. Assert that.
- **Do not weaken the zero-network test to accommodate a provider choice.** If it goes red, the
  design is wrong, not the test — it is a permanent release blocker.
- The page is executed by nothing in CI; reducer and copy are the tested half.
