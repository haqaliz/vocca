## Phase 2 — The bump, GREEN

- **Goal:** 0.1.0 → 0.2.0 in the three places; the guard turns green.
- **Files:**
  - `App/Info.plist` — `CFBundleShortVersionString` → `0.2.0`.
  - `Vocca.xcodeproj/project.pbxproj` — `MARKETING_VERSION = 0.1.0;` → `0.2.0;` at both
    sites (lines ~298, ~330). Keep the two in sync — the workflow's tag==bundle gate reads

- **Validation:** `./Scripts/test-with-floor.sh` green, floor 1756.
- **Commit:** `release-distribution: bump the bundle version to 0.2.0 (GREEN)`

## Phase 3 — PR, merge, pre-tag checkpoint

- **Goal:** the code lands on `master`.
- Push `feat/release-distribution/aliz`, open the PR (base `master`), CI green, merge.
- ⛔ **Checkpoint (founder):** before any tag push —
  1. **OQ1 — `vocca.dev` ownership.** If the founder does NOT own the domain, changing the
     bundle id is now-or-never (resets every user's TCC grant later; `runbook.md:296-300`).
     If the answer is "not owned and not changing", record the decision in the aspect record.
  2. **OQ3 — v0.2.0 confirmed.**

**Decision record (2026-09-03):** OQ1 answered — the founder does **not** own `vocca.dev`
and **chose to keep the frozen `dev.vocca.Vocca`** over switching to an owned-domain id
at the pre-tag checkpoint. Consequences accepted and recorded: the id implies a domain the
project does not own; a future change would reset every user's TCC grants. This is a
founder decision, not an oversight — re-surfaced in `record-and-sync`, never silently
re-decided. OQ3 confirmed: `v0.2.0`.
- The notes-heredoc fix (claims-and-record Phase 1) must be in the same merged tree BEFORE
  the tag — sequence the two PRs so the notes fix merges first.

## Phase 4 — Tag and run

- **Goal:** the first real-bundle release execution.
- `git tag v0.2.0 && git push origin v0.2.0` (from `master`). `release.yml` runs (~40-min
  timeout). ⛔ **Checkpoint:** record every step's outcome — run URL, DMG name, `SHA256SUMS`
  line, the packaging gate's symlink + `codesign --verify` output. If the workflow fails:
  the defect is fixed test-first in a new PR, re-merged, re-tagged — never a broken artifact
  ("a release that ends broken is retracted", PRD R1).
- **Validation:** the release page shows `Vocca-v0.2.0.dmg` + `SHA256SUMS.txt`; the notes
  carry the corrected claims; `gh release view v0.2.0` output recorded.

## Edge cases

- **Secrets absent:** if `APPLE_CERT_P12_BASE64` is not set in repo secrets, the workflow
  fails loudly at "Refuse to release unsigned" (`release.yml:128-132`) — that is by design;
  configure the secret (the existing Apple Development export, same pair deck uses) and
  re-tag. Recorded, not worked around.
- **Workflow defect:** any failure between suite and Release creation is a first-execution
  defect to fix test-first — the v0.1.0 precedent says expect the unexpected here.
- **Tag already exists:** `v0.2.0` must not exist; if the founder already tagged it, choose
  `v0.2.1` after checking the bundle state — record the deviation.

## Agent execution notes
