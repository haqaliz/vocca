## Testing strategy

- All new tests run headless in CI except the digest-verification row (env-gated).
- The zero-network invariant is the load-bearing guard: `configure` must never provision
  (a download there would fail the interposer run).
- The founder machine's real flows: (1) run `provision-kokoro-fixtures.sh` → commit the
  digests; (2) `VOCCA_RUN_REAL_SPEECH=1 VOCCA_KOKORO_MODEL_DIR=<extracted>` for the suite;
  (3) a full launch with `VOCCA_KOKORO_MODEL_DIR` unset — the app must not download at
  launch unless the store's marker is missing... note: at launch, `prepareSpeechModels`
  WILL download when the marker is absent — that is the designed behavior (the ASR
  pattern); the probe never calls it because the probe doesn't run `main()`.

## Environment & privacy

- `VOCCA_MODEL_DIR` (digest row), `VOCCA_RUN_REAL_SPEECH` + `VOCCA_KOKORO_MODEL_DIR`
  (suite, from engine-binding). Zero-egress default: the only network in the whole unit
  is the store's opt-in model download at launch when the marker is absent — the
  recorded ASR pattern; the port's own downloader never runs.

## Edge cases

- **Interrupted extraction:** the trio marker self-heals on the next launch run.
- **Single-flight slot:** TTS provisioning is sequenced after ASR preparation; a racing
  provision would silently skip — the sequencing is the guard, noted in the record.
- **Artifact layout drift:** if the tarball's real layout differs from the assumption
  (no `vocab_index.json`, different voice naming), the script's listing output decides;
  adjust the extractor's trio marker and the manifest accordingly — recorded, not
  assumed.
- **Engine unprovisioned:** first `speak` throws the mapped clean error (engine-binding's
  pin); the app has no speak surface this unit, so the failure cannot be user-visible.
