## 2. Implementation phases

### Phase 1: CI green with the binary target (verify, don't invent)

- **Goal:** the headless job builds the package with the whisper XCFramework and runs
  the full suite; env-gated real tests skip visibly; budget held.
- **Prerequisites:** bridge-integration (the binary target), fixture-harness (the
  skip-visible real tests).
- **Files:** `.github/workflows/ci.yml` (edit only if the job genuinely needs a
  change — e.g. resolution retry for the binary fetch; otherwise untouched and
  verified).
- **Validation:** push the branch; the headless job is green; the job log shows the
  `XCTSkip` for both real WER tests (asserted in the run, not assumed); local
  `Scripts/test-with-floor.sh` matches.
- **Commit message:** `Verify CI headless with the whisper binary target; real-engine tests skip visibly`

### Phase 2: Docs to the repo's honesty standard

- **Goal:** every doc claim about the whisper engine is backed by a merged artifact or
  a marked-provisional measurement; manual steps recorded where CI cannot reach.
- **Prerequisites:** whisper-engine, model-lifecycle (license record), fixture-harness
  (tolerances + RTF record).
- **Files:**
  - `docs/SMOKE_CHECKLIST.md` — add the whisper steps: real WER run
    (`VOCCA_MODEL_DIR`), the manual picker smoke, and the license-verification
    reference.
  - `docs/technical/ARCHITECTURE.md` — engine table + seam row (already amended in
    whisper-engine Phase 4; verify consistency here).
  - `README.md` — the ASR-second-engine row moves from "planned" to shipped wording
    ("whisper.cpp large-v3-turbo shipped — proves the seam"; no latency claims).
  - `CLAUDE.md` — status section records C3 as merged with the honest "what C3 is NOT"
    block (real-engine numbers env-gated; picker executed by nothing in CI; weights
    license verified on the record).
  - `docs/planning/local-asr/fixture-suite/ci-wiring-decision_20260809.md` — append
    the C3 entry: F1 verdict status for whisper real runs (unchanged decision:
    env-gated; upgrade path recorded, not decided).
- **Validation:** a doc-audit pass over the diff: no unmeasured latency/accuracy
  claims; every "shipped" claim traceable to a commit.
- **Commit message:** `Record the whisper engine in the smoke checklist, README, and project context`

### Phase 3: Floor ratchet + final green

- **Goal:** the suite floor after the merge ≥ the floor before (the repo's
  invariant); the branch is merge-ready.
- **Prerequisites:** all phases.
- **Files:** `CLAUDE.md` floor number updated if the count changed (it will — the new
  tests raise it); verify the floor guard in `test-with-floor.sh` passes.
- **Validation:** full local run + CI green; `git log` on the branch reads as the
  aspect sequence.
- **Commit message:** `Raise the suite floor with the whisper engine tests`

## 3. File-by-file build order

CI verification → SMOKE_CHECKLIST → ARCHITECTURE consistency → README → CLAUDE.md →
F1-decision doc append → floor ratchet.

## 4. Testing strategy

- This aspect is verification + docs: the test surface is the whole suite + the CI
  job itself.
- The skip-visible assertion is checked in the CI run output, not by a new test.

## 5. Environment & privacy

- No env vars, no network changes. The binary fetch happens at package resolution
  (build-time), not in the shipped app.

## 6. Edge cases & error handling

- Headless job times out with the new dependency → record the numbers and optimize
  (e.g. `swift test` filter ordering) at the checkpoint; never weaken any-warning-
  fails.
- The XCFramework fetch intermittently failing on a hosted runner → a
  `retry` on the SPM resolve step in the workflow is acceptable; changing the
  integration path is not (surface it instead).
- Docs drift (ARCHITECTURE vs code) → fix in this phase; the repo's rule is docs
  keep in sync as things ship.

## 7. Agent execution notes

- Checkpoint at Phase 1 (CI green + skip-visible proof) — the load-bearing check.
- Doc edits follow the existing files' voice and honesty standard; the agent must
  not add claims the artifacts don't support.
- The floor guard is a hard gate: if the floor check fails, find the count change —
  do not bypass the guard.
