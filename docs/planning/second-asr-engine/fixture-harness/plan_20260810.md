## 3. File-by-file build order

Runner extraction → runner contract tests → whisper WER test + tolerance record →
swap test → RTF record.

## 4. Testing strategy

- Headless: runner contract tests, swap test (stubs), Parakeet shell regression.
- Env-gated: both real WER tests (skip visibly in CI; founder machine runs them).
- Zero network throughout: stub transports only.

## 5. Environment & privacy

- `VOCCA_MODEL_DIR` is the only env var; never committed. No network in any test.
- The real run stays on the founder's machine (1.5 GiB artifact, GPU/Metal preferred —
  CPU fallback allowed but slow).

## 6. Edge cases & error handling

- Fixture missing golden / empty fixtures dir → runner fails loudly (existing
  `ASRFixtureSuite` errors) — never a green zero-result run.
- Whisper real-run failure → the per-fixture WER + transcript is printed so the
  re-baseline decision has data; the test failing is the correct outcome, not a
  silent skip.
- The two-hundred-ms substitution rule applies to both engines identically.

## 7. Agent execution notes

- The runner extraction must not change Parakeet's numbers or behavior — regression
  is a hard gate.
- Checkpoint after Phase 1 (Parakeet unchanged + runner contract green) and after
  Phase 3 (swap pinned) — both are review-worthy seams.
- Phases 2/4 real-run steps need the founder's machine; agents can land the env-gated
  code + skip-path without it.
