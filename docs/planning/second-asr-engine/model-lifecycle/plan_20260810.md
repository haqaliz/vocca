## 1. Project setup checklist

- The founder's machine must be able to download the GGUF artifacts (HF
  `ggerganov/whisper.cpp`): `ggml-large-v3-turbo.bin` (1.5 GiB) and
  `ggml-large-v3-turbo-q5_0.bin` (547 MiB). The manifests are committed; the artifacts
  are not.
- Tooling: `shasum -a 256`, `stat -f%z` (macOS), `jq` optional.

## 2. Implementation phases

### Phase 1: Generalize the provisioning script (RED first)

- **Goal:** `Scripts/provision-asr-fixtures.sh` handles both engines: Parakeet's
  multi-file SDK layout and whisper's single-file flat layout, via `--engine` and
  `--tier` arguments, keeping the Parakeet path byte-identical.
- **Prerequisites:** none.
- **Files:**
  - `Scripts/provision-asr-fixtures.sh` (edit) — add `--engine parakeet-tdt-0.6b-v3 |
    whisper-large-v3-turbo` and `--tier turbo | q5_0`; branch on engine for
    REQUIRED-files, `SDK_DIR`, and manifest shape (`sdkDirectory` present for
    Parakeet, absent for whisper — single file at `<version>/<file>`); emit the
    manifest JSON with real `sha256` + `byteCount`.
  - `Tests/HarnessTests/ProvisioningScriptTests.swift` — **RED first**: a test that
    runs the script's manifest-generation logic over a scratch dir with two tiny fake
    files and asserts the JSON shape (engineID, version, no sdkDirectory, matching
    digest/byteCount) — i.e. test the script's contract without downloading anything.
    (Follow the repo's pattern of testing scriptable logic — if the manifest
    generation is inside the bash script, extract the JSON generation into a
    testable helper invoked by the script, or assert on the script's emitted file.)
- **Validation:** the Parakeet path still produces the current manifest shape
  (regression); the whisper path produces the flat shape.
- **Commit message:** `Generalize provision-asr-fixtures to engine/tier, with the flat single-file whisper shape`

### Phase 2: The checked-in manifests (RED first)

- **Goal:** both whisper manifests committed with real digests — the founder runs the
  generalized script on the downloaded GGUFs and commits the output.
- **Prerequisites:** Phase 1; founder downloads the two GGUFs (founder-executed step,
  ~2 GiB total — a manual step; the script validates before committing).
- **Files:**
  - `Sources/VoccaASR/Models/Manifests/whisper-large-v3-turbo.json` —
    `engineID "whisper-large-v3-turbo"`, `version "1"`, one file
    `ggml-large-v3-turbo.bin` (real SHA-256/byteCount), **no `sdkDirectory`**.
  - `Sources/VoccaASR/Models/Manifests/whisper-large-v3-turbo-q5_0.json` — same,
    `ggml-large-v3-turbo-q5_0.bin`.
  - `Tests/HarnessTests/WhisperManifestTests.swift` — **RED first**:
    `ModelManifest.load` succeeds for both, round-trips, and the
    `ModelManifestTests` validation machinery passes (digest shape, safe path, no
    sdkDirectory → flat layout).
- **Validation:** `swift test --filter WhisperManifestTests`; the manifests are
  immutable once committed (version bump, never rewrite).
- **Commit message:** `Ship the whisper GGUF manifests: turbo and q5_0 tiers, verified digests`

### Phase 3: Store round-trip proof (RED first)

- **Goal:** a headless test proves the single-file manifest works through the shipped
  store over a stub transport.
- **Prerequisites:** Phase 2.
- **Files:**
  - `Tests/HarnessTests/WhisperStoreRoundTripTests.swift` — **RED first**: scratch
    store root; stub transport serving a small fake file with the manifest's digest;
    `downloadIfMissing` → verified marker → `isPresent` true; a `.part` remnant →
    `isPresent` false; digest mismatch → `checksumMismatch` retry behavior (the
    `ModelDownloaderTests` patterns).
- **Validation:** targeted filter; full suite green.
- **Commit message:** `Prove the single-file manifest round-trips the store over a stub transport`

### Phase 4: License verification (founder-signed, pre-merge)

- **Goal:** the weights' license verified from a primary source and recorded; whisper
  entries in `THIRD_PARTY_NOTICES.md` completed with the weights line.
- **Prerequisites:** none.
- **Files:**
  - `THIRD_PARTY_NOTICES.md` (edit) — whisper.cpp (MIT), ggml (MIT), and the GGUF
    weights entry with the verified license + source repo.
  - `docs/planning/second-asr-engine/model-lifecycle/license_20260810.md` — the
    verification record (what was checked, where, conclusion).
- **Validation:** founder confirms the record; the notice file is complete.
- **Commit message:** `Record the GGUF weights license verification and complete THIRD_PARTY_NOTICES`

## 3. File-by-file build order

Script generalization (Phase 1) → manifests (Phase 2, founder-run provisioning) →
store round-trip tests (Phase 3) → license record (Phase 4).

## 4. Testing strategy

- `ProvisioningScriptTests` (contract of the script's output shape),
  `WhisperManifestTests` (decode/validate/round-trip), `WhisperStoreRoundTripTests`
  (store semantics over stub transport) — all headless, all RED-first.
- No real 1.5 GiB artifact ever enters CI.

## 5. Environment & privacy

- The GGUF downloads happen on the founder's machine (provisioning step); nothing
  network-y runs in tests or in the app's default path (the store's download path is
  exercised only via the stub transport in tests; the real `DefaultModelTransport` is
  invoked at app runtime only when the user chooses the engine and the model is
  missing — an explicit user action, no egress of audio/text).

## 6. Edge cases & error handling

- Digest mismatch → refuse + restart (existing downloader behavior, re-pinned by the
  round-trip test).
- Manifest with wrong engineID → validation rejects (existing machinery).
- Founder machine lacks disk space (1.5 GiB) → script fails with a clear message
  before writing the manifest.
- Version immutability: re-provisioning a different artifact bumps `version`, never
  rewrites digests (`ci-wiring-decision_20260809.md:27-29`).

## 7. Agent execution notes

- Phase 2 and Phase 4 need the founder (downloads + license sign-off) — sequence them
  with the founder's availability; everything else is agent-executable.
- Do not commit a manifest with copied digests; only script-produced digests.
- Checkpoint after Phase 3 (store proof green) before the license phase.
