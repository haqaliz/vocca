# engine-picker — implementation plan (2026-08-10)

> Aspect: `docs/planning/second-asr-engine/engine-picker/spec.md` · PRD:
> `docs/planning/second-asr-engine/prd.md` (M8, S2). Executed by the agents team under
> strict TDD; every phase leaves the suite green. All decisions live in headless,
> tested code — the panel itself is executed by nothing in CI (window-server
> precedent).

## 1. Project setup checklist

- Core: `EngineSelection` is new surface in `VoccaCore` (no `Config/` exists yet —
  this is the first selection value; keep it a plain value type + pure functions, no
  persistence framework).
- UI: `VoccaUI` already ships `DownloadProgressView`, `DownloadState`,
  `StoreModelDownloadSession` (the C2 download surface) and the Failsafe panel — reuse
  them; do not build new download machinery.
- No settings window exists in the product yet — this aspect scaffolds the minimal
  panel hosting the Speech tab (see Open Questions in the spec; the reducer + selection
  ship regardless).

## 2. Implementation phases

### Phase 1: Core selection value + decision table (RED first)

- **Goal:** `EngineSelection` — candidates (seeded: Parakeet v3, Whisper turbo),
  per-engine tiers (whisper: turbo / q5_0), default (Parakeet), and pure mutation rules
  (tier scoped to its engine; no invalid combination representable).
- **Prerequisites:** none.
- **Files:**
  - `Sources/VoccaCore/EngineSelection.swift` — value types `EngineSelection`
    (engineID + tier), `EngineTier` (whisper: `.turbo`, `.turboQ5`), the candidate
    table (engineID, displayName, tier set, default tier), pure functions:
    `defaultSelection`, `validTiers(for:)`, `selecting(engine:tier:)` (rejects
    invalid pairings by construction — e.g. a switch over engine-scoped tier enums).
    All Sendable/Equatable; no I/O.
  - `Tests/HarnessTests/EngineSelectionTests.swift` — **RED first**, table-driven:
    default is Parakeet; each engine's tier set is exactly its own; changing engine
    resets tier to that engine's default; the (engine, tier) space is exhaustively
    valid (closed-set walk, the repo's table-test style).
- **Validation:** `swift test --filter EngineSelectionTests`; full suite green.
- **Commit message:** `Add the Core engine-selection value with its decision table`

### Phase 2: Picker state reducer (RED first)

- **Goal:** the headless state machine for the picker: selection change, tier change,
  download lifecycle (idle → downloading → committed/failed/cancelled via the
  `ModelDownloadSession` vocabulary), installed-state, and the never-auto-switch rule.
- **Prerequisites:** Phase 1.
- **Files:**
  - `Sources/VoccaUI/EnginePickerState.swift` — state + pure reducer
    (`EnginePickerAction` enum: selectEngine, selectTier, downloadStarted,
    downloadProgress, downloadCommitted, downloadFailed, downloadCancelled) — the
    `FailsafeState`/`DownloadState` pattern; the reducer takes `ModelDownloadSession`
    events and the store's `isPresent` answer (injected, not called).
  - `Tests/HarnessTests/EnginePickerStateReducerTests.swift` — **RED first**:
    decision table — a download event never changes selection; selecting the
    currently-installed engine stays committed; a failed download returns to the
    pre-download selection state without auto-switching; tier change during an active
    download is refused or queued (decide: refused — documented in the table).
- **Validation:** targeted filter; full suite green.
- **Commit message:** `Add the engine-picker state reducer with the never-auto-switch rule`

### Phase 3: The Speech-tab panel (thin shell, no decisions)

- **Goal:** the minimal settings panel: Speech tab with the two radio rows (exact
  `PRODUCT_SPEC.md:189-196` copy), per-engine installed state, whisper tier menu, and
  the download affordance wired to `StoreModelDownloadSession` + `DownloadProgressView`.
  The panel is a view over the tested reducer — translation only.
- **Prerequisites:** Phases 1–2; `model-lifecycle` manifests (installed state reads
  `ModelStore.isPresent`).
- **Files:**
  - `Sources/VoccaUI/EnginePickerView.swift` — SwiftUI panel: rows bound to reducer
    state; copy constants `enum EnginePickerCopy` (the exact PRODUCT_SPEC strings —
    the honest-tradeoff surface, tested).
  - `Sources/VoccaUI/EnginePickerView.swift` wiring: `StoreModelDownloadSession`
    started with the selected manifest; progress via `DownloadProgressView`.
  - `Tests/HarnessTests/EnginePickerCopyTests.swift` — **RED first**: the copy
    constants match `PRODUCT_SPEC.md:189-196` verbatim ("Parakeet v3 — Fastest. 25
    European languages." / "Whisper turbo — Slower, broader language coverage.") —
    the honesty contract, not just strings.
- **Validation:** the copy tests green; the view compiles under `swift build` (it
  runs nowhere in CI — that is the repo's precedent, recorded in SMOKE_CHECKLIST).
- **Commit message:** `Add the minimal Speech-tab engine picker over the tested reducer`

### Phase 4: Selection-reads-at-session-start test (RED first)

- **Goal:** switching engines requires no restart: a session begun after a selection
  change uses the new engine.
- **Prerequisites:** Phases 1–3.
- **Files:**
  - `Tests/HarnessTests/EngineSelectionConsumptionTests.swift` — **RED first**: a
    session-start shaped function takes the current `EngineSelection` and resolves it
    to an engine factory; the test asserts the resolved identity follows the
    selection value at session start (a mid-session change does not affect the
    running session — consistent with the never-auto-switch rule).
- **Validation:** targeted filter; full suite green.
- **Commit message:** `Pin that engine selection is read at session start, not on the fly`

## 3. File-by-file build order

`EngineSelection.swift` + tests → `EnginePickerState.swift` + reducer tests →
`EnginePickerView.swift` + copy tests → consumption test.

## 4. Testing strategy

- Headless: selection table, reducer table, copy contract, consumption — all in CI.
- The view itself is executed by nothing in CI (window-server precedent) — the
  SMOKE_CHECKLIST gains the manual step in `ci-wiring`.

## 5. Environment & privacy

- No network in tests; the download affordance runs only on real user action at
  runtime; `isLocal` engines only (no badge).

## 6. Edge cases & error handling

- Download fails → reducer returns to a pre-download state with the failure visible;
  selection unchanged (never auto-switch).
- Engine installed but tier missing → the tier menu shows the tier as unavailable
  (installed-state per manifest, not assumed).
- Selected engine's model missing at session start → the session path surfaces
  `modelUnavailable` (engine-side, already handled) — the picker's job is only to
  never hide the state.
