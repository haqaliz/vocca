## Testing strategy

All offline; the wiring round trip runs over a temp-directory store through the real bindings
closures and the real conditions fold; the menu row itself is window-server glue executed by
nothing in CI — the tested halves are the condition, the copy, the closure wiring, and the call
site (the kill-row test's precedent).

## Environment & privacy

No env vars; the app's real `conversation.json` is written only by real use; CI/tests use temp
directories. The `onChange` fold carries a count, never text. Zero network.

## Edge cases

Launch with an existing file → conditions true from the load; clear while a session is live
(menu path) → row disappears, next turn re-creates history; a failed store write (disk) → the
condition fold still reflects the in-memory count, conversation continues; settings window open
during a mutation → the page reflects the load-time snapshot (read-on-open, recorded).
