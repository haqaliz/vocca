## 1. The lint entry — the reviewed edit

`Tests/HarnessTests/ActionTransportProhibitionTests.swift` currently holds
`filesPermittedToNameATransport: Set<String> = []`.

It becomes **exactly one** entry: `VoccaActions/MCP/StdioMCPTransport.swift`.

The entry's comment must carry the **D2 answer** from the card, in short form:

> The child is **not** observable — a restricted child ignores `DYLD_INSERT_LIBRARIES` and
> purges `DYLD_*` from the environment it passes on. The claim is therefore not "we watch it"
> but "**the default configuration cannot create one**": no server is configured out of the box,
> so the probe never reaches a spawn, and a configured server is a trust the user extends to
> that server's author — stated in the docs, not implied away.

**If more than one file needs to name `Process`, STOP AND REPORT.** The spawn must be confined
to one file or the confinement means nothing.

The lint's three legs, the planted control and the comment-strip control all stay. Leg (b) —
every permitted file *does* name the family — stops being vacuous for the first time.

## 2. Phases

### Phase 1 — RED: the transport contract

**File:** `Tests/HarnessTests/StdioMCPTransportTests.swift`

RED against a type that does not exist is a compile failure — the established precedent.

1. `StdioMCPTransport` conforms to `MCPTransport`. **Second implementation ⇒ guardrail 7 met**
   for that seam; assert both conformances through the same parameterized body where possible.
2. `spawnsSubprocess == true` for stdio, `false` for `InMemoryMCPTransport`. The declaration is
   a *value*, not a comment.
3. **A real frame round-trips across a real child.** Use a child that is guaranteed present and
   scriptable — `/bin/cat` echoes stdin to stdout, which is enough to prove framing over a pipe
   without shipping a fixture server. Say in a comment why `/bin/cat` and not a shell.
4. **A child that exits mid-exchange yields a typed failure** — never a hang, never a trap.
5. **A child that never responds hits a bounded timeout.** Pin the bound in one place.
   `/bin/cat` with nothing written, or `/bin/sleep`, gives the unresponsive case.
6. **A flooding child is bounded** — no unbounded read. Assert the read stops.
7. **No orphan survives teardown**: after the transport is torn down the child is not running.
   Assert on the real pid, not on an internal flag.

### Phase 2 — GREEN

**File:** `Sources/VoccaActions/MCP/StdioMCPTransport.swift`

- The **only** file in the module naming `Process`.
- Bounded reads, a bounded timeout, explicit termination on teardown.
- **Untrusted-peer discipline**: everything off the pipe is hostile — no force-unwraps, no
  `try!`, nothing indexed unchecked. A child is a *less* trustworthy peer than the in-memory
  transport, not more.
- The doc comment carries the D2 answer and the narrowed claim.

## 4. Agent notes

- **Stop and report if** more than one file needs `Process`, or if the default configuration
  turns out to be able to spawn (that would break the whole D2 answer and is a design failure,
  not a test to adjust).
- Prefer `/bin/cat`, `/bin/sleep` and similar guaranteed-present binaries over writing a fixture
  server. Note in a comment: these are Apple platform binaries and therefore **blind** to the
  interposer — which is the very fact D2 records, demonstrated by the test suite itself.
- The timeout must be **injected**, not wall-clock-hardcoded, so the test suite does not sleep.
  Follow the repo's injected-clock precedent.
