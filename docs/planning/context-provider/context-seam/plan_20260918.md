## Design decisions (pinned — do not re-decide)

- **D1 — Where the seam lives.** Three new files under `Sources/VoccaCore/Context/`, the
  capability-directory convention (`Mode/`, `Reply/`, `VoiceDetection/`). The protocol lives in the
  core with every other seam (`ARCHITECTURE.md:75`); `VoccaContext/` (`ARCHITECTURE.md:151`) is the
  *adapter module* reservation, claimed by `accessibility-context`, never by this aspect.
- **D2 — Synchronous, non-throwing, plain-data handoff.** `func resolveCurrent() -> ContextSnapshot`
  — synchronous and non-throwing (R1: the adapter "returns an empty snapshot rather than throwing
  on failure", `prd.md:168-170`; "never throws" is a compile property of the signature, and a
  runtime property of `NullContext`). Reads happen at turn start, off the key-release →
  text-on-screen critical path (`prd.md:149-151`); `AccessibilityContext`'s timing (its own serial
  queue, 0.5 s per-call timeout) is that aspect's, and if it forces an async leg that is a
  signature reconsideration for `accessibility-context`, recorded rather than added now (the
  frozen-signature doctrine). No identity, no provider name: a snapshot is consumed immediately.
- **D3 — The vocabulary is three optional fields, distinct nil-vs-empty.** `ContextSnapshot` has
  `bundleID: String?`, `windowTitle: String?`, `selectedText: String?`, public memberwise init,
  `Sendable, Equatable` — the `TargetContext` shape. `nil` = absent (nothing focused / no title /
  no selection — the `NullContext` case); `""` = present-but-empty (a window with no title). Both
  are pinned by tests so the later adapter's semantics cannot blur them. No `ContextSnapshot`
  helpers: the vocabulary is built by hand in tests (`TargetContext` precedent) and no minting row
  is needed — "snapshots are ephemeral" is a life-cycle property of the wiring, not a construction
  property, and unlike `ModeSession` there is no reset-carryover invariant to make structural.
- **D4 — The seam-family lint is the `ReplySeamBoundaryTests` per-family table over
  `VoccaCore`.** Scan root `VoccaCore`, three families: `ContextProvider` → the protocol file +
  the conforming implementation; `ContextSnapshot` → the vocabulary file + the protocol's
  signature + `NullContext`'s construction; `NullContext` → exactly its own file. A second file
  branching on the shipped default is caught. No `AccessibilityContext` row — the name does not
  exist yet and will land in a different module; the doc records that obligation. No constructor
  row (see D3).
- **D5 — The doc amendment to `ARCHITECTURE.md` is conditional (Phase 4), default: none.**
  The seam table row at `ARCHITECTURE.md:281` already names `ContextProvider` →
  `AccessibilityContext`, `NullContext`, "No — by design"; the layout already reserves
  `VoccaContext/` (:151). The §3 `VoccaCore/` listing enumerates only a few directories and does
  not claim to be exhaustive (no `Reply/`, `Speech/`, `VoiceDetection/` either). This aspect's
  decisions contradict none of it — so no amendment ships here. Only if a Phase 2 review finds a
  contradiction does Phase 4 run (a one-line doc edit in its own commit).

## Phase 2 — GREEN: the vocabulary and the implementation

**Goal.** The three production files under `Sources/VoccaCore/Context/` make every Phase-1 test
green. The signatures pinned here are the contract `accessibility-context` (the adapter) and
`bootstrap-wiring` (the composition) compile against — final after this phase.

**Files:**

1. `Sources/VoccaCore/Context/ContextSnapshot.swift` — the plain-data vocabulary, the
   `TargetContext` shape exactly:
   `public struct ContextSnapshot: Sendable, Equatable { public let bundleID: String?; public let windowTitle: String?; public let selectedText: String?; public init(bundleID: String?, windowTitle: String?, selectedText: String?) }`.
   Doc pins each field's nil meaning (`nil` = absent; `""` = present-but-empty), the ephemeral
   life-cycle (`prd.md:119-121` — never persisted beyond the turn, never in a BYOK payload without
   the separate grant), and that the vocabulary is built by hand in tests.
2. `Sources/VoccaCore/Context/ContextProvider.swift` — the seam:
   `public protocol ContextProvider: Sendable { func resolveCurrent() -> ContextSnapshot }`.
   Doc pins: the pluggable boundary (`ARCHITECTURE.md:281`, `CAPABILITY_ROADMAP.md:416` — local
   only, **no hosted counterpart by design**); synchronous and non-throwing (R1 — failure resolves
   to an empty snapshot, never throws); reads happen at turn start off the latency path; the two
   implementations at ship (``NullContext`` here, ``AccessibilityContext`` in `accessibility-context`'s
   new `VoccaContext` module — the seam doctrine met, not exempted, `CAPABILITY_ROADMAP.md:432`);
   the privacy contract (consent gate, indicator, kill switch are the later aspects' — the seam
   itself carries no consent and no state).
3. `Sources/VoccaCore/Context/NullContext.swift` — the shipped default, the
   `EchoReplyGenerator.swift` shape:
   `public struct NullContext: ContextProvider { public init() {} public func resolveCurrent() -> ContextSnapshot { ContextSnapshot(bundleID: nil, windowTitle: nil, selectedText: nil) } }`.
   Doc pins the honesty posture: reads nothing, deterministic by construction (the constant
   function), stdlib-only, zero-network; the honest shipped default until the consent gate is on
   (`prd.md:72-75`).

**Also in this phase:** none — no doc amendment, no other file. `ARCHITECTURE.md` already matches
D1–D3 (Phase 4 is conditional).

**Why these signature choices (pin the reasoning in the seam doc comments):**

- **`resolveCurrent()` — one requirement, synchronous, no provider identity.** The seam is the
  plainest possible boundary: the caller asks for the current snapshot and gets it. No
  `prepare()`, no `supportsStreaming`-style capability flag, no identity — a snapshot is consumed
  immediately and discarded; nothing downstream attributes it.
- **Optional fields, never a sentinel.** `nil` answers "there is no such thing right now"; an
  empty string answers "there is such a thing, and it is empty". `NullContext` returns the first,
  and the later adapter returns whichever is honest (a window with no title, a collapsed
  selection).
- **The empty snapshot is the failure value, not a throw.** R1 (`prd.md:166-170`) is expressed in
  the type system: a seam that never throws cannot be caught mid-turn, and the `NullContext`-style
  honesty the PRD names is the empty snapshot. `AccessibilityContext` inherits this posture
  structurally — the later adapter cannot invent a throwing shape without a reviewed signature
  change here.
- **`Sendable` by construction, never `@unchecked`.** Plain data with three `String?` fields and a
  protocol whose only requirement returns it — the conformance is automatic. The house aversion to
  `@unchecked Sendable` is structural, not stylistic (`ReplySeamTests.swift:47-50`).

**Validation.** `swift test --filter ContextSeamTests` GREEN; `swift build --build-tests -Xswiftc -strict-concurrency=complete`
clean; `swift test --filter CoreBoundaryTests` still GREEN (the new files import nothing);
`git diff --stat HEAD` shows only the Phase-1 test file and the three production files.

**Commit message.** `context-seam: the ContextProvider seam, the ContextSnapshot vocabulary, and the NullContext default (test-first)`

## Testing strategy

**The seam contract** — one suite, the `ReplySeamTests` shape: the seam is a `Sendable` protocol
with exactly one requirement (`resolveCurrent() -> ContextSnapshot`, synchronous, non-throwing);
`NullContext` resolves to the all-nil snapshot, is deterministic across calls, never throws, takes
no input; callers speak the protocol through the existential (a `FixedContextProvider` drives it,
never naming the default at a decision point).

**The vocabulary** — three optional fields with nil-vs-empty semantics pinned by equality; the
memberwise init is public and read-back-tested (a missing adapter read cannot hide behind a
default).

**The family lint** — per-family confinement over `VoccaCore`, the three non-vacuous guards, the
planted-violation controls for all three names, and the comment-strip control. A future file in
`VoccaCore` that branches on `NullContext` or reaches for `ContextProvider` fails the lint; the
`accessibility-context` and `bootstrap-wiring` files are outside the scan root by construction.

**Lint controls**: planted uses of all three family names, the comment-strip control, and the
non-vacuous guards (empty permitted set fails; each permitted file must name its family;
`sightings.count == permitted.count`).

## Environment & privacy

- Pure local, zero network: the new code is stdlib-only in a module that imports nothing (the
  empty `CoreBoundaryTests` allow-list). No `Foundation`, no AX, no `URLSession`, no model bytes,
  no C2-store interaction. The zero-network interposer suite covers the whole package and stays
  green.
- No user-visible surface: the seam is machinery only — the consent store, indicator, and kill
  switch are the other aspects'. `NullContext` is the honest shipped default: it reads nothing
  until the consent gate's aspect wires a real provider.
- No content ever reaches a network path from this aspect: the BYOK payload exclusion is
  `byok-context-grant`'s, and this aspect's vocabulary is never persisted (M10).

## Edge cases

- **Empty vs absent fields** → `nil` is absent (the `NullContext` case), `""` is present-but-empty
  (a titleless window); pinned distinct by `Equatable`. The later adapter returns whichever is
  honest; the seam's consumers must not conflate them.
- **Sendable under Swift 6 strict concurrency** → plain data, automatic conformance, no
  `@unchecked`; pinned by `requireSendable` in Phase 1 and by the `-strict-concurrency=complete`
  build at the end of Phase 2 and Phase 3.
- **The lint's comment-strip controls** → `SwiftSourceScanner.stripComments` runs before the scan,
  so the seam's own docs may name the confined family to explain what is confined — and the
  planted-violation tests prove the detector still catches a *type in code*.
- **"Reads nothing" honesty** → observable half: determinism + no-input signature (Phase 1);
  structural half: the empty `CoreBoundaryTests` allow-list keeps any AX surface out of the module
  this file lives in. No separate "reads nothing" lint row is needed at this aspect's scale — the
  content-read boundary is `consent-store`'s and `accessibility-context`'s to define.
- **A caller that names `NullContext` at a decision point** → the protocol-only caller test is the
  behavior pin; the lint's `NullContext` row is the structural half.
- **The floor arithmetic** → the ratchet constant is at `:1770`, not the `:1763` the `dual-mode`
  plan cited; re-read it before editing. Skips count as executed (the script's own note,
  `test-with-floor.sh:1758-1760`).
