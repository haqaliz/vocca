## What this aspect ships and what it deliberately does not

Ships: the **persisted global grant** — the `settings.contextGrantEnabled` frozen key
(`UserDefaultsSettingsStore`), the `PersistedSettings` three-answer encode/decode ("enabled" /
"disabled"; absent → `false` silently, unreadable → `false` loudly — the safe direction, never a
spent grant the user never gave), the `SettingsStore` seam's two new methods and the test-double
compile-fixes; the **grant-gated payload field** in `BYOKCleanupProvider` — the new defaulted
`grantedContext:` init parameter (nil = today's byte-identical shape), the `RequestBody.context`
leg, and the `ContextPayload` vocabulary ({bundleID, windowTitle, selectedText}, optional fields
mirroring the snapshot's nil-vs-empty semantics); the **`GrantedContextSource` seam** in
`VoccaCore/Context/` — the per-turn source of already-gated snapshots the wiring implements and
the provider consumes; the **`ContextGrantGate`** — the pure AND-gate (consent ∧ grant) plus the
≤4 KB selected-text bound (4096 UTF-8 bytes, valid-prefix truncation), stdlib-only in
`VoccaCore/Context/`; the **never-in-payload acceptance** (no grant → the body's key-set is
exactly `{model, messages}`, system prompt byte-pinned as today); the **key-never-in-logs**
extension of the B8 sweep (granted context text rides the wire in the body and appears in no
error description); the **Ollama never-carries-context pin** (local egress is not egress,
`prd.md:209-211`); the Settings toggle near the BYOK config / egress badge (Cleanup tab, the
`CleanupTabCopy` pins + defaulted `SettingsBindings` closures); the **context-seam lint row
amendment** (the two new `VoccaCore/Context/` files name `ContextSnapshot` — a reviewed
permitted-row edit, the `context-seam` plan's own anticipated record); and the floor ratchet.

Does NOT touch: the consent store (`consent-store`'s — this aspect's gate takes the consent fact
as a `Bool` parameter; nothing here reads or stores consent), the widget (no badge surface — that
is `widget-indicator`'s), `AppBootstrap.swift` (G5-pinned — the wiring that composes the source
from consent store × grant × `ContextProvider` is `bootstrap-wiring`'s; this aspect builds the
provider-side capability + the persisted grant + the gate, driven by stubs), the pinned dictate

## Vetted facts (recorded — do not re-research)

- **The BYOK payload is built in exactly one place** (`Sources/VoccaText/LLM/BYOKCleanupProvider.swift:90-129`):
  `clean(_:context:)` reads the key (absent ⇒ `keyUnavailable`, no request — B4), builds
  `RequestBody {model, messages}` (:133-136), encodes, posts, parses `choices[0].message.content`.
  The body test (`BYOKCleanupProviderTests.swift:91-123`) decodes the JSON and asserts keys/values
  — `messages[0].content == CleanupPrompts.byokSystem` (the byte-pinned prompt, B5) and
  `messages[1].content == transcript` verbatim. `JSONEncoder` synthesizes `CodingKeys` in
  declaration order and omits `nil` optionals — so an optional `context` field declared **last**
  leaves the absent-grant body byte-identical to today's. The B8 key-hygiene sweep
  (`:364-435`) asserts the sentinel key rides the wire in the `Authorization` header and appears
  in **no** error description across the closed failure set.
- **Per-turn context cannot ride `CleanupContext`** — and that is the load-bearing constraint.
  `CleanupContext` (`Sources/VoccaCore/CleanupContext.swift:35-57`) is plain memberwise with no
  defaults, constructed at its only sites in `DictationPipeline.swift:442,468-470` — a digest-
  pinned file, byte-for-byte (`TurnTakingComposedAcceptanceTests.swift:317-347`; the C11 contract:
  re-anchors recorded, never an edit-to-match). A new context field could only ever be `nil` on
  the dictate path (the pinned pipeline cannot fill it), so the field would be dead. **The only
  route that respects the pin is provider-side**: the provider holds a per-turn source, injected
  at construction (resolve-once in the resolver — `CleanupResolver.build`, `CleanupResolver.swift:239-243`,
  which is **not** pinned) and asked per `clean()` call.
- **The provider is a dumb adapter by the seam's own contract** (`CleanupProvider.swift:39-41`:
  "The context is the caller's, not the provider's … a conformer reads it and must not reinterpret
  it") — so the AND-gate is the caller's decision, never the provider's (D2).
- **The seam doctrine** (`ARCHITECTURE.md:82-84`): `VoccaCore` owns every seam; `VoccaText`
  imports only `VoccaCore` (`ARCHITECTURE.md:84-86`), so the granted-context seam the provider
  types against must live in `VoccaCore`.
- **The context-seam lint anticipates this amendment** (`context-seam/plan_20260918.md:282-286`):
  the `ContextSnapshot` family's permitted set is `{Context/ContextSnapshot.swift,
  Context/ContextProvider.swift, Context/NullContext.swift}` with `sightings.count ==
  permitted.count` — "Only a future file *inside `VoccaCore`* naming a family requires a reviewed
  row edit". This aspect's two new `VoccaCore/Context/` files are exactly that future file; the
  row edit is reviewed and lands in the same commit as the gate (Phase 3).
- **`ContextSnapshot` is three optional fields** (`context-seam` D3, `plan_20260918.md:210`):
  `{bundleID: String?, windowTitle: String?, selectedText: String?}`, `Sendable, Equatable`,
  nil-vs-empty pinned distinct. `VoccaCore` imports nothing (`CoreBoundaryTests.swift:98-116`) —
  the gate and the seam must be stdlib-only.
- **The three-answer settings contract** (`PersistedSettings.swift:88`, `:185-226` — the
  keep-in-tray pair is the toggle-shaped precedent): string spellings, absent → default silently,
  unreadable → default **loudly** through the injectable log, safe direction argued per setting.
  The cloud-acknowledgement direction is the grant's precedent (`:149-163`): unreadable → `false`
  loudly, because "degrading a corrupted preferences entry to `true` would spend an agreement the
  user never gave". `UserDefaultsSettingsStore` freezes each key as a literal pinned by test
  (`UserDefaultsSettingsStore.swift:62-99`) and routes present-non-strings through the sentinel
  (`:222-231`) so they take the loud path.
- **`SettingsStore` conformers** (`Sources/VoccaCore/SettingsStore.swift:43-79`): the shipped
  `UserDefaultsSettingsStore` plus the test doubles — `EphemeralSettingsStore`
  (`ActivationPersistenceTests.swift:220`) and `AgreementSettingsStore`
  (`EngineStateAgreementTests.swift:374`). A protocol addition breaks all three; the doubles'
  compile-fixes land in the same GREEN commit as the protocol change.
- **Ollama is local egress, and the grant governs only the cloud provider** (`prd.md:209-211`:
  "Context in Ollama (local LLM) payloads — local egress is not egress; the grant governs the BYOK
  cloud provider only"). `OllamaCleanupProvider`'s body is `{model, prompt, stream}` — no
  messages/context shape at all; untouched, and pinned by an additive test.
- **`ContextSnapshot`'s plain-data constraints**: the bound's truncation is UTF-8-byte arithmetic
  on a `String` — stdlib-only (`String.utf8`, prefix slicing at a scalar boundary), no
  `Foundation`, no `Data`, no `NSString`.
- **Floor mechanics** (`Scripts/test-with-floor.sh:1770,1795-1801`): `swift test` exits 0 when it
  discovers nothing; the floor is the guard. Filters are for RED/GREEN loops only.

## Design decisions (pinned — do not re-decide)

- **D1 — The per-turn route is provider-side, because the pipeline is pinned.** A context field
  on `CleanupContext` would be dead (the pinned `DictationPipeline` constructs the context and
  cannot fill it) — so `BYOKCleanupProvider` gains `grantedContext: (any GrantedContextSource)? = nil`
  on the init: `nil` (the shipped default) means today's behavior byte-for-byte; set, the
  provider asks the source per `clean()` call and appends the granted context to the payload.
  The `CleanupResolver` construction site compiles unchanged; `bootstrap-wiring` fills the
  parameter (recorded handoff).
- **D2 — The AND-gate is caller-side; the provider is consent-agnostic AND grant-agnostic.**
  Two options were weighed: (a) the wiring passes an already-gated snapshot per call, or (b) the
  provider checks a gated seam itself. Decision: **(a), via the `GrantedContextSource` seam** —
  `public protocol GrantedContextSource: Sendable { func grantedSnapshot() async -> ContextSnapshot? }`
  in `VoccaCore/Context/GrantedContextSource.swift`. The source returns **only already-gated**
  snapshots (`nil` unless the AND-gate holds); the provider's only decision is "is there a granted
  snapshot for this turn?" Justification: (1) the seam's own contract — the caller owns context
  decisions, the provider must not reinterpret (`CleanupProvider.swift:39-41`); (2) option (b)
  would force `BYOKCleanupProvider` to evaluate per-app consent, which lives in a module it may
  not import (`VoccaContext`'s store) — it cannot be done honestly in `VoccaText`; (3) the gate
  stays a pure, headless-tested function and the provider stays a dumb adapter, each testable with
  stubs. The gate itself — `ContextGrantGate.granted(snapshot:consentActive:grantEnabled:)` in
  `VoccaCore/Context/ContextGrantGate.swift` — returns the bounded snapshot iff
  `consentActive && grantEnabled && snapshot != nil`, else `nil`. The wiring's composed source
  (consent store read × grant read × `ContextProvider.resolveCurrent()` × the gate) is
  `bootstrap-wiring`'s, recorded as a handoff.
- **D3 — The source is total.** `grantedSnapshot()` never throws: any failure inside the wiring's
  composed source degrades to `nil` — the R1 doctrine (`prd.md:170`: "best-effort … returns an
  empty snapshot rather than throwing on failure"). The provider never throws for context, and a
  context-read failure can never block a dictation (context is enrichment, not load-bearing) and
  never fails open into sending context.
- **D4 — The gate owns the ≤4 KB bound, in exactly one place.** `ContextGrantGate.maxSelectedTextBytes = 4096`:
  `selectedText` is truncated to the largest UTF-8 prefix ≤ 4096 **bytes** (a character count
  would overflow the bound on multibyte text; the truncation never splits a scalar — valid-UTF-8
  prefix). Applied by the gate, so the source's snapshot is already bounded when it reaches the
  provider; the provider trusts the typed seam (one place for the rule — the house convention).
- **D5 — The payload field.** `RequestBody` gains `context: ContextPayload?` declared **last**
  (`model`, `messages`, `context` — the encoder omits `nil` optionals, so the absent-grant body is
  byte-identical to today's). `ContextPayload` mirrors the snapshot's nil-vs-empty semantics:
  `{bundleID: String?, windowTitle: String?, selectedText: String?}` — absent subfields omitted by
  the encoder, never coerced to `""` (the `context-seam` D3 discipline preserved on the wire). The
  shape pin: grant absent → the decoded body's key-set is exactly `{model, messages}` and the
  messages content is untouched; grant present → key-set exactly `{model, messages, context}` with
  the three subfields.
- **D6 — The key path is untouched and first.** The key read stays the first act of `clean()`:
  key absent → `keyUnavailable`, zero requests, and the source is **never asked** (B4 unchanged —
  context must not precede or shadow the key path). The granted-context leg runs only after the
  key exists.
- **D7 — The persisted grant.** New frozen key `settings.contextGrantEnabled` (literal pinned by
  test); spellings `"enabled"` / `"disabled"` (the keep-in-tray toggle-family spelling); decode:
  absent → `false` silently (a fresh install has granted nothing), unreadable → `false` loudly
  through the injectable log (the cloud-acknowledgement direction — never spend a grant the user
  never gave). `SettingsStore` gains `contextGrantEnabled() -> Bool` /
  `setContextGrantEnabled(_ enabled: Bool)`; `UserDefaultsSettingsStore` implements them; the test
  doubles gain the two methods in the same commit. The Cleanup tab's toggle sits in a new section
  beside the egress summary (the "Using"/"Text leaves this Mac" block,
  `CleanupSettingsPage.swift:51-78` — M7's "surfaced near the BYOK config / egress badge"), with
  `CleanupTabCopy` strings pinned by `CleanupTabCopyTests`, and `SettingsBindings` gaining
  `isContextGrantEnabled: () -> Bool = { false }` / `setContextGrantEnabled: (Bool) -> Void = { _ in }`
  (the "defaults claim nothing" doctrine, `SettingsView.swift:192-193`). The bindings' wiring to
  the store is `bootstrap-wiring`'s.
- **D8 — Key hygiene extends to the context text.** The B8 sweep's shape, applied to the granted
  path: the granted context (and the sentinel key) appear in the wire body — the one place each
  may be — and in **no** error description across the closed failure set. The provider adds no log
  line for context (it logs nothing today; the loudness of the settings read lives in
  `PersistedSettings`'s injected log, which never sees the snapshot).

## Edge cases

- **Key absent with the grant on** → `keyUnavailable`, zero requests, source never asked (D6,
  tested) — context can neither precede the key path nor mask a missing key.
- **Malformed grant value** → the sentinel path (`presentButNotAString`) and unknown spellings
  both read `false` **loudly** (tested) — never silently "on", never silently "off".
- **Budget overflow** → > 4 KB selected text truncates at the byte boundary without splitting a
  scalar (tested with multibyte content); exactly-at-bound and under-bound pass untouched;
  `""` stays present — nil-vs-empty preserved on the wire.
- **Payload shape stability** → the absent-grant body's key-set is exactly `{model, messages}`
  (byte-identical by construction — the optional is declared last and the encoder omits nils) and
  the messages content is untouched (the B5 system-prompt pin still holds verbatim); a future
  field addition must be declared after `context` or the key-set pins fail.
- **Source failure** → total seam: any failure inside the wiring's composed source degrades to
  `nil` (D3); the provider never throws for context and never fails open into sending context.
- **Ollama interplay** → untouched, pinned by test: local egress is not egress; the grant governs
