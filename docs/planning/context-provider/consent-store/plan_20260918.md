## Vetted facts (recorded — do not re-research)

- **The store shape to mirror** (`PersistentInjectionStrategyStore.swift`): a versioned
  top-level container (`{"version":1,...}`, `:155-158`), `JSONEncoder` with `.sortedKeys` for
  byte-stable encodes (`:165-169`), `JSONSerialization` for the top level then **one
  `JSONDecoder` per element** so one bad entry skips rather than costing the file (`:179-213`),
  three whole-file tolerance gates each emitting exactly one line through the **injected**
  log (`:130-133`), `load()` never throws and never rewrites (`:220-230`), the atomic
  temp-write → `replaceItemAt` commit (`:255-265`; `moveItem` refuses an existing destination —
  the hard-won comment at `:61-67`), a cap of 512 apps (`InjectionStrategyStore.swift:65-67`)
  with **refusal, never eviction** (`:237-246`), and an actor over an injected
  `…FileSystem` protocol + injected log (`:110-138`).
- **The byte-level pin precedent** (`PersistentUsageStoreTests.swift:390-425`): encode a
  window folded from sessions carrying a distinctive phrase, assert on the bytes — the phrase
  absent, no `[0-9]:[0-9]` time-of-day, no ISO `T` marker, no `Z` suffix, no 10-digit epoch —
  with vacuity guards (non-empty days, real sessions) and the honest "what each half is worth"
  note. The store's doc states the same promise the test asserts (`PersistentUsageStore.swift`
  "no transcript, no wall-clock time").
- **The FileManager family is per-seam within a module** (`InjectionSeamBoundaryTests.swift:1140-1197`):
  the table `filesPermittedToNameFileManagerIdentifiersBySeam` (`:1171-1177`) is keyed by seam
  and the module-root table (`:1185-1191`) resolves each seam to its module; the scan walks
  each module and permits only that module's seam files (`:1250-1278`). The exact-set pin
  `testTheFileManagerSeamTableNamesExactlyTheFiveShippedSeams` (`:1321-1327`) asserts the keys
  are exactly `{journal, dictionary, config, strategy, usage}` and the usage-store aspect
  already widened it once (`:1314-1320`). This aspect widens it **five → six** and renames the
  test, in the same commit as the first `VoccaContext` file that names `FileManager`.
- **Why the store lives in `VoccaContext`** (`ModuleBoundaryTests.swift:106-113`, the
  `VoccaUsage` rationale verbatim): `VoccaCore` imports nothing (so it cannot name
  `FileManager`), `VoccaInject` is the injection module (its FileManager rows are the journal
  and strategy seams), and a UI module owning persistence inverts the layering. The consent
  store is part of the context surface, so it lives in the module the PRD reserves for it

- **The never-read precedent** (`AccessibilityRungStrategy.swift:99-104`): the rung declines an

  read-then-discard path here." The gate is the same shape, one level up.
- **The content-read boundary** (M5, `prd.md:86-91`): `AXSource.focusedApp()` (`:85-94`) and

## Design decisions (pinned — do not re-decide)

- **D1 — The store's home is `VoccaContext/Consent/PersistentConsentStore.swift`** (one file,
  which is also the module's one `FileManager`-naming file, carrying the `DefaultConsentFileSystem`
  conformance beside the actor — the `PersistentInjectionStrategyStore`/`PersistentUsageStore`
  shape). The PRD's M3/M4 reading is confirmed by the FileManager family's per-module rule; no
  move is proposed and none should be improvised.
- **D2 — The seam is `Sources/VoccaCore/Consent/ConsentStore.swift`**: `ConsentStore` (the
  protocol: `load() async -> Set<String>`, `set(_ bundleID: String, consented: Bool) async
  throws -> Bool`, `save(_ ids: Set<String>) async throws`), `ConsentStoreConstants.maximumConsentedApps = 512`,
  and `ConsentBundleID` (the validation: a pure, stdlib-only predicate). No `Foundation`.
- **D3 — The file is `context-consent.json`**: `{"version": 1, "consent": ["<bundle ID>", …]}`,
  `.sortedKeys` bytes, atomic temp-write → `replaceItemAt`, tolerant per-entry decode with
  bundle-ID validation (invalid entry skipped with one loud log), load never rewrites, cap
  refusal-not-eviction, `save` uncapped (the user-owned wholesale path — the future Apps-tab
  edit; the strategies precedent `:107-109`).
- **D4 — The bundle-ID validation is what makes the pin honest.** `ConsentBundleID.isValid`:
  a reverse-DNS shape (at least one dot, no whitespace/control characters, ≤255 chars — the
  `injection-matrix.sh` bundle-column discipline at `:324-335`). Write-side: `set` refuses an
  invalid entry (returns `false`, persists nothing, one loud log). Read-side: an invalid
  entry in a hand-edited file is skipped with one loud log. The only strings the vocabulary
  can hold are bundle-ID-shaped, which is the privacy claim in type form.
- **D5 — The gate is `ContextConsentGate.allows(bundleID:)`** — nil → false, invalid → false,
  unconsented → false, consented → true (the `AccessibilityRungStrategy.swift:99-104` shape,
  as a pure decision over the loaded set). It is consulted **after** the metadata read (bundle
  ID + window title — allowed, M5's scoping) and **before** the content read (selected text).
  The composition that performs that ordering is `bootstrap-wiring`'s; this aspect pins the
  contract it must satisfy (D6).
- **D6 — The never-read acceptance is asserted without the adapter.** The test owns a small
  composed probe (the real gate + a recording `ContextAXReading` fake that records its
  content-read calls): consent off → the metadata read may happen, the content read records
  **zero** calls, and the result is the refusal; consent on → exactly one content read. The
  planted-violation control (a composed probe that consults the content read before the gate)
  fails the test — proving the detector works (the `KokoroSeamBoundaryTests` planted-control
  shape). The adapter's own consent-agnosticism is `accessibility-context`'s D7.

**Goal.** Every test this aspect will ship, written first against a store that does not exist.
Compile-time RED is the right reason for a new store (the `mode-machine` precedent). No

**Files (all under `Tests/HarnessTests/`):**

1. `ConsentStoreSeamTests.swift` — seam-shape compile pins (the `ASREngineSeamTests` shape):
   `requireConsentStore(_ store: any ConsentStore) -> any ConsentStore`; `ConsentStore` has
   **exactly** `load`/`set`/`save` (a fourth member fails to compile); `ConsentBundleID.isValid`
   answers on the pinned reverse-DNS vocabulary (nil, empty, whitespace, no-dot, a real bundle
   ID, a 256-char string); `maximumConsentedApps == 512`.
2. `PersistentConsentStoreTests.swift` — the store contract, the
   `InjectionStrategyStoreTests` template (real temp directories, real `FileManager`, plus the
   three recording filesystem doubles — a recording actor, a failing rename, a refusing
   create-directory):
   - Empty: missing file → empty consent, **silent** (a first run is not an error).
   - Corrupt: top level not an object → empty + exactly one loud log; unknown version → empty +
     one log; no `consent` list → empty + one log. A load never rewrites the file.
   - Tolerant per entry: a hand-edited file mixing valid bundle IDs with a content-shaped
     string and a time-shaped string → the valid entries load, each invalid entry is skipped
     with exactly one loud log.
   - Validation: `set("meeting at noon with Alice", consented: true)` returns `false`,
     persists nothing, logs once; the reverse-DNS boundary rows from the seam pins.
   - Cap: fill to `maximumConsentedApps`, then a new bundle → `false` + nothing persisted;
     an update of a known app always succeeds; `save` is uncapped.
   - Atomicity: a failing rename leaves the previous committed content intact (the durable
     claim); a refusing create-directory throws; the temp path is `<dir>/context-consent.json.tmp`
     and is never loaded.
   - Byte stability: two encodes of the same set are byte-identical (`sortedKeys`).
   - **The byte-level pin** `testTheEncodedBytesCarryNoContentAndNoWallClockTime`: encode a
     genuine multi-app set that includes digit-bearing bundle IDs; assert the bytes carry no
     phrase, no `[0-9]:[0-9]`, no ISO-8601 `T` marker, no `[0-9]Z`, no standalone 10-digit
     epoch; **and** the key-set pin — the decoded object's keys are exactly `{version,
     consent}` and every entry passes `ConsentBundleID.isValid` (a future `grantedAt` field, a
     display-name field or a selection-text field fails this). Vacuity guards: the set is
     non-empty and every entry validates. Stated honestly like the usage pin: the time
     assertions have teeth against the format as it stands — a `grantedAt` is one line away —
     and the text assertions are guaranteed by the vocabulary, kept because they fail on the
     day a row is widened to carry a name.

`PersistentConsentStore` types exist. Name the RED reason in the commit message.

## Testing strategy

- **The store's decisions run headless** over the injected `ConsentFileSystem` and `log`: real
  temp directories for the happy path (FileManager works on a hosted runner — the
  `InjectionStrategyStoreTests` header), the three doubles for the failure paths. The
  `context-consent.json` shape is asserted on the bytes (the key-set pin) and by round trip,
  never by re-reading this plan.
- **The byte-level pin is the privacy claim in test form** (M10): no content, no time-of-day,
  no timestamp — asserted on the artifact with the vacuity guards and the honest "what each
  half is worth" note. The validation (D4) is what makes "bundle IDs only" a property of the
  vocabulary, and the pin protects the day the format grows a slot.
- **The never-read acceptance is structural** (M5): the ordering contract (metadata → gate →
  content) is asserted with recording fakes and the planted-violation control proves the
  detector; the raw AX family itself is `accessibility-context`'s lint's concern, and the two
  aspects' tests agree on the boundary (R2).

## Environment & privacy

- Pure local, zero network: the Core seam is stdlib-only (the empty allow-list is unchanged);
  the module files import `VoccaCore` + `Foundation`/`OSLog` in the one store file only (its
  lint row). Nothing egresses; nothing new reaches a URL.
- The consent file is the auditable artifact: a user opens `context-consent.json` and sees
  exactly bundle IDs. That is the whole answer to "what does Vocca keep".
- No user-visible surface: no Apps-tab rows, no badge, no kill switch — the widget aspect's;
  this aspect's machinery must be indistinguishable from dead code to a user.

## Edge cases

- **Missing file** → empty consent, silent. **Unreadable file** → empty, one loud log.
- **Corrupt top level / unknown version / no list** → empty, one loud log each; never repaired,
  never rewritten (a load that rewrites can delete what the user opened the file to read).
- **Invalid entry in a hand-edited file** (content-shaped, time-shaped) → skipped, one loud
  log, the valid remainder loads; the file is left exactly as written.
- **Cap overflow** → refusal, never eviction: a new bundle at 512 returns `false` and persists
  nothing; updates of known apps always succeed (the strategies contract).
- **Hand-edited duplicates** → `Set` semantics collapse them; a hand-edited file over the cap
  loads uncapped (`load`/`save` are user-owned — the strategies precedent).
- **Concurrent writes** → single process, one writer, an actor, the atomic rename: a racing
  pair of updates ends with one complete file, and a concurrent read sees the old or the new
  complete file, never a partial one (the strategies concurrency contract verbatim).
- **The pin's teeth** → the regexes catch a `grantedAt` (ISO/epoch) the day it is added; the
  key-set pin catches a display-name or selection field the same day. The vacuity guards
  prevent the pin passing against an empty set.
