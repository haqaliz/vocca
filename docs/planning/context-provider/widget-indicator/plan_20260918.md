## Design decisions (pinned — do not re-decide)

- **D1 — One new reducer state + one new closed action.** `WidgetReducerState.context:
  WidgetContextState` (`Sources/VoccaUI/WidgetContextState.swift`):
  `public enum WidgetContextState: Equatable, Sendable { case off; case reading(appName: String?) }`
  — the egress shape, with the doc's non-dismissable argument repeated. The one new action case:
  `case contextChanged(WidgetContextSignal)` where
  `public struct WidgetContextSignal: Equatable, Sendable { public let consentActive: Bool; public let secureInputActive: Bool; public let appName: String? }`
  — **raw facts**, so the two rules this aspect owns live in the reducer, not the wiring. The
  closed-set test pins the set stays exactly `{projection, timerFired, partial, egressChanged,
  contextChanged}` (the exhaustive-switch compile pin, `SessionEffect` discipline).
- **D2 — The reducer owns both badge rules; the kill is one fold of the signal.** Rule 1
  (M8): badge `.reading(appName)` iff `consentActive && !secureInputActive` — the wiring's
  `consentActive` is already the composition of per-app consent ∧ focused-app-is-consented ∧
  ¬killed, but the Secure Input refusal is a **reducer row** (a signal with
  `consentActive: true, secureInputActive: true` folds `.off` — never on), because the pill's
  views are window-server glue executed by nothing in CI and the reducer is the tested half
  (`WidgetCopy.swift:20-25`). Rule 2 (M9): the kill lands as the wiring folding a
  `consentActive: false` signal — the badge clears **in that one fold** (no intermediate state,
  no timer); a dedicated `contextKilled` action is rejected: the badge outcome is identical, the
  closed set stays minimal, and the reads-stop + snapshot-discard the kill also triggers are
  wiring-side regardless (see D6). The carry-forward rule (the egress precedent): `adopting(_:)`
  and the notice branch must carry `context` forward — a session fold never clears the badge; a
  test pins it.
- **D3 — The Secure Input fact comes from the wiring's own `SecureInputReading`, never the
  snapshot.** Module rules: `VoccaUI` imports only `VoccaCore`; the reader is `VoccaInject`'s
  seam; `ContextSnapshot` carries no secure-input field (`context-seam` D2/D3). So
  `bootstrap-wiring` folds `secureInputActive` from its own `SecureInputReading`
  (`AppBootstrap.swift:188` already holds `SystemSecureInputRead`) at context-resolution time —
  the same fresh-read discipline `TargetResolution.swift:137-170` applies. This aspect's
  contract is the reducer's handling of the fact; the wiring's composition is `bootstrap-wiring`'s,
  recorded as a handoff.
- **D4 — The marker renders in the egress branch set, not IDLE/DELIVERED.** The context marker
  joins `egressMarker`'s branches (OPENING, RECORDING/TRANSCRIBING, CONVERSING); IDLE keeps the
  mic alone (`PRODUCT_SPEC.md` idle art) and DELIVERED stays a 600 ms confirmation. "Persistent"
  is the per-fold non-dismissable argument (`WidgetEgressState`'s doc), not per-branch. The
  branch structure is the pin (the `switch` in `content`); the wiring guarantees a fresh fold at
  every resolution so the badge reflects the current turn's armed state.
- **D5 — Copy, decided here and pinned by exact equality** (the `FailsafeCopy` custody-line /
  `UsageTabCopyTests` precedent — new copy `PRODUCT_SPEC.md` does not write, O2):
  - `BadgeCopy.contextGlyphSymbolName = "eye"` — the SF Symbol for the marker, distinct from the
    ☁︎ egress glyph at a glance (shape-carrying; the menu-bar "shape carries the state" doctrine
    applied to the badge).
  - `BadgeCopy.contextHoverText(appName:)` = "Vocca can read \(appName). \(appName) allowed this."
    — the egress hover's fact-then-consequence shape (`BadgeCopy.egressHoverText`,
    `PRODUCT_SPEC.md:323`), naming what is being read (M8's "explaining what is being read").
    The empty-name fallback (the dangling-arrow honesty rule, `WidgetCopy.swift:29-33`):
    "Vocca can read the focused app. It allowed this."
  - `MenuBarCopy.contextKillRowTitle = "Stop reading context"` and
    `MenuBarCopy.contextKillAccessibilityLabel = "Stop Vocca from reading the focused app's
    content"` — consequence-first action copy (the `statusDetail` doctrine, `MenuBarCopy.swift:74-78`),
    never an invitation to grant.
  - `SettingsCopy.contextSectionTitle = "Context"`, `SettingsCopy.contextReadingTitle = "Read the
    focused app's content"`, `SettingsCopy.contextReadingDetail` — the detail states the revoke
    plainly ("Off stops Vocca from reading the focused app's content until the next launch. Apps
    you've allowed stay allowed." — grants and revokes are different axes, `understanding.md:130-132`).
- **D6 — The kill is a runtime revoke, not a persisted setting.** One action stops reads and
  discards the turn's snapshot; the wiring's kill handler (1) sets its runtime revoked flag — all
  further resolutions answer nil, (2) discards the in-flight snapshot (context is never persisted,
  M10, so the discard is total), (3) folds the `consentActive: false` signal — the badge clears in
  that fold. It is **not** persisted: a standing kill would read as a permanent master switch
  rather than a one-action revoke (M9's "never reads as an invitation to grant"), and the
  persisted axis of this unit is the BYOK grant (`byok-context-grant`'s). At the next launch,
  per-app consent resumes — the normal, honest state. The Settings equivalent (D5's section)
  reflects the same runtime state through the bindings.
- **D7 — The menu row rides a third `apply` input and a defaulted closure.** `MenuBarItem`
  gains `onKillContext: () -> Void = {}` (the `onSelectMode` precedent — `AppBootstrap`'s
  construction compiles unchanged) and `apply(_:mode:contextReading: Bool = false)` — the third
  input to the idempotence guard (:99), so the kill row's presence is rebuilt exactly when the
  fact changes. The row appears only while `contextReading` (a kill row shown when nothing is
  being read is an invitation; M9). `MenuBarConditions` gains `isContextReading: Bool = false`
  (the `mode` defaulted-field precedent) as the pure fact the root feeds. The row-presence
  decision is glue (the mode-row precedent — untested `MenuBarItem`, tested copy).
- **D8 — The Settings control is the General tab's "Context" section.** `SettingsBindings`
  gains `isContextReading: () -> Bool = { false }` and `setContextReading: (Bool) -> Void = { _ in }`
  — the "defaults claim nothing" doctrine (`SettingsView.swift:192-193`); the toggle reflects the
  runtime kill state; the wiring of the closures is `bootstrap-wiring`'s. The General tab is the
  home of global behavior (hotkeys, activation, closing) — the kill is a global behavior, not a
  cleanup concern.

## Environment & privacy

- Pure local, zero network: the new code is VoccaUI Foundation+Core only; no URL, no AX, no
  Secure Input reader is named by this aspect (D3 — the fact arrives pre-read). The zero-network
  interposer suite covers the whole package and stays green.
- No content is ever held: the badge state carries an app **name** for copy, never a selection;
  the snapshot that may exist is the wiring's (and the wiring discards it at kill — M9's total
  discard, because nothing persists, M10).
- No user-visible surface beyond the badge, the row, and the Settings section — which are this
  unit's point (M8/M9). The badge's honesty contract: it lights only from a folded signal, the
  wiring can never light it by omission (the fold is the only writer — D2), and Secure Input
  suppresses it structurally (a reducer row, not a wiring courtesy).

## Edge cases

- **Secure Input mid-turn** → the signal's `secureInputActive: true` clears a `.reading` badge in
  the same fold (tested) — the badge never lies while a password field is focused.
- **Kill with no badge showing** → folding the kill signal from `.off` stays `.off` — a no-op,
  the B9 no-op posture (`SessionMachine.swift:631-633`); the row is hidden while nothing is read
  (D7), so the kill can't be pressed into a state with no context anyway.
- **A session fold over an active badge** → the badge survives (carry-forward, tested) — a
  delivered confirmation must not flick the badge off while the focused app is still consented.
- **`appName` nil with consent active** → `.reading(nil)` renders the fallback hover copy (the
  dangling-arrow honesty rule) — the badge is the message, the name is the detail.
- **The closed set** → a future sixth `WidgetAction` case breaks the exhaustive-switch pin in the
  test before it can hide a transition no signal can carry (D1).
- **`contextReading` and the idempotence guard** → the third `apply` input is in the guard
