## Design decisions (pinned — do not re-decide)

- **D1 — The seam names this aspect compiles against.** `ContextProvider`
  (`ARCHITECTURE.md:281`) yields `ContextSnapshot` — plain-data, `Sendable` (PRD M1): active
  bundle ID, window title, selected text; `NullContext` resolves to the empty snapshot. The
  resolution is `async` (the reads cross actor boundaries — the `FocusedAppReading` doctrine,
  `TargetResolution.swift:59-70`). The exact signature is `context-seam`'s; pinned here so
  Phase 2's compile pins are unambiguous.
- **D2 — The adapter split, inside the module.** `AccessibilityContext` (actor, public,
  conforming to `ContextProvider`) receives two module-internal seams: `ContextAXReading`
  (raw bundle ID + window title + selected text, class-bound — `FocusedAppReading`'s shape)
  and `ContextSecureInputReading` (the one `Bool`). The real conformances live in the two
  permitted files; every *decision* — empty on nil, refusal on Secure Input, never throwing
  (R1) — lives in the adapter, where CI reaches it.
- **D3 — Secure Input refusal is ordered before the AX call.** `resolve()` consults the
  secure-input read **first**; active → empty snapshot, and the AX read is **never consulted**
  — for a password field, never *ask*. Asserted with a recording fake (zero `ContextAXReading`
  calls when the secure-input fake answers true).
- **D4 — The permitted files.** `VoccaContext/Accessibility/AXContextSource.swift` (the AX
  family's second seam row, `"context"`) and
  `VoccaContext/Accessibility/ContextSecureInputRead.swift` (the Secure Input family's third
  seam row, `"contextRead"`). Both are the house adapter shape: raw translation only, no
  decisions, 0.5 s per-call budget on a serial queue (the AX one), public constructors for the
  composition root (the `AXSource`/`SystemSecureInputRead` publicity rationale), `Sendable`
  checked not asserted. A `FileManager`-naming file in the module is NOT this aspect's (the
  consent store is `consent-store`'s; the FileManager family is per-module, so its row lands
  there).
- **D5 — Resolution correctness = bundle ID + selected text.** Window title is carried but
  **not scored**: it is metadata for the failsafe copy, not a decision
  (`TargetResolution.swift:124`), and titles vary with focus. The scorer: ≥95% inclusive,
  throws on an empty corpus; the corpus rows seed the stub AX read and the harness asserts the
  adapter's snapshot.
- **D6 — The probe drive's recorded posture.** The probe's `ContextDrive` constructs the real
  adapter and calls `resolve()` once. In CI, without a grant, the AX calls answer failure and
  the snapshot is empty — the drive exercises the adapter's honest empty path (R1)
  deterministically, and the AX file's **failure path executes in CI**. This amends the letter
  of "executed by nothing in CI" (`AXSource.swift:34`) for this file, recorded in its doc
  comment: the grant-dependent *success* path remains unreachable and unexecuted; the
  two-sided pin keeps the family confined; the empty path is the contract the harness
  measures. Integrator checkpoint 2.
- **D7 — The adapter is consent-agnostic.** `AccessibilityContext` never consults consent; it
  reads what it is asked to. The never-read gate is `consent-store`'s (its acceptance is
  asserted there with recording fakes). Pinned here so the two aspects cannot each assume the
  other owns the sequencing.

## Testing strategy

- **Resolution correctness (S1).** The corpus is scripted, the adapter is real, the reads are
  stubs: every decision the adapter makes — carry, empty on failure, refusal on Secure Input —
  runs in CI. The real number is Phase 5's, recorded-never-gated. The corpus's rows are the
  C8 matrix's rows, so the CI harness and the real run measure the same shape.
- **Secure Input (M5b), two legs.** Behavior: the refusal returns the empty snapshot. Structure:
  the recording fake proves the AX read is never consulted (D3). The raw `Bool` itself is not
  asserted (it is a fact about every other app on the machine — `SecureInputRead.swift:26-33`);
  only the decision over it is.
- **The lint's two-sided pins** are the family confinement: after Phase 3, exactly the two
  `VoccaContext` files join the two tables' unions, and each actually names its family.
- **The planted corpus is the gate that cannot pass by accident:** 2 wrong rows in 22 is below
  the bar, and the harness asserts the failure.

## Environment & privacy

- Pure local, zero network: the new module imports only `VoccaCore` plus the two system
  frameworks the permitted files need; no `URLSession`, no URL constructed. The zero-network
  interposer drives the module through `ContextDrive` on the default-configuration path.
- The AX file's CI execution is the D6 recorded posture: the failure path only; the success
  path needs a grant and a focused app and stays unreachable in CI, now and ever.
- No user-visible surface: the badge, the kill switch, and the consent UI are the other
  aspects'. This aspect's machinery must be indistinguishable from dead code to a user.

## Edge cases

- **AX timeout / failure** → nil at the seam → empty snapshot; never throws (R1). The 0.5 s
  budget is the raw file's translation property, reviewed, not CI-asserted (`AXSource`
  precedent).
- **Stale or empty selection** → `""` passes through as `""`; nil stays nil; both mean "no
  content" to the scorer and the gate (the `consent-store` aspect's boundary).
- **Unconsented app** → not this adapter's question (D7): the adapter reads what it is asked
  to; the gate declines before the adapter is reached (`consent-store`'s acceptance).
- **Secure Input** → refusal before the AX call, empty snapshot; the indicator never lights
  (the widget aspect consumes the refusal — M5b's second half).
- **Swift 6 Sendable** → every cross-seam type is plain `Sendable` data; the only
  `@unchecked Sendable` is the AX file's `TimedResultBox`, the `AXSource` shape; the strict
  build is run at every phase boundary.
- **A second `FileManager`-naming file in the module** → not this aspect's; the consent store
  owns the module's one FileManager row (`consent-store`'s Phase 2).
