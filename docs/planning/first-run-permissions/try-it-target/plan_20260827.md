# Plan — first-run-permissions / try-it-target (A4) — 2026-08-27

Source: `docs/planning/first-run-permissions/prd.md` (M6, M7; R3). Depends on A1, A2.

## Goal

TRY IT runs a **real dictation** whose transcript lands in the onboarding window's own
field — "only the delivery end swapped": one `DictationPipeline`, injector chosen once at
root composition (ladder vs onboarding sink), no caller branches anywhere
(`DictationPipeline.swift:132` takes `injector: any TextInjector`).

## Files to create/modify

| File | Purpose |
|------|---------|
| `Sources/VoccaCore/Onboarding/OnboardingTranscriptSink.swift` | The delivery seam: `deliver(_ transcript: String)` — plain protocol, stdlib-only |
| `Sources/VoccaInject/Onboarding/OnboardingInjector.swift` | `TextInjector` conformance: resolve → onboarding target, inject → `sink.deliver`, no decisions |

## Implementation steps

1. **Read first**: `Sources/VoccaCore/TextInjector.swift` (the seam's exact shape —
   `resolve`, `inject`, `failsafe`, `TargetContext`, result vocabulary) and the
   `TextInjector` conformance shape of `LadderInjector` (`Sources/VoccaInject/Ladder/`)
   before writing. The onboarding conformance must answer the same surface.
2. **Test first (RED)**: `OnboardingInjectorTests` — drive `DictationPipeline` end to end
   with a stub engine (the `DictationCycleDrive`/fixture-replay shape) and the onboarding
   injector: transcript delivered to the sink; a cancelled session (`cancel()` during
   TRANSCRIBING) delivers nothing and finalizes `.aborted`; an empty transcript skips the
   injector (the pipeline's existing empty-skip row must hold with the onboarding
   injector too).
3. **Core seam**: `OnboardingTranscriptSink` — the sink's only job is delivery; the
   window's field binding (A5) conforms to it.
4. **The injector** (VoccaInject — adapter module, imports VoccaCore only): translation
   from the pipeline's call to `sink.deliver`; must be durable-before-return? No — it has
   no journal; the *sink* decides delivery semantics (A5's binding holds the text; a
   failed delivery surfaces the TRY IT failure copy, M7). Document the divergence from
   `LadderInjector`'s durable-before-return in the file header (the C4 contract is a
   ladder property, not an injector-universal).
5. **Root composition**: in `configure`, choose the injector once from
   `CompletionFlagStore.isComplete()`; the onboarding pipeline shares the engine
   resolver's `prepare()`/readiness gate, so `.modelUnavailable` refusal (M7) comes from
   the existing machinery unchanged.
6. Raise floor; run `Scripts/test-with-floor.sh`; confirm the zero-network probe's
   `PROBE-CYCLE` post-condition is byte-identical (the default configuration is complete →
   ladder, unchanged).

## Validation

- Full-cycle headless test green (deliver/cancel/empty rows).
- Zero-network: `PROBE-CYCLE`/`PROBE-LATENCY` strings unchanged; `ZeroNetworkTests` green.
- The injector contains no branching policy beyond translation (review).

## Edge cases

- Onboarding injector while the completion flag flips mid-launch: the choice is made once
  in `configure`; a flag set later (TRY IT success) changes nothing for the running
  process — the next launch uses the ladder. Pin this in a test/comment (the resolve-once
  doctrine, `DictationEngineResolver` shape).
- The onboarding injector must never be reachable when complete — the composition
  decision is the only branch (no caller checks state at session time).
