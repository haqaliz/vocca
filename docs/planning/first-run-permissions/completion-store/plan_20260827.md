# Plan — first-run-permissions / completion-store (A3) — 2026-08-27

Source: `docs/planning/first-run-permissions/prd.md` (M4, M8; R4). Depends on A1
(`OnboardingState.completed` is the only writer). Parallel with A2.

## Goal

The persisted "onboarding complete" flag: a UserDefaults-backed one-file seam, synchronous
read (the `main()` show decision needs it without async), write-on-TRY-IT-success only.
No `UserDefaults` exists anywhere in Sources today — this is the first, and it gets a
deliberate seam-family row in the lint table so the "one file per seam" claim is explicit
and enforced from day one.

## Files to create/modify

| File | Purpose |
|------|---------|
| `Sources/VoccaUI/Onboarding/CompletionFlagStore.swift` | The one-file seam: `isComplete() -> Bool` (sync), `markComplete()` |
| `Tests/HarnessTests/CompletionFlagStoreTests.swift` | Read/write/absent-default tests, scoped suite to avoid touching the user's real defaults |
| `Tests/HarnessTests/InjectionSeamBoundaryTests.swift` | Add the UserDefaults family row (one permitted file, two-sided pin: the file must name `UserDefaults`, no other file may) |
| `Scripts/test-with-floor.sh` | Raise floor |

## Implementation steps

1. **Test first (RED)**: absent flag → `false`; after `markComplete()` → `true`; a second
   `markComplete()` is idempotent; a fresh store instance reads the same flag (persistence
   across instances). Tests run against a scoped `UserDefaults(suiteName:)` injected via
   the initializer (never `UserDefaults.standard` in tests).
2. **The seam**: `CompletionFlagStore` — `init(defaults: UserDefaults = .standard,
   key: String = "onboarding.complete")`; the flag key is a frozen constant (pinned by a
   test — the smoke rows and any future surface read the same key).
3. **Lint amendment**: add a `UserDefaults` family to the seam table in
   `InjectionSeamBoundaryTests` with exactly this one file, plus the negative control (any
   other file naming `UserDefaults` fails). Keep the FileManager table at exactly three.
4. Raise floor; run `Scripts/test-with-floor.sh`.

## Validation

- `isComplete()` returns `false` on a fresh suite; `true` after `markComplete()`;
  cross-instance persistence; the key constant pinned.
- Lint: exactly one file names `UserDefaults` (the two-sided pin).
- Nothing here touches the network or the window server; `ZeroNetworkTests` green.

## Edge cases

- `markComplete()` must be idempotent and must never throw (best-effort write; a failed
  write means the window re-shows next launch — safe direction, worth a comment).
- The store is read at `main()` time and also at root composition (injector choice, A4) —
  the sync read is the requirement that justifies UserDefaults over the FileManager idiom.
