## Goal

The five-step window, the store that drives it, and the wiring: lazy like the settings
window (`AppBootstrap.swift:731-757`), the second focus-taking window (`.regular`/`.accessory`
dance, `SettingsWindow.swift:47-76`), auto-shown by `main()` until the completion flag is
set (A3), reopenable from the menu bar. Executed by nothing in CI — window-server object;
the reducer/copy/store are the tested half, the smoke rows (A6) are the execution.

## Implementation steps

1. **Store first (RED)**: `OnboardingStoreTests` — actions fold through the reducer;
   status reads/events arrive from injected closures (the `SettingsBindings` closure-seam
   shape, `SettingsView.swift:24-58`); the store never calls a system API.
2. **View**: five steps over `OnboardingState`; the TRY IT field's binding is the
   `OnboardingTranscriptSink` conformance (delivery appends to the field; failure sets
   `tryItFailed`); the MODEL step presents the shipped `DownloadWindow.present` /
   `DownloadProgressView` machinery (its first real caller) and folds
   `ModelDownloadSession` events into `modelStatusChanged`; skip → `modelDownloadCancelled`.
   Permission rows: one at a time with live ✓/✗, the pane button (A2), and the M5c
   three-state accessibility row with `[Restart Vocca]` (A2's `AppRelaunch`).
3. **Window**: the `SettingsWindow` dance exactly — lazy `NSWindow` + hosting view,
   `show()` = `.regular` + activate + makeKey, `windowWillClose` = `.accessory` (every
   close path; SMOKE_CHECKLIST step 80's load-bearing row). Contract tests drive the
   routing with fakes.
4. **Wiring**: `root.showOnboarding()` lazy property (settings shape); `main()` calls it
   when `CompletionFlagStore.isComplete() == false` (synchronous read); the menu bar gains
   a "Welcome…" item that calls it (post-completion reopen, M4); the store's reads come
   from A2's adapters and the root's tap health.
5. **Restart safety**: the restart button is single-fire (guard against double-invocation);
   after relaunch the flag semantics are unchanged (incomplete → window re-shows).
6. Raise floor; run `Scripts/test-with-floor.sh`; confirm the probe's `PROBE-BOOTSTRAP`
   output is unchanged (configure still constructs nothing window-server).

## Validation

- Store tests green over fakes; window contract tests green (lazy, focus policy routing).
- `main()` auto-show and the menu-bar item are window-server paths — asserted by source
  contract (the `MenuBarItem` precedent: built in `main()`, never `configure`) and by the
  A6 smoke rows.
- `ZeroNetworkTests` green (the MODEL step's download is user-initiated from the window —
  never on a CI path; the probe drives `configure` only).

## Edge cases

- Close on any step → `.accessory`; next launch re-shows at the first incomplete step
  (S3, reducer entry — A1).
- TRY IT without a model → `tryItUnavailableReason = .modelUnavailable` with [Download
  now] (M7); never auto-downloads.
- Grant arriving mid-flow → live ✓/✗ via the grant signal (S1); restart offered at the
  permission surface, flow not yanked backwards.
