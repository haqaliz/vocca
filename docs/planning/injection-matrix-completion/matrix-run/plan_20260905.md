## Harness invocations (the whole vocabulary)

```bash
Scripts/injection-matrix.sh --self-check          # CI-covered; run once for the record
Scripts/injection-matrix.sh --verify-bundle-ids   # Phase 0 — plutil-confirm every installed row
Scripts/injection-matrix.sh --dry-run             # Phase 0 — the installed set, the denominator
Scripts/injection-matrix.sh --row <Name>          # one row (run log auto-created)
Scripts/injection-matrix.sh --run-log <path>      # pin ONE file per run (append-only) — use it so
                                                  # every row of this run lands in one JSONL file
Scripts/injection-matrix.sh                        # the full run + tally (not used here: the
                                                  # control row and the sessions run via --row)
```

Run-log default: `~/Library/Application Support/Vocca/matrix-runs/<timestamp>.jsonl`
(`injection-matrix.sh:128`, created at run start, printed at `:161`). **Pin it once** per run:
`--run-log "$HOME/Library/Application Support/Vocca/matrix-runs/20260905-completion.jsonl"`.
`strategies.json` lives at `~/Library/Application Support/Vocca/strategies.json`.

Evidence vocabulary (exact strings): `session opened mode=dictation` and
`delivery target=<bundleID> rung=<rung> attempted: [<rungs>] verified=<bool>`
(`Sources/VoccaCore/MatrixEvidence.swift:21-27`); the refusal spelling is **`attempted: []`**.

5. **Optional N1 — step 89's Docs half** (seeded-hostile first run): requires **fresh memory**

6. **Memory state snapshot:** `cat ~/Library/Application Support/Vocca/strategies.json` —

**Validation:** v0.2.1 confirmed; `--verify-bundle-ids` 19/0/3 (or a recorded delta); the

## Phase 1 — The control row: Notes re-run (`--row Notes`)

**Goal:** the harness's first live execution on v0.2.1 against a row with a **recorded prior
outcome** — a changed outcome is itself evidence, and a harness break has a specific regression
shape to pin RED→GREEN. Also: the prior byte side was "recorded, not adjudicated" — **this run
adjudicates it** (Phase 4).

**Prerequisites:** Phase 0 complete; Vocca running armed; memory **not** reset.

**Steps:**

1. Re-read `strategies.json`: Notes must still carry the demotion with the re-probe window
   (2026-09-10, not elapsed). Record.
2. `Scripts/injection-matrix.sh --run-log "<...>/matrix-runs/20260905-completion.jsonl" --row
   Notes`. Record the printed run-log path.
3. Founder: click into a new note, dictate the fixed phrase (`the quick brown fox jumps over the
   lazy dog`), press return once the text has landed.
4. **Expected outcome on v0.2.1:** the memory is demoted, so the ladder opens with
   `.clipboardPaste` — no `.accessibility` attempt (window not elapsed). The harness's rung
   prompt asks ".accessibility?" — the **honest answer is N**, and the harness logs
   `bytes_matched: true, verdict: failed, note: "log did not name .accessibility"`. That is the
   **demotion honored**, not a defect — the row records as a **miss** against the steady-state
   expected rung, with the demotion cited (decision point D2: the FMS discipline counts it; the
   prior run's own demotion is the reason, and that is exactly demote-on-fail working).
5. **If bytes still mismatch:** the byte side goes to Phase 4 adjudication before the row is
   recorded — this closes the prior run's "recorded, not adjudicated" gap.
6. Record the row's outcome beside its prior state (tracked-row language): prior = byte
   mismatch + demoted + unadjudicated; now = bytes matched/mismatched + rung landed = clipboard
   (demotion honored) + adjudication note.
7. **Harness break = STOP.** The specific regression shapes (what first executions have
   produced before and what this run would reproduce): a run-log line missing, malformed, or
   duplicated; a VOID mislabeled as a byte failure (sentinel leak); the byte-compare failing
   when the field visibly holds the phrase; the rung prompt naming a rung the log cannot spell;
   `strategies.json` not written when a strategy changed (or written when nothing changed).
   Each shape lands as a **RED test first** (regression test pinning the shape), then the fix,
   then GREEN — floor 1758 — then the row re-runs. See Phase 6.

**Validation:** a run-log line exists for Notes (`{"row": "Notes", ...}`) with `bytes_matched`,
`verdict` and `note`; `strategies.json` still shows the demotion (window 2026-09-10); the
outcome is recorded beside the prior state; any harness break produced a RED→GREEN commit and a
clean re-run.

**Commit message:** only if a defect surfaced: `matrix-run: fix the <shape> harness defect
(RED→GREEN, floor 1758)`. Otherwise none.

## Phase 2 — The remaining 16 deliverable rows, session by session

**Goal:** every installed deliverable row executed and recorded with a run-log line + rung y/N +
`strategies.json` delta. Session counts are guidance, not gates — sessions can split across days;
the daily-use log covers the gaps.

**Prerequisites:** Phase 1 clean (or its defect fixed and the row re-run). Memory steady-state.

**Per-row steps (the evidence checklist — every row, every session):**

1. `Scripts/injection-matrix.sh --run-log "<...>/20260905-completion.jsonl" --row <Name>`.
2. Founder: click into the named field (`injection-matrix.sh:92-115` target column), dictate the
   fixed phrase, press return once the text has landed.
3. Harness: select-all/copy/`pbpaste` byte-compare (sentinel-guarded — a denied Automation grant
   is a VOID, not a failure).
4. Founder: read the landing rung (widget Apps tab / `log show --predicate 'subsystem ==
   "dev.vocca.Vocca"' --last 30m`), answer the rung y/N prompt **from the log, not memory**.
5. **Run-log line:** copy the printed JSONL line into the run sheet — row, `rung`, `bytes_matched`,
   `verdict`, `note`.
6. **`strategies.json` check:** `cat ~/Library/Application Support/Vocca/strategies.json` and
   record the delta for that bundle id. Expected: unseeded clipboard success **mints a
   promotion-candidate window** (`reprobeWindows[.accessibility] = now + 604_800`); seeded
   allowlist rows confirm/pin; nothing appears for a row that changed nothing.
7. **Byte mismatch:** immediately record the **delivered transcript** (what the widget/failsafe
   showed at delivery) beside the captured bytes — the adjudication input for Phase 4. Do not
   re-run the row to "fix" it; adjudication is the fix.

**Sessions (per-row class from the harness table; the class is the swap invariant, the sessions
are founder flow):**

- **Session A — native AppKit:** TextEdit, Mail, Xcode, Messages. Expected rungs: `.accessibility`
  for the seeded allowlist rows (TextEdit, Mail); `.clipboardPaste` for Xcode and Messages
  (promotion candidates — a clipboard success here mints their step-91 windows).
- **Session B — Electron:** Telegram, VSCode, Teams, Discord, ChatGPT, Obsidian, Warp. All
  `.clipboardPaste`. Warp is terminal-class in the table but lives here per the founder's
  grouping — the class column governs swaps, not session order.
- **Session C — browsers:** Safari, Chrome (plain field), GoogleDocs, Firefox. All
  `.clipboardPaste`. Chrome is seeded hostile browser-wide (`SeededHostileApps`) — the expected
  rung is `.clipboardPaste` and an `.accessibility` attempt on Chrome is a seed failure, not a
  surprise.
- **Session D — terminals and the skips:** Terminal (`.clipboardPaste`); Ghostty and Zed
  re-confirmed skipped by the Phase 0 dry-run (no same-class swap available — recorded in the
  tracked row's Skipped column; they need no run-log lines, they are not runnable rows).
- **Session E — hostile:** Passwords, PasswordField — these are **Phase 3** (step 92), not this
  phase; the refusal rows expect rung `none` and never get a byte-compare.

**Validation:** every row of sessions A-D has a run-log line + a rung y/N answer + a
`strategies.json` delta (or an explicit "no change") in the run sheet; PASS = bytes **and** the
log named the expected rung; byte mismatches carry the delivered-transcript note; the run sheet
names the VOIDs (granted) and their re-runs.

**Commit message:** none.

## Phase 4 — Adjudication (M4): every byte mismatch, triaged

**Goal:** every byte mismatch is triaged to one of three verdicts — **ASR's matter** (the engine
mis-transcribed the real utterance), **injection failure** (transcript right, field wrong), or a
**lying read-back defect** (`.accessibility` named with wrong bytes in the field) — and never
auto-counted as an injection failure.

**Prerequisites:** Phase 1-3 done; the run sheet carries, per mismatch, the captured bytes and
the delivered transcript.

**Steps (per mismatch):**

1. **Compare the three texts:** the fixed phrase (golden), the captured bytes (harness), the
   delivered transcript (widget/failsafe at delivery time).
2. **Transcript ≠ phrase** (and equals the captured bytes): the engine itself mis-transcribed —
   **ASR's matter**, step 19's issue. Record the utterance's WER (substitutions) in the run
   sheet; the row's byte failure is expected given the transcript. **Not an injection failure.**
   This is the adjudication the Notes control row's prior state was missing.
3. **Transcript == phrase but captured ≠ phrase:** the ladder delivered wrong bytes — an
   **injection failure**. If the landing rung was `.accessibility`, the read-back verification
   lied — a **defect** (Phase 6, RED→GREEN); if a fallback rung landed, it is the matrix's
   expected finding for that row, recorded.
4. **Engine-health cross-check** (the WER machinery, `VOCCA_MODEL_DIR` set to the store-shaped
   version directory; `Scripts/provision-asr-fixtures.sh` for the provisioning path):
   `VOCCA_MODEL_DIR=<version dir> Scripts/test-with-floor.sh --filter WhisperCppEngineWERTests`
   and `--filter ParakeetEngineWERTests` — the six fixtures must stay within the provisional
   tolerances. A tolerance break is its own defect. For a phrase-specific re-transcription, run
   the engine over a `matrix-phrase.wav` + `matrix-phrase.txt` pair through the
   `ASRFixtureSuite`/`RealEngineWERRunner` path — or, pragmatically, re-dictate the phrase and
   compare (a transcript that repeats the captured text confirms ASR consistency; a transcript
   equal to the phrase points at the ladder).
5. **Record the verdict per row** in the run sheet: `adjudicated: ASR / injection / lying-readback
   (+ defect card reference)`.

**Validation:** every row with `bytes_matched: false` carries an adjudication note; no mismatch
is left un-triaged; the Notes control row's prior "recorded, not adjudicated" gap is closed.

**Commit message:** only if adjudication surfaces a defect (Phase 6 shape).

## Phase 6 — Defect fixes and the tally handoff

**Goal:** every defect the run surfaced is fixed test-first with the floor intact; the run's
numbers are assembled for the `record-and-sync` aspect. No number becomes a gate pass.

**Steps:**

1. **Defect discipline (M6):** every harness break, unperformable row, lying read-back, or
   evidence gap lands as a **RED test first** — the regression test pins the exact shape — then
   the fix, then GREEN via `Scripts/test-with-floor.sh` (floor 1758, never lowered). The branch
   stays green after every task.
2. **Escalation rule:** a fix that needs a PRD-level decision or a seam-contract change — the
   ladder, the memory's record semantics, `MatrixEvidence` strings, the harness row table, a
   checklist row's expected rung — escalates as **its own card**: record the finding, do not fix
   it here.
3. **Not-closeable acceptance (D4, R2):** FMS = deliverable rows whose expected rung landed /
   deliverable rows actually run, skips and voids named. The ≥19/20 bar is against the
   20-row denominator; with Ghostty/IntelliJ/Zed skipped, **≥19/20 is structurally unreachable**
   (max 17/20) — unless the founder installs a same-class app, the v0.2.1 row reads
   **"not closeable on this machine"**, recorded as itself, never as a pass or failure
   (`_card/understanding.md:47-49`). The founder's alternatives: accept and record, or install
   e.g. Ghostty itself and re-verify its bundle id (it would leave the skipped set and the
   denominator moves). Decision point, default = accept and record.
4. **Handoff bundle** (the `record-and-sync` aspect's input, all on-disk): the pinned run-log
   path + its lines; the run sheet (per-row: rung, bytes, verdict, adjudication note, strategies
   delta); the `strategies.json` end-state; the steps 89-92 dispositions; the window states;
   the daily-use counts; the FMS tally with its denominator spelled out.

**Validation:** `Scripts/test-with-floor.sh` green at floor 1758; every defect has a RED→GREEN
commit with the regression test; the handoff bundle is complete and self-citing.

**Commit messages (the only commits this unit makes):**
`matrix-run: fix the <shape> defect (RED→GREEN, floor 1758)` per fix. Record edits belong to
`record-and-sync`.

## Edge cases

- **A swapped app that fails its own byte-compare:** recorded as a miss, adjudicated (Phase 4),
  becomes the work list — never chased by editing expectations.
- **A candidate that is also a promotion candidate (Xcode, Messages, Telegram):** its expected
  rung stays `.clipboardPaste`; the run's success only mints the step-91 window.
- **A run-log line missing for a row:** the row is "reported, not measured" — investigate before
  re-running (did the row actually run with the v0.2.1 build?); the shape repeats the v0.1.0
  failure (`SMOKE_CHECKLIST.md:1905`).
- **Secure Input during the run** (a password prompt stealing the tap): the tap-disabled stop
  ends the session cleanly; the row is **voided, not failed** (preamble rule 1) and re-run.
- **A row whose expected rung the memory has demoted (Notes):** recorded as a miss with the
  demotion cited (Phase 1 step 4) — never a silent pass, never a harness defect.
- **An app that genuinely refuses all rungs** (not a lying read-back): a row-failure, the
  matrix's expected finding, not a defect (`spec.md` risk).
- **Notes' re-probe window elapses mid-run (2026-09-10):** if the run is still open, the Notes
  row may re-probe once on the next dictation — that is step 90's observation (Phase 5 D3), not
  a surprise.
