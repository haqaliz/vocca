## Phase 1 — FMS tally from the run log

### Goal

A tally table, computable by a reader from the run log alone: per-row verdicts (pass /
failed / skipped / voided / refusal), the FMS fraction over the deliverable rows actually
run, and the bar reading against the 20-row denominator — with the not-closeable outcome
named as such if the bar is unreachable. This is the exact input to Phase 2's tracked row.

### Prerequisites

- `matrix-run` completed: all rows run on the v0.2.1 build, adjudication recorded, step 92
  observed, steps 89-91 windows dispositioned; the run-log file(s) in hand on the founder's
  machine.
- The `matrix-run` aspect's defect-fix commits (M6), if any, named in its handoff.

### Steps

1. **Read the tally from the run log, not from memory.** For each JSONL line of the run,
   classify by verdict: `pass` (bytes_matched `true` **and** the log names the expected
   rung as the landing rung — a delivery through a fallback is a miss, `SMOKE_CHECKLIST.md:
   1806-1808`), `failed`, `skipped` (not installed), `voided` (no Automation grant), or
   `refusal` (the two rung-`none` rows, step 92). Cross-check the counts against the
   harness's printed summary (`Scripts/injection-matrix.sh:509-520`) — `deliverable =
   passed + failed`, `first-method-success = passed / deliverable`; the two must agree or
   the discrepancy is investigated before any row is written.
2. **Name the skips and voids.** The three structurally-skipped rows (Ghostty, IntelliJ,
   Zed — not installed, no same-class swap available, `SMOKE_CHECKLIST.md:1992`) are named
   in the notes, never folded into the denominator. A voided row is named with its reason
   (stale `pbpaste` = the void signal); it is a void, not a failure.
3. **Compute the FMS fraction.** FMS = deliverable rows whose expected rung landed /
   deliverable rows actually run (unit spec M3). The harness's `first-method-success` line
   is the number.
4. **Compute the bar reading — the not-closeable check.** The bar is ≥19/20 over the 20
   deliverable rows (`SMOKE_CHECKLIST.md:1986-1987`). With 3 permanently-skipped rows, at
   most 17 deliverable rows can ever run — 17/20 = 85% < 95%, so **the bar is structurally
   unreachable on this machine**. Record that disposition explicitly (PRD R2: "recorded as
   a named outcome, never as a pass or failure") — a 100% pass rate over run rows does not
   close the bar, and the row must say so.
5. **Fold in the adjudication summary (M4).** Every byte-compare mismatch's disposition
   from `matrix-run`: a transcript mismatch re-transcribed through the real engine (the
   step-19 WER machinery, `WhisperCppEngineWERTests`/`ParakeetEngineWERTests` with
   `VOCCA_MODEL_DIR`) is **ASR's matter, not an injection failure**; an `.accessibility`
   byte mismatch with a lying read-back is a **defect** and names its test-first fix
   commit. The v0.2.0 row's Notes byte-mismatch was recorded "not adjudicated"
   (`STATUS.md:251-252`) — the completion's adjudication of that same row (the control
   re-run) is part of this summary.
6. **Record step 92's four observations** (log `attempted: []`, failsafe copy, transcript
   copyable, `strategies.json` gained nothing) as refusal rows correct/wrong — excluded
   from numerator and denominator, recorded under the zero-loss invariant
   (`SMOKE_CHECKLIST.md:1810-1814`).
7. **Write the tally table** (release, date, rows run, passed, failed, skipped named,
   voided named, refusals correct/wrong, FMS fraction, bar reading, adjudication summary)
   into the `matrix-run` handoff document or a scratch note on the founder's disk — it is
   the source Phase 2 transcribes, not a repo file.

### Validation

- A reader can reproduce every number in the tally from the run-log lines alone; no figure
  is reconstructed from memory.
- `deliverable = passed + failed` matches the harness summary; the FMS fraction and the
  bar reading are computed separately and both present.
- The not-closeable disposition (if it holds) is written as a named outcome — the words
  "pass" or "failure" appear nowhere in it.

### Commit message

None — this phase computes; the tally lands in Phase 2's tracked row.

## Testing strategy

- `Scripts/test-with-floor.sh` after every commit — the suite includes the harness
  `--self-check` (`InjectionMatrixHarnessTests`), so a doc edit that drifts from the
  harness row table fails.
- No new tests; docs-only commits. (Defect fixes belong to `matrix-run`, test-first, and
  are named, not repeated, here.)

## Environment & privacy

- No env vars, no network, no founder data in the repo: the run log is cited by path
  (`~/Library/Application Support/Vocca/matrix-runs/<date>.jsonl`) and never committed;
  `strategies.json` stays on the founder's disk; no transcript text enters any doc.

## Edge cases

- **A row the run log lacks:** the row is "reported, not measured" — excluded from "rows
  run", named in the notes; never reconstructed from memory or re-claimed.
- **A run fraction of 100% with the bar unreachable:** both numbers are recorded — the
  fraction over run rows and the not-closeable bar reading; the latter wins the notes.
- **The v0.2.0 row's label:** the table records it as `v0.1.0` while the PRD names it the
  v0.2.0 run — "untouched" covers the label too; the plan never re-labels history.
- **A step-88-92 note the run contradicts:** an `*(Amended …)*` note beside it, the
  original text never edited.
- **Floor drift from `matrix-run`'s fixes:** read the floor, re-record it in every doc
  that cites it (CLAUDE.md, STATUS.md, this plan's context) — doc numbers are
  single-sourced too.
- **A defect the floor check surfaces:** test-first, own commit, floor never lowered —
  the fix escalates as its own card only if it needs a PRD-level decision (PRD M6).
