## Goal

The first in-app authoring surface for `intent-phrases.json`: an Actions-tab **Phrases**
section (add / edit / remove / validate), a `keywordFallback` toggle, persisted through
`IntentPhraseStore` — so a phrase is authored without a text editor and resolves next turn.

## Decisions (from planning)

- **D-1 — boundary:** UI-local plain types `ActionsPhraseRow { phrase, providerID, toolID }` and
  `ActionsPhraseFile { version, phrases, keywordFallback }` in `ActionsTabModel.swift`; a
  root-side mapping `AppBootstrap.phraseFile(from:)` / `IntentPhraseFile` ⇄ `ActionsPhraseFile`
  (the `agentFile(from:)` precedent). **No lint widening**; an agreement test pins the two
  spellings (the `AgentAuthoringSurfaceTests` precedent).
- **D-2 — target entry (Open Q1):** a **validated free-text pair** (`providerID` + `toolID`
  fields) with inline hints listing the known legal targets (the two audit tools; the loaded
  coding-agent ids) — *not* a full composed picker (a picker needing MCP discovery is
  disproportionate). A `dev.vocca.shell` providerID is refused in the editor **and** by the
  store. The richer picker is a recorded follow-on.
- **D-3 — `keywordFallback`:** a toggle row in the section, written to the file's field
  (retires the `composite-intent-resolver` named deferral).
- **D-4 — conflict guard:** save calls
  `IntentPhraseStore.save(_:ifUnchangedFrom:)` (added by `phrase-store-validation`, D-4) with
  the snapshot taken at load; `.fileChangedOnDisk` surfaces as "the file changed on disk —
  reopen the section" and writes nothing.
- **D-5 — duplicates:** refused at save in the editor (loud) and by the store.

   draft and a row-edit save preserves it; the toggle writes the new value.
5. **RED — A4/A5 refusals.** A shell target, a duplicate phrase, an empty phrase, an over-length

7. **RED — A7 save failure/conflict.** A `savePhrases` failure keeps the draft; a

## Edge cases

- The section is **read-on-open** (the Conversation-tab precedent); the conflict guard (D-4)
  covers a hand-edit between open and save.
- An empty `providerID`/`toolID` is refused (non-empty required) — the resolver's catalog gate
  would make it inert anyway; refuse loudly.
- A target that is legal but not currently enabled is allowed (the phrase is inert until enabled);
  the UI may hint this.
- Removing the last phrase leaves `phrases: []` (a valid file), not an absent file.
