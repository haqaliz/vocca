# Implementation plan: phrase-store-validation

> Aspect of `phrase-authoring-ui` · Date 2026-10-17 · Strict TDD (RED → GREEN → REFACTOR).
> Spec: `docs/planning/phrase-authoring-ui/phrase-store-validation/spec.md`.
> Template: `IntentPhraseStore` itself is the shape; the `ShellWiring`/registry save-validation
> precedent is the reviewer's reference.

## Goal

`IntentPhraseStore.save` gains the load-time invariants (shell refusal, duplicate, empty,
length) as **explicit refusals**, plus a read-only file-location accessor — so the new UI's
save path cannot write a row that `load` would later drop. Happy-path bytes unchanged.

## Decisions (from planning)

- **D-1 — error shape:** one `IntentPhraseStoreError.invalidRow(reason: String)` case (the reason
  is a short, copy-ready key: `"shellTarget"`, `"duplicatePhrase"`, `"emptyPhrase"`,
  `"phraseTooLong"`, `"idTooLong"`), added beside the existing `.tooManyPhrases`/`.fileTooLarge`.
  The UI maps the reason to copy; the store names the rule once.
- **D-2 — normalization:** duplicates are judged with `PhraseIntentResolver.normalized` (the
  resolver's own rule; the parity test `IntentPhraseStoreTests.swift:314-337` already exists).
- **D-3 — load unchanged:** `load` stays tolerant (first-wins on duplicates, row-skip on
  invalid); `save` is the strict gate.
- **D-4 — read-before-write (the Open Q3 decision, lives here not in the UI):**
  `IntentPhraseStore` gains `save(_ file:, ifUnchangedFrom snapshot: IntentPhraseFile) async
  throws` — it loads the committed file, and if it differs (`IntentPhraseFile` is `Equatable`)
  from `snapshot` it throws a new `.fileChangedOnDisk` case **without writing**; otherwise it
  delegates to `save`. This puts the conflict rule in the store (one place, testable) and keeps
  the UI's save path a plain call. `save(_:)` stays as-is for non-UI callers.

## Steps

1. **RED — A1–A4 save refusals.** Write tests: `save` throws `.invalidRow(reason)` and writes
   nothing (directory empty) for a `dev.vocca.shell` row (`A1`); a duplicate normalized phrase
   (`A2`); an empty / whitespace phrase (`A3`); an over-length phrase and an over-length id
   (`A4`). Assert the `reason` value each time. Run — they fail (save currently accepts all).
2. **GREEN — implement save validation.** Add the checks to `save` **before** encoding (so a
   refusal writes nothing), using `ShellProvider.providerID` and
   `PhraseIntentResolver.normalized`. Keep the existing count/byte-cap checks.
3. **RED/GREEN — A5 the bytes regression.** Assert the exact-bytes pin
   (`testEncodedBytesCarryExactlyTheNamedFields…`-style, `IntentPhraseStoreTests.swift:299-308`)
   is still green — the refusals must not touch a valid table's encoding. Add an explicit test
   that a **valid** save round-trips byte-identically.
4. **RED/GREEN — A7 the accessor.** Add `public var fileURL: URL` (or `func fileURL() -> URL`)
   returning `<directory>/intent-phrases.json`, and a test asserting it equals the path
   `save`/`load` derive (one derivation — hoist the private `intent-phrases.json` name to one
   site if it currently is duplicated).
5. **RED/GREEN — D4 the conflict guard.** Test: `save(_:ifUnchangedFrom:)` throws
   `.fileChangedOnDisk` and writes nothing when the committed file changed since the snapshot;
   saves (byte-identically to `save`) when it matches; saves when the file is absent and the
   snapshot was `.empty`.
6. **REFACTOR.** Extract the row-validation into one private `validate(_:)` helper called by
   `save` (and, if clean, reuse it to express the load filters' intent without changing load
   behavior). Run the full suite; raise `MINIMUM_EXECUTED_TESTS` in
   `Scripts/test-with-floor.sh` by exactly the new test count, in the closing commit.

## Edge cases

- A row whose `providerID` is `dev.vocca.shell` **case-variant** (`DEV.VOCCA.SHELL`): the load
  guard is exact `!=` today; mirror the same exact comparison in `save` (record the choice —
  case-sensitivity is the existing posture, `CAPABILITY_ROADMAP.md:901`).
- A duplicate where the first row is valid and the second is the shell row: both rules apply;
  define the check order and pin it (recommend shell first, then duplicate, then length — so
  the reason is deterministic).
- Whitespace-only phrase: treat as empty (trim before the empty check), matching the resolver's
  normalization intent.
