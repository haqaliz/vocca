### 1.1 Design decisions — the spec's open questions, closed here

- **S2 (attribution) and N1 (configurable budget) are skipped.** Both are "only if cheap"
  (`spec.md:104-105, 42-44`), and neither is: S2 changes `SessionRecord`'s public shape and the
  ledger's describe across the shipped suites, N1 threads a budget through the two providers'
  declared-budget contract. Skipped, documented in the commit; the PRD's M1–M10 are unaffected.
- **The endpoint for the badge comes from the resolver.** `CleanupResolver` gains
  `egressEndpoint() async -> String?` — the endpoint of the resolved provider's selected block,
  stored during `build()` (the resolver is the single source of "which provider runs"). The
  wiring folds it through a new testable helper `WidgetEgressState.fromResolvedProvider(
  requiresNetwork:endpoint:)` in `VoccaUI`, so the composition root and the headless test share
  the exact same fold.
- **The egress fold happens in a `Task` after the root is built.** `AppBootstrap.configure` is
  synchronous `@MainActor`; the resolver's `resolve()` is async, so the fold — resolve, derive,
  `setEgress` — runs in a background `Task` on the main actor (the `custodyTask` precedent). The
  default path folds `.none` (also the reducer default), so the probe's `egress=none` is
  byte-for-byte correct even before the fold lands.
- **The probe wires the resolver directly** (`spec.md:51-54`): absent config in a temp
  directory (default ⇒ rules), probe-fake transport/key factories (never reached on the default
  path), and the fold happens deterministically inside `buildDictationCycle` — not in a
  background task — so the report's `egress=none` is asserted, not assumed.

## 6. Edge Cases & Error Handling

- **Default path stays zero-network** — the resolver resolves rules (absent config), no
  transport is ever constructed or dialed; the interposer sees zero `connect(2)`.
- **`egressEndpoint()` is nil only for rules** — a `requiresNetwork` provider always has a
  validated endpoint, so the fold's fallback is dead but honest.
- **Resolve-once is the never-swap guarantee** — the root calls `resolve()` exactly once; a
  mid-session provider swap is structurally impossible.
