### 1.1 Design decisions — the spec's open questions, closed here

- **The badge is reducer state, not view state** (`spec.md:48-51`): `WidgetReducerState.egress`
  defaults `.none`, the closed `WidgetAction` set gains `case egressChanged(WidgetEgressState)`,
  and the reducer stores it — **no other action touches it, and no time-based transition
  exists** (the `FailsafeStateReducer` never-auto-dismiss precedent).
- **Non-dismissable is structural** (`spec.md:52-54`): the only writer of `egress` is
  `egressChanged`, and the composition root folds it exactly once at launch (resolve-once), so
  once `.active`, nothing automatically dismisses it. The B3 test enumerates the closed set
  minus `egressChanged` and asserts none touch egress; `egressChanged(.active)` sets and
  `egressChanged(.none)` clears — the wiring's only two calls.
- **The endpoint string for the hover** (`spec.md:89-94`): the root folds `.active(endpoint:)`
  from the resolved provider's config endpoint — never the key (`byok-provider` hygiene). The
  reducer carries the endpoint string opaquely; `BadgeCopy.egressHoverText(endpoint:)` renders
  it.
- **Hover surface mechanics** (`spec.md:95-97`): SwiftUI `.help()` — the system tooltip after a
  delay, no key/focus implications, the first hover surface in the codebase. The smoke step
  (M10) verifies it on the founder's machine.
- **Which states render the glyph**: opening/recording/transcribing (`spec.md:98-100`,
  `PRODUCT_SPEC.md:250-264`) — the PRD pins the three, DELIVERED is deliberately excluded.

## 4. Testing Strategy

- All headless; no window server — the reducer and copy are the tested half; `WidgetView` is
  thin glue executed by nothing in CI (`spec.md:48-51`). `./Scripts/test-with-floor.sh` is the
  whole check.
- The load-bearing tests: B3's no-dismissal (the closed set cannot clear `.active`), B2's
  untouched-everywhere (only `egressChanged` writes egress), B4's byte-fidelity (the badge says
  exactly what the spec says).

## 5. Environment & Secrets

- None. No network, no keys — the badge renders an endpoint string, never a key
  (`byok-provider` hygiene, `spec.md:93-94`).

## 6. Edge Cases & Error Handling

- **`.none` default** — the rules path (and the zero-network probe) is byte-for-byte today.
- **Launch-derived, never per-session** — resolve-once means the badge is static per launch;
  no per-session flip-flop exists in the reducer.
- **DELIVERED renders no glyph** — the text has left by then; the PRD pins the three states.
- **No dismissal** — no timer, no projection, no notice can clear `.active`; only the root's
  explicit `egressChanged` can, at launch.
