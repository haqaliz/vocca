### 1.1 Design decisions — the spec's open questions, closed here

- **Load-only this aspect.** No save path: the settings surface writes later, and an
  untested-by-consumer save API is pretend-fidelity (`spec.md:98-100`). The store's file-system
  seam therefore carries only the two operations load needs (`fileExists`, `read`); the atomic
  temp+rename save shape is omitted until a writer exists.
- **The config store names `FileManager` (the seam row's requirement).** It mirrors
  `FileSystemDictionaryStore`: its own `CleanupConfigFileSystem` protocol plus
  `DefaultCleanupConfigFileSystem`, the one `FileManager`-naming implementation in that file.
  The FileManager seam table gains the `config` row → `Cleanup/CleanupConfigStore.swift`
  (per-module-scoped to `VoccaText`, `spec.md:30-32, 82-85`).
- **Tolerant decode is a static function, not `Codable`.** `CleanupConfig.tolerantDecode(_:log:)`
  reads untyped JSON (`JSONSerialization`), the `FileSystemDictionaryStore.decode` precedent:
  unknown keys are ignored by construction, unknown provider kinds and invalid blocks degrade
  to `.rules` with one loud log, never throws. `CleanupProviderKind` is a raw-string `Codable`
  enum for the round-trip contract (B1); `CleanupConfig` itself needs no `Codable` until a
  writer exists.
- **The resolver derives the dictionary store from the config store's directory.** The rules
  provider's `FileSystemDictionaryStore` is built at `store.directory` — the same Application
  Support/Vocca directory — so the probe's temp directory isolates both stores and the
  constructor keeps the spec's shape (`spec.md:33-41`: store + transport factory + key-provider
  factory).
- **The endpoint is validated twice, defensively.** `tolerantDecode` rejects a block whose
  endpoint is not URL-constructible (rules + loud log); the resolver still guards its own
  `URL(string:)` with a defensive degrade-to-rules rather than force-unwrapping.

## 4. Testing Strategy

- All headless; no TCC/Accessibility/mic/network — the config store executes in CI over real
  temp directories (the dictionary-store precedent). `./Scripts/test-with-floor.sh` is the
  whole check, per aspect.
- The load-bearing tests: B3's no-rewrite (a corrupt file must never be rewritten), B4's
  resolve-once (no re-read, no overlap), B5's decision table (absent/unknown/invalid all land
  on rules with a loud log).

## 5. Environment & Secrets

- None. No network, no keys (the resolver injects a key-provider factory; nothing reads a real
  Keychain), no new dependencies.

## 6. Edge Cases & Error Handling

- **Absent file ⇒ rules, silently** — the default configuration, and the zero-network probe
  runs exactly that path.
- **Invalid file ⇒ rules + one loud log** — never silently different from the file.
- **Never throws** — a corrupt file degrades, never crashes, never rewrites the user's file.
- **Resolve-once** — a second `resolve()` returns the cached provider without re-reading the
  file; a concurrent second call shares the in-flight build.
