**Capability:** C1 · **Phase:** P0 · **Branch:** `feat/audio-capture/aliz`
**Depends on:** `hotkey-source` (merged, `5c07884`) · Baseline: 324 tests

Full adversarial review standard.

---

## 0. The organising constraint, and why it is worse than last time

`hotkey-source` could not be tested by CI because `CGEvent.tapCreate` needs a TCC grant no runner can
be given. That was a *permission* problem. This aspect's is architectural: **`AVAudioSinkNode` is
unsupported in manual rendering mode**, so the realtime capture path has no offline equivalent at
all. No grant, no entitlement, no self-hosted runner fixes it.

So the split is the same and the discipline is stricter:

- **Above the seam** — the ring buffer, the format conversion, the session wiring, the configuration-
  change policy. All of it runs headlessly, and all of it is where the branches live.
- **Below the seam** — `AVAudioEngine`, `AVAudioSinkNode`, the realtime block. **No decisions.**

`hotkey-source` proved the payoff: 310 lines of tap adapter that CI never executes, every conditional
in it verified as a translation, and the aspect still reached 324 tests.

## 1. Phases

### Phase 1 — The ring buffer

**Goal:** the one place `@unchecked Sendable` is permitted, done properly.

SPSC, preallocated, `Synchronization.Atomic` with explicit acquire/release. The realtime thread is
the sole producer; a consumer task drains it. **Poll the ring on a timer rather than signalling** —
`AsyncStream.yield`, `Task`, `DispatchSemaphore.signal` and locks are all forbidden on the producer
side, and at a 10 ms poll against a 100 ms-scale pipeline the cost is nothing.

**RED:** two real threads under TSan, thousands of iterations; wraparound; the overrun policy stated
and asserted; capacity boundaries. **The `@unchecked Sendable` must carry a comment stating the
invariant the compiler cannot verify** — it is the only one in the codebase and every reviewer will
check it.

**Commit:** `Add the SPSC ring buffer the realtime thread writes into`

---

### Phase 2 — Format conversion

**Goal:** hardware format → 16 kHz mono Float32, off the realtime thread.

`AVAudioConverter` allocates, so it runs on the consumer side. Hardware will be 44.1/48 kHz — **or
16 kHz if a Bluetooth HFP device is active**, which is a real case and not an edge one.

**RED:** a synthetic 48 kHz sine converts to 16 kHz with the expected sample count and frequency
(FFT or zero-crossing). No device, no permission, fully headless. Then the pass-through case: input
already at 16 kHz mono must not be re-converted.

**Commit:** `Convert captured audio to the ASR interchange format off the realtime thread`

---

### Phase 3 — The tap-callback decision, and the engine-start measurement

**This phase decides the thing two aspects deferred, and it comes before the engine so the answer
shapes it.**

The shipped chain is synchronous from the tap callback into `beginCapture()`. Once `beginCapture()`
is a real `AVAudioEngine.start()`, that chain earns `kCGEventTapDisabledByTimeout` — which disables
the tap **mid-session**, which is the hot mic the last aspect spent four rounds bounding.

Three constraints, all established: the callback must return fast; the start takes milliseconds; the
engine cannot be pre-warmed because that lights the microphone indicator permanently.

**Measure the start cost first** — the PRD requires it and nobody has done it. Then decide, and
implement, with the machinery `session-lifecycle` already built and tested: `isOpeningTheMicrophone`
and the deferred-stop path exist precisely for a slow open.

**Report numbers, not reassurance.** And per the lesson `hotkey-source` paid for: **a measurement of
a state must verify the state was entered.**

**Commit:** `Decide and measure the capture start off the tap callback`

---

### Phase 4 — The engine graph

**Goal:** the thin adapter. **The only phase whose code CI cannot execute.**

- `AVAudioSinkNode` on the input chain, connected at the input node's **own** output format — the
  sink node does not convert.
- The realtime block writes into the ring and does nothing else.
- Engine started on demand, stopped on session end, `prepare()` after each stop; engine, sink,
  converter and ring allocated for the app's lifetime — **never a graph rebuild per press**.
- `AVAudioEngineConfigurationChangeNotification` → end the session via the existing trigger, **keep
  the audio**.

**Two things the A3 lint requires of this phase, decided in Phase 1's review rather than discovered
here:**

- **Write the sink body as a named `func`, passed to the node** — `AVAudioSinkNode(receiverBlock:
  self.render)` — not as an inline closure. `// @realtime` marks a *declaration*; a marker above a
  closure is now a hard error rather than a marker that silently adopts the next function below it,
  which is how an allocating, logging realtime body was measured passing the entire suite. Add
  `"…: render"` to `expectedRealtimeDeclarations` in the same commit.
- **Reach the audio through `.pointee.mBuffers.mData`, not `UnsafeMutableAudioBufferListPointer(…)[0]`.**
  The lint forbids `[` on the realtime path, and the escape hatch its message offers
  (`.advanced(by:)`) does not exist on a `Collection` subscript. The pre-decided route avoids the
  subscript for the mono case. **Do not delete the `[` rule to get past it** — it is the only pass
  that catches a copy-on-write check on a stored array, which is the more likely defect of the two.

Also expect `permittedCalls` to roughly double. It is one set shared across every realtime body, so
every name added there is granted to `AudioRingBuffer.write` too; if that becomes uncomfortable, the
fix is a per-declaration allow-list, and this is the phase that makes it worth having.

**Validation:** the source lint must show no decision in this file, and the realtime block must
allocate nothing. If review finds a branch worth testing here, it moves up.

**Commit:** `Add the AVAudioEngine capture graph`

### Phase 5 — `SessionAudioSource` conformance and the release obligation

**Goal:** satisfy the constraint the seam has carried since `session-lifecycle` — **and carry the
ring's refusal count across the seam**, which is one link of the transcript invariant and not the
whole of it.

**The obligation Phase 1 hands over, and it is not optional.** `AudioRingBuffer`'s overrun policy is
drop-newest, and the entire reason that is acceptable for a product whose invariant is *a transcript
is never lost* is that the loss is **countable**: `refusedSampleCount` says exactly how many samples
the ring would not take. Phase 1 built the counter and **nothing reads it**. A counter nobody reads
does not make a loss known; it makes it recorded and ignored, which is indistinguishable from
silently short audio at every point downstream.

So: `endCapture()` must read `refusedSampleCount` and the hand-over must carry "short by N samples"
alongside the buffer, so that whatever presents the transcript can present it as incomplete rather
than as complete. A `Buffer` type that can only say *here is some audio* cannot express this, so the
type is part of this phase's design, not an afterthought to it.

**RED:** a source whose ring refused samples hands over audio marked incomplete **and the number it
carries equals the ring's `refusedSampleCount`**; a source that refused none hands over audio marked
complete. All three clauses, because a one-bit flag satisfies "marked incomplete" exactly as written
and throws away N — and *countable*, not merely *flagged*, is the entire justification for
drop-newest. The negative case is there because "always incomplete" passes a one-sided test.

**This is assigned, not enforced.** Nothing fails if Phase 5 does not do it: this is a phase goal, a
failure-table row and a named RED, and no check anywhere goes red. The mechanism was available —
this repository converted two obligations of exactly this shape into lints in the round that wrote
this paragraph — and it was not used here, because a lint requiring `refusedSampleCount` to have a
reader would be red today. That is a real choice and it is recorded as one; "open with an owner"
would read as stronger than it is.

**And it closes one link, not the chain.** Ring → `SessionAudioSource` hand-over is this phase.
Hand-over → transcript → *the user is told the audio was short* is owned by nothing in this plan or
in `CAPABILITY_ROADMAP.md`. When Phase 5 lands, the count reaches the seam and stops there. That is
acceptable sequencing and it is not a closed invariant.

`endCapture()` is non-failable, so a conformance whose teardown fails **has no way to report it** —
the machine goes `.idle`, the widget shows idle, and nothing looks again. The obligation is on
`endCapture()`'s own doc comment: **it must not return until the input device is released, and a
conformance that can fail here must trap rather than return.**

Also: `VoccaAudio` moves `leafModules` → `adapterModules` with `dependencies: ["VoccaCore"]`, and
**no `deinit` may call an asserting entry point** — that rule has been needed three times; this is
the fourth place it would be.

**Commit:** `Release the device before returning, and make failure loud`

---

### Phase 6 — Smoke steps

A6 (the indicator is dark between sessions) and A7 (engine-start latency) go into
`SMOKE_CHECKLIST.md`, with **pass criteria tighter than the failures they guard**.

The indicator step is this aspect's equivalent of the one `hotkey-source` found most valuable:
**watch the orange dot, and time it.** Lit while idle means the engine is being kept warm — the
privacy failure constraint 2 exists to prevent. Slow to go out after release means `endCapture()` is
returning before the device is released, which is constraint 3 failing silently.

**Commit:** `Record what CI cannot cover about the microphone`

## 2. Failure modes to handle explicitly

| Situation | Required behaviour |
|---|---|
| `AVAudioEngine.start()` fails | `CaptureStart.unavailable`; the machine already handles it; the user must learn something |
| Device switches mid-session | End via the trigger, **keep the audio** |
| Bluetooth HFP active | Input is 16 kHz; the converter must pass through, not resample |
| Ring buffer overrun | Stated policy, asserted — not "cannot happen". Drop-newest, whole block, counted in `refusedSampleCount`. **Phase 5 must read that counter and mark the hand-over incomplete** — a count nobody reads is not a loss anybody knows about |
| `endCapture()` teardown fails | **Trap.** It cannot report, so it must not return |
| Engine left running between sessions | The mic indicator lights. This is a privacy defect, not a performance one |

## 3. Agent execution notes

**Checkpoints:** after Phase 1 (the `@unchecked Sendable` is the only one in the codebase) and after
Phase 3 (the decision and the measurement are the deliverable, not the wiring).

**Ask before proceeding** if a phase seems to need a decision inside the realtime block or the engine
adapter. It does not — that instinct means the seam is in the wrong place.

**Do not** weaken any existing test, add a coverage-guard exclusion, let `AVFoundation` types escape
the adapter, or copy the asserting-`deinit` mistake a fourth time.
