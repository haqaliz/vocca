### 🔴 Blocker to acknowledge before Phase 5

`ROADMAP.md:308` (R9) says *"Sign and notarize from week 1 — never discover this at ship time."*
That requires an Apple Developer Program membership and a Developer ID Application certificate.
**Neither exists on this machine.**

**Decision taken (proceeding under a stated assumption, flagged for the founder):**
- Phase 5 creates a **stable self-signed identity** for local development. This is what actually
  matters day-to-day: it makes TCC grants persist across rebuilds, avoiding the failure where a
  re-signed binary silently loses Accessibility and the tap looks healthy but never fires.
- The notarization script ships, is exercised up to the credential boundary, and **skips with a
  clear message** when credentials are absent.
- **R9 is therefore only partially retired.** The pipeline exists; it has never been run
  end-to-end. That should be stated honestly rather than ticked off. Getting a Developer ID is a
  purchase decision for the founder, and until it happens, the notarization step is unproven.

> **Why a test and not just a convention:** `ARCHITECTURE.md:45` says the graph "is strictly

### Phase 3 — Zero-network interposer 🔒

**Goal:** Stand up the permanent release blocker while it is trivially satisfiable.
**Prerequisites:** Phase 1.

`CLAUDE.md:108-110` calls this a permanent release blocker for **all** configurations.
`CAPABILITY_ROADMAP.md` schedules it at C6; the review decision moved it here, because C1 is
when the suite is created and there is nothing to fix.

**RED.** `Tests/HarnessTests/ZeroNetworkTests.swift` — installs a socket interposer, exercises
the default path, asserts **zero** outbound connections. Written to fail first by asserting
against a deliberate probe connection, then inverted.

**GREEN.** Interposer harness in `Tests/Harness/NetworkInterposer.swift`.

**Implementation note:** prefer an injectable `URLProtocol` + a `getaddrinfo`/`connect`
interposer via `DYLD_INSERT_LIBRARIES` in the test process. If `DYLD` interposition proves
unreliable under `swift test`, fall back to asserting that **no target links a networking
symbol** — weaker, but still a real gate. **Flag which one was used**; do not silently ship the
weaker version as though it were the stronger.

**Validation:** `swift test --filter ZeroNetworkTests`
**Commit:** `Add zero-network CI assertion as a permanent release blocker`

### Phase 4 — App bundle, Info.plist, entitlements

**Goal:** A signed `.app` that launches invisibly and carries the exact keys the microphone
prompt depends on.
**Prerequisites:** Phases 1–3.

**RED.** `Tests/HarnessTests/BundleConfigurationTests.swift` asserts against the **built
bundle**: `NSMicrophoneUsageDescription` present and non-empty; `LSUIElement == true`;
`CFBundleIdentifier == dev.vocca.Vocca`; entitlements contain
`com.apple.security.device.audio-input`; entitlements **do not** contain
`com.apple.security.app-sandbox` or `com.apple.security.cs.disable-library-validation`.

**GREEN.** Create the Xcode app target, `App/Info.plist`, `App/Vocca.entitlements`, and a
`@main` `NSApplicationDelegate` that sets `.accessory` and shows nothing.

**Files:** `Vocca.xcodeproj`, `App/Info.plist`, `App/Vocca.entitlements`, `App/VoccaApp.swift`,
`Tests/HarnessTests/BundleConfigurationTests.swift`

**Validation**
```bash
xcodebuild -project Vocca.xcodeproj -scheme Vocca -configuration Debug build
swift test --filter BundleConfigurationTests
```
**Commit:** `Add app bundle with hardened-runtime entitlements and plist assertions`

> **Why these are load-bearing tests:** with hardened runtime enabled and
> `com.apple.security.device.audio-input` missing, macOS **denies the microphone without ever
> prompting**. The app simply receives no audio, with no error. A missing
> `NSMicrophoneUsageDescription` fails the same silent way. These two assertions are the
> cheapest possible insurance against a whole class of "why is there no sound" debugging.

---

### Phase 5 — Signing and notarization scripts

**Goal:** TCC grants survive rebuilds; the notarization path exists and is honest about being
unproven.
**Prerequisites:** Phase 4. **See the 🔴 in §0.**

**Steps**
1. `Scripts/dev-identity.sh` — create/import a **stable self-signed** codesigning identity
   (`Vocca Development`), idempotent. Documented in `README.md`.
2. `Scripts/sign.sh` — `codesign --force --options runtime --timestamp --sign "$IDENTITY"`,
   inner binaries before the bundle. Verifies with `codesign --verify --strict --deep`.
3. `Scripts/notarize.sh` — `notarytool submit --wait` → `stapler staple`. **Detects absent
   credentials and exits 0 with an explicit skip message**, so CI is not red for a reason
   nobody can fix.

**Validation**
```bash
./Scripts/dev-identity.sh && ./Scripts/sign.sh
codesign --verify --strict --verbose=2 build/Vocca.app   # must pass
./Scripts/notarize.sh                                    # must skip cleanly, not fail
```
**Commit:** `Add signing scripts with a stable dev identity and credential-gated notarization`

> **Never ad-hoc sign.** Ad-hoc (`-`) signing produces a new code identity per build, and TCC
> grants stop applying. The symptom is not an error: `tapCreate` returns non-nil,
> `tapIsEnabled` returns true, and the callback never fires. That is a day lost to debugging a
> problem that is not in the code.

### Phase 6 — CI

**Goal:** Every later aspect is guarded from its first commit.
**Prerequisites:** Phases 1–5.

`.github/workflows/ci.yml` on `macos-15` (or later): `swift build` with strict concurrency as an
error, then `swift test`. **No Xcode project build in CI** — it needs signing.

**Explicitly documented in the workflow file:** CI can never exercise the event tap, the
microphone, or `AVAudioSinkNode`. `CGEvent.tapCreate` returns `nil` without a TCC grant, and
there is no way to grant it on a hosted runner. This is why every seam sits above the system
API, and why a manual smoke checklist exists.

**Files:** `.github/workflows/ci.yml`, `docs/SMOKE_CHECKLIST.md`
**Validation:** workflow green on push.
**Commit:** `Add CI running the headless suite under strict concurrency`

- **No third-party dependencies** — which is part of why A3 passes trivially today.

## 6. Edge cases and failure modes

| Situation | Behaviour |
|---|---|
| No codesigning identity | `dev-identity.sh` creates one; never falls back to ad-hoc |
| No notarization credentials | `notarize.sh` skips with an explicit message, exit 0 |
| Xcode absent (CI) | `swift test` still runs — that is the point of the split |
| `DYLD` interposition unreliable in tests | Fall back to symbol-linkage assertion **and say so** |
| Bundle ID changed later | Silently revokes every user's TCC grant. Comment says so at the definition |
| Strict-concurrency warning appears | Build fails. Not deferred — retrofitting is the harder path |

## 7. Agent execution notes

**Checkpoints for human review**
1. After Phase 3 — confirm which interposer technique actually worked. This is the one place a
   weaker implementation could masquerade as the stronger guarantee.
2. After Phase 5 — confirm the self-signed fallback is acceptable, and decide whether to acquire
   a Developer ID now.

**Likely to need iteration**
- Phase 3's interposer under `swift test`.
- Phase 4's Xcode project generation — `.xcodeproj` is XML and hostile to hand-editing. Prefer
  generating it, or keep it minimal enough to hand-write once and never touch.

**Ask before proceeding**
- If Phase 4 requires enabling a capability beyond `audio-input`, stop and ask. The entitlement
  set is a security surface and a notarization-scrutiny surface, and additions are not routine.

**Do not**
- Add any third-party dependency without raising it — each one is a new zero-network risk and a
  new signing surface.
- Weaken `ZeroNetworkTests` to make it pass. It is a release blocker by design; if it fails,
  the code is wrong, not the test.
