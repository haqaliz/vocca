# Implementation plan — `session-lifecycle`

**Date:** 2026-08-04 · **Aspect:** [`spec.md`](./spec.md) · **PRD:** [`../prd.md`](../prd.md)
**Capability:** C1 · **Phase:** P0, week 1 · **Branch:** `feat/session-lifecycle/aliz`
**Depends on:** `project-skeleton` (merged, `fec6f2c`)

Executed under strict TDD through the agents team, at the **full adversarial review standard** —
this is the aspect where a defect means the microphone stays open or the user's words are lost.

---

## 0. Why this aspect is different

Every other part of C1 fails loudly. This one fails *silently*: a session that outlives its key-up
leaves the mic hot while the widget says nothing is happening. `PRODUCT_SPEC.md:11` states the
invariant as *"There is no state where Vocca is listening and doesn't look like it"*, and
`CLAUDE.md` sells the product on *"your audio never has to leave it"*. A hot mic is not a bug in
that product, it is the end of it.

So the whole aspect is **pure Swift with zero system APIs** — no `CGEvent`, no `AVAudioEngine`, no
AppKit — which means 100% of it runs headlessly on any runner with no permissions, no microphone and
no network. That is a deliberate design constraint, not a convenience: `CGEvent.tapCreate` returns
`nil` without a TCC grant and no hosted runner can be granted one, so logic that lives below the
seam is untestable forever.

**Carry-forward from the last aspect's final review** (see `spec.md` — these were each earned by a
defect that shipped past a green suite):
- **Assert the effect, never the reference.** `stop()` being called is not the microphone being
  released.
- **Fail closed on unclassifiable input.** A watchdog that cannot tell what state it is in must
  fault, not assume idle.
- **Every zero-assertion needs a positive control sharing its mechanism.**
- **Exhaustive switches, no `default:`.**
- **Give this suite its own test-count floor** — `swift test` exits 0 when it discovers nothing.
- **Do not add a sixth `packageRoot` walker** — consolidate the five that exist, in task 1.

### Phase 2 — `RawKeyEvent`, `SessionState`, `EndReason`, `Decision`

**Goal:** the vocabulary, with no behaviour.

**Commit:** `Add the session vocabulary with an enforced system-API boundary`

---

### Phase 3 — `decide(_:state:)`, the pure decision function

**Goal:** the single place the stuck-recording bug can live, and therefore the single place its tests
live.
**RED first, table-driven**, covering every case in `spec.md` acceptance B2/B3/B4/B11:
- start rule: keyDown + configured key + configured modifiers + `!isAutorepeat` + `state == .idle`
- stop (a) keyUp on the configured key
- stop (b) `flagsChanged` no longer carrying the modifier ← **covers release-Option-first**
- stop (c) any event whose flags lost the modifier
- autorepeat during `.recording` neither restarts nor ends
- a later unmatched `keyUp` after a modifier-first release starts nothing and ends nothing
- purity: identical output over 10,000 randomised sequences
**GREEN:** derive modifier state from `event.flags` on **every** event. Never accumulate — that is
the [Handy #840](https://github.com/cjpais/Handy/issues/840) defect: v0.1.4 derived and worked,
v0.2.0 accumulated on `flagsChanged` and desynced permanently after one missed event.
**Commit:** `Add the pure session decision function`

### Phase 4 — The session state machine and the custody funnel

**Added after task 3's review — a user-visible bug this phase must fix.**

After a rule-(b) stop (modifier released before the key), the still-held configured key starts
**passing through**, so the OS's autorepeat types plain characters into the very field the transcript
is about to be injected into — at the system repeat rate, unless the user releases within ~30-60 ms.
This is the same failure as an unswallowed `⌥Space` inserting U+00A0, reached from the other side of
the modifier release. Separately, `claimsThisEvent` requires the chord for `.keyDown` but not
`.keyUp`, so a passed-through key-down can be followed by a swallowed key-up, leaving the focused app
an **unpaired key-down** — a key it believes is still held, which is worse than an unpaired key-up.

It is not fixable in `decide`: a stateless function cannot know that a physically-held key is the tail
of a press Vocca swallowed. **The session must carry it.** Task 4 already reads physical key state for
stop rule (f); that read is the missing fact. Carry "the hotkey key has not yet come back up" in
session state and keep swallowing that key code until it does, regardless of chord — then release the
claim. Test both halves: no character reaches the app after a modifier-first stop while the key is
still held, and the app is never left an unpaired key-down.

**Also pinned for this phase, from task 2's re-review:**
- `endSession` returns `SessionOutcome<Audio>` — **non-optional, not `.Content`, not a tuple.** That
  one sentence closes two of the five audio-discard shapes tried against the sealed type.
- Pass `make` the reason it was given and the buffer it captured.
- The property test must assert the payload **equals the known captured buffer**, not merely that the
  case is `.completed` — otherwise a shape that swaps in an empty buffer passes. `XCTUnwrap` the
  outcome.
- `any CapturedAudio` does **not** self-conform, so `SessionOutcome<any CapturedAudio>` is illegal and
  `VoccaCore` cannot name `VoccaAudio`'s buffer type. **The machine must be generic** —
  `SessionMachine<Audio: CapturedAudio>` — and that parameter propagates to everything holding it.


**Goal:** `idle → recording → ending → idle` with an injected clock, and **one**
`endSession(reason:)` through which every path passes.
**RED:** B8 is the invariant made executable — *property-based: for every `EndReason` except
`.userCancelled`, the captured audio is emitted exactly once.* Plus B9: double-start,
stop-without-start and stop-twice are safe no-ops. Plus B5/B6: ceiling expiry fires at exactly the
configured deadline; poll-reported release ends within one interval.
**GREEN:** `SessionActor`-shaped type with an injected clock. Discard must not be *representable*
for any reason except `.userCancelled` — express that in the type, not in a comment, so a later
refactor cannot route another reason through it (`spec.md` open question 3).
**Assert the effect:** the test must observe *audio emitted*, not *`endSession` called*.
**Commit:** `Add the session state machine with a single custody funnel`

### Phase 5 — Watchdog policy and system triggers

**Goal:** the hot-mic guarantee.
**RED:** ceiling (120 s default) fires; the injected physical-key poll ending a session is observed
as an *effect*; each `SystemTrigger` (`willSleep`, `screensDidSleep`, `sessionDidResignActive`,
`audioConfigurationChanged`, `secureInputEnabled`) maps to a stop with its own `EndReason`; and a
**positive control** proving the harness can detect a session that *did* stay open — otherwise
"the mic did not stay open" asserts nothing.
**GREEN:** policy only. The physical-key read is injected (it is a system call and belongs to
`hotkey-source`). Poll interval a named constant at **150 ms** with the tradeoff in a comment
(`spec.md` open question 2). The watchdog stays a **dumb timer** — the moment it makes a
speech-boundary decision it becomes VAD, which `ROADMAP.md:45` defers to P3.
**Commit:** `Add the watchdog policy and system-trigger mapping`

## 4. Failure modes to handle explicitly

| Situation | Required behaviour |
|---|---|
| Key-up never arrives | Watchdog ends the session **and still emits the audio** |
| Modifier released before the key | Stop rule (b). The commonest stuck-recording cause |
| Event tap disabled mid-session | End immediately — the key-up is never coming |
| System sleeps mid-session | End via `SystemTrigger`, audio preserved |
| Clock jumps backwards | Must not extend a session. State it, test it |
| Session state unclassifiable | **Fault, do not assume idle** |
| `Esc` cancel | The only path that discards, and it must be structurally distinct |
