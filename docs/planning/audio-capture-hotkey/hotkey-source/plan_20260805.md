## 0. The organising constraint

`CGEvent.tapCreate` returns `nil` without an Accessibility grant, and **no hosted runner can be
granted one**. So the aspect is drawn in two halves:

- **Above the seam** — flag translation, tap-health policy, permission state, session wiring. Every
  branch worth testing lives here and runs headlessly.
- **Below the seam** — `tapCreate`, the C callback, `CGEventSourceKeyState`. This half must contain
  **no decisions**: it translates, forwards, and returns. If it grows an `if`, the `if` is in the
  wrong half.

The previous aspect proved this pays: 143 tests, ~150 mutations, and everything that mattered was
testable because the system APIs sat in two files with nothing to decide.

## 1. Phases

### Phase 1 — Flag translation and the `fn` rule

**Goal:** the pure function that turns a `CGEventFlags` bit pattern plus a key code into Vocca's
`ModifierSet`, correctly.

**RED:** table-driven over every modifier; then the `fn` set — F1–F20, arrows, Home/End/PgUp/PgDn,
forward-Delete, Help — each key code named individually, asserting `fn` is stripped. Then the
inverse: a genuine `fn`-held binding on a key that does *not* carry it implicitly keeps the bit.

**Why first:** it is the only part of this aspect that is pure, and it is where the founder's `fn`
decision lands. `ModifierSet.swift`'s doc comment states the decision and warns that nothing in the
core will catch a `VoccaHotkey` that forgets it.

**Commit:** `Translate event flags into a modifier set, stripping implicit fn`

### Phase 2 — The `HotkeyEventSource` seam and a driveable fake

**Goal:** the protocol, plus a fake that lets the whole session pipeline be driven headlessly.

**RED:** the 100-cycle acceptance from `CAPABILITY_ROADMAP.md:42` — 100 synthetic key-down/key-up
pairs at 80 ms – 60 s, asserting 100 started, 100 ended, zero overlapping, zero orphaned — now driven

own seam; this proves it over the one the tap will implement.

**Also RED:** a source lint asserting no `CGEvent`/`CGEventFlags`/`CFMachPort` type escapes the
implementation file (H7).

**Commit:** `Add the HotkeyEventSource seam and drive the machine through it`

### Phase 3 — Tap health policy

**Goal:** the decisions about a dying tap, with the tap injected.

**RED:** a tap-disabled event ends the in-flight session **and** re-enables (H3); when re-enable
fails, the policy re-creates (H4); `tapCreate` returning `nil` surfaces as "permission missing", not
a crash or silence (H5); a re-created tap always ends any in-flight session — a tap that died may
have dropped the key-up, so continuing would be a hot mic.

**GREEN:** policy only, over an injected tap handle. No `CGEvent` call in this file.

**Amended 2026-08-05, review round 1: the ~1 s health poll belongs here and this plan omitted it.**
`spec.md:57` puts it in scope — *"A health poll (~1 s) on `tapIsEnabled`; if re-enable fails, tear
down and re-create"* — and H4 is phrased in terms of it. It appeared in no phase. That was a planning
error, and it mattered more than it looked: **the poll is the only thing that catches a tap which
dies with no notification of any kind**, and measurement confirmed the gap — armed, delivering,
session in flight, tap dies silently, and the microphone stays open with the machine `.recording` in
*both* activation modes. In toggle it is worse than in hold-to-talk: there is no physical-key poll
behind it (`SessionRules.swift:357-359` — with the poll gone, rule (d) is *"the only stop that a dead
tap can still deliver"*), so the residual is a two-minute hot mic bounded only by the ceiling.

So the **policy half is built in this phase**: `pollTapHealth()`, over an injected `isDelivering`
read, plus `TapHealthPolling.interval`. It is the one entry point that does **not** end the session
unconditionally — it runs once a second for as long as Vocca runs, so applying that rule without
thinking would cut every session off within a second of starting. **The timer that drives it belongs
to Phase 5**, beside the watchdog timer and subject to the same two unmeasured hazards (run-loop mode
during a drag, App Nap).

**Commit:** `Add tap health policy over an injected handle`

### Phase 4 — The real tap

**Goal:** the thin adapter. **The only phase whose code cannot be tested here.**

- `.defaultTap` / `.cgSessionEventTap` / `.headInsertEventTap`, mask
  `keyDown | keyUp | flagsChanged`.
- Non-capturing `@convention(c)` callback; context via `Unmanaged.passUnretained`, **held strongly
  for the tap's lifetime** or it is a use-after-free.
- `MainActor.assumeIsolated` in the callback; the machine constructed in that domain (constraint 5).
- Returns `nil` to swallow, the event to pass through — **driven entirely by the machine's answer,
  never decided here** (constraint 4).
- The callback does nothing else (constraint 7).

**The decision this phase must make on purpose** *(added 2026-08-05, phase 3 review)*: the two
disable notifications are delivered **to the callback**, so the adapter's only route to
`TapHealthPolicy.tapWasDisabled(_:)` is from inside a synchronous C function that must return a
disposition. What that callback then executes is an `AVAudioEngine.stop()` (through the session end),
a `CGEventTapEnable`, and — on the failing path — a `stop()` that **invalidates the `CFMachPort`
whose callback is currently on the stack**. That violates inherited constraint 7 as squarely as the
start path does, and it is *worse* on the `.timeout` route, because that timeout was earned by the
callback being slow and the recovery adds more slow work to the same callback.

The likely shape — end the session synchronously, since immediacy is the entire point of it, and
defer **only** the teardown-and-re-create to the next run-loop turn — is a real design decision with
a real cost. Decide it here rather than discover it. **Only `tapWasDisabled` has this shape**:
`systemDidWake`, `accessibilityGrantChanged` and `pollTapHealth` arrive on notifications and timers,
so deferring all of them would pay the cost four times over. `TapHealthPolicy.tapWasDisabled(_:)`'s
doc comment carries the call graph.

**Validation:** the source lint from Phase 2 must still pass, and this file must contain no branch
beyond translating the machine's answer. If review finds a decision here, it moves up.

**Commit:** `Add the CGEvent tap adapter`

### Phase 5 — The physical-key reader and the watchdog timer

**Goal:** wire the two things `session-lifecycle` left injected, and **measure the hazards it
refused to claim**.

- `CGEventSourceKeyState` / `FlagsState` with `.combinedSessionState` behind the existing protocol.
- The timer driving `SessionWatchdog.wake()`.
- **The timer driving `TapHealthPolicy.pollTapHealth()`**, at `TapHealthPolling.interval` (1 s). Phase
  3 built the policy half; this is its clock. Both hazards below apply to it identically, and it is
  the backstop with the widest reach — it is the only one that works in toggle mode.

**The measurement, which is the point of this phase.** Task 5 flagged two hazards explicitly
unverified, and together they are the last remaining unbounded hot mic:
1. A timer in the default run-loop mode stops firing during menu tracking and window drags →
   add it in `.common` modes, and **verify by dragging a window during a session**.
2. App Nap may throttle an `LSUIElement` app's timers → `ProcessInfo.beginActivity` is the usual
   countermeasure. **Measure whether it changes anything, and what it costs.**

Report numbers, not reassurance. If the ceiling does not fire during a window drag, the microphone
stays open while the widget says it is not — which is the sentence `PRODUCT_SPEC.md:11` exists to
defend.

**Commit:** `Add the physical-key reader and the watchdog timer`

---

### Phase 6 — Secure Input, and the smoke checklist

**Goal:** the failure that looks like a Vocca bug and is not.

`IsSecureEventInputEnabled()` — when any app enables it, taps receive **no key events at all**.
Detect and surface it distinctly (H8).

**This phase owns the half of "silently dead" that phase 3's health poll cannot see** *(added
2026-08-05, phase 3 re-review)*. The poll's detection is one read, `CGEventTapIsEnabled`, so it
catches a tap that was *disabled* silently. It cannot catch a tap that is **enabled and deaf** —
created successfully, reporting itself enabled, delivering nothing. There are two known instances and
both are this project's own claims: a tap created before the Accessibility grant has its mask cleared
at creation (inherited constraint 3, and the reason `accessibilityGrantChanged()` re-creates rather
than re-enables), and Secure Input. Only the second has an API. In toggle mode the uncaught shape is
still a 120 s hot mic with nothing but the ceiling under it, which is what makes H8 a safety item here
and not only an honesty one. `TapHealthPolicyTests.testThePollCannotSeeATapThatIsEnabledAndDeaf`
measures the gap and will fail when it is closed — updating it is how the limit moves on purpose.

Then `SMOKE_CHECKLIST.md`: every step this aspect cannot automate, with the exact gesture. At
minimum — grant Accessibility and confirm the tap arms; revoke it and confirm the honest message;
hold the hotkey while dragging a window and confirm the ceiling still fires (**H10**); focus a
password field and confirm Secure Input is reported rather than looking broken; sleep and wake and
confirm the tap re-creates.

**Commit:** `Detect Secure Input and record what CI cannot cover`

## 2. Failure modes to handle explicitly

| Situation | Required behaviour |
|---|---|
| Accessibility not granted | `tapCreate` returns `nil` → honest "permission missing", never a silent no-op |
| Granted while running | Re-create the tap; `CGEventTapEnable` cannot resurrect a cleared mask |
| Tap disabled by timeout | Re-enable **and** end the session — the key-up is not coming |
| Tap dies across sleep/wake | Re-create on `didWakeNotification` |
| Secure Input active | No events arrive; say so rather than looking broken |
| Timer starved (drag, App Nap) | **Measure.** This is the last unbounded hot mic |
| Key code carries `fn` implicitly | Strip it, or single-key bindings break |

## 3. Agent execution notes

**Checkpoints:** after Phase 1 (the `fn` rule is a founder decision with a documented failure mode)
and after Phase 5 (the measurement is the deliverable, not the wiring).

**Ask before proceeding** if a phase seems to need a decision inside the tap callback. It does not —
that instinct means the seam is in the wrong place.

**Do not** weaken any existing test, add a coverage-guard exclusion, or let `CGEvent` types escape
the adapter. Run `./Scripts/test-with-floor.sh`, never bare `swift test`.
