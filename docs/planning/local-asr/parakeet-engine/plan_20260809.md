## 0. The organising constraint

Three things in this aspect cannot run in CI — the FluidAudio SDK's behaviour, the CoreML
model, and the adapter's hold on the manager object — so the aspect's entire structure is
the tap-adapter lesson applied a third time: **extract every decision above the FluidAudio
line, test it headlessly, and keep the adapter itself thin glue that CI never executes —
stated, not hidden.** The first phase is the F1 spike, which decides how much more than
that is possible (the stop/go on the CI-gated real-model suite).

Two decisions recorded so the agents do not relitigate them:

- **The mapper, the load state, the timing, and the identity constant contain no FluidAudio
  names.** `ParakeetTranscriptMapper` takes primitives (`text: String`) and returns the
  seam's `Transcript`; `ParakeetLoadState` is a pure struct; `EngineTiming` takes
  `MonotonicClock` (Core's injectable clock). Only `ParakeetEngine.swift` names the SDK.
- **If the SDK answers differ from the provisional shapes** (Sendability, result fields,
  `ModelHub.offlineMode` readability), the adapter adapts, the seam does not, and the
  difference is recorded in `spike_20260809.md` — the spike's findings are the law for the
  adapter, not this prose.

### Phase 1 — The SDK-shaped store layout (the spike's load-bearing finding, `spike_20260809.md` §4.1)

**Goal:** the store can produce the layout `AsrModels.load(from:)` demands — files under a
`<repo.folderName>/` subdirectory of the version dir, nested paths included — without
weakening the verified-presence contract.

**RED first** — extend `Tests/HarnessTests/ModelStoreTests.swift` and
`Tests/HarnessTests/ModelDownloaderTests.swift`:
- A manifest with `sdkDirectory: "parakeet-tdt-0.6b-v3"` downloads, verifies, and commits
  with every file under `<version>/<sdkDirectory>/`; the marker stays at `<version>/`;
  `isPresent` is true only at commit.
- Nested manifest names (`"Encoder.mlmodelc/model.mil"`, `"Encoder.mlmodelc/weights/x.bin"`):
  intermediate directories are created by the downloader; the commit's rename crosses them;
  the final tree mirrors the manifest.
- **Recursive presence:** a `.part` file nested two levels deep keeps `isPresent` false even
  with the marker present (the "a `.part` anywhere" promise survives nesting); the
  immutability snapshot becomes recursive (a second `downloadIfMissing` on a committed
  sdkDirectory version leaves the tree untouched).
- Resume across nested paths: a dead transfer leaves `<version>/<sdkDirectory>/<nested>.part`,
  and the next run resumes from its size.

**Then implement** (in `VoccaASR/Models/`): `ModelManifest.sdkDirectory: String?` (Codable,
validated: a single path component, no `..`, no leading slash); the store's
`performDownload` prefixes file paths with it; the downloader creates intermediate
directories before the first write; `ModelStore.isPresent` and the snapshot helper scan
recursively.

**Validation:** suite green; floor raised; the Phase 1 store tests unchanged and green.

**Commit:** `Shape the model store for the SDK's repo layout`

  - `identity` = the Phase 2 constant; `supportsStreaming == false`.
  - Init sets `ModelHub.offlineMode = true` (readable and settable — measured), stores the
    injected `ModelStore`/`ModelManifest`/transport, an injected loader seam (default = the

    **`store.baseURL(for:engineID, version:) + sdkDirectory`** — the SDK's layout rule

    short-circuit via the mapper (the seam's policy, kept above the SDK).
  - Holds the SDK manager directly — **`AsrManager` is a Swift actor, Sendable by
    construction** (measured); no wrapper needed. **The file is thin glue; its decisions

## 2. Failure modes to handle explicitly

| Situation | Required behaviour |
|---|---|
| Model absent (user skipped the download) | `prepare()` throws `VoccaError.modelUnavailable(identity, reason:)` with an honest reason; the engine is not loaded; a later `prepare` after the download succeeds — `ParakeetLoadState` guarantees retry |
| Load fails mid-way | Not loaded; next `prepare` retries; the store's `.part`/verified semantics are the downloader's, untouched |
| SDK errors on empty samples | The engine short-circuits empty buffers through the mapper (valid empty Transcript) — the seam's policy, kept above the SDK |
| SDK error on transcription | `VoccaError.transcriptionFailed(identity, underlying:)` — attributable, never swallowed |
| Second `prepare` | No reload (load state); warm load-once |
| `offlineMode` not readable | The SMOKE step carries the assertion (stated honestly, acceptance 7) |
| The runner cannot run the model | The spike's NO-GO verdict; the real-engine suite is founder-hardware/smoke, CI runs the seam tests — the SMOKE_CHECKLIST fallback, documented, not silent |

## 3. Agent execution notes

**Checkpoints:** after Phase 0 (the verdict is the deliverable — record it, do not let it
dangle in a workflow run), after Phase 1 (the core is headless and green), after Phase 2
(the lints are the point: H8b must fail in both directions; the module move must be the
reviewed edit the lint demands).

**Ask before proceeding** if: the adapter needs FluidAudio names outside `ParakeetEngine.swift`
(the answer is no — put the name in the adapter or behind the mapper's primitives); the
module-boundary lint's negative control does not cover the moved module; the spike's verdict
contradicts this plan's phase order.

**Do not** weaken any existing test, add a coverage-guard exclusion, import a Vocca module
other than `VoccaCore` from `VoccaASR`, name FluidAudio in more than one `Sources/` file,
call any FluidAudio download API (only `load`), or leave the spike verdict unwritten.

**Not in this plan:** the bridge (`asr-seam` Phase 3, gated), the fixture suite/WER/CI
cache (`fixture-suite`), the engine picker (C3), streaming (C7), the download UI
(`download-ui`).
