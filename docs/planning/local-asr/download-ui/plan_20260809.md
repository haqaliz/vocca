## 0. The organising constraint

`VoccaUI` may import only `VoccaCore` among Vocca modules — so the store stays unreachable
from the UI, and the contract between them is a **Core-owned seam**. Every decision in this
aspect is on the testable side of a line: the reducer and the session adapter run headless
forever; the window is thin glue "executed by nothing in CI", stated plainly (the same line
as the tap adapter and the Parakeet adapter).

---

## 1. Phases

### Phase 1 — The seam and the adapter

**RED first** — `Tests/HarnessTests/ModelDownloadSessionTests.swift`:
- Happy path: `StoreModelDownloadSession` over the stub transport + temp store → events are
  monotonic progress ending in `.committed`.
- Failure: corrupt-serving transport → `.failed` naming the cause; store not present.
- Skip: `cancel()` mid-download → `.cancelled`; the `.part` survives; a subsequent
  `downloadIfMissing` resumes from it.

**Then implement:** `Sources/VoccaCore/ModelDownloadSession.swift` (the event enum + the
protocol — stdlib-only, Core imports nothing new) and
`Sources/VoccaASR/Models/StoreModelDownloadSession.swift` (an actor: `start()` drives
`store.downloadIfMissing(manifest:transport:onProgress:)`, feeding events; `cancel()`
cancels the driving task; `ModelDownloadError.interrupted` maps to `.cancelled` — the skip
semantics — everything else to `.failed`).

**Validation:** suite green; floor raised. **Commit:** `Add the model download session seam and its store adapter`

---

### Phase 2 — The reducer and the window

**RED first** — `Tests/HarnessTests/DownloadStateReducerTests.swift`: the transition table
from the spec (clamping, terminal states, no-regression, cancelled → skipped).

**Then implement:** `Sources/VoccaUI/DownloadState.swift` (the enum + pure reducer) and
`Sources/VoccaUI/DownloadProgressView.swift` (SwiftUI: progress bar, status text driven by
the reducer, Skip button calling `cancel()`), plus a small `DownloadWindow` (NSWindow +
NSHostingView) — the window is thin glue, executed by nothing in CI, stated in its doc
comment. `VoccaUI` gains `SwiftUI`/`AppKit` imports — allowed (the boundary rule restricts
*Vocca* imports, not system frameworks; `ModuleBoundaryTests` stays green).

**Validation:** suite green (the reducer's table is the decision); floor raised.
**Commit:** `Add the download progress window over the tested state reducer`

## 2. Failure modes to handle explicitly

| Situation | Required behaviour |
|---|---|
| User hits Skip mid-download | `.cancelled` → UI shows skipped; `.part` preserved; engine answers `modelUnavailable` honestly |
| Download fails | `.failed(reason)` — the window shows the reason, never a silent spinner |
| Progress goes backwards | Clamped — the reducer never regresses the bar |
| Events after `.committed` | Ignored — the reducer is terminal-state-safe |
| The store is already present | `start()` yields `.committed` immediately (the store's no-op) |

## 3. Agent execution notes

**Checkpoints:** after Phase 1 (the adapter's event stream proven headless), after Phase 2
(the reducer table is the decision; the window is glue).

**Ask before proceeding** if: the UI needs a store type (the answer is no — the seam exists
precisely so it cannot); the reducer needs to be async (it does not).

**Do not** weaken any existing test, add a coverage-guard exclusion, import a Vocca module
other than `VoccaCore` from `VoccaUI`, or put a decision in the window.
