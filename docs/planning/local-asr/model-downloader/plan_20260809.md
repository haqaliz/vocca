## 0. The organising constraint

The zero-network invariant is the product's promise, and the downloader is the hole in it
by design. The entire aspect is organised around keeping that hole **one file wide**: the
transport seam, the confinement lint, and the rule that `isPresent` means *verified*.

Two decisions up front, so the agents do not relitigate them:

- **`VoccaASR` stays a leaf.** The downloader is engine-agnostic machinery (`engineID:
  String` directory keys) and imports no Vocca module — Foundation + CryptoKit only. The
  `EngineIdentity` binding is `parakeet-engine`'s. `Package.swift` is untouched: new files
  land inside the existing `Sources/VoccaASR/` target directory.
- **The manifest content is data, the machinery is code.** Tests build synthetic manifests
  through the same JSON loader the real manifest will use. The real manifest
  (`FluidInference/parakeet-tdt-0.6b-v3-coreml` file list + SHA-256s) is generated from the
  founder's first real download during the F1 spike, and lands in
  `Sources/VoccaASR/Models/Manifests/` as a checked-in JSON file. Nothing in this plan
  needs that content.

## 1. Phases

### Phase 1 — Manifest and store

**Goal:** the data model (`ModelManifest`) and the presence truth (`ModelStore`), with
atomic-verified semantics.

**RED first** — `Tests/HarnessTests/ModelManifestTests.swift` +
`Tests/HarnessTests/ModelStoreTests.swift`:
- Manifest: a valid synthetic JSON decodes; near-misses are rejected — non-hex digest,
  wrong-length digest (not 64 hex chars), duplicate file names, unknown fields, missing
  engineID/version (the `CapturedAudioFormat` near-miss pattern).
- Store (temp root URL per test, never the real Application Support):
  - `isPresent` is false on an empty root; false while any `.part` file exists; **true only
    after every file verified**; false again if a checksum fails mid-download.
  - The verified marker is written last; once committed, a second `downloadIfMissing` with
    the same version does not touch the directory (immutability, `PRODUCT_SPEC.md:273`).
  - `baseURL(for:)` == `<root>/<engineID>/<version>/` with a trailing-slash-safe join.
- The store is an **actor** (single-flight: a concurrent second call awaits the first —
  test: two concurrent `downloadIfMissing` calls result in one download, asserted by the
  stub transport's call count).

**Files to create:** `Sources/VoccaASR/Models/ModelManifest.swift` (Codable types + JSON
loader + validation),
`Sources/VoccaASR/Models/ModelStore.swift` (actor: root URL, marker, isPresent, baseURL,
`downloadIfMissing` one-flight guard — the download invocation is Phase 2's, so this phase
leaves a clearly-marked seam for it),
`Sources/VoccaASR/Models/ModelTransport.swift` (the seam declaration — the protocol shape
Phase 2 implements; it is declared here so the store's single-flight test can drive a stub
through the real seam), the two test files + `StubTransport` in
`Tests/HarnessTests/ModelTransportTestDoubles.swift` (Phase 1 needs the happy-path and
call-count modes; the failure modes arrive with Phase 2's tests).

**Validation:** `./Scripts/test-with-floor.sh` green; floor raised in the same commit;
`ModuleBoundaryTests` green unchanged (VoccaASR still a leaf — the new files import
Foundation only).

**Commit:** `Add the model manifest and the verified-presence store`

### Phase 2 — Transport seam and the downloader

**Goal:** every download decision — resume, verify, retry, cancel, progress — above a seam;
the only `URLSession` in `Sources/` below it.

**RED first** — `Tests/HarnessTests/ModelDownloaderTests.swift` with `StubTransport` in
`Tests/HarnessTests/ModelTransportTestDoubles.swift` (in-memory byte source; modes: happy,
fails-after-N-bytes, corrupt-bytes, ignores-Range; call counters):
- Happy path: three files download, verify, commit; progress monotonic 0...1 and exactly
  1.0 only after all bytes; `isPresent` true only at commit.
- Resume: transport fails after N bytes → `.part` of size N remains; retry requests a Range
  starting at N (asserted on the stub), writes only the remainder, verifies once, commits.
- Checksum mismatch: corrupt bytes → `.part` deleted, file restarted from zero; after the
  bounded retry limit → `.retryLimitExceeded(file:)`, `isPresent` false.
- Resume refused: a transport that ignores Range (serves the full body) → `.resumeRefused`
  recorded, the file restarts once, commit correct — never a corrupted file assembled from
  a misaligned append.
- Cancellation: cancelling mid-download → `.interrupted`, `.part` preserved, next run
  resumes.
- Errors: every failure leaves `isPresent` false — **no failure state is "present"**.

**Then implement:** `Sources/VoccaASR/Models/ModelTransport.swift` (protocol: ranged,
streaming, byte-counted progress, Sendable) and
`Sources/VoccaASR/Models/DefaultModelTransport.swift` — **the one file in `Sources/` that
may name `URLSession`**, using the async bytes API streamed to the destination file
(never `data(for:)` — the artifact is ~2 GB), Range request headers, byte-counted progress
through a delegate or the async-bytes counting equivalent. And
`Sources/VoccaASR/Models/ModelDownloader.swift` (per-file `.part` lifecycle, SHA-256 via
CryptoKit, delete-and-restart on mismatch, bounded retries, aggregate progress, marker
commit through `ModelStore`, `Task` cancellation).

**Also:** `Sources/VoccaASR/Models/ModelDownloadError.swift` — the error vocabulary from
the spec, each case carrying the file name where it is about a file.

**Validation:** suite green; floor raised in the same commit; strict-concurrency build
clean; the default transport compiles under `-strict-concurrency=complete` (it is not
exercised in CI — that is the founder's first real download and the smoke checklist; its
code is the adapter, its decisions are all above the seam and tested).

**Commit:** `Add the model downloader over an injected transport`

## 2. Failure modes to handle explicitly

| Situation | Required behaviour |
|---|---|
| Transport fails mid-file | `.part` of size N kept; next attempt resumes with a Range from N — never a restart from zero |
| Corrupt bytes | File's `.part` deleted; file restarts from zero; bounded retries; then `.retryLimitExceeded`; `isPresent` stays false |
| Server ignores Range | Detected and recorded (`.resumeRefused`); file restarts once; commit correct — a misaligned append must be impossible |
| Cancellation | `.interrupted`; `.part` preserved; next run resumes |
| Concurrent downloads of the same model | Single-flight — one download, the second caller awaits it (the actor) |
| Disk full / write failure | `.diskWriteFailed`; `.part` left for resume; never a marker, never `isPresent` |
| Bad manifest JSON | `.manifestInvalid`; nothing is downloaded; the store is untouched |
| A verified model's directory already exists | Immutable — never touched, never refetched (`PRODUCT_SPEC.md:273`) |

## 3. Agent execution notes

**Checkpoints:** after Phase 1 (manifest + store contract pinned) and after Phase 2 (the
resume/verify/retry table pinned over the stub). Phase 3's lint must be able to fail in
both directions — a lint that cannot fail when violated is decoration.

**Ask before proceeding** if: a file outside `DefaultModelTransport.swift` needs to name
`URLSession` (the answer is no — put it behind the seam); the downloader needs `VoccaCore`
types (the answer is no — strings only); progress needs to be non-monotonic (it does not).

**Do not** weaken any existing test, add a coverage-guard exclusion, import `VoccaCore` or
any Vocca module from `VoccaASR`, write a hardcoded `~/Library` path anywhere (the root is
injected; the default is computed from `FileManager`), buffer a whole model file in memory,
or touch `Package.swift` (VoccaASR stays a leaf).

**Not in this plan:** the engine binding, the trigger wiring, the download UI, the real
manifest content, load-time re-verification — the next aspects own those.
