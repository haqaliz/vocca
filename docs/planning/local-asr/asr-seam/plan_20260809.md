## 0. The organising constraint

`VoccaCore` imports nothing — `CoreBoundaryTests` enforces it with a forbidden-framework
list and a rule that the core has no mutable global state. The seam must be implementable
by *any* adapter (FluidAudio now, whisper.cpp at C3, a hosted provider later) and testable
headlessly: no model, no network, no microphone. That is what makes this aspect the first:
**every line of it runs in CI, now and ever.** The only part that cannot — the bridge —
depends on a type the `audio-capture` branch defines, and it is the last phase.

The one deliberate deviation to record up front: `ASREngine` will have exactly **one**
implementation for the duration of this capability (the stub in tests does not count — the
repo's rule is a seam needs two *shipped* implementations, `CAPABILITY_ROADMAP.md:27`). That
is the accepted C1-pattern deviation, time-bounded by C3 (`audio-capture-hotkey/prd.md:400-404`).

## 1. Phases

### Phase 1 — The vocabulary

**Goal:** the types `ARCHITECTURE.md` §4 names, as code, in `VoccaCore`, with their
contracts pinned.

**RED first** — `Tests/HarnessTests/ASRVocabularyTests.swift`:
- `EngineIdentity` round-trips its three fields; `id` distinguishes engines; `isLocal`
  is carried (the egress-badge flag, `ARCHITECTURE.md:152-156`); `Hashable`/`Codable`
  work (directory key + persistence at C8/C14).
- `AudioBuffer` accepts exactly 16 kHz mono: init at 16 000 × 1 succeeds; a validity
  predicate rejects every near miss — 44 100 Hz, 48 000 Hz, 2 channels, 0-sample-rate
  (the `CapturedAudioFormatTests` near-miss pattern); `audioDuration ==
  samples.count / 16_000`.
- `Transcript` requires an `engine` (non-optional — compile-time), carries `text`,
  `segments`, `isFinal`, `audioDuration`, and `missingSampleCount` **defaulting to 0**
  (complete unless told otherwise; the default must not be skippable into a lie — the
  memberwise init should not allow omitting it for incomplete audio, so give it an
  explicit default that tests pin as "0 means complete").
- `TranscriptSegment` carries `text`, `range`, and `confidence: Float?` (nil is the
  "engine exposes none" signal, `ARCHITECTURE.md:146-150`).
- `VoccaError` has `modelUnavailable(EngineIdentity, reason: String)` and
  `transcriptionFailed(EngineIdentity, underlying: Error)` — and the vocabulary tests
  assert the engine identity is *in* both cases (the error must be attributable too).

**Files to create:** `Sources/VoccaCore/EngineIdentity.swift`,
`Sources/VoccaCore/AudioBuffer.swift`, `Sources/VoccaCore/TranscriptSegment.swift`,
`Sources/VoccaCore/Transcript.swift`, `Sources/VoccaCore/VoccaError.swift`,
`Tests/HarnessTests/ASRVocabularyTests.swift`.

**Discipline:** every file carries the Apache-2.0 header (`LicenseHeaderTests`); `VoccaCore`
imports nothing (no Foundation is not required — Foundation is allowed; *no Vocca module, no
system audio/CoreML/graphics framework*); `CoreBoundaryTests` must stay green unchanged —
if a new type needs a system import beyond what the core already uses, stop and ask.

**Validation:** `./Scripts/test-with-floor.sh` — suite green, floor raised in the same
commit (`MINIMUM_EXECUTED_TESTS` + the ledger line), headless job in CI would pass.
Expected new tests: ~8.

**Commit:** `Add the ASR vocabulary to the core, with the completeness count on the transcript`

### Phase 2 — The seam

**Goal:** `ASREngine` as `ARCHITECTURE.md:219-229` specifies, with the batch streaming
default and the empty-buffer policy pinned.

**RED first** — `Tests/HarnessTests/ASREngineSeamTests.swift`, with `StubEngine` in
`Tests/HarnessTests/ASRTestDoubles.swift`:
- A stub implements `identity`, `supportsStreaming` (false), `prepare()`, `transcribe(_:)`
  — and **not** `stream` — yet satisfies the protocol: the batch default exists.
- **Attribution (the C2 acceptance's identity clause, `CAPABILITY_ROADMAP.md:60`):** the
  stub's `transcribe` returns a `Transcript` whose `engine == stub.identity`; the field is
  non-optional so mis-attribution is structurally impossible. A second stub with a
  different `id` produces a different `engine` — the C3 swap test's seed.
- **Empty buffer (PRD M3):** `transcribe(AudioBuffer(samples: []))` returns a *valid empty*
  `Transcript` — `text == ""`, `audioDuration == 0` — and does not throw.
- **Batch default (constraint 4):** feeding the inherited `stream` three chunks yields
  exactly one final `Transcript` whose text equals the concatenation of what the stub would
  transcribe; `isFinal == true` on the last element and the stream terminates.
- **Sendable:** the protocol is `Sendable`; the stub and its transcript cross actor
  boundaries in a test that calls `transcribe` from a `Task.detached`.
- **`prepare()` idempotence contract:** documented on the protocol; the stub counts calls
  and the test asserts `transcribe` does not implicitly require a second prepare (the
  engine owns the policy; the seam only states it).

**Files to create:** `Sources/VoccaCore/ASREngine.swift` (protocol + doc comments carrying
the §4 and §5 cross-references; the batch-default extension in the same file),
`Tests/HarnessTests/ASRTestDoubles.swift`, `Tests/HarnessTests/ASREngineSeamTests.swift`.

**Protocol shape** (from `ARCHITECTURE.md:219-229`, verbatim intent):

```swift
public protocol ASREngine: Sendable {
    var identity: EngineIdentity { get }
    var supportsStreaming: Bool { get }
    func prepare() async throws
    func transcribe(_ buffer: AudioBuffer) async throws -> Transcript
    func stream(_ chunks: AsyncStream<AudioBuffer>) -> AsyncThrowingStream<Transcript, Error>
}
```

The extension provides `stream` by buffering all chunks into one `AudioBuffer` and calling
`transcribe` — the documented batch default. `supportsStreaming` stays `false` until C7
(`ARCHITECTURE.md:226-228`); no engine at C2 implements `stream` directly.

**Validation:** suite green via `test-with-floor.sh`; floor ratcheted; `ModuleBoundaryTests`
unchanged and green (VoccaASR still a leaf; the seam is Core's).

**Commit:** `Add the ASREngine seam and its batch streaming default`

### Phase 3 — The bridge (GATED on the `audio-capture` merge)

**Goal:** the completeness link (I1). The captured buffer's `refusedSampleCount` becomes
`Transcript.missingSampleCount`; the conversion lives in `VoccaAudio` (the adapter that
produced the audio, spec constraint 9).

**⛔ Gate:** this phase executes only after `feat/audio-capture/aliz` has merged into
master and this branch has been rebased/merged onto it — the captured Buffer type with
`refusedSampleCount` (`plan_20260806.md` Phase 5) is the input. If the merge has not
landed when the agent reaches this phase, **stop and ask** — do not invent the captured
type, do not substitute a test double for it in production code.

**RED first** — `Tests/HarnessTests/CapturedToInterchangeBridgeTests.swift`, three clauses
(the C1 Phase-5 RED shape, `plan_20260806.md:318-322`):
1. A source whose ring refused N samples converts to a `Transcript` with
   `missingSampleCount == N` — the number, not a flag.
2. A source that refused none converts to `missingSampleCount == 0`.
3. An empty captured buffer converts to a valid empty `Transcript` (`text == ""`,
   `audioDuration == 0`) with `missingSampleCount` carried through unchanged.

**Files to create/modify:** a conversion (initializer or extension) in
`Sources/VoccaAudio/` mapping the audio-capture Buffer type to `VoccaCore.AudioBuffer`,
plus the tests. `VoccaAudio` already imports `VoccaCore` at this point (it becomes an
adapter at audio-capture Phase 5 — the merge provides the `Package.swift` change).

**Also in this phase:** amend `ARCHITECTURE.md` §4 — the `Transcript` vocabulary gains
`missingSampleCount` with the one-line rationale (I1; short audio is visible, never
masquerading), and any §4 drift from what shipped is corrected (the C1 M37 pattern,
`audio-capture-hotkey/prd.md:242`). Reviewer: aliz.

**Validation:** suite green; floor ratcheted; the zero-network probe still green unchanged
(no network code in this phase).

**Commit:** `Carry the capture-completeness count into the transcript`

## 2. Failure modes to handle explicitly

| Situation | Required behaviour |
|---|---|
| Engine not prepared | Seam documents it; engines own the policy. The stub asserts the documented shape (no implicit re-prepare). Real engine policy is `parakeet-engine`'s |
| Empty / near-empty buffer | Valid empty `Transcript`, never an error (PRD M3) |
| Sample rate ≠ 16 kHz at the seam | Trapping init + testable validity predicate; the near-miss tests pin every plausible wrong rate |
| Engine identity omitted | Structurally impossible — `Transcript.engine` is non-optional; the tests assert it |
| Captured audio short by N | `Transcript.missingSampleCount == N` — visible, countable, never a silent `0` (Phase 3) |
| A new Core type needing a system framework | Stop and ask — `CoreBoundaryTests` is the contract |

## 3. Agent execution notes

**Checkpoints:** after Phase 1 (vocabulary complete, floor raised) and after Phase 2 (seam
exists, attribution pinned). Phase 3 does not start without the merge — see the gate.

**Ask before proceeding** if: a vocabulary type needs a system import Core doesn't already
use; the protocol shape deviates from `ARCHITECTURE.md:219-229`; the batch-default stream
would need allocation-free or realtime considerations (it must not — it is consumer-side).

**Do not** weaken any existing test, add a coverage-guard exclusion, let `FluidAudio` or any
model type enter this aspect (that is `parakeet-engine`'s), or copy the asserting-`deinit`
mistake (none of these types needs a `deinit` — if one appears, the design is wrong).

**Not in this plan:** the downloader, the Parakeet engine, the fixtures/WER/CI cache, the
download UI, the probe extension — those are the next four aspect plans under
`docs/planning/local-asr/`.
