## 0. The organising constraint

The C2 acceptance's suite needs a model; CI's ability to hold one is the **pending F1
verdict**. So this aspect is organised around one rule: **everything above the real-model
line runs in CI now, and the real-model line is env-gated with a visible skip — never a
green that proves nothing, never a test that cannot run.** The scorer, the harness, the
fixtures, the provisioning — all land; the model's presence is a variable, not an
assumption.

## 1. Phases

### Phase 1 — The fixtures and the scorer

**Goal:** the measurement's raw material (five 16 kHz mono clips + goldens) and the pure
scorer — both before any engine runs.

1. **Fixtures** (deterministic TTS stand-ins, per `spec.md`): generate `accented.wav`
   (a second `say` voice), `noisy.wav` (clean + synthetic noise at a fixed SNR, mixed once
   and checked in), `sixty-second.wav` (a ~150-word paragraph), `two-hundred-ms.wav` (one
   word); reuse the existing `spike-clip.wav` as `clean.wav`'s stand-in (rename or alias);
   write the five `.txt` goldens and `FIXTURES.md` (provenance, the stand-in labeling, the
   provisional tolerances' home).
2. **`WER`** (`Tests/HarnessTests/WER.swift`) — a pure enum with
   `compute(reference:hypothesis:)`: normalize (lowercase, split on non-alphanumeric, drop
   empties), word-level Levenshtein, WER = edits / reference count; empty reference → 0 iff
   hypothesis empty else 1. `WERTests.swift` — table-driven over every edit class + the
   normalization cases + the empty rule.

**Validation:** suite green; floor raised. **Commit:** `Add the fixture stand-ins and the WER scorer`

### Phase 2 — The harness and the parameterized seam-level tests

**Goal:** one test body, parameterized over engines, proven end-to-end with stubs.

- `Tests/HarnessTests/ASRFixtureSuite.swift`: `loadFixtures()` (discover `*.wav` + matching
  `.txt` under `Tests/Fixtures/`; wav → `AudioBuffer` at 16 kHz mono — reuse the spike
  probe's AVFoundation read, moved into the harness; a malformed fixture is a loud failure,
  not a skip) and `evaluate(_ engine:) async throws -> [FixtureResult]` (per-fixture WER +
  transcript + engine identity).
- `Tests/HarnessTests/ASRFixtureHarnessTests.swift` — parameterized over two stubs: a
  golden-echoing stub (WER 0 everywhere, attribution asserted) and an **imperfect stub**
  (drops every third word — its per-fixture WER is asserted to equal the scorer's own
  computation over the golden; this is what proves the plumbing without a model). Plus the
  loader's failure mode (a missing golden fails loudly).

**Validation:** suite green; floor raised. **Commit:** `Add the parameterized ASR fixture harness`

### Phase 3 — The env-gated real-engine run and the provisioning script

**Goal:** the C2 acceptance's real-number half, runnable on any machine with a model — and
the script that makes a model exist in Vocca's shape.

- `Tests/HarnessTests/ParakeetEngineWERTests.swift` — env-gated:
  - `guard let modelDir = ProcessInfo.processInfo.environment["VOCCA_MODEL_DIR"]` else
    `throw XCTSkip("set VOCCA_MODEL_DIR to a store-shaped version directory ...")`.
  - Builds `ModelStore(rootURL: parent)` + the shipped manifest (read from
    `Sources/VoccaASR/Models/Manifests/`), the engine with the default transport and clock.
  - `prepare()` → five fixtures → per-fixture WER within the **provisional** tolerances
    (clean ≤ 0.10, accented ≤ 0.12, noisy ≤ 0.20, 60 s ≤ 0.10, 200 ms ≤ 1 substitution —
    in one place, per spec acceptance 6); asserts `ModelHub.offlineMode == true` after
    init; asserts `Transcript.engine == ParakeetEngineIdentity.parakeet` on every result.
- `Scripts/provision-asr-fixtures.sh` — given a source model directory (FluidAudio-shaped or
  any directory holding the TDT v3 int8 files: Preprocessor, Encoder, Decoder,
  JointDecisionv3 `.mlmodelc` bundles + `config.json` + the vocab), writes the Vocca-shaped
  install: `<root>/<engineID>/<version>/<sdkDirectory>/…`, the verified marker, and the
  SHA-256 manifest JSON at `Sources/VoccaASR/Models/Manifests/parakeet-tdt-0.6b-v3-1.json`;
  prints the `VOCCA_MODEL_DIR` value. Idempotent (re-running re-verifies).
- A headless test of the script's output shape: `ModelProvisioningTests` — runs the script's
  *copy+manifest logic* against a temp dir of known bytes (the script's core is a small
  Swift driver? — no: the script is shell; the test re-implements? **Decision: the script
  stays shell and its output is verified by the env-gated test on the founder's machine;
  in CI, a fixture-less shape test constructs a manifest + marker by hand and asserts the
  engine's `prepare()` path reaches the loader** — the store's contract already covers the
  layout; this aspect pins the manifest→load directory resolution via the shipped manifest's
  presence check only. Stated plainly in the review: the script's output is verified by
  smoke, like every other human-run provisioner in this repo.)

**Validation:** suite green (the real-engine test skips visibly); floor raised.
**Commit:** `Add the env-gated Parakeet WER run and the model provisioning script`

## 2. Failure modes to handle explicitly

| Situation | Required behaviour |
|---|---|
| No model (env var unset) | Visible XCTSkip naming the variable — never a silent pass |
| Malformed fixture or missing golden | Loud failure in the harness — a suite that cannot measure must not read as green |
| Real engine WER exceeds a provisional tolerance | The env-gated test fails loudly on the fixture that missed — the number is the gate |
| The stand-ins' TTS cleanliness skews tolerances | Documented in `FIXTURES.md`; numbers are provisional by decision and live in one place |
| The script's source lacks a required file | The script fails listing what is missing — no half-install |

## 3. Agent execution notes

**Checkpoints:** after Phase 1 (the scorer's table is the decision), after Phase 2 (the
imperfect-stub assertion proves the plumbing), after Phase 3 (the skip is visible in the
log, not silent).

**Ask before proceeding** if: the harness needs a network or a model (the answer is no —
stubs only); the tolerances need adjusting before the founder's first run (the answer is
no — they are provisional by decision and stay in one place).

**Do not** weaken any existing test, add a coverage-guard exclusion, make the env-gated
test silently pass without a model, or commit the real manifest before the provisioning
script generates it.
