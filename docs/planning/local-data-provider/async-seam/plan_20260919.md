# Implementation plan — `async-seam` (2026-09-19)

Card: `docs/planning/_card/issue.md` (read the scope-change block first)
Predecessor: `action-safety-spine`, merged `397bfd1`, floor **2551**

**Aspect 1 of 3.** Make `ActionProvider` async so a provider whose work is asynchronous can
exist at all. Ships **no new provider** — that is aspect 2. Landing the contract change
separately keeps the two reviewable apart.

---

## 0. Why (put the short form in the doc comment)

`describe` and `invoke` are synchronous. The audit store is an actor with `async throws`
methods, and a `nonisolated` synchronous witness cannot await an actor — so the second real
implementation **cannot be written** against the shipped contract. The C12 D1 route
(actor + `nonisolated` witness) works only when the underlying work is synchronous, as AX is;
for file I/O, MCP over stdio, or a subprocess it is not.

Guardrail 7 found this on its first real exercise, which is what it is for.

---

## 1. The change

```swift
func describe(_ invocation: ActionInvocation) async -> ActionSummary
func invoke(_ invocation: ActionInvocation, confirmation: ActionConfirmation) async -> ActionOutcome
```

**`async`, NOT `async throws`.** This is load-bearing and must be stated in the doc comment:
failure stays a **returned value** (`ActionOutcome.failed(reasonKey:)`) precisely so an omitted
`catch` cannot silently drop an audit record. Slice 1's property survives verbatim; adding
`throws` would destroy it.

`ActionGate.submit` becomes `async` — it awaits both call sites
(`ActionGate.swift:328`, `:348`).

## 2. Phases

### Phase 1 — RED

**Files:** `Tests/HarnessTests/ActionSeamTests.swift`, `Tests/HarnessTests/ActionGateTests.swift`

Change the existing tests to `await` the seam and the gate. RED here is a **compile failure**
against a still-synchronous protocol — the established precedent.

Add **two new tests** that only become expressible with this change, so the aspect is not a pure
refactor:
1. **A provider that genuinely suspends is usable.** A stub whose `invoke` awaits something
   (e.g. a `Task.yield()` or an injected continuation) can be driven through the gate and
   returns its outcome. This is the capability the aspect exists to add; assert it directly.
2. **Suspension does not break the refusal.** A destructive invocation against a *suspending*
   provider, submitted without a token, is still refused and the provider's invoke counter
   still reads zero. The refusal must not become a race.

**Commit.** `async-seam: pin the asynchronous ActionProvider contract — RED against a synchronous seam that cannot serve an actor-backed provider`

### Phase 2 — GREEN

**Files:** `Sources/VoccaCore/Actions/ActionProvider.swift`,
`Sources/VoccaCore/Actions/NullActionProvider.swift`,
`Sources/VoccaCore/Actions/ActionGate.swift`

- Both requirements become `async`. Doc comment records **why** (§0) and why **not** `throws` (§1).
- `NullActionProvider`'s witnesses become `async`; behaviour unchanged — zero tools, refuses
  everything.
- `ActionGate.submit` becomes `async`, awaiting both call sites.
- **Everything else is unchanged**: the escalate-only policy, the `internal` init, the
  never-read ordering (a disabled tool is still declined *before* `describe`), the
  refusal-versus-failure distinction.
- No imports in `VoccaCore` — the allow-list is still empty.

**Commit.** `async-seam: ActionProvider and ActionGate become asynchronous (GREEN)`

### Phase 3 — the dependents

**Files:** `Tests/HarnessTests/ActionProviderStubs.swift`,
`Sources/VoccaNetworkProbe/ActionAuditDrive.swift` (only if it touches the seam),
`Tests/HarnessTests/ActionAuditStoreTests.swift` (only if it drives the gate)

- `RecordingActionProvider` becomes async. **Keep `describe` and `invoke`/`execute` counted
  separately** — that separation is what makes the dry-run assertion expressible.
- Keep the fail-if-invoked mode working, and keep its self-check that watches it actually fail.
- If the probe drive calls the gate, update it; if it only drives the store, leave it alone.

**Commit.** `async-seam: carry the asynchronous contract through the stubs and the probe drive`

### Phase 4 — floor ratchet

Integrator-owned. Count from the script's own parse. Expect **+2** (the two new tests); a pure
signature change adds none.
