## 2. Implementation phases

### Phase 1: Headless benchmark + gate mechanism

- **Goal:** the harness proves the span contract (B1) and the gate's mechanism (B2) in CI.
- **Files:**
  - `Tests/HarnessTests/LatencyBenchmarkTests.swift` (RED first):
    - a harness that composes the route like `DictationCycleDrive` (root + stub engine +
      fake injector + injected `TestClock`-style clock) and replays ≥ 3 fixture-derived
      cycles (read WAV bytes via the existing fixture loader; different lengths: e.g. the
      200 ms, the clean, and the 60 s fixture);
    - B1: each record has captureClose+asr+inject spans in order, no cleanup token, engine =
      the stub's identity, spans equal the injected clock's deltas exactly;
    - B2: a `LatencyGate`-shaped check (decide the minimal shape: a pure function over
      `[SessionRecord]` + a threshold table returning pass/fail + per-span verdicts) —
      fast fakes pass; a seeded ~100 ms injector against a ~10 ms inject threshold fails;
      both asserted; the gate's failure must be able to fail the build (a test that fails
      when the gate fails is the mechanism; CI's strict-concurrency warnings-as-errors plus
      the suite is the enforcement).
    - a single named threshold-table constant set (B4) that the gate consumes.
  - New source types if needed: keep them in `Tests/HarnessTests/` (test-only) unless the
    gate must ship in a module — decide: the gate is a CI test concern; a test-only type is
    honest. If it must live in a module, it goes in `VoccaCore` with zero imports — prefer
    test-only.
- **Validation:** filter green (RED watched); floor script green.
- **Commit message:** `Add the headless latency benchmark and the regression gate's mechanism`

### Phase 2: Env-gated real run

- **Goal:** the founder's real numbers, produced with the WER gating discipline (B3, B4).
- **Files:**
  - `Tests/HarnessTests/LatencyBenchmarkTests.swift` (RED first) or a sibling
    `LatencyBenchmarkRealEngineTests.swift`:
    - env-gated: without `VOCCA_LATENCY_BENCH` (new env var) the real-engine benchmark skips
      visibly (`XCTSkip` with the env var named, the `ParakeetEngineWERTests` pattern);
      with it, it requires `VOCCA_MODEL_DIR` (reuse the WER provisioning path), drives the

      beside every row;

      named place and is *recorded*, not gated, until the founder re-baselines (the C3
      tolerances precedent) — but the test asserts the table exists and is referenced.
- **Validation:** without the env var the suite runs and skips visibly; with it (if the
  founder's machine has the model) it prints the numbers. CI runs the skip path.
- **Commit message:** `Add the env-gated real-engine latency benchmark with suppression-state rows`

## 4. Testing strategy

- B1–B6 written first (RED → GREEN → REFACTOR), one commit per phase. No real engine, no
  mic, no network in CI: the harness uses the stub engine + fakes; the real-engine path
  skips without its env var.
- The gate mechanism test is the load-bearing one: a gate that cannot fail proves nothing.

## 5. Environment & privacy

- New env var: `VOCCA_LATENCY_BENCH` (real-engine benchmark, off in CI). `VOCCA_MODEL_DIR`
  reused for model provisioning. Nothing new touches the network or disk beyond the existing
  model/journal paths; the ledger remains in-memory.

## 6. Edge cases & error handling

| Case | Behaviour |
|------|-----------|
| Env var absent | Real benchmark skips visibly; CI green on the skip path |
| Env var present, model absent | Runner fails loudly with the provisioning instructions (the WER pattern) |
| Suppression in force during a run | Every printed row carries the state; a throttled row is never presented as clean |
| Gate fails | The mechanism test fails → CI red; the failure names the span and threshold |
