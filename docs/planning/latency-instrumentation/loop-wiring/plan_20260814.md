## 2. Implementation phases

### Phase 1: Pipeline records its routes (Core)

- **Goal:** `DictationPipeline` records ASR/inject spans and finalizes on every row of its
  own decision table.
- **Files:**
  - `Tests/HarnessTests/DictationPipelineTests.swift` (RED first, acceptance W1): a new
    suite section driving the table with a real `LatencyLedger`, a hand-moved clock
    (`TestClock` from `SessionTestDoubles.swift`), and a fixed `SessionRecord.ID` (minted by
    the ledger): each of the eight rows → exactly one record, class per the table, spans
    `asr` then `inject` in order, `cleanup` `notPresent`, engine = the fake engine's
    identity, delivered rows carry rung + verified. Absence assertions: recorder == nil
    (defaults) ⇒ route records nothing and returns the same surfaces as today.
  - `Sources/VoccaCore/DictationPipeline.swift` (GREEN): defaulted `recorder` + `clock`
    stored; `route(_:target:sessionID: SessionRecord.ID? = nil)` passes them through; in
    `transcribeAndInject`, when all three are present: measure the ASR span around
    `engine.transcribe`, record it with `transcript.engine`; record the inject span from
    `result.elapsed`; finalize on every return path (the guards at
    `DictationPipeline.swift:160,180` included) with the table's class; the two
    `return .idle` rows that predate any engine work (`:147` empty buffer, cancelled
    outcome `:139`) finalize too (emptySkip / aborted). The cleanup span is never recorded —
    the record carries it as `notPresent` by construction.
- **Validation:** filter green (RED watched first); `Scripts/test-with-floor.sh`.
- **Commit message:** `Record the dictation pipeline's routes into the latency ledger`

### Phase 2: Router begin/finalize + capture-close at the source

- **Goal:** the loop's session lifecycle is closed — begin at `.opening`, finalize on every
  terminal, capture-close measured on the stop path.
- **Files:**
  - `Tests/HarnessTests/DictationLoopTests.swift` (RED first, W2): with the recorder wired
    into the composed root, a delivered cycle leaves exactly one record (class `delivered`);
    a `captureUnavailable` cycle leaves one `failed`; an Esc-cancelled cycle leaves one
    `aborted`; after each, the ledger's snapshot equals the finalized set (nothing
    in-flight). The existing composed-root fakes are reused.
  - `Tests/HarnessTests/MicrophoneSourceTests.swift` (RED first, W3): injected recorder +
    fixed ID ⇒ `endCapture()` records a `captureClose` span whose elapsed equals the fake
    graph's `stop` duration; absent recorder/ID ⇒ nothing recorded.
  - `Sources/VoccaBootstrap/AppBootstrap.swift` (GREEN): `LatencySessionBox` (a
    `@unchecked Sendable` final class holding `SessionRecord.ID?`, doc-commenting the

    the box + router state; `.captureUnavailable` finalizes `failed` and clears; the
    `.ended` task passes the ID to `route` and the no-pipeline branch finalizes `failed`;
    after the route returns the box/router ID is cleared. `DictationLoopRoot.configure`
    wires the recorder, the clock (`ContinuousMonotonicClock`), and the box into the
    pipeline and the source.
  - `Sources/VoccaAudio/MicrophoneSource.swift` (GREEN): defaulted `recorder` +
    `sessionIDProvider` inits; `endCapture()` measures `graph.stop()` on its caller side and
    records `captureClose` when both are present.

## 4. Testing strategy

- All acceptance tests (W1–W6) are written before their code — RED → GREEN → REFACTOR, one
  commit per phase. Reuse existing fakes and doubles (`TestClock`, graph fakes, probe
  fakes); add no new test-double types unless a phase requires it.
- No real engine, no mic, no network, no Accessibility anywhere: the composed root in tests
  drives fakes exactly as `DictationLoopTests`/the probe do today.
- The floor script is the gate after every commit (floor 836; expect ~855+ after
  core-ledger's 19 new tests plus this aspect's additions).

## 5. Environment & privacy

- No env vars, no external tools, no network. The ledger records durations and classes only
  — never audio, never text, never transmitted (the interposer asserts the cycle's zero
  `connect(2)`). Nothing new writes to disk.

## 6. Edge cases & error handling

| Case | Behaviour |
|------|-----------|
| `.opening` then `.captureUnavailable` | Router finalizes `failed`, clears ID — no in-flight record |
| `.ended` with no pipeline installed | Router finalizes `failed` before the `.exhausted` panel |
| Esc during TRANSCRIBING | The cancelled route finalizes `aborted` (its own `Task.isCancelled` guards) |
| Empty press / empty transcript | Route finalizes `emptySkip` |
| Recorder/clock/sessionID absent | Route behaves exactly as before (surfaces identical) — absence assertions in W1 |
| ID box with a second concurrent session | Impossible by the machine's single-session invariant; documented on the box |
| Duplicate span / double finalize | The ledger refuses loudly (`Bool` returns); W1's one-record-per-row assertions would fail |

## 8. Executed deviations (recorded after the run, 2026-08-14)

- **P1 — stored clock type is `(any MonotonicClock & Sendable)?`.** Swift 6 rejects a
  non-Sendable existential in a `Sendable` struct's stored property (`DictationPipeline` is
  `Sendable`; `MonotonicClock` has no `Sendable` requirement). The root's
  `ContinuousMonotonicClock` conforms, so the wiring is unaffected.
- **P1 — attribution is per-row, not per-class.** The engine identity is non-nil on every
  row that *reached* transcribe (including `aborted`/`emptySkip` classes), nil only on the
  three never-asked rows — matching `SessionRecord`'s own doc ("nil only for the paths that
  never asked the engine"), which wins over the plan's shorthand.
- **P1 — the table drives 10 executions**, not 8: delivery over all three rungs, the
  failsafe row split held/nothing-held, and cancellation exercised at all three guard
  positions.
- **P2 — W2 cycles drive press and release as separate turns** (drain until the box holds
  the minted id before key-up), because the mint is an actor hop and the capture-close span
  at key-up requires it to have landed — modelling the real key-down-to-key-up gap.
- **P2 — capture-close determinism** via a fake graph whose `stop()` advances the injected
  `TestClock` by a fixed 7 ms; the span's hand-over task is ordered before finalize with a
  main-actor barrier task (a bare `Task.yield()` was a hint, not a barrier — a 1-in-5 flake
  caught and fixed).
- **P4 — `describe()` renders only recorded spans**, so "cleanup `notPresent`" is asserted
  as the *absence* of the cleanup token in the PROBE-LATENCY payload (cleanup is never
  recorded; W1's "never fabricated" holds by construction).
- **Phase 5 outcome:** no fixes were needed — the floor (869), `OwnershipGraphTests`, the
  realtime set, and the boundary lints all passed with zero edits. No Phase-5 commit.
