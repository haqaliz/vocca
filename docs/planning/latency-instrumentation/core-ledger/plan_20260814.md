## 1. Project setup checklist

- **No new package target, no `Package.swift` change, no new dependency.** All new files
  live in the existing `VoccaCore` target (`Sources/VoccaCore/`) and its existing test
  target (`Tests/HarnessTests/`). No `PackageManifest.swift` update is needed.
- Toolchain: the repo's Swift 6 package; every validation runs in the worktree root.
- Fast cycle: `swift test --filter <SuiteName>`; authoritative gate at each phase end:
  `Scripts/test-with-floor.sh` (floor 836, strict concurrency — any warning fails, and the
  script also compiles the `Tools/` measurement harnesses).
- **License headers required on every new file** (`LicenseHeaderTests`): copy the Apache-2.0
  header verbatim from an existing file.
- **Forbidden tokens in `VoccaCore`** (lints, `Tests/HarnessTests/CoreBoundaryTests.swift`):
  zero imports (the allow-list is empty) — new files must have **no `import` statements**;
  no `@discardableResult`; no `@MainActor`, `@unchecked Sendable`, `@globalActor`,
  `nonisolated(unsafe)`, or stored `static var`; no `ContinuousClock`/`SuspendingClock`
  reads (doc comments mentioning them are fine — comments are stripped). Time enters only
  through the injected `MonotonicClock` (`Sources/VoccaCore/MonotonicClock.swift`).

## 2. Implementation phases

### Phase 1: Span and outcome vocabulary

- **Goal:** The pure vocabulary — `LatencySpan` with its presence state and `SessionOutcomeClass`
  with the five classes — compiled, tested, and pinned by the boundary lints.
- **Prerequisites:** none beyond the checklist. The failing tests are written before the
  types exist (RED).
- **Files:**
  - Create `Tests/HarnessTests/LatencyVocabularyTests.swift` (RED first):
    - span name enum is the closed four (captureClose, asr, cleanup, inject), `Sendable`,
      `Equatable`;
    - the cleanup span's presence state: `notPresent` exists and is *distinct* from a
      recorded elapsed of zero — the test asserts `LatencySpan.presence` is an enum with
      `recorded` and `notPresent`, and that `notPresent` never carries a duration;
    - `SessionOutcomeClass` has exactly the five cases — `delivered(rung:verified:)`,
      `failsafeHeld`, `aborted`, `failed`, `emptySkip` — and the delivered case carries an
      `InjectionRung` and a `Bool` (constructed by hand, the `InjectionResult` precedent —
      `Tests/HarnessTests/InjectionVocabularyTests.swift`);
    - the whole file is `Sendable`-clean under strict concurrency.
  - Create `Sources/VoccaCore/LatencySpan.swift` (GREEN): the closed `SpanName` enum, the
    `LatencySpan` struct (`name`, `presence`, `elapsed: Duration`), a `recorded(name:elapsed:)`
    factory and a `cleanupNotPresent` factory so a `0` can never be written by accident.
  - Create `Sources/VoccaCore/SessionOutcomeClass.swift` (GREEN): the five-case enum with
    the `delivered(rung:verified:)` payload. Doc comment states the classes are never
    force-labeled: the P0 first-method-success metric is derived from `delivered` counts.
- **Validation:** `swift test --filter LatencyVocabularyTests` green, then
  `Scripts/test-with-floor.sh` — CoreBoundaryTests must pass **with no edits** (zero imports
  holds).
- **Commit message:** `Add the latency span and outcome-class vocabulary in Core`

### Phase 2: Session record and the recorder seam

- **Goal:** `SessionRecord` (id, outcome class, ordered spans, engine attribution) and the
  `LatencyRecorder` protocol the wiring will record through.
- **Prerequisites:** Phase 1.
- **Files:**
  - Create `Tests/HarnessTests/LatencyVocabularyTests.swift` additions or
    `Tests/HarnessTests/LatencyLedgerTests.swift` (RED first) covering:
    - `SessionRecord` carries an `ID`, a `SessionOutcomeClass`, spans in record order, and
      `engine: EngineIdentity?` — **non-nil whenever a transcription was attempted**; nil
      only for paths that never asked the engine (the C2 attribution rule, scoped honestly:
      `aborted`/`emptySkip` records may carry nil);
    - the `delivered` class carries the rung and verification read off a hand-built
      `InjectionResult` (`rung`, `verified` fields, `Sources/VoccaCore/InjectionResult.swift`);
    - `LatencyRecorder` has exactly three entry points — `beginSession() -> SessionRecord.ID`,
      `recordSpan(_:for:)`, `finalize(id:outcome:engine:)` — all `async`, all `Sendable`;
    - the ID is `Hashable` and stable across calls.
  - Create `Sources/VoccaCore/SessionRecord.swift` (GREEN): the struct, the `ID` wrapper
    (`Hashable`, `Equatable`, stdlib-only).
  - Create `Sources/VoccaCore/LatencyRecorder.swift` (GREEN): the protocol. Doc comment
    states the ledger conformance is the only shipped one and that this seam is what lets
    engines/injector/pipeline record without `VoccaCore` importing anything.
- **Validation:** filter green; `Scripts/test-with-floor.sh`.
- **Commit message:** `Add the session latency record and the recorder seam in Core`

### Phase 3: The bounded ledger actor

- **Goal:** `LatencyLedger` — begin/record/finalize/snapshot/`describe()`, bounded, refusing
  duplicates and out-of-order writes loudly.
- **Prerequisites:** Phase 2.
- **Files:**
  - Create `Tests/HarnessTests/LatencyLedgerTests.swift` (RED first) — acceptance A1, A3,
    A4, A5, A7, A8 from the spec:
    - **A1 closed-set coverage**: a table over all five outcome classes drives
      begin → record (one span per name) → finalize; exactly one record per begin, class
      preserved.
    - **A3 duplicate refusal**: recording a second span with the same name for the same
      session returns a refusal the test asserts (the entry point returns a value —
      `Bool` — so a wiring bug fails in a test, not silently; no `@discardableResult` in
      Core means the caller sees the unused-result warning, which CI turns into a failure).
    - **A4 bounded**: fill past the cap (`maximumRetainedRecords`, a documented
      `static let`, e.g. 512); assert the oldest dropped and the newest retained, and that
      the cap holds after more writes.
    - **A5 pure describe**: `describe()` is deterministic (mint order) and contains every
      session's id, class, span names, and elapseds.
    - **A7 injected clock**: drive the ledger with a hand-moved `MonotonicClock` double (the
      `SessionTestDoubles.swift` / test-doubles precedent) — spans record exactly the deltas
      handed in; the ledger never reads a clock of its own.
    - **A8 isolation**: begin/record/finalize from a non-main `Task` context; strict
      concurrency clean; types `Sendable`.
    - **Edge policy**: finalize twice → second refused; record after finalize → refused;
      unknown id → refused (each asserted; refusals are the loud failure, never a crash, and
      never a silent drop).
  - Create `Sources/VoccaCore/LatencyLedger.swift` (GREEN): the `actor`, the minted `ID`
    counter (actor state — the mutable-global lint permits actors), the bounded array
    (append; on overflow drop-first), the refusal rules, `snapshot() -> [SessionRecord]`,
    and `describe() -> String`. The actor conforms to `LatencyRecorder` (async methods).
- **Validation:** filter green; `Scripts/test-with-floor.sh`.
- **Commit message:** `Add the bounded in-memory latency ledger actor in Core`

## 4. Testing strategy

- Unit tests (the acceptance list in `spec.md` A1–A8) are written **before** each type —
  strict RED → GREEN → REFACTOR, one commit per phase.
- No integration harness, no real engines, no network, no mic: everything here is pure
  stdlib + an injected clock, so the whole aspect runs in CI forever.
- Every phase ends with the full floor: `Scripts/test-with-floor.sh` — the floor number must
  not drop below 836.
- The `delivered(rung:verified:)` mapping test builds `InjectionResult`s by hand (the
  fault-injection precedent from `InjectionVocabularyTests`) — no real injector needed.

## 5. Environment & privacy

- No environment variables, no external tools, no network anywhere in this aspect. The
  ledger is in-memory by construction; nothing here writes to disk. Privacy note for the
  doc comments: the ledger records durations and classes only — never audio, never text.

## 6. Edge cases & error handling

| Case | Behaviour (fails loudly, never silently) |
|------|-------------------------------------------|
| Duplicate span name for a session | Recorder entry point returns refusal; test asserts it; unused-result warning is a CI failure |
| `finalize` called twice for an id | Second refused |
| `recordSpan` after `finalize` | Refused |
| Unknown/forgotten id | Refused (no crash) |
| Ledger at cap | Oldest record dropped; newest retained; cap asserted |
| Cleanup span before C5 | `notPresent`, never `0`, never missing from the record |
| Attribution when no engine was asked | `engine == nil` only on `aborted`/`emptySkip`; the test pins the two allowed nils |
